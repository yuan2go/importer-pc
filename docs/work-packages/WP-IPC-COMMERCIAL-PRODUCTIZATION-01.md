## 1. 目标与完成标准

把已有工业工位参考工程完善为可交付、可配置、可连续操作、可恢复、可维护的桌面产品。用户提出的“逐步安装”和“首次启动选择相机驱动、RCS 组件并填写参数”纳入完整生命周期：客户能完成安装和站点配置；操作员能理解当前状态及下一动作；维护人员能定位问题、升级、备份恢复；交付人员能重复部署并核对准确版本。

本包要求工业级完整闭环，不能以界面原型、按钮空实现、只跑通成功路径、把必需操作留在手工 JSON/命令行或大量 TODO 代替交付。工业级在本包中指责任、权限、事务、故障恢复、版本身份、可操作性和证据完整，不代表获得任何工业认证或已通过真实现场验收。

核心范围是 COMM-00～10。后续商业策略项在第 7 节单独列出，缺少客户决策不阻塞其余工程；真实 SDK、协议和资格缺失只阻塞对应 Production 路径，必须同时交付明确的诊断、受控模拟验证和接入交接。

## 4. 不变的架构与业务边界

1. 保持 Platform、Application、Driver、Component 四类职责。Application 独立拥有主流程、业务状态、守卫和 UI 契约；打包时选业务，一个实例服务多个页面/布局。不能做页面切换即重启连接，或新增通用工作流替代三个独立业务。
2. Sportmaster 左右 reader/投递位独立，扫码取得上游格口，不下 PLC、不加图片展示或长期图库。DirectPlc 与 WcsToPlc 按各自拓扑；DirectPlc 完整 UI 延期保持。Supply/Inspection 兼容入口按原契约，不套用 Parcel 数据和操作。
3. 安装不等于启用，启用不等于资源就绪，就绪不等于允许开工；目录/包、配置修订、连接健康、业务许可分别有来源和时间。
4. 配置沿唯一有效账与候选机制。站点模板和首配草稿没有业务权威；保存参数不自动启动设备，连接检查不提交真实任务，缺 Production 必需能力不回退模拟。
5. 原请求保持原身份、报文、目标、合同和精确实现。Unknown 不自动重发，不用“重新安装”“恢复默认”“重新登录”清除原责任。相同条码可以是不同作业，取得格口不等于实体完成。
6. 程序和受保护维护程序在可信、不可被日常运行身份改写的目录；配置/业务数据/日志各有明确所有权。用户可选程序根必须贯彻全链路权限和路径验证，不能只去掉 ProgramFiles 路径判断。
7. 保留 REQ/BR/CAPI/F/D/RV 编号及来源；真实资格、字段、角色策略、SDK 方法不能推测。沿 [公开范围](../baseline/PUBLICATION.md)交付通用代码、文档与合成数据，不上传客户原稿、生产参数、凭据、私钥、未许可 SDK/字体。

### 5.1 安装与首次运行的产品划分

安装推荐顺序为：欢迎与产品身份 → 程序/数据位置 → 运行账户与组件/依赖 → 检查摘要 → 执行 → 完成。现有向导中填写业务配置来源的能力保留为高级导入或已有部署入口；普通新客户通过产品首配表单完成参数收集。合理默认减少无效步骤，只有条件性必填项才出现；允许返回、保存和继续。

首次配置推荐顺序为：识别新站/已有部署 → 站点信息或受控模板 → reader/相机选择与稳定身份绑定 → 当前 Application 支持的外部组件参数 → 分层检查 → 保存候选 → 显式激活及开工检查。实体设备未就绪不应阻止填参；Production 资格不足不能被“跳过检查”变成可运行。

必须区分操作系统/厂商驱动安装、应用 driver/adapter 包安装、具体设备实例绑定、业务参数配置、部署激活和连接探测。安装器不得提权执行未受信插件来生成表单；没有经确认的驱动再分发或设备枚举能力时显示精确缺口，完成通用安装和配置体验。

### 5.2 配置修复的必须解决项

基线代码的 Pending 激活受 Effective 首次确认状态限制；离线 Stage 仍调用严格部署校验。因此，不能把“已有离线保存”当作完整首次配置闭环。

实施须按 [实现逻辑](../implementation/commercial-productization-01.md)分离草稿、结构/包闭包校验、资格和连接报告、受控激活；设计应用拥有的首次初始化和未确认配置修复转换。保全原 envelope、修订与尝试记录，并在同一所有权下检查原业务责任；有旧请求/原件或身份冲突时保持原恢复规则。不能简单清除 Confirmation、覆写 Effective、选空数据根或放宽 Production 验证换取首次启动成功。

### 5.3 商业化质量要求

交互必须表达加载、空、成功、部分完成、失败、取消、需重启、权限不足和环境缺失；返回页面保留必要草稿/筛选/选择。错误主文案应给出用户可执行动作，技术详情、堆栈及评审编号放到详情或诊断。

耗时安装、查询、导出、探测、恢复离开 UI 线程，具有超时/取消与结果归属；取消和超时不伪称底层设备已停止。当前数据与历史详情各自绑定明确对象和请求代次，迟到结果不覆盖新选择。日志和查询有容量策略，不通过无界缓存、无限轮询或全库导出维持体验。

保留离线工业部署能力：正常安装、启动、首配和维护不依赖云账号或在线商城；不要求 PowerShell。商业签名、厂商驱动和凭据材料按真实来源接入；本包不生成假许可或假生产证书。

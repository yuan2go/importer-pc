# SM 海康原生识码

每台相机在“设置 → 左右相机 → 高级设置 → 识码方式”选择软件识别或海康原生识码。新站默认海康原生识码；已有配置不自动改动，两台相机可以分别选择。保存沿用完整配置草稿、版本防覆盖和原有即时生效守卫，只重连修改的相机；未确认请求等条件下仍要求保存后重启。不自动回退，也不让两套 SDK 同时打开同一相机。

现场只需填写相机 IP 和独立的 RCS 相机编码。序列号显示只读：新 IP 在保存检查时按当前识码方式枚举唯一设备，自动读取并随完整配置保存；已有 IP 和序列号不会在打开设置时重新绑定。同一 IP 更换设备后可明确点“重新读取”，实际采用新身份仍须保存并通过原设备替换守卫。身份读取只枚举设备，不创建采集句柄；未找到、IP 冲突、序列号无效或 SDK 释放失败时保留草稿并停止本次保存。配置保存不代表设备已连接或可以供包。

身份读取的 SDK 所有者由能力工厂持有，只有 `Shutdown` 成功才清除引用。释放失败时，下次读取先对原对象重试释放，不能先初始化另一个对象来掩盖 MVS 的进程级计数；枚举与释放同时失败时同时保留两项错误。运行中读取加入原外部调用排空，运行退出经工厂重试释放；首配维护服务持有自己的工厂，重新读取配置或关闭窗口前排空实际读取并释放。失败保留原服务、窗口和所有者，允许再次退出，不宣称资源已释放，也不通过超时包装器放弃在途原生调用。

SM 首配和日常设置不提供“扫码消息缓冲上限”“待处理作业上限”或“接收与等待限制”页面。相机输入在完成校验、放置判定和作业登记后交给本件独立执行；同一投递位继续处理新鲜的下一件条码，不等待上一件 RCS 返回。已有配置中的作业数量上限不限制 SM 相机或人工新件准入，旧配置原值仍保留。换件仍须当前相机会话的有效证据，同次放置不重复请求；每个原请求、回执及晚到响应保持原身份，不能覆盖下一件结果。内部输入交付、真实存储故障、空间保留和持久化守卫保留，不把它们当作现场需要设置的包裹排队流程。

## 数据与业务责任

原生路线为相机 → `MVIDCodeReader.dll` → 同帧原图、条码及四角位置 → Application 条码规则、放置判定和 RCS 请求。参考旧供包台使用的 `MVID_CR_*` 接口，固定版本 `1.1.4.0_3.6.0_2.2.2`，不是仓库旧驱动的 `MV_CODEREADER_*` 接口。当前只接入 Windows x64、GigE、连续采集和紧密 Mono8 原图。

原生输出的图片属于 SDK，下一次采集前复制；条码、框和图片使用同一次输出。应用不释放 SDK 私有图像指针，销毁句柄成功才释放相机占用。停止采集失败继续尝试销毁，销毁失败保留占用，不伪报停止或自动重开。

原生库已经完成识别，结果在采集线程按顺序处理，不经过可覆盖的“待软件解码帧”槽。等待原图容量时停止，也保留已识别输入的身份与原像素，阻止该源重新启动；释放 SDK 不代表输入已经交付。放稳时间只控制结果进入业务的时机，放置过程仍更新预览；持续不稳时保留约 1.5 秒一次的接收机会。RCS 离线或管理中心未明确触发时只采图，不调用原生识码。

不按条码文字去重，不丢弃 SDK 标记已过滤的候选。两处真实同码仍保留两个框、进入多码拒绝。原生模式接收 SDK 返回的全部码制，不提供软件码制和反色筛选设置；码制选择和反色搜索只适用于软件识别。列表饱和、非法长度/编码/位置等拒收整帧，不截成一个可提交条码。有效原图仍用于预览及漏读画面比对。

同一次放置只请求一次，静止包裹的漏读与识别失败保持原作业卡；相机会话改变后必须重新读到码，才能恢复同一次放置的原结果。空托盘、换码、重连、人工输入及 Unknown 原请求继续由同一个 Application 实例处理。

## 安装依赖

原生路线使用匹配的 MVIDCodeReader 组件、VC++ 2008 SP1 x64、VC++ 2010 SP1 x64 和相机传输驱动。包含 MVID 的完整安装包内置这两份微软官方运行库安装程序，交互安装、静默安装和修复共用同一流程。Windows 授权后检测实际加载能力，已可用的运行库直接跳过，缺失的离线补齐，确认可用后再提交供包台安装登记。共享运行库在卸载供包台后保留。

打包使用 `scripts/package-application.py --mvid-runtime <已获授权的本地运行库目录> --vc-redist <官方运行库安装程序目录>`。也可设置进程环境变量 `IPC_MVID_RUNTIME` 和 `IPC_SM_VC_REDIST`。MVID 目录须包含固定清单中的五个 DLL 及原厂告知文件 `SDK-NOTICE.txt`。脚本核验长度、SHA256 和 AMD64 后写入 `app/desktop` 的 `vendor/hikrobot-mvid`，并把核验后的微软安装程序写入 `prerequisites`。仓库只保存清单、接口和自行编写的配置。

配置文件由项目提供，关闭 SDK 工作目录日志。SDK 及工作目录配置仍须通过现有受保护安装目录和文件完整性检查。运行库不可在进程中更换版本；更新用完整安装包及正常停止/重启流程。未提供原生构建输入的包保留软件识别能力，不能用于原生路线的现场验收。

诊断中的原生识别时间来自 `GetOneFrameTimeout` 调用耗时，包含等待图像，不能与 ZXing 纯解码耗时直接比较。

## 调试

现有 RCS 调试继续使用生效配置，明确点击发送才增加独立请求。相机调试复用当前 MVID 会话的原图、条码及四角位置；管理中心打开时暂停自动供包和识码，明确触发时锁定本轮图片，不换成后续帧。已冻结但确认尚未发送的调试请求不占用生产位置，避免调试图片先保存完成时挡住同帧的正常供包。发送后、结果未确认或存在回执责任时仍按原守卫处理。

开始/结束采集沿用 Application 权限和同源守卫。原生 ABI 没有软件路线的清缓存接口，适配器通过 `GetImageBuffer` 的有界零超时原图读取确认队列已空，不在丢弃缓存时调用 `GetOneFrameTimeout` 识码，避免持续进图时因识码耗时而无法清空。无法确认仍明确失败，不假定切换成功。RCS 不可用及管理中心未明确触发时也使用原图读取保留预览，暂停原生识码；明确触发的调试轮次独立于 RCS 连接。新轮次仍等待采集、解码及缓存边界，不沿用旧帧。这项原生队列行为仍需真实相机验证。

## 验证边界与入口

- `--mvid-reader`：合成原生帧端口，真实 Application、SQLite、环回 RCS；验证两处同码、放稳、漏读保持、防重、重连、空托盘释放及销毁失败。
- `--hikrobot-sdk-editing`：配置模型和 Windows WPF 设置页验证，包含两台相机独立选择及完整草稿保存。
- `python -m unittest discover -s scripts -p test_mvid_runtime.py`：用合成 PE 验证打包清单与失败边界，不含真实 SDK。
- `--mvid-runtime-probe`：在受保护安装目录中验证真实 DLL 版本与两个独立句柄，不绑定相机。开发目录运行会被安装权限检查拒绝，不能据此跳过权限检查。

本机直接 ABI 探针已验证旧项目运行库的版本、两个句柄创建和销毁、设备枚举（发现 0 台）；受保护应用加载探针在开发目录被 ACL 拒绝。真实相机绑定、采图、原生识别效果、拔线重连、安装交付、客户 RCS 与现场连续运行尚未验收。模拟通过不代表这些项目通过。

## 授权、目标与继承

在既有 C#/.NET10/WPF/SQLite 工程渐进完成可组合边界、任务数据链、多页面/布局、操作工作站及后台隔离。保留 HARDENING-04 的 IRequestContract、独立活动报警、Prepared 非交付证明、本地终结、过载证据版本、最终发送裁决；不重建框架。本文为本次用户明确实施要求的落地，不改变 D 批准、历史 RV 或生产准入。

基准差距：Platform 配置校验硬编码 supply/固定模块/双通道/模拟规则；通用设备端口依赖 Supply；任务无波次/SKU/格口/单位来源快照；View 未实际选页、布局强写 workstation；主屏含工程控制、记录只有 JSON；数据库同步方法可在 UI 线程运行，Snapshot 调用 SyncAlarms 写库；响应式仅改边距字号。RUNTIME-03 implementation 中“Platform contains no supply rules”和“S4 完成”是原交付记录，当前差距由本文限定，不能作为本包已通过证据。

## 实施设计与文件责任

采用显式产品定义注册 + 单业务后台串行协调器 + 带生成版本/时间的只读投影。备选的全新插件框架、UI 分别拥有业务实例均不采用：它们扩大范围或破坏请求身份。保持单进程、单发送器。

1. `Ipc.Platform/Configuration.cs` 提供结构/依赖/版本/模式/路径/哈希检查；产品定义拥有业务/允许模块、驱动能力、页面/布局与业务校验。设备观察类型和能力端口移到 Platform，JSON 字段不改名；Supply 专有集成端口和 IRequestContract 留在业务。产品注册不是任意 DLL 扫描。
2. `Ipc.Supply/Model.cs` 增加可缺省语义数据快照与来源（来源、合同版本、证据ID、取得时间）；Context 与 Item 波次分别保存，旧数据为 null。独立合成接收夹具提供语义数据，SIMULATION-v1 请求保持原形；新响应字段可选，不改写原报文。Store 前向存储格式迁移独立记录，旧 schema1 SQL/校验和不变；旧程序拒绝新格式。
3. `StationApplication` 所有读写通过有界串行后台所有者，普通命令与关键控制有界隔离。网络在外部异步等待；设备回调只入队，过载以原 marker 语义保留证据。快照不写报警，维护脉冲更新时效/报警，输出投影版本、生成时间、当前箱唯一接受量、最近作业；读取失败/过期 UI 禁止业务，命令仍重检。
4. `Ipc.Desktop` 受控 View 注册实际选页，合法布局偏好保留当前 View；多窗口共享 Runtime/Application，窗口独立草稿、取消、选区/焦点/滚动。主屏当前箱/箱波次、双通道任务/条码/数量、原因/下一步、固定主操作、最近记录。工程事件/故障/角色在独立按模式/权限开放页面。维护表单编辑驱动/端点/站点参数，展示校验/差异/生效时机/失败保旧；JSON 仅高级诊断。记录为 Operation→Request→Attempt→Response/Audit。
5. 标准布局双列、紧凑按有效客户区切换单列并保留主操作，长内容可滚动/换行；最小有效区 800×420 DIP，低于时明确阻断输入并提示扩大窗口。与原 tokens 1280×680 设计假设分开：本包扩展到 1366×768 在 150% 下的可用区域，实际 Windows/DPI 仍需验收。扫码输入仅局部接受终止符，危险确认不响应扫码 Enter。

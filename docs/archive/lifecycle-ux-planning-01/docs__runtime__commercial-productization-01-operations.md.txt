# Importer PC 商业交付操作指南

适用：COMM-00～10的操作机制；当前版本和介质沿上方唯一入口核对。原文形成时Sportmaster1.12.0、DirectPlc/WcsToPlc1.6.0、Contracts1.17.0、DB9，COMM早期1.4.0/1.10.0/DB8均保留历史身份。具体源码、介质与已执行结果见[实施结果](commercial-productization-01-results.md)。旧 ZIP 仍按各自 SourceCommit 和随包说明使用。通用工程能力不代表真实设备、客户协议、Windows 现场或投产资格通过。

> 当前安装交付为普通人工安装包和必要说明，见[范围收敛记录](installation-delivery-scope-01.md)。下列人工向导是正常路径；已有高级部署入口仅保留实现说明，不是交付前置条件。

## 安装和首次配置

1. 从可信渠道取得同源单EXE及交付回执，核对SourceCommit和哈希。双击后自动准备、校验，进入目录/快捷方式选项；无须手工解压或预装.NET。ZIP/Setup.cmd仅为兼容入口，按其同版回执使用。
2. 核对程序目录、独立数据目录和开始菜单/桌面快捷方式。本机全部项目与运行数据使用D盘，受保护根沿管理员配置的HKLM政策；拒绝时处理真实权限问题，不用链接绕过。当前普通向导不提供运行账户、站号、模式或信任/扩展文件选择器。
3. 新部署沿现有安装逻辑生成Production首配种子并读取介质离线包；已有部署保留原身份、账户范围、站、用途和数据根。安装器静态校验，不执行SDK或建立真实业务资格；不通过换空根掩盖原责任。
4. 审阅后点击安装，沿固定helper进行Windows授权。提交后不以关窗视为取消；仅可信回执支持完成。结果待确认时不再次提交，当前核对入口缺口见LIA-01。
5. 从正常非提权入口打开软件，新站进入独立首配。管理模式与Windows安装权限、操作员身份分开；首次设密沿既有批准。首配与日常参数共用四类目录和完整候选，逐页校验，保存回读与明确启动分开。
6. 相机/RCS可明确稍后配置；未配置能力不构造真实连接且拒绝相关业务。PR107的仓ID、生产线ID、单供包台编号、新请求quantity=1和新站7天默认保持；旧请求和旧配置不静默覆盖。Sportmaster无PLC/图片；其他产品的参考壳和现场资格分别核对。

独立启动修复使用 `Maintenance.cmd` 或开始菜单“启动修复”；不依赖业务 Start 成功。草稿可包含未填/无效字段，加密本地保存并绑定配置 hash、草稿 hash、同版源码文件身份；草稿不是配置账，运行不读取它。并发窗口不能覆盖新草稿。历史加密草稿保留最多128份，到限报错、不自动删除。Windows 使用 DPAPI 与私有 ACL；跨机器不复制秘密。portable 仅允许显式 Simulation 合成草稿。

完整恢复保留的原机器DPAPI草稿在本机不能解密时，离线页明确显示“草稿不可用”，继续加载当前配置字段；原密文保留且不能自动覆盖，可重新填写候选后受控提交。该诊断不解除换机隔离、来源退役或真实资格门槛。

“分层检查”分别报告结构、精确包/参数闭包、部署资格、真实连接。连接 NOT_RUN 不伪称就绪；Production 缺必需能力/资格时拒绝 Stage/业务，但仍可填写和保存非生效草稿。没有批准的独立探测合同，本入口不会通过发送真实任务试参数。

## 未确认配置启动失败的修复

正常“保存待生效”仍保留原 Effective，不能绕过其未确认状态。若原配置始终无法建立资源，选择“受控修复未确认配置”，填写原因并接受 Windows 维护授权。应用在同一 owner 下检查完整历史、原请求/回执、图像、冲突及隔离责任，保存含原 envelope 字节/散列和候选散列的明确修复意图。

原数据库存在而配置账缺失，或业务库缺失但原回执/图片、原账确认/启动尝试/激活事实仍存在时，启动拒绝补建种子账/空库。保持原目录，通过完整恢复集核对恢复；不能用首次配置覆盖原责任。首次离线首配尚无启动事实时才可正常创建首库。继续草稿/导入模板须先完整构造替代编辑模型，任一提供者或字段恢复失败仍保留当前未保存输入。

重试正常启动再次核对身份、责任、严格资格，沿原 BeginActivation/ConfirmActivation 尝试候选；全部资源启动成功才成为 Effective。失败保持原 Effective/Pending/确认和失败记录；中断标为 Interrupted，须审阅后显式重存。不能清 Confirmation、删除 marker、改目标或要求坏配置先成功。原 Unknown、恢复隔离、原件或身份冲突未清时拒绝此修复出口。

## 统一设置和连续操作

作业、作业记录及管理模式中的参数设置、日志查询共用同一 Application。辅助窗口有自己的筛选、选择和草稿；切页/切布局/关闭辅助窗口不会重建 reader、作业或发送器。软件暂停仅暂停允许暂停的新入场，不是安全急停；停止未完成保留 owner/资源，不能接着启动第二实例。

设备与维护先读取原配置和精确目录。站/模式和稳定读码身份保持只读边界；结构化表单与高级 JSON 通过显式切换决定唯一编辑来源。维护原因、原 Revision/CAS、差异及待生效状态均保留；校验不保存，Pending 不代表生效。暂停并认证维护后，可“加密保存未完成设置”；“继续未完成设置”保留无效字段、新增未绑定能力和编辑来源。独立首配草稿与运行内设置草稿有类型标识；从原编辑入口继续，不互相套用。基线/源码变化保留草稿并拒绝静默套用。

紧凑布局为当前 Windows 用户的独立展示偏好，只影响显示；不改变业务配置、暂停/恢复、目标或部署。实际客户区不足时保留视图保护和独立暂停入口，空间恢复后仍须人工确认，不自动 Resume。

每位分别显示最近观察、分类、准入/作业/原请求、主结果及未清责任。失败观察不沿用旧终结格口。健康有来源、确认时间和有效期；网络通不表示业务准入。状态区提供 CP-CONFIG/UNKNOWN/RESTORE/STORAGE/HEALTH 的影响及下一动作。Unknown 先保留原实体并选择准确原请求，仅按合同允许的查询核对；不得自动重发、换目标、重新安装清责任。格口、请求接受、物理完成各自有证据。

## 历史筛选、指标和导出

作业记录支持完整条码、位、状态、原请求和带明确时区的时间。开始包含、结束不包含；“查询并固定范围”冻结序号上界，下一页和导出沿同一筛选。改条件后先重新查询，不能续读/导出旧筛选。相同条码仍是不同实体；记录详情绑定原作业，迟到结果不能覆盖新选择。紧凑页面可展开筛选后收起，不占用持续查看记录的空间。

指标分别计实体作业、WCS请求、WCS接受、待核对、物理完成、发送尝试；不把取得格口当作实体完成。CSV 最多10万作业/64MiB/2分钟，独立只读连接、流式输出，停止会等待读取者释放。导出到业务根之外的新文件；可取消，取消/失败不发布部分 CSV，保留 `.result.json`。若最终 CSV 已落盘而回执写入失败，按 CompletedReceiptPending 核对文件和空间，不重覆盖结果。字符串列带显式文本标记，条码另有 UTF-8 base64 精确列，保留前导零/长码并防公式解释；使用文本/显式解码导入。

## 完整备份、隔离恢复和原机迁移

创建备份复用原完整恢复集引擎，保留数据库及同名 `.recovery` 全目录（配置、原回执/图片、独立维护原配置/操作证据、加密草稿/历史、COMPLETED 清单及引用）。不得只复制在线 DB。完整集包含业务数据、配置参数及私有维护证据，须选择受控私有备份目录并按授权保管；DPAPI密文不因此获得跨机器解密或资格。独立维护可以在业务无法启动时创建完整备份；预检对原 DB+WAL/原件作私有完整副本，不以 SQLite 打开原库。

备份列表最多256份，显示时间/大小/完整性，逐文件核验原集合；InvalidOrIncomplete 保留、不隐藏。计划备份在唯一配置账显式启用并指定绝对目录、周期15～10080分钟、份数上限1～1000；未配置不启用。只有已暂停、维护授权有效且无在途外呼时触发；不会自动暂停生产。条件不足 Pending、目标/容量失败 Failed，到限保留全部备份、不自动删除。

恢复先检查计划，再复制到新的隔离 Application 目录；不覆盖原根。Windows 新数据根按原机指定 SID 创建 Modify 权限，既有目录必须能核验权限，不递归重置原 ACL。恢复完成仍有 RESTORED-ISOLATED，保持暂停与原请求责任。

原机接管前，两根必须均为匹配本发布的DB9（`ParcelRestoreHandoff`）：先在原根按新发布清偿并受控迁移，再创建并恢复新的完整备份；不能直接接管旧格式恢复集。原机迁移另选“接管已恢复的原机目录”：原根/新根 owner 均空闲，数据库逻辑内容、配置和全部原件与备份一致，原机政策和登记匹配后，先持久化原根退役围栏，再切唯一登记到新根。备份后原根有新事实则拒绝，须停机重做完整备份/恢复。中断后围栏保留，可按同一备份和目标继续，不让两根双活。新根重启后在维护页读取交接，认证并填写核对原因；受保护登记/原围栏/审计一致才确认，仍保持暂停，准入继续由原请求/设备/数字范围守卫决定。原DB8/DB7说明保留在归档，不用新文字覆盖其历史验收。

换机缺少可验证的来源退役、Windows账户/秘密作用域、精确组件/设备资格或外部编号范围时保持 BLOCKED/隔离。安全站点模板只含同版本白名单策略/提供者选择，排除站点、稳定设备、目标、参数、凭据、备份路径、原请求和已用编号；不能代替换机恢复证明。

新空站建账前形成私有 `machine-origin.bin`，沿机器DPAPI和指定运行SID ACL绑定原Application/站/模式/目录，完整恢复集保全其原密文。原机接管及确认还须能解密并核对来源；复制政策hash不能证明同一机器。合法迁移沿原围栏/交接链核验，最多16级且不补发来源。既有库无该证据时不自动补盖本机证明：完整备份/隔离恢复可用，自动原机接管BLOCKED；原根和接管链证据须保留。portable来源只用于显式Simulation，无Windows机器资格。

## 升级、修复和保留数据卸载

使用同源可信完整介质进入安装向导，带入原账户/站/模式/数据根。升级前先停止并完成释放，预检全部原责任与DB兼容性，审阅完整备份位置；执行在同一 owner 下再次核对计划并完成备份，再并排部署/切登记。不能以旧 EXE 回读新库，不回滚业务账、改标旧包或删除原 Unknown。

程序文件损坏且仍有Unknown时，仅与原登记相同SourceCommit的完整可信介质可进入同源Repair：先持owner并完整备份，原Effective/Pending/请求/目标/合同/包引用及隔离标记全部保留，不启动、不激活。不同SourceCommit仍按Upgrade拒绝未清责任；修复后原实现字节/资格不匹配仍拒绝Start，不重发Unknown。

系统“已安装应用”的修改/卸载和 `desktop/Ipc.Desktop.exe --product-maintenance` 打开同一独立产品维护。系统项/快捷方式损坏可按唯一受保护登记重建；程序损坏从完整介质并排修复。卸载前重新检查责任并备份，只移除原库存中的本发布文件、版本快捷方式及系统项；默认保留数据、种子、机器政策、永久身份、信任、扩展、消费者、备份及其他发布/共享驱动。被占用文件使用 Windows 重启删除并返回 RestartRequired，不谎称已删除。

卸载中断后原登记可已退役而清理未完成，必须保留固定清单和回执。当前同源介质的ResumeRemovalAsync能力尚未接入用户可达入口，不能按旧说明寻找“继续退役程序的中断清理”按钮；LIA-01负责补齐。在此之前交获授权维护者核对，不反复提交或猜路径递归删除；重装仍沿原身份/责任守卫。

## 管理模式、操作员与日志

当前完整操作见[管理模式](management-mode-01.md)与[当前日志入口](lifecycle-ux-current-guidance-01.md)。管理模式无需正常管理员用户名，独立于操作员账号/免登录；进入和浏览不暂停。参数保存仍按暂停/排空/CAS及唯一账执行，受限读取和操作由服务鉴权。帮助与支持及旧摘要已删除；实际软件日志按时间/级别/来源/关键词或显式正则查询，查看原始上下文，并按固定匹配或整个时间范围导出。[账号版旧说明](operator-administrator-logs-01.md)只保留SM1.10.2及显式迁移语境。

### 已有高级部署入口（按需使用）

以下仅记录既有 `DeploymentBatch` 接口，退出普通安装交付与默认验收范围。普通用户无需导出计划、准备响应文件或使用以下命令。代码和历史验证未在本次修改。

已有人工摘要页可保存已审阅的逐站部署计划，固定介质、种子/包/信任散列、原登记 CAS 和维护计划。计划只引用输入路径，不复制数据库；仍应保护实际配置及计划文件。明确的管理员部署会话中执行（不隐藏提权）：

```powershell
.\app\Ipc.Assembly.exe --deployment-plan C:\delivery\site-plan.json --receipt C:\delivery\new-preflight.json --preflight
.\app\Ipc.Assembly.exe --deployment-plan C:\delivery\site-plan.json --receipt C:\delivery\new-install.json
```

退出0为 PreflightPassed/Installed/同一计划 AlreadyInstalled，2为无效格式/输入变化，5为缺维护权限，10为IO失败/需核对恢复。逐站回执必须用新文件；成功重入只核验原已提交计划，不重置站点。预检不安装/启动；输入变化须重新审阅。资格、真实 SDK/协议/实体及现场授权未获得时逐项 BLOCKED，不生成生产默认或虚假商业许可。

开发者冻结后可运行 `scripts/verify-commercial-media.ps1 -Media <同一win-x64介质目录> -Output <新证据目录> -Dotnet <固定SDK>`，将该提交的现有合成夹具绑定到介质真实 DLL，校验原介质未变化。该夹具显式注入内部合成身份/端口，不提供运行时绕过选项，不构成实际UAC安装或现场资格证据。原生权限/重启清理/跨账户、触控DPI、设备组合逐项按[验收计划](validation/commercial-productization-01.md)后验。

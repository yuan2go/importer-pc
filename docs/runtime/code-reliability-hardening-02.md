## 所有权与恢复

Start是一次性操作。Stop先围栏新输入并请求取消启动，等待真实启动及失败审计结束，之后才停止来源、排空逐笔输入、读操作、业务和外部任务。调用者取消只取消等待；同一真实Stop任务继续持有资源，后续Stop等待它。停止失败可重试；失败时不释放下游连接、工厂、数据库或租约。Dispose也经过同一串行停止边界，不把超时当作安全退出。

原接收回调可能仍在落盘时，关闭队列必须取得该位接收门；成功Stop之后不会遗留未排空生产者。重连Epoch切换与健康结果发布共用原子边界，旧回调不能覆盖新连接状态。没有新增生产子进程、守护服务或第二套业务账。

进程崩溃后保留原责任：Pending输入变为需检查的Interrupted；Prepared仍需原实体检查及显式继续；Dispatching无可靠回包维持Unknown。已有durable原回包可按原合同恢复事实。不会因启动、恢复、软件暂停解除而自动重新发送Unknown，不把接受当物理完成。工具中的强杀发生在合成Simulation数据，不能用来测试生产目录。

## 日志查询

每个查询固定当前运行/认证日志文件对象、长度和顺序；最多4个快照，10分钟单调寿命。常规快照首次扫描建立最多131072行的定位/匹配元数据，后续每200行页只读取所需原记录；不缓存整份原文。复读按原字节hash核验；轮转保持旧文件对象，截短或原位置变更报错。

超过定位缓存预算时明确提示并沿用有界流式读取，翻页可能较慢；完整原记录、上下文和导出仍保留，不要求删除日志以满足缓存。原有单文件16MiB、单行256KiB、查询20秒、导出5分钟上限保持。撤权/过期/淘汰立即阻止新读并取消在途读，最后一个实际读者退出才关文件和CTS。撤权后不能公布旧结果或完成导出。

摘要、JSON多行字段和上下文文本在后台格式化。列表摘要最多384个UTF-16字符，详情/上下文总呈现预算65536字符，超出明确显示提示；通过原有“导出全部匹配”或“导出时间范围”及上下文设置取得完整脱敏记录。详情不是原始证据文件，hash仍指向读取时的原字节，脱敏、原文JSON、行号及完整导出语义保持。布局、字号、导航及管理模式守卫不变。

## 存储与时间

SQLite保持WAL/FULL、原5秒busy timeout及每位有界队列。只有成功持久接收后才能交接true；共享写锁超时返回false并围栏共享存储故障，不能仅标为一个相机故障。恢复后拒绝过的输入不会被应用伪造为已接收或自动补发，来源需按真实实体检查后显式交接。队列满保留原过载责任及暂停检查流程。

RuntimeJournal故障重探测用单调经过时间，时钟回拨不推迟恢复，前跳不跳过退避。业务、原报文、审计时间及跨重启UTC日期清理继续使用原墙钟语义。健康证据的未来时间/已过期检查保持；不修改系统时钟。

## 升级、回退和复现

停止旧实例并确认真实资源排空，保存原业务目录和原介质，再部署完整同源发布目录，不能只拷贝个别DLL。没有新数据库迁移；既有DB9及永久防重、未决请求不删除。未决原请求绑定实现hash；若升级后的能力与原请求不兼容，启动按既有守卫拒绝，须使用匹配的原介质核查、处置，不能改hash或批量重投绕过。

回退同样完整停止后使用保留的旧完整介质和当前DB9账；不得用旧备份覆盖现账制造重复机会。历史冻结介质保持原版本/SourceCommit。程序集或扩展变更仍服从现有精确兼容和签名策略。

Windows先执行`. ./scripts/project-environment.ps1`。真实代码的独立验证入口为`dotnet run --project tests/Ipc.Application.Verification -c Release -- . --reliability-02`和`--h02-crashes`；后者由外部控制器强杀测试子进程，独立来源/模拟HTTP接收账及退出结果写入输出的EvidenceRoot。原生WPF用`tests/Ipc.Desktop.UiVerification`的`--reliability-logs`；冻结介质用`scripts/verify-commercial-wpf.ps1 -Media <介质> -Output <新D盘目录> -ReliabilityLogs`。

所有命令只可对隔离合成环境执行。目标IPC、真实SDK/RCS合同、物理断电、完整24h/72h及现场验收未由本轮短测替代；具体已执行范围以验证记录为准。

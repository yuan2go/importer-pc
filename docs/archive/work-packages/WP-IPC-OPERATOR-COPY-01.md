# OPERATOR-COPY-01 · 供包员界面文案工业化

2026-11-01。用户要求从工业现场角度修复供包台界面文案问题并更新到 main。基线 main `02b0891`（含 PR167 实时呈现；其新增连续性提示一并按本规则调整），分支 `codex/operator-copy-industrial-01`。

本包只改展示文案和少量展示守卫，不改变业务状态机、准入、RCS 请求、Unknown 防重、原请求责任、配置账或权限。合同、审计、草稿及日志原文保持原值。

## 问题

供包员每 1–3 秒处理一件，看屏幕只有一瞬间。原界面的问题：

1. 合同术语直接显示给供包员：准入、原件、原请求、回执、快照、作业身份、受控重启、能力库存、完整拓扑。
2. 异常提示只写“联系维护人员核对”，没有告诉供包员手上的包裹怎么办。
3. 顶栏状态用正面语句配警告色，例如左位异常时，黄色顶栏写“右投递位可以供包”。
4. 暂停时同一卡片重复显示“供包已暂停”；RCS 未配置时重复显示两句同义原因，标点为“。；”。
5. 参数页的“已读取完整拓扑与能力库存……”泄漏到操作员登录框和设置页状态栏。原因是设置文案与屏蔽条件中的文字不一致（多/少“表单为当前编辑来源”），屏蔽一直没生效。
6. 部分展示逻辑靠文案字符串或颜色十六进制值判断，改文案或改颜色时会悄悄失效。

## 文案规则

| 层级 | 规则 | 示例 |
|---|---|---|
| 状态 | 名词短语，6 字以内，说结果 | 投递格口、格口未确认、未分配格口、正在获取格口 |
| 下一步 | 动词开头，说手上包裹怎么办 | 勿重复上件：包裹暂放一旁，通知维护人员核对。 |
| 原因 | 一句话，给维护人员 | RCS 返回的结果互相矛盾，格口未确认。 |
| 禁用词 | 作业页不出现合同术语 | 准入→受理；原件/原作业→上一件；回执未包含→未返回；受控重启→重启软件 |

统一称“投递位”“包裹”“格口”“扫描”；单条原因以句号结束，同一条件只显示一次。

## 实现

- 新增 `OperatorCopy`：集中供包员常用句和 `JoinReasons`（去重、去掉被更长原因包含的前缀、统一句号）。设置页“已读取当前设置”提示改为同一常量，同时用于设置和屏蔽，修复登录框与状态栏泄漏。
- `ParcelStatusPresentation.NeedsAttention` 由工厂颜色常量推导，作业卡不再比较十六进制颜色字符串。
- 操作员登录框只显示本框登录/登出结果。
- Application 层：人工供包的 RCS 待配置只报告一次；暂停原因保留“供包已暂停”前缀并说明恢复方式；连接待配置提示改为“重启软件后生效”。
- 历史筛选、状态转换器和详情中的 SM 状态名与作业卡统一。PLC、称重、图像等暂停业务的状态名不变。

管理模式 → 调试。操作原因与资源限额在首个展开区。生产观察会继续正常业务，请勿当成测试隔离；实机测试必须选择“进入实机隔离”，确认停止真实投放及两位实体，等待明确进入回执。普通心跳和已发原请求的回执不等于新扫码业务请求；隔离不负责切断全部网络或物理设备。

“业务扫描”查看原业务审计，“关联帧/未读码”查看当前或历史会话。空相机页仍可继续翻页，因为游标按全站有界输入区间推进；不会扫描到无限远或跳过尚未读取的本相机输入。新数据到达后按页追赶，容量限制只影响显示。取消跟随或暂停画面只冻结查看，Application关联采集继续，直到明确停止、期限/权限失效或故障。Simulation入口继续沿原准入合同，生产模式不显示。

输入/请求/响应预览为有界显示，截断显式标记，完整业务原件仍在原账中。HTTP成功、识别成功、业务接受和物理完成分开显示；未知原请求不重发，新扫描是否准入由现行SM规则决定。原请求不因进入、离开或重启调试改换目标、合同、版本或报文。

## 实现与资源所有权

- `ObservationInspection.cs`、`IMonoBarcodeDecoder`/`SoftwareDecoder`及`MvsInspection.cs`：沿原MVS独占连接、原生帧归还及软件识别路径；原始像素在对比度增强前复制，位置来自已安装ZXingCpp 0.5.3管理契约的`Position`四角。数据与标注坐标都对应完整原始帧，不增加图像裁剪变换。
- 新增`MV_CC_ClearImageBuffer`绑定依据本机已安装MVS 4.8官方`MvCameraControl.h`声明。它只清理SDK内部缓存，当前SM为GigE相机，不宣称清理采集卡/相机内部所有缓存，也不将软件完成回执等同于现场清场。SDK调用在已有采集所有者的循环边界执行，先归还当前原生帧；失败保留隔离。实际设备及传输中的迟到帧行为必须在后续资格验证中确认。
- `ParcelCameraInspection.cs`：管理命令串行、来源切换等待、撤权/单调期限及隔离恢复；`ParcelInspectionQueries.cs`：审计游标、原件详情、持续结果投影和导出。新读操作沿原并发预算及真正完成后释放所有权的机制，取消不伪报资源已结束。
- 业务`CameraIsolationStarted/Released`审计及原暂停账承担持久隔离权威。`SharedReady`、准入、派发、附加发送、配置与自动恢复守卫共同拒绝绕过。重启先恢复栅，再给MVS来源恢复隔离标记，最后启动采集；新的SDK连接不会把旧隔离输入送入业务。
- `CameraInspectionStore.cs`：业务根下独立`camera-inspection/index.db`及`images/`，WAL/FULL、单写入所有者、元数据和原图hash。图片无损Brotli，UI按需要解压，并校验长度、压缩件hash和原始像素hash。诊断集合不替代原业务库、原回执或完整业务备份。
- `CameraOriginalExport.cs`：标准8位灰度PNG，独立临时文件、原件/provenance JSON、完成状态及hash，不覆盖已有目标。ZIP流式写入、按高水位截取、原图可用性逐条记录；原作业摘要标明读取时间、业务修订、原始请求/回执hash与预览脱敏/截断状态，不伪称包含完整业务账。导出并发与清理互斥，导出失败保留原集合。
- `StationDebugControl.cs`：只持有有界可视行、当前原图、选择和本窗草稿；迟到结果按页面/选择代次拒绝。切页、失权清除图像及敏感投影，采集与隔离的生命周期继续由Application掌握。原导航与配置体系不另建第二权威。

默认会话10分钟、共享原图预算1024MiB、元数据200000条；期限不能超过当前管理授权。输入允许范围1～60分钟、64～2048MiB、1000～500000条。128项队列及128MiB待写原图、最多32MiB单帧；磁盘原图最多10000件，索引有效页预算512MiB，保留至少512MiB与当前Effective业务最低余量中较大的磁盘余量。实际累计原图共享预算随会话设置执行，可能轮替以前会话原图；轮替不冒充完整图像覆盖，关联元数据保留至清理。

满载或持久化失败显式停止收集并报告缺口，实机隔离继续保持。到期/撤权停止记录不会强制停止正常相机采集。当前Effective诊断保留天数（缺省7天）只清理已结束、未被原隔离保护、未在导出的诊断会话，保留会话身份和原始计数。用户也可经管理操作及原因清理已结束会话。业务原件不在此清理范围。进程中断后未知尾部覆盖明确标记，不把剩余文件补造成已入账证据。

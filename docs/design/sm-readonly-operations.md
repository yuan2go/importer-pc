# SM 只读运维工具与本机通道

第一阶段的当前实现。基线为 main `c72c7ad5`，需求来源为 [PR #278](https://github.com/yuan2go/importer-pc/pull/278) 的双程序提案。原型仅供界面分工参考，不作为协议、参数、权限或设备能力的依据。

## 设计核对和范围

| 提案/原说明 | 当前代码事实与本阶段处理 |
|---|---|
| 独立运维进程 | 新增 `Ipc.Operations.Desktop.exe`。工作站 `ParcelApp` 继续创建唯一 `ParcelAssembly` / Application。工具不引用装配、存储实现、驱动或 RCS 实现。 |
| 查看与管理暂停分离 | 原管理中心通过 `SetManagementWorkspaceAsync` 暂停，保持原行为。新工具只读连接不进入管理模式，不申请工作区或调试会话。 |
| 共享 WPF 资源 | 实际主题移到 `Ipc.Presentation.Wpf/Themes/Workstation.xaml`。原 Desktop 路径为合并入口，安装器、工作站和工具使用同一字典及字体。 |
| 五页运维、现场设置迁移、按位调试和离线维护迁移 | 尚未实施。本阶段只有运行总览、日志只读查询，不显示无实现的操作入口。原设置、调试及受保护维护继续沿原入口。 |
| 旧 Windows 指南中的 Parcel10→11 迁移、仅换车开下一件、缓存排队重启删除 | 均非当前契约，已从关联当前说明清除。当前仅 schema3 / DB14，同格式保留原件，轮次及缓存余项按 AGENTS 执行。 |

## 所有权、权限和暂停矩阵

| 行为 | 权限与数据来源 | 生产影响 |
|---|---|---|
| 打开工具、在线运行总览 | 当前受保护安装、安装指定日常 Windows 账户；同账户、同 Windows 会话的已登记双 EXE | 无业务命令，不暂停、不连接设备 |
| 在线/离线日志查询 | 同一安装与账户只读权限；实际文件读取仍受 Windows ACL 限制 | 仅读本站运行日志，不读数据库、配置账、图片、认证日志或机器凭据 |
| 原管理中心、设置、调试 | 原管理密码临时授权及 Application 执行守卫 | 保持现行整站管理暂停及收口，不因工具查看改变 |
| 安装、修复、回滚、恢复、卸载 | 原 Windows 管理维护权限、受保护原操作及实际所有权 | 工具不提供这些命令，仍从原入口办理 |

新只读权限允许安装指定的日常账户查看已脱敏运行日志，无需取得或撤销管理密码会话；它不授予认证日志、导出发布、管理命令或维护权限。指定账户为 Windows Users 组时沿原 `MatchesRuntimeAccount` 规则；在线额外要求与实际运行工作站相同的用户 SID 和会话。离线查看不提权，不创建业务库或配置，不自动启动工作站。

## 通道和失效

`Ipc.Operations` 只引用公共契约、平台和共享日志读取器。工作站启动成功后建立通道；源码运行或安装证明不完整时不开放在线端点，写本机启动诊断，不把只读端点失败变成业务暂停。工具从自己的已安装目录解析当前登记，不接受任意数据根、程序路径、信任文件或业务命令参数。启动核验受保护库存、登记来源、程序和托管依赖字节；每次读取复核当前登记及账户权限，登记被取代即失效。

本机命名管道使用显式 SID ACL、首实例独占及 `PIPE_REJECT_REMOTE_CLIENTS`（[Windows API 定义](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createnamedpipew)）。客户端只提供身份核验级令牌，不授予服务端冒用其文件权限的能力（[Identification 语义](https://learn.microsoft.com/en-us/dotnet/api/system.security.principal.tokenimpersonationlevel?view=net-10.0)）。双向核对内核返回的实际进程、安装路径、用户 SID、Windows 会话；响应再绑定协议 v1、安装身份、读取权限、请求编号、RuntimeId、PID 及进程启动时间。协议仅接收总览读取 DTO，拒绝未知字段、超长消息和非白名单权限。没有通用远程调用或业务命令分派。

两个异步管道工作者，每连接共用3秒预算、128 KiB上限；客户端共用2秒连接/读取预算。完整读取后回一个接收确认，服务端才断开，避免 Windows 丢弃未读响应；半包、拒绝和客户端异常只结束原连接。只读失败不代表任何原业务命令已取消或未发送。Windows 管理员和同用户恶意代码注入不在此本机进程隔离的抵御范围内，不能把哈希清单称为发布者签名。

运行总览复用既有 `IParcelPresentationSource` 的有界最新快照订阅，不按客户端增开业务轮询，也不传输完整配置、原请求、凭据或图片。保留 Application 的单调发布时间，5秒内未更新即失效，读取和排空订阅不续期。页面每秒读取，独立检查新鲜度；断线或失效立即撤下工位和设备实时值，重新连接必须重新握手。新进程有新的运行身份。连接正常、设备确认和允许供包分别显示；可见未确认数量不代表全部历史责任。

## 日志和离线

`Ipc.Diagnostics.SoftwareLogReader` 从原 Application 移为共享实现，原管理日志的权限、查询、上下文、导出及释放契约保留。工具使用无导出权限的只读构造入口，仅枚举当前登记数据根中的合法运行模式/站点 `sportmaster/diagnostics`，最多1024个站点目录。不接受任意日志路径，不读取 `security/diagnostics`。查询只打开写入器所有的四份 `runtime.jsonl` 轮转文件，继续使用原文件对象固定、读取长度/哈希核验、16 MiB单文件预算、10分钟查询寿命、200条分页、取消、凭据脱敏及完整性提示。

时间快捷范围每次新查询取当前时刻；翻页使用已应用的固定条件。详情和多选复制来自原页原文，不自动抢滚动。取消或失败清空本次结果；选中时才展开原文。关闭工具取消并等待本窗读取后释放文件和单实例句柄。

未连接工作站时可读取同一合法范围的落盘日志。页面明确“未连接不代表已停机”，不从日志空白推断未发送、资源已释放或业务安全，也不把历史日志重建为实时状态。离线日志不取得业务所有权；工作站同时启动不会因查看被阻塞。运维工具的单实例锁独立于业务资源锁，异常退出由 Windows 释放。

## 构建、安装和验证

Windows SM 构建流程发布两个同源宿主，合并到同一 `desktop` 部署前逐字节核对共享文件，再生成同一份发布清单及安装库存；不建立第二个产品登记。工具自身依赖闭包检查拒绝业务、驱动、RCS 和 SQLite 实现。第一阶段从已安装 `desktop/Ipc.Operations.Desktop.exe` 打开；原开始菜单/桌面、安装完成启动及离线维护入口保持。完整快捷方式和维护迁移仍属后续阶段，不能据本阶段宣称完成全部双程序安装验收。

```powershell
. ./scripts/project-environment.ps1
dotnet build src/Ipc.Desktop -c Release -p:BusinessModule=Sportmaster -p:RestoreLockedMode=true -m:1 -nr:false
dotnet build tests/Ipc.Operations.Verification -c Release -p:RestoreLockedMode=true -m:1 -nr:false
tests/Ipc.Operations.Verification/bin/Release/net10.0-windows/Ipc.Operations.Verification.exe $PWD.Path D:/new-isolated-operations-evidence
```

验证使用真实 Windows 命名管道、进程/令牌、WPF、Application 和 SQLite；相机边界及本机 RCS 为合成替身。测试安装登记注入仅存在于 friend 验证程序集，没有生产启动参数或用户环境变量后门。未登记工具拒绝走真实入口；正向运行使用隔离登记替身，不等于完整受保护安装端到端已验收。

本机验证与最终 PR 中列示的静态检查、Windows构建、跨进程回归及原生截图分别核对。真实厂商 SDK、真实相机、客户 RCS、目标工控机、100%/150%系统缩放、长稳、同源安装/回滚/卸载端到端和现场验收单独待验。不得据模拟或本机通过声称双程序已达到生产交付标准。

# SM 双程序分工与 UI / 运行边界设计

状态：**设计提案，尚未实现**（2026-11-17）。本文不覆盖当前 AGENTS.md 的生产规则；开发阶段逐项落地并同步修改当前规则和关联文档后才能声明生效。设计只涉及 Sportmaster（SM）及必要共享基座；DirectPlc、WcsToPlc 等暂停范围不因此重新启用。

## 1. 目标、现状和决策

目标是将现有“一套 WPF 作业窗口 + 需要管理密码且会整站暂停的管理中心”调整为**一个产品、两个随包 EXE、一份业务运行状态、一份配置账、一组受保护维护记录**：

- **供包工作站**：面向操作员/现场管理员。始终保留“作业、记录、设置”三个入口。启动后默认作业页，无新增操作员登录体系。
- **供包运维工具**：面向实施/技术运维。左侧固定“运行总览、日志中心、设备调试、专业参数、维护中心”五个入口；默认仅查看，不因打开或认证而暂停生产。
- 两者共享 WPF 字体、资源、状态语义和许可已核验的原生控件；针对用途采用不同布局与信息密度，不依赖 React、CSS、JS、WebView 或第三方动画运行时。

当前代码事实：业务运行实例在 src/Ipc.Desktop/ParcelApp.xaml.cs 启动，并经 ParcelAssembly.Create 持有资源；src/Ipc.Application.Sportmaster.Desktop/SupplyStationWindow.Administration.cs 的 EnsureManagementWorkspaceAsync 调用 IManagementWorkspace.SetManagementWorkspaceAsync 为当前弹窗建立整站暂停；受保护启动/维护宿主 ParcelStartupServices 明确不创建 IBusinessRuntime。新双程序必须先解决此进程边界，不可以把 UI 分离误认为业务运行已经独立。

## 2. 运行所有权与通信架构

**本阶段保持唯一业务实例随工作站运行**，避免在视觉改造时搬迁相机/RCS/原请求生命周期；运维工具是不同进程的授权客户端，不能启动第二套业务实例。

路径：
- 工作站：WPF Shell → 当前 SM Application 与运行装配 → 唯一相机/读码/RCS/原请求所有者。
- 运维工具：独立 WPF Shell → 本机受限 IPC → 同一个运行实例的快照、只读诊断和明确授权的命令。
- 离线维护：工作站真正停止并释放所有权后，由运维工具使用现有受保护维护入口/服务办理只读查询、安装修复、回滚、恢复、卸载；不打开相机、不自动启动 SM Application、不绕过维护独占锁。
- 现有受保护凭据/维护宿主保持原职责；不能未经审计把它改造成第二个会持有设备的业务宿主。

建议在现有装配边界实现本站**本机命名管道**，协议由现有 Contracts 明确类型并严格白名单；不开放远程 TCP/HTTP 管理端口。管道使用安装身份/Windows ACL 约束、客户端身份与实际安装登记核对。每次连接握手验证本站、运行 RuntimeId、业务构建身份、协议版本、权限和数据快照修订；不匹配仅允许安全的状态说明，禁止在线写操作。UI 看见“连接成功”不等于已取得业务命令权限。

状态订阅采用有界、最新快照合并与失效时间标记；图片显式请求、限频传输/复制，不能新增第二个相机消费者或让日志刷新争用扫码关键线程。工作站或 IPC 异常时，运维工具标记“离线 / 数据已过期”，禁用控制并重新核对原操作。**断线不是撤销，超时不是未发送**：有副作用的命令使用固定操作身份和权威回执，掉线后按原操作核对，不盲重试。

## 3. 授权与操作占用分离

以行为权限而非“打开某窗口”为界：
- 作业、记录：当前操作员流程不增加登录。现场设置可只读查看；开始修改时校验现有管理凭据并按操作执行时复权，不自动开启管理暂停。
- 运维只读：查看运行总览、许可范围内的状态/日志，不申请调试占用；涉及凭据、原始敏感数据或受保护文件仍按现有 Windows/管理授权检查。
- 配置修改：管理授权 + 配置修订/CAS + 执行中资源围栏；授权和是否影响运行分开说明，不通过认证自动重连设备。
- 调试：先选择设备和动作，再由 Application 计算影响范围、请求明确的“调试占用”；只在该动作实际需要时暂停，不能只根据 UI 显示推断能单工位隔离。**若目前仅支持整站安全暂停，则必须真实显示“整站受影响”并先保留现有守卫**，完成按位资源与 RCS 责任证明后才能缩小作用域。
- 离线安装/恢复/卸载：使用原受保护维护及 Windows 授权路径；不可用普通运维窗口权限代替实际独占和安装证明。

调试占用生命周期：申请 → 原核心返回影响范围与会话身份 → 执行动作 → 受控释放/核对 → 返回实际作业准入。顶部始终显示“只读 / 调试中 / 收尾中 / 状态待核对”；结束按钮只发送结束请求，未确认释放不能显示“已恢复生产”。关闭页面、授权到期或运维进程异常时，运行核心负责有界收口和保留真实未决责任，不能仅凭租期超时解除已发/不确定的外部效果。普通授权过期不可自动当作结束调试或恢复供包命令。

## 4. 供包工作站 UI

默认作业页，**顶部紧凑：本站身份 + 作业/记录/设置 + 运行摘要**；软件名称可在 Windows 标题/产品信息体现，不恢复过去删除的大号“供包台”页眉。1366×768 DIP 优先保护双位结果空间，不为了顶部导航堆叠多行标题。

作业页继续使用现有左右独立卡片和同轮绑定：工位启停、小车到位提示、扫码框、状态/下一步、有效格口或异常、当前轮次图片入口、任务号等必要字段和底部动作。保留 F2/F3、点击卡片选位、Esc 取消选位及 PDA 连续输入的原有规则；不要因新原型的“人工录入”按钮而改成另开对话框，也不要创建第二条提交路径。

**当前准入与上一件结果分离**：真实“等待投包 / 等待下一车 / 暂不能投包 / 调试占用”等来自 Application；上一件仅按现行条件短暂显示“上一件格口·仅供查看”、条码及任务号，禁止重新绑定上一件图片/详情/提交动作。新轮或当前新车正式候选出现时马上撤下旧摘要，3 秒展示期不构成重新提交准入。

“已取下包裹”仅在现有视觉降级与当前轮次守卫允许时提供，可信空盘不重复确认；相机离线但人工输入仍可用时不能把全卡改成不可投包。RCS 超时/结果未知说明原请求仍需核对，不添加模糊“重试发送”；如果客户 RCS 无查询能力，只展示当前原件与人工核对路径，不能假装支持远端查询。

记录页：常用时间/条码/记录号/供包位/结果筛选；列表和展开详情保持原滚动/复制/定位。只展示**确实持久化的**业务记录和事件：未识别、未提交、无条码轮次等按当前数据是否有明确可查询身份决定记录或转到运维诊断，不靠 UI 创建虚假作业。Unknown 及历史请求仍可查询，不移除防重责任。操作级详情不显示敏感报文/堆栈。

设置页：本站/业务 RCS 接入、左右相机地址与 RCS bcrCode、设备物理序列号只读、已有格口处理方式和个人提示音/窗口偏好。仓/产线等字段只在真实 schema 支持时展示，不能凭原型捏造参数。名称区分 StationCode、RCS 相机业务编码、相机 IP、物理序列号；更换 IP 按现有 SDK 枚举/设备身份与资源释放守卫，不把“软件设置 IP”误写为修改硬件网络。只读 → 授权编辑 → 校验与变更预览 → CAS 保存 → Effective / Pending / Failed / Unknown 原始事实。偏好仍按 Windows 用户独立存储，不能因偏好保存而重复提交业务配置。

首配保持原真实必填、设备身份核验及完整候选；专业字段使用已有默认值并在运维端编辑，不随意缩短现有校验。启动失败仍显示原因、构建来源、复制诊断、可允许的重试和运维入口；不在主软件重新实现完整维护中心。

## 5. 供包运维工具 UI

固定左导航五项与顶部本站身份、当前构建、运行/离线模式、认证、调试责任条。全部页面共享当前设备和作业关联上下文，按需展示技术详情。

- **运行总览**：左/右相机、RCS、存储与各工位实际准入；当前异常、未确认请求、待生效配置和维护任务。区分连接正常与允许作业，不做营销型仪表盘。
- **日志中心**：时间、级别、来源、关键词，更多关联编号按需展开；有界分页、前后上下文/原始堆栈、关键词或显式正则、禁用自动抢滚动和受控脱敏导出。主软件关闭时只走当前真实落盘日志的只读入口，不伪造实时状态，也不抢业务数据库锁。
- **设备调试**：默认仅观察，不自动识码、标定、断开相机或发 RCS；相机的原图/扫码/空台校准和 RCS 的通讯/真实请求分开，所有有副作用动作明确对象、工位、责任、权限及影响范围。原图带采集时间和有效性，失效帧须标注旧数据。RCS 真发送明确“发送真实请求”；当前未决请求不能自动重发。结束调试展示原核心的实际释放、恢复结果及剩余阻塞。
- **专业参数**：通讯与超时、读码与采样、处理与资源、日志与存储；仅真实有消费者和合法编辑契约的字段。RCS 1000ms 请求期限、1000ms 心跳默认、识读期限、放稳 200ms、码制等按现行字段与单位展示，不重复推断新默认。规则正则、采样频率、缓冲等技术参数不要在主软件可编辑。写入仍生成同一完整候选，权限按字段作用域校验，保存前展示当前生效/已保存待生效/未保存三态、来源与影响范围。两个编辑器并发 CAS 冲突保留草稿，不能静默覆盖。
- **维护中心**：只读运行信息、日志/诊断包、完整备份与保管、历史维护结果、更新/回滚/安装修复、已结记录清理、卸载入口。运行中允许的操作与必须离线/授权的操作分开展示；恢复沿原隔离、原请求、Unknown 与编号高水位围栏，复制完成不等于恢复生产。清理预览不能删除未知文件/活动证据。

## 6. 安装、构建、权限和数据一致性

单个安装包与单个 Windows 产品登记项，安装两个同源 EXE 和原受保护维护配套组件。桌面快捷方式仅供包工作站；选择开始菜单时有“供包工作站”“供包运维工具”两个入口，不选时两个程序仍安装且可从安装目录或合法维护入口启动。安装完成只突出启动工作站。

当前 DeploymentShortcuts.Plan 仅生成“运行 / 启动修复 / 安装维护”的 SM 开始菜单项，需以受保护原登记、旧目标/参数验证和被用户重定向快捷方式保护为前提调整；不能只改快捷方式文案。统一更新、回滚、修复、卸载时按**一份构建身份/介质清单**核验并管理两个 EXE；回滚不混用不同构建的工作站与运维工具。产品业务版本当前固定 1.0.0，完整来源提交/发布介质身份单独展示。两套程序不各自管理数据库迁移、受保护凭据、授权票据或备份集。对 UI 关闭、后台调试、IPC 会话及待释放资源分别核验，满足实际维护所有权后才允许替换程序。

安全边界：协议不向外网监听、IPC 严格 ACL/身份和请求绑定、凭据不通过日志或导出泄漏；客户端不可凭“按钮已禁用”替代服务端授权/业务守卫。故障/中断后保留运行实例 ID、操作 ID、原回执、错误与上下文供复盘。

## 7. 分阶段交付与验收

1. **基线和设计契约**：把本设计与现行 AGENTS/管理/参数/安装文档的冲突逐条核对，落实字段归属表和权限/暂停矩阵，确定 IPC 命令及离线可用能力；此阶段不宣称新规则已上线。PR #277 作为已有 WPF 样式收敛单独审查，不混进运行架构修改。
2. **只读运维工具与 IPC**：独立 EXE、运行总览/日志只读、安装身份握手、数据新鲜度/断线、在线与离线模式；工作站保持当前现行生产行为。验证运维工具在运行中和离线时不打开第二个业务/相机/RCS。
3. **现场设置拆分与授权解耦**：工作站三个入口、参数字段权限和完整 CAS/生效反馈、个人偏好保留；运维专业编辑复用原配置账。认证不暂停生产，调试仍按当前安全守卫明确占用。
4. **调试会话与设备行为收敛**：显式占用、申请/结束/异常掉线核对；必要时再按实际资源隔离实现按位暂停，未经证明保持真实整站范围。正常操作不因只读连接受影响。
5. **离线维护和整体安装收敛**：既有维护能力迁出内嵌管理窗口，双 EXE 同源安装/更新/回滚/卸载与快捷方式验收，清理过期 UI 入口和文档，确认原受保护权限及恢复规则。

关键验收：正常左右连续供包；PDA 连扫不拼码不串位；开关运维/查日志/单纯验证密码不改变供包资格；真实调试显示影响范围、不会自动发 RCS；断线和工具崩溃不伪报已释放；历史 Unknown 不再发送；两端同时编辑 CAS 冲突及 Pending 不丢；主软件未启动仍可读授权范围内日志与修复；两个 EXE 不双连设备；安装/升级/回滚/卸载形成同源一致集；原生 Windows 100%/125%/150% DPI、1366×768 DIP、键盘焦点/复制/滚动/格口可读性、实际 SDK 与客户 RCS 分层验证。仅新增覆盖真实改动风险的必要回归，不靠截图或模拟测试宣称现场验收。

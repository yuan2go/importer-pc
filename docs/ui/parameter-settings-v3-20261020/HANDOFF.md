# 参数设置 V3 · 开发交接

本轮决策见 [PARAM-UX-02](../../design/parameter-settings-experience-02.md)，逐字段去向见 [FIELD-MIGRATION.csv](FIELD-MIGRATION.csv)，实际验证见 [QA.md](QA.md)。本文件描述当前参数体验；V2 的首次启动、作业责任及 RCS 合同继续有效。

## 1. 为什么改

实际查看用户上传的 `download.png`（1708×960，原图不在公开包内）。截图可以证明布局和文字，不能证明响应速度、按钮执行结果或权限状态。

| 截图区域 | 可见问题 | 本轮处理与目的 |
|---|---|---|
| 左侧日常导航、顶部四类标签、内部对象列表 | 一次选参数需要辨认三套导航；表单被横向挤压 | 参数模式隐藏日常宽侧栏，保留“返回作业”；一个左目录直接选真实对象 |
| 顶部大面积暂停提示及多行技术说明 | 正常维护的状态说明占据填写空间；警告与普通信息主次不清 | 暂停用紧凑文字状态；确有阻断、失效或未知时才使用显著提示 |
| 参数对象、技术身份与表单 | 对象名、内部解释重复；常用参数与低频内容竞争空间 | 名称、用途和当前对象常驻；精确版本、实例 ID、协议键按需展开 |
| 系统页“维护与迁移” | 名称没有说明要做什么，聚合了互不相同的高风险任务 | 按模板、备份、安装、原账核对等具体任务命名，保留能力与原守卫 |
| 底部检查、跨对象修改、保存准备、保存按钮 | 用户必须理解内部流水线才能保存 | 自动校验 → 一次保存审阅 → 原有 Stage/Inspect；底部只保留更改摘要和主要保存入口 |

减少的是选择层级、重复判断和无意义切换。本轮没有编造旧流程耗时或效率提升百分比。

## 2. 导航与对象

| 分类 | 直接入口 | 归属和范围 |
|---|---|---|
| 系统 | 供包台标识、数据与记录、自动备份、显示偏好 | 取格口 zoneId/projectId/stationCode 和本机配置；心跳工位身份按真实用途独立维护 |
| 业务模块 | 条码筛选、取格口请求、处理参数 | 当前 Application 的规则与限额，不是运行中切换业务流程的开关 |
| 驱动 | 左相机、右相机 | 同一已安装读码驱动的两个实例；数量与位置由 Sportmaster 决定，不提供任意增加或删除相机的日常按钮 |
| 组件 | RCS 连接，以及实际安装的其他组件 | RCS 是一个共享连接；维护认证等既有组件沿真实角色和描述显示，不能把“一份 RCS”误解为只能安装一个组件 |

页头、选中项、搜索结果及保存差异都保留对象归属。系统/业务中编辑的外部协议字段仍通过已有参数所有权映射写入同一完整候选，不建立四个独立文件或配置账。同一用途只有一个可写入口。

“首次配置”只在尚未完成首次配置时出现，继续复用五步启动流程与正式参数模型；已配置的连接故障从诊断处理，不重新覆盖首配。

## 3. 核心任务闭环

| 目标 | 入口与步骤 | 成功反馈 | 失败及返回 |
|---|---|---|---|
| 修改指定相机 IP | 参数设置 → 驱动 → 左/右相机；核对位置与驱动；填写地址；保存更改 | 差异列出所属相机、原值和新值；成功说明已保存待受控重启 | 错误定位原字段，其他输入保留；切对象或返回作业保留当前草稿 |
| 修改站点身份或请求规则 | 系统供包台标识或业务取格口请求；按用途填写；跨对象一起审阅 | 完整修订包含全部未保存对象 | 旧左右站码冲突要求核对后显式统一；不擅自选左值或右值 |
| 判断是否生效 | 固定保存栏、状态页或保存回执 | 分别显示编辑基线、已保存状态和运行状态；待重启明确标识 | Unknown 先核对原提交；重连不应用 Pending；运行状态未知不能显示成功 |
| 处理 RCS 异常 | 作业提示共享影响 → RCS 诊断 → 相关设置 → 原有适用恢复 | 实际链路和当前业务资格分别反馈 | 未知业务请求不自动重发；缺查询合同如实显示；恢复操作结束后按原守卫决定能否恢复接收 |
| 导入同版模板 | 设置工具 → 导入设置模板 → 适用对象与变更预览 → 应用到草稿 | 仅白名单策略进入未保存更改，等待统一保存 | 类型/版本/提供者不兼容则拒绝并保留原稿；不带站码、IP、目标、凭据或业务数据 |
| 暂时离开或结束编辑 | 普通“返回作业”直接离开并留稿；关闭/重读等可能丢失内容时明确选择 | 加密保留成功后才能继续需保留的离开操作 | 继续编辑、保留未完成内容、放弃范围清楚；保留失败不能默默关闭 |

## 4. 主要动作契约

| 动作 | 作用对象 / 启用条件 | 进行中与成功 | 失败处理 |
|---|---|---|---|
| 返回作业 | 当前页面，普通导航允许 | 回到同一运行实例；草稿继续在本窗中 | 不自动恢复新入场；实际关闭另走草稿保护 |
| 保存更改… | 全部未保存的完整候选；不以尚未认证阻止进入审阅 | 自动提交当前启用控件的绑定，校验字段及 Application 候选，成功打开审阅 | 定位首个真实错误；原始无效文本也保留，不用旧 VM 数值替代 |
| 查看更改 | 本窗相对加载基线的全部修改 | 只读列出对象、参数、原值/新值；敏感值隐藏 | 尚不能组装候选时说明原因并定位输入；不偷偷保存 |
| 确认保存 | 审阅仍对应当前输入，且 Application 真实资格满足 | 冻结本次候选，保存后核对原所有者/修订/指纹 | CAS 冲突、NotSaved、Unknown 分别表达；不吞异常或重复 Stage |
| 暂停新入场 | 现有独立暂停通道 | 显示真实暂停状态，等待当前外呼完成 | 软件暂停不是安全急停；不因保存忙碌阻断独立暂停 |
| 按需维护认证 | 本机原有维护授权机制；无需每日强制登录 | 沿已有有效授权，最终提交再检查资格 | 组合资格为 false 不等于未认证；没有独立会话状态就不伪造“已过期”或强制重登 |
| 核对保存结果 | 原次未确认提交 | 使用原配置账和指纹核对，不发新的保存 | 无法确定时继续待核对，保留原提交和输入 |
| 撤销本次更改 | 本次未保存草稿，明确全范围 | 恢复到已保存基线，不改运行配置 | 不清除 Unknown 提交标识或解除防重；不是回滚生产配置 |
| 连接诊断 | 明确选中的运行对象 | 展示已有证据和具体参数入口 | 没有安全草稿 Probe 契约就只展示实际支持的层，不能用业务 POST 代替测试 |
| 导入/导出设置模板 | 同 Application、同版允许范围 | 文件操作单独进行；导入先预览再改草稿 | 不兼容、权限或文件错误保留当前输入；模板不冒充完整恢复集 |
| 立即完整备份 | 原备份目标、权限和 Application 守卫 | 原一致性备份，包含数据库与同名 `.recovery` 目录 | 说明对象及原因，不把不完整目录称为可恢复备份 |

## 5. 编辑、保存和运行状态

| 状态 | 必须显示 | 可执行的下一步 |
|---|---|---|
| 未修改 | 没有未保存更改；当前读取基线 | 导航、搜索、诊断；保存不虚假启用 |
| 编辑未保存 | 变更数量与对象；输入保持 | 继续编辑、查看更改、保存 |
| 校验中 | 正在检查本次候选 | 防重复检查；允许不冲突操作，不重建整个界面 |
| 字段错误 | 中文原因、单位/格式、错误定位 | 修正当前值，其余输入保留 |
| 关联冲突 | 涉及对象及冲突原因 | 回到相关字段显式处理，不能自动选值 |
| 保存中 | 正在保存并核对；冻结的提交范围 | 防重复提交；保留独立暂停与状态刷新 |
| 已确认未保存 | 原修订未改变的证据及原因 | 修正后再提交，不把普通 Rejected 当作未落盘证明 |
| 结果未知 | 暂时无法确认保存结果 | 核对原次保存；草稿撤销不抹掉此状态 |
| 已保存待生效 | 已保存与仍运行的配置分别标识 | 按原流程受控重启；重连不会应用新设置 |
| 应用中 / 应用失败 | 实际启动阶段与故障对象 | 沿原生命周期诊断/恢复；没有证据不宣称新旧哪一份正在运行 |
| 离开有草稿 | 将丢失的范围和三个明确动作 | 继续编辑、加密保留、放弃；普通切页不弹此框 |

不提供无依据的“全部恢复默认”。驱动描述中存在已声明默认时才允许依规则使用；恢复上一有效配置沿既有可证明的修订和恢复机制，不在 UI 写回旧 JSON 冒充回滚。

## 6. “维护与迁移”能力的去向

| 原能力 | 当前入口与处理 |
|---|---|
| 计划备份、立即备份 | 系统 → 自动备份；立即备份进入具体“创建完整备份”任务 |
| 安全模板 | 设置工具 → 导入设置模板 / 导出设置模板 |
| 保存/继续未完成编辑 | 设置工具 → 加密保留草稿 / 继续未完成设置 |
| 重新读取 | 设置工具 → 重新读取；明确会替换本窗草稿，先处理未保存内容 |
| 运行/已保存配置与旧账确认 | 高级工具 → 已保存与运行中 / 原配置账核对 |
| 高级 JSON | 高级工具 → 高级 JSON 编辑；切换来源显式完成，只有一个有效编辑来源 |
| 驱动与组件安装、角色绑定、库存 | 高级工具下按具体任务进入；数量和兼容性由 Application 及真实安装描述判断 |
| 原机恢复交接 | 诊断/高级工具 → 原机恢复后核对；不与模板导入混合 |
| 旧版策略/左右身份冲突 | 只在实际 schema/冲突适用时显示兼容路径；必要能力不删除 |
| 原作业、接受事实及恢复责任 | 原诊断/受控维护任务；原件、原请求和原目标保持 |
| 其他独立 Application 的登录、称重、图片、上传策略 | 按原适用性在其业务/组件参数及具体工具中保留，不进入 Sportmaster 日常表单 |

## 7. 可开发的视觉规格

主方案为浅色 Windows 设置工作区。标准原型逻辑尺寸1600×900；参考截图1708×960。假设鼠标/键盘输入；触摸需求及目标工控机 DPI 另验。

| 项目 | 规格 |
|---|---|
| 布局 | 一列浅灰目录、一块左对齐白色编辑区；宽屏相关字段可两列，窄窗单列；正文与目录独立纵向滚动 |
| 字体 | 原生使用 Windows 系统中文字体；正文14 DIP、辅助12、分组16、页标题24；数字等宽用于 IP/标识等需要逐位辨认处 |
| 颜色 | 正文 `#1F2937`，辅助 `#64748B`，线条 `#D8E1EB`，目录 `#F4F6F9`；主要蓝 `#1763C7`，错误红、待核对琥珀、成功绿均伴随文字或图标 |
| 间距 | 4/8基准；分组24～32；标签到控件8；禁止多层卡片和巨大装饰留白 |
| 输入 | 视觉36～40 DIP；数值180～240，编码/IP约400，长地址/规则至760上限并随实际槽位收缩；不因值短缩成极窄输入框 |
| 操作 | 关键动作至少44 DIP命中区；一个主要强调按钮；对象诊断及工具为次级动作；稳定底部保存栏 |
| 焦点与错误 | Tab顺序跟随阅读顺序；明确焦点描边；错误文字靠近控件，搜索/错误定位展开并滚到原控件 |
| 长内容 | 必要地址和任务内容可读/复制；辅助技术信息换行或纵向滚动，不能用截断的关键身份让用户猜测 |
| 空、禁用、忙碌 | 空搜索给清除入口；缺驱动显示缺失原因并保留参数；禁用解释真实依赖；耗时任务不冻结整个窗口 |

1092×614原型只模拟约1366×768在125%下的可用逻辑空间，不是 Windows 125% 验收。800×420为兼容最小窗口，允许纵向滚动，不是主推舒适尺寸。原生不足空间暂停保护继续保留。

## 8. 当前实现与原型的边界

原生代码已实现目录、同窗专注工作区、统一保存审阅、搜索定位、具体工具入口、绑定错误保护及输入保留，继续调用既有 Application。代码在开发分支进入 main PR，设计包按用户授权入 main。

原型的“检查编辑地址”是分层诊断的交互目标，全部为合成数据；本轮没有新增抢占硬件的 Probe 或 RCS 业务试单。原生仍用已存在的诊断和受控重连。任何新增安全检查层须先获得确切、无业务副作用的组件契约。

原生维护授权仅有组合资格，没有原型可自行演示的独立认证会话；不得从 `CanConfigure=false` 推导用户未认证。原型版本12/13、相机连接、IP及任务只是示例，原生读取真实运行/配置证据。原型相机摘要明确写“运行连接”和运行版本，不能把新编辑地址显示为已经连通。

## 9. 实现优先级与必要验收

P0：四类对象与单一候选、保存/Unknown/CAS、错误原文保留、左右结果对应与运行配置来源。P1：原生小窗/DPI/输入连贯、模板和具体工具可达、精确安装适用性。P2：只有经证实存在业务需要及安全接口后，才增加独立草稿连接检查；不扩建通用配置管理平台。

至少实际走查：左右连续扫码；指定相机修改；非法输入定位并保留；保存与运行判定；共享RCS异常及适用恢复；普通返回留稿与实际关闭处理。Windows须用最终冻结源码和实际客户区/DPI取得截图与输入记录。原型通过、交叉编译通过、原生运行通过、设备联调通过分别登记。

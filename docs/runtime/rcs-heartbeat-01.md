# RCS 心跳与投递位启停

每台相机只填写一个相机编码，在参数“左相机/右相机”页唯一编辑，取格口请求与心跳共同读取同一映射。当前规范保存位置是已选RCS组件的left-bcr-code/right-bcr-code；驱动仅保存连接、采集和识别参数，不再声明bcr-code。两个用途没有各自的可写副本，不从IP、序列号、条码或DeviceId推测业务编码，模拟Reader也使用同一配置来源。

投递位的“启用 / 停用”决定是否发送本位心跳，与相机连接状态或是否已填 IP、序列号无关。默认两位启用，状态持久化。启用位有有效相机编码时发送，停用中及已停用位不发送；两位都停用或没有可用编码时不发送空心跳，不伪造编码。相机离线时仍可人工输入条码，启用位继续心跳。投递位完全停用后主动停止并释放对应相机，只有重新启用才连接；有任务时先保留采图与必要恢复，等待本次放置结束和原请求确认后再断开。重启和保存连接参数也不启动已停用位；释放失败保留占用，不声称已断开。心跳报文不新增启停字段，沿用已有“发送心跳表示启用”的接口逻辑。

切换后按新的启用位集合生成下一批心跳，仍在途的旧批次保留其原映射用于校验，但响应不再更新当前小车状态。停用位的小车提示立即撤下；全部停用时不继续声称有新的远端确认。重新启用后等待新的实际响应。取格口原请求仍固定原 RCS 绑定、编号和报文，Unknown 不自动重发。相机编码唯一、位置映射和缺失校验沿完整候选执行，不能从 IP、序列号或条码推测业务编码。

供包台编号读取系统StationCode，并沿既有完整候选统一到取格口映射。接口为sorter.task.station_heartbeat，沿当前RCS端点，source固定BAR、locale固定zh_CN，version=1、数值requestId及UTC Unix毫秒timestamp。默认1000毫秒，参数范围100～3600000毫秒（支持500、1500毫秒）；已保存的间隔保留，可在设置中调整。心跳按 Unix 毫秒生成编号，取格口按 Unix 微秒与永久编号下限自动生成并持久化，不配置或消耗编号段。失败不重发旧心跳，不重发Unknown业务请求。

响应先核对本次requestId，再按result各项的index、command、success和data.stationCode/bcrCode匹配本次发送的映射。result顺序可变化。有效agvNo/status只作为本位小车提示：IDLE绿色显示“空闲，可以投包”，TASKING显示“工作中，不可以投包”，不参与扫码、人工输入或取格口守卫。缺失、失败、身份不符、重复或未知状态不推测空闲。响应读取和体积有界；HTTP错误、响应体超时或不完整会清除旧状态。原秒值配置在当前配置编辑时等值换算，冻结原请求不改写。状态有效期为至少3秒、或3个当前心跳间隔，停止与重连后立即清除。HTTP传输及小车提示均不确认任何取格口或实物投递结果。

沿用唯一RCS实例和生命周期。运行中的实例禁止重配；受控停止排空定时任务及HTTP调用，保存后Pending与Effective分离。真实SDK、真实RCS、现场验收分别记录；环回HTTP和原生UI验证不是现场证据。

# Sportmaster 交付、支持与生命周期手册

本手册随同版 Sportmaster 介质交付。先核对 `ASSEMBLY.json` / `composition.lock.json` 的 SourceCommit、业务/契约/DB 及 `SHA256SUMS`；ZIP 与解压目录必须同源完整。当前候选未提供生产签名证书、真实 SDK/合同/实体资格或现场放行，不可投产。

## 安装和首配

1. 使用可信完整 win-x64 介质运行 `Setup.cmd`，选择已有 Windows 运行账户、程序位置与数据目录。审阅安装摘要、目录、SID、介质后授权原受保护 helper；不要提升日常运行进程。不能用复制文件代替受保护登记/ACL。
2. 普通指定账户打开工作台。首次工位配置从“1 目录与工位”核对原目录和工位，再填“2 设备与服务”“3 运行策略”。按业务位录入稳定设备身份，选择随包精确提供者；登录按组合可选。Sportmaster 无 PLC 和图片。
3. 可保存未完成草稿，不能当有效配置。到“4 检查与启动”执行分层检查，审阅缺口，保存待生效并重新检查后启动；资源及资格全部成功才确认。字段改变后重新检查，目录改变后重新读取。
4. 未确认配置启动失败：从原“启动修复”进入，保留原目录/账/失败记录。改正候选并检查，在“恢复与维护”执行“受控修复未确认配置”，再回检查启动。不得删除租约/改站号/新建空根以绕过原责任。
5. 配置编辑关闭、重读或打开程序维护前处理未保存输入；加密草稿换机不可解密时保留密文，在当前配置重新输入秘密。换机仍需来源退役与资格证明。

## 日常故障分诊与支持升级

|观察|操作员应做|维护/支持核对与升级条件|
|---|---|---|
|Unknown / 超时|保留实体与原请求；停止重复放货和重发|核对原目标/合同/请求及真实对端证据；无查询能力保留阻断，不能标成功|
|读码失联或健康过期|暂停受影响入场，核对电源/线缆和来源|受控重连后读取新鲜健康；不借上一件格口；仍异常交组件维护方|
|磁盘/保存失败|停止受影响作业，保留原库/原件|检查卷容量/ACL/占用、完整备份和迁移；归档不等于释放磁盘|
|首配/启动失败|保持原目录，使用独立启动修复|对照检查层/精确组件/账户/资格；原责任未清不得强行生效|
|计划备份待执行/到限|不自行删旧备份或在线复制db|安排维护窗口，核验授权/暂停/无在途；校验离机副本后按批准保留策略处置|
|安装/卸载中断或要求重启|保留回执，停止反复执行旧介质|在获授权维护窗口重启/从完整可信介质继续；核对保护登记、占用与原数据|

在“帮助与支持”搜索任务，选择带时区范围及原作业，预览再保存本地支持摘要。启动失败从独立维护导出轻量摘要。不自动上传；摘要排除秘密、完整参数、条码、原报文、数据库、原件。生产附件须另有范围授权。

支持请求附：失败步骤/时间时区、SourceCommit、ZIP SHA256、配置修订与状态、原作业/请求的获准引用、支持摘要和已尝试的只读检查。支持负责人、客户联系人、工作时间、严重级别响应/恢复目标、升级通道、离线应急联系方式由真实交付合同填写，当前均待指定；不得默认对外承诺某个 SLA。

## 受控备份窗口、恢复与升级

维护前由获授权人员确认允许停机窗口，软件暂停新入场并核对在途/Unknown/实体责任；软件暂停不是安全急停。维护认证须有效。计划备份仅在既有守卫允许时执行，不自动暂停，到份数上限保留旧备份并报错。

完整备份为数据库与同名 `.recovery` 同伴目录；一起保存并校验，保留机源证据、配置账、原责任及编号范围。记录时间、来源身份、容量、完整性和离机副本；抽样恢复到新隔离根，恢复成功不等于业务允许恢复。维护窗口频率、保留时长、离机位置和批准删除人由实际部署合同/容量计划填写，不能擅设生产默认。

升级前检查原责任和完整备份，停止原实例，按同版介质并排安装/修复；程序切回不回滚新 DB。损坏登记从唯一保护登记重建。系统“已安装应用”进入产品维护，读取原责任、完整备份计划，再保留数据卸载；不得手删共享驱动/扩展、机级身份和原数据。占用/重启按实际回执处理。

原机换根需原根退役围栏与部署登记接管；新根仍隔离，原请求不重发。换机另外核对原机退役证明、账户/SID/秘密重填、SDK/驱动/精确包、设备稳定身份、外部编号责任和部署资格。证据不足保持 BLOCKED，不能复制 DPAPI 文件充迁移批准。

## 同版 Windows 生命周期验收

先在开发 Windows 运行：

```powershell
python scripts/release-windows.py --profile sportmaster --source <完整冻结SHA> --output <全新发行目录> --dotnet <固定SDK>
./scripts/verify-sportmaster-delivery.ps1 -Release <发行目录> -Output <全新证据目录> -Dotnet <固定SDK>
```

该命令仅执行冻结实际 DLL 的核心/WPF/卸载内核与双目标介质校验，产出 `acceptance.json`、工程/生产分开裁决。它不创建账户、不安装或卸载共享系统、不重启、不连接设备；管理员生命周期不能因此 PASS。

在已授权一次性 Windows VM 使用同一介质和现有 Setup/Maintenance，按下列顺序执行；每项记录系统版本/账户令牌、步骤、期待与实际结果、日志/回执/截图的哈希，退出码和重启前后身份。保存原失败，不覆盖历史模板；PASS 的人工验收写真实 Reviewer，证据散列只保证文件一致，仍需负责方审查。

|Case|前提/步骤|必须可观察的断言|
|---|---|---|
|windows-install|干净隔离 VM、两个已有账户、允许 UAC；选择非默认程序/数据目录，完成 Setup，以指定账户普通令牌启动，换错误账户尝试|目录贯穿 ACL/helper/受保护登记/快捷方式/维护；错误 SID、真正提升、服务账户拒绝；日常非提权可用|
|windows-repair|同版介质/完整备份；保存未确认不可启动配置，退出后修正；中断安装并继续，破坏可重建系统项再修复；使用错误介质|原配置与失败尝试保留，修复后才确认；原责任未清拒绝；原数据不变；错介质拒绝；不执行不受信插件|
|windows-uninstall|隔离快照/可重启；通过系统入口卸载，制造实际占用并按回执重启；中途退出后继续|先完整备份再卸载；只删除登记白名单，原数据/共享组件保留；重启删除真实完成，中断回执不丢|
|windows-migration|新根和另一 VM/账户、完整恢复集；原机接管/换机恢复并核对来源退役|源/目标不能同时控制；DPAPI 不适用显式拒绝；恢复隔离不自动 Resume/重发；原请求目标和合同保留|
|field|获授权真实 SDK/合同/设备、实体与编号/角色批准、目标显示/触控|连续操作、断网/断电/重启/恢复、真实接受语义与实体安全逐项验收；未提供 BLOCKED|
|signoff|可信分发证书、精确包资格及授权负责方|真实签名/介质/源码一致，现场逐项放行；未提供 BLOCKED|

`check-commercial-delivery.py --release <发行目录> --evidence <acceptance.json> --level engineering|production` 复核介质并拒绝必需项缺失/错源/被改/非 PASS。工具不能签发生产批准。当前未签名候选保留工程范围，实际发布前必须另有可信签名流水线与授权放行。

## 交付签收清单

交付负责人填写：产品组合与精确源码/介质/业务/契约/DB；目标 Windows/账户/目录；组件许可/SDK与真实部署资格；安装/恢复/升级卸载证据；备份窗口/容量/退役责任；支持联系人和响应承诺；培训/操作权限；未关闭 NOT_RUN/BLOCKED、风险接受和批准来源。公开仓库仅保留通用模板和合成证据，客户实值存获授权位置。

# 保留配置与历史的Parcel10→11更新

用户于2026-11-02授权更新本机D盘软件，先解决旧库与格式11兼容。工作包见[DB22](../work-packages/WP-IPC-DB11-COMPATIBLE-UPDATE-22.md)。本包只增加已知Parcel10→11路径；新库仍直接创建11，运行端不自动转换旧库。格式9及更早、未来格式、错误Application、基线哈希或实际结构不同，均保留原件并拒绝。

## 更新步骤

先完整退出原客户端，保持原种子、唯一配置账、数据根及原发布，不另建空站点。使用同源新安装EXE选择更新原登记；保留原程序根、运行账户、配置来源和数据位置，指定D盘新的完整备份目标。安装仍申请Windows管理员授权，验证受保护根、ACL、介质哈希/来源、普通祖先及原application-owner。未取得停止所有权不能并行更新。

预检将原DB/WAL和原配置/回包/图片等保管文件复制到私有维护区；只在副本核对格式、配置及原责任，不让SQLite只读连接在原根生成SHM或收拢WAL。获准10的基线SHA为 `ECC9F99AFD48F914765248A6B39064A49F0DCBF3DDD2F208C87C75F8E07FEB23`，同时逐项比对真实SQLite表/索引/触发器定义。仅改版本号不能通过。

原未决请求、未核对输入、回包缺失、身份冲突和隔离标记仍阻止程序切换；升级不结清它们。核对本机旧库时发现一条Prepared且发送次数0的作业，用户明确确认为“本机测试遗留，可按审计流程关闭”。该授权只用于这条已定位原意图，不代表可关闭其他未知或已发送请求。

准备阶段先调用原完整备份机制，复制唯一配置账及原件并最后发布COMPLETED；再次验证备份数据库、所有附属文件及原DB/WAL身份。进入提交后，单一SQLite事务添加统计表与三个索引，CAS替换10为11的精确格式身份、增加升级审计并保持软件暂停。原业务行、请求/报文字节、回包、原数字身份及配置均不重写，不根据条码重建实体，不倒填已清理明细的统计。

数据库事务失败时回滚完整10身份，不留下部分统计结构。数据库已提交但部署登记失败时保留11及原完整10备份，以同一新介质重新预检和前向完成部署；不自动用旧库覆盖现库，也不删除旧发布。格式10备份保留其真实格式，普通格式11恢复入口不会把它冒充当前备份；回退前须依据原发布、原完整恢复集及原隔离恢复守卫另行核对。

首次升级启动保留暂停，有健康连接也不会自动恢复供包；暂停不代表安全急停。进入管理模式，核对配置/历史和原请求责任后，可在维护中心“备份后恢复供包”中执行“检查并恢复”。真正执行Resume时再次检查管理授权、连接、容量及原责任，并持久记录StorageUpgradeReviewed；界面切换、调试结束或后台健康变化不能代替这次明确核对。本次本机启动验证不发送测试业务请求，也不自动恢复供包。

## 离线关闭从未发送的测试遗留

这是一项明确的受保护维护命令，不是数据库升级的自动步骤。只接受原作业ID、原body的精确SHA256和实体核对依据；原软件须暂停并完全退出。全部已有阶段必须为Prepared/Attempts0，不能有任何原发送/回包登记、图片责任、已接受、未知或冲突。先生成完整原件备份，再以事务复用在线AbandonUnsubmitted的状态转换，只取消未发送意图、保留原行和全部冻结请求，增加操作者/原因/前后哈希及备份审计。重复执行旧body哈希会拒绝并要求重新核对，不猜测结果。

在已获Windows管理员授权的控制台中，用同一新完整介质的自带宿主运行；下列占位值须替换为实际审阅对象，不能批量猜测作业：

```powershell
<新介质>/app/Ipc.Assembly.exe --action close-unsubmitted --file <原配置目录>/business.json --data-root <原数据根> --operation <明确核对的原作业ID> --sha256 <原body精确SHA256> --reason <明确核对依据> --destination <D盘新完整备份.db>
```

该入口不创建业务运行时、相机、SDK或发送器。需处理已发送或未知状态时，仍使用原请求核对及原匹配发布，不能借此命令降级责任。

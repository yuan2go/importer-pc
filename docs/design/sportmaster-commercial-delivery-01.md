## 产品旅程与唯一权威

安装继续用四步 Setup 和唯一 WindowsDeploymentSetup；目录选择通过原 helper、SID ACL、登记及后续维护传播。首配继续用 IStartupMaintenance/StartupConfigurationDraft：路径、设备/服务、策略、审阅四个任务区，另设恢复维护区。切区只改变可见性，输入保留。低频动作放所属区，底部只保留前后导航及本步主要动作。目录改变后必须重新读取；重新读取、关闭或切换安装前明确保护未保存输入。检查显示来源和时间；输入改变使其失效，保存/启动始终再走业务守卫。

首次安装无有效账也能离线修正：不先启动设备/数据库；保存首配及未确认失败修复调用现有 RepairInitial，不新建配置文件或授权开关。Desired/Pending/Effective 和旧失败尝试分开；启动检查全部资源成功才确认。备份/隔离恢复/原机接管各保留原实现的预览、CAS 和责任守卫。

视觉继承 v1.1 中性背景、专业标题、44 DIP 触控、文字状态和固定操作区。原 HTML/CSS/JS 已逐项读取且原内联块与分离版一致；共享箱/数量演示不移植为 Sportmaster 规则。错误原因持续可见、详细散列可展开；不把诊断隐藏成短暂 toast。帮助按任务导航和搜索，生产秘密及原报文仍排除于支持摘要。

## 发行与证据门禁

扩展现有 release-windows.py 的 profile，默认完整矩阵不变；Sportmaster profile 只含 portable/win-x64。复用 package-application、SourceCommit、composition.lock、SHA256SUMS 和 verify_package，不引入第二构建器。

交付裁决接受该发行库存与逐项证据：校验完整媒体/ZIP、源 SHA、固定必需 case、唯一 case ID、证据文件散列/相对路径、状态枚举。工程候选必须通过本机可运行核心、WPF、身份/介质检查；原生安装管理员全旅程可 NOT_RUN，但结果必须持续显示。生产裁决额外要求完整 Windows 生命周期、真实接口/设备、部署资格、分发签名与负责方放行证据全部 PASS；状态缺失、NOT_RUN/BLOCKED/FAIL 必拒绝。人工验收的责任和内容不能由哈希证明，报告明确其信任边界，不自动产生资格。

PR Windows CI 自动运行受影响测试与构建，保持仿真范围，不操作机级安装/真实设备。服务端是否设为 required check 按实际仓库权限核验，代码工作流不能冒称已配置分支保护。合并使用服务器 expected-head，禁止强推或跳过失败。

## 支持与 Windows 生命周期

随包交付任务手册、受控维护窗口、故障分级和升级路径、完整恢复集/退役清单、版本身份核对及验收表。支持联系人/响应时间由真实交付合同填写，未提供写待指定，不编造客户规则。维护窗口须先暂停并核对在途和 Unknown；计划备份不会自动暂停，到份数上限不删除旧备份。备份、恢复验证和外部核对分开。

Windows 计划绑定本次冻结介质，输出逐项 NOT_RUN 模板及环境检查；提供每项前提、执行、可观察断言、证据范围。普通当前主机可以运行非提权身份和 WPF/DPAPI等局部检查；没有已授权一次性 VM/第二账户/提升环境时，不修改共享安装、创建账户、重启宿主机或虚构生命周期 PASS。缺真实 SDK/合同/实体的项目保持 BLOCKED。

保持四层职责、Application 独立生命周期，不新增业务状态服务、PLC 能力、传图平台或远程遥测。

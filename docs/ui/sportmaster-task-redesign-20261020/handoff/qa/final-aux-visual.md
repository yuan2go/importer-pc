## 实质问题

### A1 · 原配置核对场景存在明确的接收状态矛盾

- 文件：`41-reconcile.png`。
- 可见事实：页面底部黄色提示为“核对结论已记录，作业仍保持暂停”；全局状态栏却显示“接收中”，并保留绿色左右位置状态。
- 影响：维护人员无法据此确认新包是否已经停止接收。这直接影响“记录核对不等于恢复业务”的语义。
- 建议：将该导出场景的全局接收状态设为暂停，再导出本图。真实核对按钮的辅助交互此前已同步 `S.paused=true`；本问题看起来出在用于静态导出的场景赋值，需父任务核实。
- 状态：已报告父任务；本审查未修改代码。此文件记录的是修复前截图。

### A2 · 安装完成场景的待配置对象与全局运行对象不明确

- 文件：`35-install-complete.png`（`33–34` 沿用相同全局状态栏）。
- 可见事实：安装完成页写明“现场运行：尚未配置和验证真实设备 / 待首次配置”，全局状态栏却显示左、右格口、WCS 连接可达、“接收中 / 运行 v12”。
- 影响：在“首次安装”任务中，容易把背景示例作业状态理解为刚安装客户端已可作业。
- 建议：安装任务采用明确的“安装演示 / 待配置”底部状态；如果这些数据意在表示另一份既有运行配置，应在状态条标明其归属。不要让待首次配置与本次接收中无范围说明地同时出现。
- 状态：已报告父任务判断。由于页面明确声明离线模拟，该问题属于设计语义歧义，不构成真实作业已经错误启动的证据。

### A3 · 未修改对象的连接测试文案被写成“未保存”

- 文件：`compact-wcs-failed.png`。
- 可见事实：顶部为“编辑状态：未修改”，固定保存栏为“没有未保存修改”；右侧测试摘要却写“测试使用编辑值 · 未保存”。
- 影响：把“测试没有执行保存”与“存在未保存编辑”混为一个状态词，削弱保存/运行状态的可信度。
- 建议：测试区改为行为说明，例如“测试使用当前编辑副本；本次测试不保存、不应用配置”。只有编辑值确有变更时，另行显示“编辑尚未保存”。
- 状态：已报告父任务；本审查未修改代码。

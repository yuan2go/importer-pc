# Sportmaster 供包台重设计交付包

设计交付 v1 · 2026-10-20 · importer-pc / C# / WPF

## 先打开什么

1. 双击 `Sportmaster-Prototype.html`，在桌面浏览器中打开可点击原型。无需安装依赖，无需联网。
2. 双击 `Sportmaster-UI-Gallery.html`，搜索和逐张查看全部48个画面。它内嵌清晰预览，完整包中的 `screens` 文件夹提供高清PNG。
3. 用 `Sportmaster-Field-Mapping.html` 搜索58条字段/状态、39条操作的原文、来源截图、新位置、校验及生效说明。
4. 阅读 `Sportmaster-Design-Handoff.pdf`（22页）及 `Sportmaster-UI-Atlas.pdf`（49页）。同名HTML和Markdown用于查阅或编辑交接说明。

浏览器直接从ZIP里预览文件可能无法加载相邻文件；请先完整解压。三个主要HTML各自可独立打开；图集到高清PNG、对应原型和交接文件的链接在完整包中使用。

## 亲自走一遍参数配置

打开原型 → 设备与设置 → 右位相机 → 将连接端口改成 `abc` → 点击校验或保存。

应看见错误定位在右相机端口，其他输入保留。把端口改为 `9001`（仅为演示值）后保存：已保存版本前进，实际运行版本不变。点击“查看并应用”查看完整变更和整站暂停范围。在模拟维护条件满足后，执行受控应用，读取运行确认，再决定恢复接收或继续维护。

相机地址/端口、WCS地址、设备身份、版本和延时均为示例。真实字段、范围、默认值及协议需根据实际驱动和服务核实。

## 亲自走一遍WCS异常恢复

作业页底部的演示场景选择“WCS中断” → 诊断WCS → 重新检查连接 → 模拟现场修复 → 再次检查 → 查询原请求 → 返回作业。

连接恢复不自动确认原包结果。“查询原请求”只演示核对既有请求，没有重复创建供包请求。正常连续扫码仅用“模拟左/右位下一包”代替真实相机输入，正式软件不需要每包点击这些演示按钮。

右下角“演示控制”可以注入保存失败、应用失败、运行版本无法确认、修订冲突等结果。刷新或重开原型会重置模拟状态；不会写入真实配置或恢复本地生产数据。

## 业务与验收边界

Sportmaster只演示左右相机读包裹号、请求WCS并显示格口，不下发PLC，也未新增包裹图片预览。正常组合不强制操作员登录；登录仅作为已确认适用的可选能力状态。其他主业务流程应保持独立Application。

附件36张原截图已逐张查看，35张唯一图像。原附件说明其为冻结WPF视觉树和合成数据；本次没有读取其冻结提交源码。

六项核心模拟任务已有通过记录；最终构建另做10项针对实际发现问题的定向复核。各次检查对应的SHA、过程和修正均保留，没有把旧构建验证冒充最终全量回归。

PNG、HTML和模拟QA不证明Windows实机、DPI、相机SDK、WCS协议、配置事务、安装、性能或商业交付已通过。这些项目已在交接说明中独立列为实机验收。

# 参数继承增量：运行与操作

本轮沿 PARAM-01 / PARAM-UX-02 实施，Sportmaster 版本 1.8.0；共享合同 1.14.0，DirectPlc/WcsToPlc 1.5.0。具体源码、原生截图和安装介质身份由本轮验证记录给出；本文不是现场验收。原 1.7.0 / PR80 介质和 PR81/82 验证各守原 SourceCommit。

设计与证据依据见[本轮裁决](../design/parameter-inheritance-02.md)和[93项统一迁移表](../design/parameter-legacy-migration-02.csv)。旧字段来自用户的旧系统盘点；被引用的旧读取源码当前未取得，不执行猜测式自动转值。迁移前保留旧配置原件，逐行确认单位、用途和对应 Application，然后在现有首配或参数目录中填写；不能将旧 JSON 改键后直接用于生产。

## 日常参数与首配

首配和日常页面编辑同一个完整候选，系统取格口身份只有一个编辑来源；心跳身份及各相机编码分别维护。左右相机仍为两个独立 Reader，调度系统仍为一个共享连接。运行地址、安装版本和当前候选分开显示；连接诊断读取当前运行事实，不测试尚未保存的目标。

目录、搜索、错误定位、差异审阅使用相同的四类归属：系统负责身份、记录、备份和显示；业务模块负责接受条件、等待期限和作业登录；驱动负责读码、称重、PLC和采图等硬件协议；组件负责调度、登录和上传服务。字段来自实际安装描述，未安装精确提供者会明确阻断。Sportmaster不提供新增称重、PLC、采图或上传入口。历史可选能力原件保留，诊断和高级完整候选仍可核对，不静默丢弃绑定。

修改运行参数后用统一“保存更改”核对差异、原因和权限。无差异不新增修订；保存为待重启配置，受控重启成功才生效。重连继续使用当前运行配置。保存结果未知时只核对原提交，不生成第二次保存。原作业固定原配置、原目标和原报文。

## 条码允许与排除

“业务模块 → 条码筛选”包含允许正则、可选排除正则和本地候选样例。两种正则都整串匹配，不自动补通配符。先符合允许规则，再由排除规则否决；剩余恰好一个有效候选才能继续原准入守卫。例如允许 `OK[0-9]+`、排除 `OK00[12]` 时，样例 `noise`、`OK001`、`OK003` 分别显示未允许、被排除、有效，最终只选择 `OK003`。示例不是生产默认。

每行作为本次观察的一个候选；测试复用 Application 的实际筛选机制，不创建作业或外呼。修改样例或任一规则都会使原结果过期。单次匹配预算25毫秒，两条规则共用总预算100毫秒；不完整、超配额、超时、非法规则和多个有效码均拒绝。重复候选不合并；同码的左右实体仍独立处理，不使用跨位去重窗口。

旧 `BarcodeFilter=null` 保留严格单原始码兼容；旧仅 `Pattern` 的序列化与指纹不变。新增排除参与新规则指纹，候选结果和拒绝原因随输入/作业保留。清空已经存在的允许规则不等于恢复旧兼容，必须修正有效规则后保存。

## 可选作业登录

“业务模块 → 作业登录”选择已有操作员登录绑定，首配使用相同草稿中的启用选择。连接目标、协议与敏感引用在对应组件维护。作业会话时长为100～86400000毫秒，只有绑定操作员登录或存在需修正错误时显示。解绑保留原时长，不修改维护认证绑定；维护权限仍由独立 Application 守卫检查。

缺少实际登录提供者/合同只阻断该能力。内置参考登录为显式模拟能力，不是可用于生产的账号系统。原敏感引用通过既有受保护编辑入口处理，不将凭据显示在差异审阅中。

## 记录、日志和图片

三种保留策略不能互相替代：

| 设置 | 实际行为 |
|---|---|
| 常驻历史条数 | 1～10000，控制运行投影/同库归档；不代表删除磁盘历史。未决责任仍受保护。 |
| 诊断日志保留天数 | 可空；1～3650天作为最长保留期限，仅管理诊断目录的 `runtime.jsonl` 及 `.1`～`.3`。沿原每份约5 MB、最多四份预算；空间轮转可能更早淘汰，天数不是最低保留承诺。启用后启动、写入和每分钟维护；不跟随待重启配置或普通重连生效。 |
| 图片证据 | 沿当前 Application 的采集/上传责任及引用计数释放；日志期限不删除图片、恢复集、作业数据库或审计。Sportmaster当前界面不增加传图设置。 |

日志路径拒绝链接/重解析点，失败通过原辅助诊断反馈，不吞异常换成功。磁盘保留空间单位为MiB（1048576字节），不足时保留原责任并阻断新准入。完整备份继续复用原引擎、维护授权、暂停和无在途外呼要求，不以参数模板替代恢复集。

## 本机显示

“系统 → 显示偏好”可填写站点显示名称（最多64字）和目标效率（选填1～100000件/小时），点击“应用本机显示”。工作台同时保留内部站点标识；目标只显示为目标效率，不控制输送速度、采集触发或业务等待期限。

该偏好按当前系统用户、Application和站点存于现有 `ImporterPc/presentation` 目录，立即更新当前窗口，新窗口重新读取；不进入运行配置Revision。应用失败保留输入和旧显示，非法原偏好文件保留供核对。未应用的显示输入参与关闭保护，并可随原加密编辑草稿保留/恢复；恢复不自动应用显示，站点身份改变时拒绝移用。标准/紧凑布局继续使用原入口。当前仅提供真实实现的简体中文和浅色界面，其他语言和主题不提供占位选择。

## 适用称重业务

DirectPlc/WcsToPlc保留各自独立业务流程。重量来源、单位、精度、数据新鲜度和本件等待期限继续由原策略消费；驱动负责实际协议、换算与信号判稳。新增可选包裹范围与重量策略使用同一单位、精度，满足0≤下限≤上限≤100000且上限大于0，边界包含在内。

越界、不稳定、零值、单位不符、过期或身份不符的测量均无效；等待期间显示拒绝原因但不延长原期限。超时仍需原受守卫的检查处置，不生成默认有效重量；下一件同码实体必须获得自己的有效测量。显式配置重量保持“配置来源、非设备测量”标记，且必须满足范围；迁移旧超时默认重量必须先取得业务依据。

仅参考端口已具备条件的链路执行合成验证。旧PLC协议、串口秤判稳参数、体积、FTP/HTTP上传、机器人、远程主控配置、标定及入站事件合同各按迁移表列出缺口；不会因字段名相近而宣称真实协议已支持。

## 实现定位

合同扩展在 `Ipc.Application.Contracts`；`BarcodeFiltering`、`WeightRules`和`ParcelGuards`消费冻结业务策略；`ParcelRuntime`成功激活后配置 `RuntimeJournal`。`ConfigurationPolicyDraft`共用于首配/日常，`ParameterOwnership`统一分类；显示使用`PresentationPreferences`及`StationDisplayPreferences`，不产生第二套运行配置账。

必要验证沿现有 `--parameter-refactor`（包含继承专项）、`--parameter-v3`（包含真实WPF继承交互）和登录专项；发行沿原冻结构建、原生验证与同源安装器入口。真实SDK、外部服务、目标工控机和现场验收单独登记，不由合成验证替代。

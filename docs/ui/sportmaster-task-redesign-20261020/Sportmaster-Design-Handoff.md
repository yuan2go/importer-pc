## 1. 本次设计的核心决定

### 1.1 产品的基本单位

以“某个人对某个对象完成一项任务”为设计单位：操作员读取当前左右包裹结果；调试人员建立明确的设备实例与位置绑定；维护人员定位故障、修改参数并判断实际生效。现有技术页签不是新导航的约束。

主导航固定为 **作业 / 记录 / 设备与设置 / 诊断**。首次配置、安装维护、备份恢复和帮助支持从设置或底部入口进入。首次配置使用向导，日常修改直达对象表单，不重新走向导。

### 1.2 必须保持的业务语义

- Sportmaster：左右相机分别读取包裹号 → 请求 WCS → 取得格口 → 页面展示。没有 PLC 下发，也不凭 UI 截图新增包裹图片预览。
- 取得格口只代表本次 WCS 结果已取得，不能写成“包裹已完成”或代替现场实体完成证据。
- 不同主流程仍属于独立 Application；DirectPlc、WcsToPlc 的能力不能通过作业页下拉切换混入 Sportmaster。
- 默认正常连续扫码自动推进；不新增每包确认、人工提交或常规启停步骤。既有“暂停新入场”只在维护或适用异常处置中呈现，并说明不是设备安全急停。
- 登录只在当前组合已经安装、启用且业务需要时呈现。维护认证沿用既有边界，不由设计擅自增加操作员强制登录或复杂权限体系。
- 称重、传图和旧版协议字段在库存或兼容区域保留，不能据此认定 Sportmaster 当前需要这些功能。

### 1.3 配置的明确约定

**对象表单限定编辑范围；保存仍形成经过整站关联校验的完整配置修订。** 不因为把相机分成左右两个表单，就假设后台已经支持独立对象保存或独立热应用。

原截图出现完整候选、草稿 CAS、Effective/Pending 和保存待重启。本设计保留这些工程语义，用清楚的中文表达：**编辑基线 / 已保存配置 / 最后确认运行配置**。默认运行参数在保存后等待受控重启，设备是否能够单独重连或热应用作为后续实现验证事项。

## 2. 新任务结构与入口

| 任务区 | 主要内容 | 用户为何能更快定位 |
| --- | --- | --- |
| 作业 | 左右当前包裹、格口、本次状态、作用范围明确的异常、必要详情 | 当前包裹和操作位置一一对应；技术日志和配置不挤占结果区域。 |
| 记录 | 固定查询快照、包裹号/位置/状态/时间筛选、详情和适用原请求核对 | 查询时不被新扫码不断插入打断；技术筛选按需展开。 |
| 设备与设置 | 概览、左相机、右相机、WCS 服务、位置与绑定、运行规则、组件 | 先确定正在改谁，再显示该对象适用参数；安装、实例、绑定、连接各有明确含义。 |
| 诊断 | 当前故障、受影响对象与包裹、分层检查、恢复条件、技术详情 | 从故障直接到相关参数或证据，不要求维护人员猜技术页签。 |
| 首次配置 | 工作站与目录 → 设备和绑定 → 运行规则 → 检查及保存 | 为首次部署形成顺序；完成后日常维护直接使用对象表单。 |
| 安装维护 | 目录与运行账户 → 介质与组件 → 安装计划 → 结果 | 安装、组件库存和配置生效分开；后续步骤属于本次设计提案，原附件只提供安装首屏。 |
| 备份恢复 | 配置模板、修改记录、完整备份与恢复 | 模板迁移配置、备份恢复作业责任，各自范围清楚，避免误把模板当全量恢复。 |
| 帮助支持 | 离线任务帮助、诊断摘要预览、关于与版本 | 根据当前任务或错误进入，导出前能看到对象、时间和脱敏范围。 |

### 2.1 操作员：开始与连续供包

**目标**：知道工位是否可接收，准确读取左右各自的本次结果。

**入口**：启动后作业页；未完成首配或被维护阻断时就地显示原因及入口。

**步骤**：查看工作站与当前接收状态 → 左或右相机读入新包裹 → 该位进入处理中并移除上一件格口的主显示 → 对应请求的有效响应更新该位 → 按现场既有方式投递。

**成功反馈**：固定区域显示当前包裹号、格口、获取时间与“已取得格口”。

**失败处理**：该位显示超时、拒绝、结果待核对或设备故障的具体状态。共享 WCS 故障是否影响两路由 Application 返回；一路故障不能让界面自行推导另一路可继续或必须停止。

**返回作业**：打开记录或诊断时仍显示紧凑作业摘要；返回后恢复完整实时视图，无须重新选择工位。

### 2.2 调试人员：首次配置并判断能否使用

**目标**：把安装好的实现、具体实例与实际左右位置正确关联，并知道哪些检查完成。

**入口**：首次配置向导；已配置工位从设备与设置进入。

**步骤**：核对工作站身份、Application 与环境 → 选择已安装且适用的驱动 → 配置具体设备实例 → 绑定左右投递位 → 配置 WCS 实例 → 查看运行规则 → 分层检查与变更摘要 → 保存完整修订 → 在受控启动/重启后读取运行状态。

**成功反馈**：保存完成明确写“已保存，待受控重启生效”；只有运行确认后才能写“运行配置已确认”。

**失败处理**：就地定位对象和字段；保留其他输入；未安装、未启用、未绑定、连接失败与业务响应未验证分别显示。

**返回作业**：可以先保存后返回，但作业状态必须反映真实接收能力；首次工位没有可运行配置时不能显示可投入运行。

### 2.3 维护人员：修改指定相机参数

**目标**：改对相机，保留其他配置，明确何时影响运行。

**入口**：设备与设置 → 左相机或右相机；也可从诊断中的相关对象进入。

**步骤**：核对标题、投递位与设备身份 → 修改适用连接参数 → 检查修改 → 定位并修正错误 → 查看本次差异与完整修订保存范围 → 保存 → 比较已保存与运行状态 → 按维护安排受控重启并读取确认结果。

**成功反馈**：未改其他对象时，差异摘要只列选定相机的字段；保存提示仍明确是完整工作站修订，当前运行值继续独立显示。

**失败处理**：字段错误保留输入；并发修订冲突保留草稿并展示差异；保存失败不改变运行状态；应用失败按可确认的运行证据显示，不能默认回滚成功。

**返回作业**：编辑未保存时提供明确离开处理；已保存待生效时可直接离开并保留待生效提示。

### 2.4 维护人员：WCS 异常诊断与恢复

**目标**：判断影响、查到故障层级并恢复适用业务，避免重复请求。

**入口**：作业异常条或某包裹异常详情 → 诊断，带入 WCS 对象及原包裹/请求。

**步骤**：阅读受影响范围 → 查看最后确认状态 → 选择“检查运行连接”或明确的“测试编辑参数” → 分层结果定位 → 必要时进入 WCS 设置 → 保存与受控重启 → 重新读取运行连接状态 → 单独核对未知原请求。

**成功反馈**：连接恢复、运行修订确认、原请求结果确认分别陈述。

**失败处理**：只读检查不可用就明确“未验证”；原请求结果未知继续保留未知，不自动重发，也不把网络恢复当作该包成功。

**返回作业**：确认仍存在的阻断；“标记已阅”不能清除故障，恢复接收不能代替原请求核对。

## 3. 设备与设置：对象模型及字段安排

| 对象代码 | 用户看到的名称 | 本页编辑范围 | 保持可见的归属信息 |
| --- | --- | --- | --- |
| summary | 配置概览 / 工作站 | 工作站摘要、文件位置及运行/保存状态；身份本身只读 | 工作站、Application、模拟/生产、编辑基线、已保存与运行修订。 |
| left | 左投递位相机 | 左相机实例的适用连接与驱动参数 | 左位置、相机名称、稳定设备身份、实例编号、所用驱动及版本。 |
| right | 右投递位相机 | 右相机实例的适用连接与驱动参数 | 右位置、相机名称、稳定设备身份、实例编号、所用驱动及版本。 |
| wcs | WCS 服务 | 当前 WCS 实例的适用连接与协议参数 | 服务名称、实例、实现、版本、绑定的投递位和运行状态。 |
| bindings | 位置与绑定 | 左右位置到设备实例、WCS 实例的关联 | 显式左右行；已配置实例选择器；物理身份和占用情况。 |
| policies | 运行规则 | Application 处理策略与记录保留相关参数 | 作用对象、单位、当前值来源和影响；语义未确定的字段保留待核实标识。 |
| modules | 已安装组件 | 库存检查、适用实例的启用/配置入口、安装维护入口 | 已安装、适用于当前 Application、已启用、已绑定、连接状态分别表达。 |

### 3.1 分开四种容易混淆的任务

1. **选择驱动**：在已安装、兼容的实现中选择类型和版本，不代表选中某台物理设备。
2. **配置实例**：创建或选择具体实例，输入该驱动描述的参数，显示稳定实例编号。
3. **识别物理设备**：SDK 发现或离线录入设备身份；离线输入显示“待真实设备核验”。
4. **绑定作业位置**：把已配置实例放到左位或右位，并按业务规则校验重复或缺失关联。

更改人类名称不应改变稳定实例 ID 或物理设备绑定。现有工作站身份保持只读；新增工作站应通过已安装的身份创建/装配路径完成，不把编辑主键当普通表单任务。

### 3.2 原字段迁移的依据与裁决

完整明细来自 [parameter-migration.csv](handoff/data/parameter-migration.csv)（P01–P58）、[action-migration.csv](handoff/data/action-migration.csv)（A01–A39），以及 [workflow-inventory.md](handoff/data/workflow-inventory.md) 中的作业、记录和支持映射。文件名及编号是本次交接引用，不代表源代码已采用该模型。

| 原内容 | 新归属 | 处理结果 |
| --- | --- | --- |
| 维护账户、口令、原因（P01–P03） | 维护身份入口 / 保存摘要 | 身份只用于既有维护授权；原因按原必填规则保留，不每字段重复填。 |
| 编辑来源、CAS、Effective/Pending（P04–P06） | 固定配置状态区 / 高级详情 | 编辑基线、保存修订与运行确认拆开。CAS 基于所加载完整修订，不应笼统改叫“基于运行版本”。 |
| 设备ID、角色、提供者、实例（P07–P10、P45–P46） | 左/右相机、位置与绑定 | 人类名称主导，稳定标识可查可复制；驱动、实例、物理身份、位置分别表达。 |
| 完整候选JSON、SchemaVersion（P11–P12） | 高级维护 → 配置文本 | 保留专业维护能力，默认只读；不以 JSON 作为日常参数入口。 |
| 原账、SHA256、核对说明（P13–P14） | 诊断 → 配置核对 | 证据明确；确认核对仍不代表已启动资源或可开放新业务。 |
| 模块元数据与要求（P15–P23） | 组件 → 安装及兼容性详情 | 改成可读元数据；空 Parameters 显示没有可配置参数，不虚构隐藏字段。 |
| 能力类型、启用、提供者、协议目标（P24–P30） | 组件 / 对应服务实例 | 安装库存、实例状态和业务绑定分开；协议目标按实现定义控件，不一律当 URL。 |
| 旧称重与传图策略（P31–P38） | 高级维护 → 旧格式兼容 | 保留和核对；不变成 Sportmaster 新增称重、图片预览或上传开关。 |
| 离线包、SHA、目录未准备（P39–P41） | 组件安装检查 / 安装维护 | 提供文件选择与校验结果；库存不可读、未安装和未启用分别说明。 |
| 配置目录、数据根、身份（P42–P44） | 工作站摘要 / 首次设置 | 保留环境、站、Application 隔离；选目录、读取、迁移各自独立。 |
| 队列、超时、作业容量、历史（P47–P50） | 运行规则 | 集中展示，同一保存修订；不把样例当默认，不擅自把“作业容量”改称并发数。 |
| 备份规则、首配原因、备份清单（P51–P54） | 备份与恢复 / 首配检查 | 保留可见约束；未提供频率或份数输入时不编造默认计划。 |
| 恢复交接、命令目标、身份冲突、RawDurable（P55–P58） | 诊断与记录中的确切对象处置 | 技术证据按需展开；无标签字段标待核实；动作必须绑定原作业。 |
| 重复辅助工作台、经典布局、最小尺寸变体 | 同一作业页的视图与尺寸策略 | 能力迁移后再移除重复入口；不能仅凭重复截图断言所有辅助窗口功能相同。 |

分析清单中的早期建议若写“保存摘要只包含右相机”，最终解释为**变更差异只包含右相机，持久化仍为完整关联修订**。若写“左相机单独生效”，应替换为本稿的受控重启约定，直到源码和实机证实更窄的应用粒度。

### 3.3 新原型连接参数的证据标签

左相机 `192.0.2.21`、右相机 `192.0.2.22`、端口 `9000`、WCS `wcs.example.test` 仅为本次**设计演示值**。原截图没有证实真实相机 IP、端口、SDK 参数、WCS URL、认证字段或业务接口路径。演示控件用于走查对象选择、错误和保存状态，不可将这些值提交为生产默认配置。

生产字段清单应从当前 Drivers / Integrations 的参数描述中获取，包括类型、中文标签、说明、适用条件、格式、单位、合法范围、是否有默认值和生效影响。不存在可信默认值的字段不提供“恢复默认”；精确作用域不明的“调用超时”、含义不明的“作业容量”“精度”在实施前核实，不能用常识改写协议语义。

## 4. 编辑、保存与生效状态

### 4.1 三份内容不能混为一份

| 内容 | 面向用户的说法 | 含义 |
| --- | --- | --- |
| 草稿 | 正在编辑 / 未保存 | 以某个完整配置修订为基线的修改；可包含不合法或未完成输入。 |
| 已保存配置 | 已保存修订 / 待生效 | 后端确认持久化的完整配置候选；不代表运行资源已使用。 |
| 运行配置 | 最后确认运行修订 + 确认时间 | 从真实运行资源读回的已确认状态；确认过期时必须标为过期或未知。 |

示例：“编辑基于修订 12；已保存修订 12；运行修订 11，10:34:12 已确认”。修订数字是演示数据，生产版本由后端返回。不要用一个“已保存”提示替代运行确认，也不要从磁盘候选文件内容推断正在运行的版本。

### 4.2 编辑与保存状态表

| 状态 | 页面反馈 | 可用操作 | 不可做的事 |
| --- | --- | --- | --- |
| 未修改 | 显示对象、基线、已保存与运行状态；保存按钮无待保存内容说明 | 编辑、检查连接、比较版本 | 不能把“无修改”当作所有设备正常。 |
| 编辑未保存 | 对象标题旁“有未保存修改”；底栏显示差异数量与范围 | 检查修改、保存、撤销本次编辑、离开处理 | 自动刷新不得重写草稿或悄悄更换 CAS 基线。 |
| 正在校验 | 写明校验对象及整站关联；锁定重复提交，保留输入 | 必要时取消可取消的校验 | 不显示伪百分比，不保存，不启动设备。 |
| 字段错误 | 字段红框、中文原因、修正提示；摘要可跳转第一项 | 修改错误字段，保留其他输入 | 不用反复弹窗，不清空表单。 |
| 关联冲突 | 明确冲突的两个对象与字段，如左右绑定重复；提供跳转 | 修正绑定或相关实例 | 不能仅显示“配置无效”而不给对象。 |
| 正在保存 | “正在保存完整工作站修订”；列明本次差异；运行状态独立 | 查看必要状态，避免重复提交 | 保存未获后端确认前不显示成功。 |
| 保存失败 | “未保存”；错误及是否需要重新读取；草稿仍在 | 再次保存、复制详情、继续编辑 | 不丢输入，不自动声称旧保存状态已更新。 |
| 保存并发冲突 | 本地编辑基线与最新修订不一致；差异预览 | 保留草稿，重新读取并合并后复核 | 不覆盖较新修订，不自动强制保存。 |
| 已保存待生效 | 明确已保存版本、当前运行版本、需受控重启 | 查看差异、稍后处理、进入受控重启 | 不因为保存成功而把连接状态变绿。 |
| 应用中 | “正在受控重启并核对运行配置”；阶段与影响范围 | 查看过程；仅真正可取消阶段可取消 | 不提前恢复接收，不把已启动进程等同于设备已可用。 |
| 应用成功且已确认 | 已确认运行修订、确认时间、资源状态 | 返回作业，按真实条件恢复接收 | 未知原包裹不会因此变成成功。 |
| 应用失败 | 分别显示失败阶段、已保存目标修订和可确认运行状态 | 诊断、重新读取状态、按证据恢复上一有效配置 | 不能自动假定回滚成功或把最后确认值写成当前实况。 |

### 4.3 保存完整修订的建议实现顺序

1. 草稿记录其加载的完整基线修订，以及本次被修改对象和字段。
2. 对象表单更新草稿中的相应对象；其他未改字段按原内容保留，不能重新生成时丢失未知兼容字段。
3. 保存前从同一草稿生成完整候选并执行字段、实例引用、绑定、组件兼容和 Application 关联校验。
4. 使用基线修订进行 CAS。后端发现新修订时返回冲突，UI 保留草稿，不强制覆盖。
5. 成功后以持久化回执更新“已保存修订”，保留后端返回的修订、摘要及变更原因；不同时更新“运行修订”。
6. 默认标为待受控重启。受控重启有独立命令、资格检查、结果和运行读回。

本顺序是产品契约。是否已有原子写入、CAS 回执、未知字段保留和完整候选验证，须核对代码后再复用或补齐，不能仅因截图有这些文案就认定已正确实现。

### 4.4 受控重启与失败后的实际状态

受控重启入口应显示**影响当前工作站的完整运行装配**。在没有证据支持对象级重启前，不写“只重连左相机、右位不受影响”。

按已有能力检查维护身份、暂停新接收、在途处理责任、所需资源与待生效修订；完成安全边界后才停止/启动相关服务。现场真实的在途判定与恢复围栏须沿用当前实现，不能通过 UI 重新定义。

失败后的运行提示至少区分：

- **旧修订仍在运行，已确认**：只有实际读回证据才能使用；显示修订与时间。
- **服务已停止**：不显示“正在运行某修订”，明确当前不能接收新包。
- **运行版本待确认**：显示目标修订、最后确认修订及时间，但将后者标为历史确认；禁用依赖可信运行状态的恢复操作。
- **部分资源状态不一致**：显示受影响资源，整体不冒充已应用成功；是否允许受限运行由 Application 决定。

“恢复上一有效配置”应载入已确认有效的完整修订作为新的候选，先展示差异与兼容性，保存后受控应用。除非后台能够证明回滚已经完成，否则按钮返回不能直接显示“已回滚”。

### 4.5 离开、撤销、默认与恢复的范围

| 操作 | 明确范围 | 结果 |
| --- | --- | --- |
| 继续编辑 | 当前对象未保存内容 | 留在原对象、原字段和原输入。 |
| 保留草稿并离开 | 当前编辑会话中的对象草稿 | 导航离开但不保存运行修订；再次进入仍提示未保存。若只在当前进程内保留必须说明，不能承诺进程退出后仍可恢复。 |
| 放弃本次修改 | 对话框列明的当前对象改动 | 还原到该对象的编辑基线，不回滚已经保存或正在运行的配置。 |
| 保存后离开 | 本次差异合入完整配置修订 | 通过完整校验与 CAS 后离开；保存失败留在编辑页；仍待生效。 |
| 撤销本次编辑 | 当前对象草稿 | 恢复已加载基线；与“恢复出厂默认”不同。 |
| 恢复默认 | 具有可信参数默认值的选定字段或对象 | 先生成草稿差异，随后常规校验保存；没有默认信息时禁用并说明原因。 |
| 恢复上一有效配置 | 明确选定的完整工作站修订 | 先预览，后保存待生效；不清历史作业，不重放业务。 |

不要求同一离开对话框同时塞入四五个按钮。主原型可用“继续编辑 / 保留草稿并离开 / 放弃本次修改”三项，显式保存仍在页面底栏。关闭窗口或进程退出时再按实际草稿持久化能力设计，不能用浏览器会话演示冒充已有恢复能力。

## 5. 连接检查：对象、层级与下一步

连接入口须写明**测试编辑参数**或**检查运行连接**。前者读取草稿，后者读取已确认运行对象；不能让用户猜测测试哪份值。

| 层级 | 应显示的结果 | 失败的下一步 |
| --- | --- | --- |
| 参数格式 / 关联 | 格式合法、绑定可解析，或具体字段错误 | 跳到出错字段或绑定，保留其他输入。 |
| 地址 / 端口可达 | 当前测试对象、目标与可达结果 | 查看地址、端口、网络或防火墙；此层成功不等于协议成功。 |
| 设备 / 服务会话 | 指定实例成功建立协议连接，或握手/认证失败 | 对应驱动或服务连接参数；技术错误可复制。 |
| 数据 / 响应 | 收到读码数据、只读健康响应，或尚未观察到数据 | 检查设备触发/数据链路；没有数据不能报错为“设备必坏”。 |
| 业务有效性 | 只在已有合规证据下显示业务响应验证；否则“未验证” | 进入受控联调或查看真实请求证据；不通过按钮发送普通生产扫码业务来制造绿色结果。 |

上述层级是呈现框架，不要求每个驱动支持全部主动测试。没有安全只读接口时，将层级标为未验证并给说明；真实 SDK 打开设备是否影响现有会话也须核实。测试不保存、不应用参数、不改变绑定、不发送真实业务、不悄悄消耗原请求。

每次检查显示对象、输入来源、时间及结果新鲜度。结果只对本次被测试参数成立；测试后修改关键参数应将结果标为“参数已修改，需要重新检查”，不能保留旧绿色结果。

## 6. 作业状态与主要按钮契约

### 6.1 固定左右结果区域

每一侧按“位置 → 当前包裹 → 当前结果 → 下一步”组织。位置标签和结果数字位置固定，状态变化不引起左右交换或控件抖动。当前结果与历史记录分开，不用同一数字区域同时表达旧件格口和新件处理中。

| 状态 | 结果区表达 | 允许的下一步 |
| --- | --- | --- |
| 等待扫码 | 等待本位读码；当前结果区无上一件格口 | 自动接收下一件，无每包确认。 |
| 处理中 | 当前新包裹号与“正在查询格口”；旧格口退出主结果区 | 自动等待；详情可查看，不重复提交。 |
| 已取得格口 | 本包裹号、格口与结果时间 | 按现场流程投递；需要时查详情。 |
| 业务拒绝 | 原因与本包裹身份；格口区不显示伪成功 | 按 Application 的拒绝处置规则执行，不自动重发。 |
| 超时 / 结果待核对 | 未确认取得格口；明确保持原请求 | 只读核对原请求（具备能力时），不提供泛化“重试”。 |
| 相机中断 | 本位相机状态及接收影响；其他位状态独立 | 诊断相机；影响范围从运行状态读取。 |
| WCS 中断 | 服务故障和实际影响范围 | 诊断 WCS；网络恢复后原请求仍单独核对。 |
| 状态失效 | 不能确认当前结果；显示最后确认时间 | 读取新状态 / 诊断；旧格口只能出现在明确历史区域。 |
| 恢复中 | 正在连接/读取状态，不提前宣布正常 | 等待真实运行与资源结果。 |

记录详情应锁定所选包裹和请求。新扫码不能让“核对原请求”动作悄悄改作用到新的当前包裹。长条码保留前导零和完整字符串；长格口不得以省略号隐藏决定投递的关键部分，采用换行或受控字号并保留全文查看。

### 6.2 按钮行为

| 按钮 | 对象 / 启用条件 | 执行中 | 成功与失败 |
| --- | --- | --- | --- |
| 检查修改 | 当前草稿及完整候选的关联依赖；有可检查内容 | 标明校验中，防重复点击 | 返回具体字段/关联结果；不保存、不启动。 |
| 保存修改 | 本次对象差异合入完整候选；满足必要输入与维护规则 | 保存完整修订，保留运行信息 | 成功待生效；错误或CAS冲突保留草稿。 |
| 查看变更 | 草稿或待生效修订与相应基线 | 读取比较中 | 列对象、字段、旧值、新值；敏感值只显示变化事实。 |
| 撤销本次编辑 | 当前对象存在未保存改动 | 通常本地即时 | 还原基线；不影响已保存和运行版本。 |
| 受控重启并应用 | 存在待生效修订且真实维护资格、在途责任、资源状态满足 | 逐阶段反馈与全站影响 | 以读回运行修订确认；失败按已停止/旧版已确认/未知分类。 |
| 测试编辑参数 | 指定对象草稿格式合法且实现支持安全测试 | 明示草稿目标、层级、时间 | 仅更新测试结果；失败保留参数，提供相关字段跳转。 |
| 检查运行连接 | 指定运行实例可识别且状态来源可信 | 明示运行对象与修订 | 分层显示，不影响配置或原业务。 |
| 查看本包详情 | 存在明确包裹或选定历史记录 | 局部加载 | 固定对象；失败保留已有内容与对象。 |
| 核对原请求 | 原请求身份明确、后端具有可靠只读核对能力 | 写明左/右、包裹与请求，防重复点击 | 已确认或仍未知均为有效结果；不改成重新发送。 |
| 继续未执行步骤 | 后端能证明该阶段未曾尝试且满足资格 | 指明具体阶段，非笼统“继续” | 读回阶段结果；失败不自动循环，不重发未知阶段。 |
| 暂停接收新包 | 既有运行能力支持、范围明确、授权满足 | 等待后端确认 | 仅改变入场许可；失败或未知明确显示，不模拟机械急停。 |
| 恢复接收 | 暂停状态且全部适用阻断解除、状态新鲜 | 恢复中 | 读回可接收范围；失败保持阻断说明。 |
| 标记已阅 | 当前报警通知 | 即时记录已读 | 仅确认人已看见，不清故障、不改业务结果。 |
| 查询记录 | 筛选合法；无重复查询 | 保留上一快照并标查询中 | 成功整体换新快照；失败保留旧快照并说明。 |
| 导出筛选结果 | 有合法且完成的查询快照 | 固定范围、进度和取消 | 成功明确文件与范围；失败不伪报完整导出。 |
| 导入配置模板 | 文件版本、当前 Application、目标对象可验证 | 解析并生成差异预览 | 导入先形成草稿；敏感值补齐；不自动生效。 |
| 导出诊断摘要 | 合法时间范围和有效已审阅预览 | 明确导出当前预览 | 成功本地保存；失败保留预览，不扩大采集范围或上传。 |

## 7. 商业配置维护的有限闭环

### 7.1 配置摘要与修改记录

摘要回答当前工作站、Application、环境、左右绑定、WCS实例、已保存/运行修订和未完成事项。修改记录围绕版本、对象差异、原因、时间和生效结果，不建设与任务无关的审计大屏。

敏感值以“已设置 / 未设置 / 已更改”表达，复制与诊断默认脱敏。技术字段可按需展开，主表单仍用中文名称。访问控制继续以已存在能力为基础；没有证据时不虚构登录用户、授权角色或签名结果。

### 7.2 配置模板与完整备份分开

- **配置模板**：用于同版适用对象的快速配置；导入前显示 Application、工作站适用性、驱动兼容、字段差异及缺失敏感值。载入仅产生草稿，保存后仍待受控生效。
- **完整备份**：包含实际要求的数据库与恢复同伴等完整责任；截图提到的 `.recovery` 与原配置证据需要保留。完整性通过不等于已满足换机接管条件。
- **完整恢复 / 换机接管**：保持隔离；核对原根退役、受保护登记、机器/目录身份等既有条件。恢复不自动开放新业务，也不重放原请求。
- **旧格式迁移**：旧schema 1/2字段按原语义保留、展示迁移差异；未识别字段不静默丢弃。旧称重/传图设置不进入 Sportmaster 常规作业。

原截图“最多256份”“计划备份需要受控维护窗口，达到份数限制不会删除旧备份”是可见说明，实际约束需核实。不可因重设计而默默改成自动删除旧备份。

### 7.3 支持导出

导出前预览当前对象、关联包裹/请求、时间范围、包含项目、缺失项目和脱敏内容。保留截图可见“最多7天”和“预览固定5分钟”的约束线索，确切含义由实现核实。日期、时间与时区分别校验；不把非法日期统一误报为时区错误。原型时间按 `Asia/Shanghai (+08:00)` 标示。导出模拟内容不连接设备、不发送外部服务、不上传用户数据。

## 8. 统一视觉规格与窗口策略

- 相机、服务和工作站长名称保留识别部分，并可查看/复制全文；完整身份不能依赖截断文字。
- 路径和地址允许选择与复制，不因输入太长挤掉标签和按钮。
- 无参数、未安装、未启用、未绑定、未收到数据分别有空状态及下一步，不用同一个空白框。
- 禁用按钮旁能找到原因，不把工具提示作为唯一信息源。
- 字段错误扩展位置应预留，尽量不推动主要保存按钮；整页滚动时对象标题和保存状态仍可定位。

## 9. 在现有 WPF 中落地

### 9.1 UI 与业务边界

界面仅将 Application 的状态转为可读呈现，并发送明确对象命令。相机参数来自 Drivers，WCS协议参数来自 Integrations；平台提供共用配置保存、版本、诊断和资源生命周期能力，不将不同主业务流程编成一个通用UI流程引擎。

建议保留现有窗口宿主与可复用组件，渐进替换视图和 ViewModel。统一样式可进入 ResourceDictionary，优先复用标准 TextBox、ComboBox、PasswordBox、DataGrid、DatePicker 与现有对话框基础。不能以更换技术栈作为改进的前置。

### 9.2 需要清楚的数据契约

不要为了新UI扩展庞大领域模型；至少让现有服务能够提供以下事实：

- 稳定对象身份、Application、物理/逻辑位置及实例引用。
- 完整编辑基线、已保存修订、差异和 CAS 保存结果。
- 运行修订的确认值、确认时间、状态是否过期或未知，以及各资源实际状态。
- 当前包裹及原请求身份、所处阶段、结果新鲜度、影响范围和可用命令资格。
- 校验错误对应的对象、字段、原因与关联冲突对象。
- 分层诊断结果、测试输入来源、时间、下一步和可脱敏技术详情。

UI 不自行猜测“网络恢复等于业务恢复”“保存即生效”“同地址就是同相机”。命令接口至少携带确切对象/包裹/请求或修订，后端仍应重新核验资格。

### 9.3 关键工程细节

- 在 UI 线程之外执行设备、网络、持久化与导出；状态更新回到 Dispatcher，避免同步等待阻塞页面。
- 绑定只读属性使用单向方式。附件说明缺失站位诊断弹窗与只读属性 TwoWay 绑定异常有关，必须在对应 WPF 窗口中修复并验证，不能用原型窗口替代验收。
- 用字段级验证结果驱动错误呈现，保留原输入；技术异常映射为中文原因和可复制详情。
- 编辑草稿与运行轮询分离，轮询不得覆盖正在输入的字段、修改焦点或重建当前对象。
- 左右状态按稳定标识关联；使用包裹/请求序列保护迟到响应。旧响应不得覆盖新件当前结果。
- 查询使用稳定快照；新数据提示由用户显式刷新，选中详情不随列表更新漂移。
- 操作中禁用重复提交，并由后端处理并发资格和幂等；不能仅靠按钮变灰保障业务安全。
- 关闭对话框后恢复原焦点；Tab、Enter、Escape行为一致；敏感或有破坏性的应用操作不应让无意按回车即执行。
- 复用必要的已有日志与追踪，避免为每个控件再建一套状态审计；围绕保存修订、应用任务、包裹请求与诊断操作记录证据。

## 11. 实现优先级

### P0：直接影响正确操作和配置可靠性

1. 左右当前包裹与结果严格关联，开始新件清出旧格口，迟到响应和状态过期正确处理。
2. 对象选择、物理身份与位置绑定清楚；左右修改不得串对象。
3. 草稿/保存/运行三种状态分开；完整修订校验、CAS冲突与输入保留；保存默认待受控重启。
4. 应用失败有真实运行版本/已停止/未知表达，不能虚报回滚或生效。
5. WCS故障分层诊断，未知原请求只核对不重发；命令固定原对象与资格。
6. 缺失站位诊断窗口可打开；普通操作不因维护技术页或重复弹窗被打断。

### P1：形成完整调试与维护体验

1. 首次配置向导与日常对象编辑共用参数定义与校验，避免两套表单漂移。
2. 覆盖运行规则、组件库存、实例创建/配置/绑定、安装维护入口。
3. 查询固定快照、常用/高级筛选、日期错误定位、详情和导出；维护时可感知作业摘要。
4. 配置差异、修改记录、安全模板导入、备份预览与恢复隔离、诊断摘要预览。
5. 主目标尺寸与1366级窗口可读，键盘和DPI必要验证通过。

### P2：在确有需求后补足

1. 经代码和真实资源验证后的对象级热应用或独立重连，先证明边界再优化交互。
2. 第二屏只读作业、特定触摸模式或更小窗口策略，按现场硬件需求安排。
3. 不常见驱动、旧格式迁移和高级恢复的进一步文案与可发现性优化。

P2不是遗漏必要兼容能力的理由：本次列出的原功能仍须保留可到达入口或明确迁移去向。是否删除旧页须先确认没有独有能力和现场依赖。

## 13. 本次方案减少的负担及集中确认项

## 14. 商业交付验收口径

商业交付应分别确认：

- **可安装**：可信介质、正确目录与运行账户、依赖组件、失败反馈和可操作的修复路径。原图只提供安装入口，本次其他安装步骤是重设计提案。
- **可配置**：每个字段有对象归属与可信语义，完整修订保存不会丢弃关联内容，并能判断保存与运行是否一致。
- **可连续作业**：真实双相机与WCS链路正确关联包裹，当前格口不会串位或沿用上一件，异常不诱导重复业务。
- **可恢复**：受控重启、未知结果核对、保存失败和运行状态未知均有明确处置边界；备份恢复不会自动释放原请求责任。
- **可维护**：诊断能定位层级与对象，记录和导出可追溯，普通操作不依赖阅读内部JSON。
- **可复核**：每项都有同一冻结构建上的实际证据，未决项明确；截图美观、模拟流程通过与测试数量不能替代上述证据。

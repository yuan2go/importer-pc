## 2. 业务理解与设计取舍

### 2.1 本期业务

Windows工控机；CAM0左、CAM1右；共享周转箱与波次；专用扫码枪先扫箱；相机自动读取Item；WCS校验Item/SKU、任务、格口和数量；按批准规则进入等量自动、不足量人工或超量拆包；WCS明确接受、拒绝或待核对；最后检查并结束周转箱，必要时少货确认；三类提示声、WCS报警及三个月明细。[P:L74–83、L124–145、L159–175、L205–258、L261–284]

不是订单/波次管理后台，不增加称重、电子秤、PLC点动、AGV调度、相机录像、图片历史或OSS。生产不保存图片；画面没有实时视频、识别框和置信度，避免把尚未核验的SDK能力画成既成事实。

### 2.2 与旧原型的主要变化

|原型表达|本次调整|理由|
|顶部箱信息、两个相机区域|保留；明确一个物理站ST-01与CAM0/CAM1来源|不把两个相机编号误当两个已确认物理工位|
|两侧蓝/紫及可点击设备标签|改为中性面板、统一状态色和只读设备状态|通道由位置和文字识别；颜色仅表达业务语义|

### 2.3 推荐布局

使用单工作台，不使用大侧栏、统计卡片阵列或图表。P0从上至下为当前箱及其校验结果、全局阻塞、通道结果和主操作。P1为Item码、SKU、任务、格口、Item波次及数量。设备状态常驻顶部；少量历史、维护入口和版本信息为P2。

每通道骨架固定：**来源标题 → 当前状态与异常原因 → 只读业务字段 → 固定动作栏**。异常只是替换状态和可用操作，不重新改变页面骨架。主要操作从不和字段一起滚走。

## 4. 字段与状态的数据来源

### 4.1 显示模型

开发应从应用层只读快照绑定界面，而不是由控件推导业务状态。建议快照至少包含`stationId, sessionId, sessionRevision, channelId, operationId, operationRevision, state, evidenceStage, sourceUpdatedAt, isStale, primaryAction, disabledReason`。上述字段为客户端设计概念，不是假定已存在的WCS字段。

|显示字段|生产数据来源/单位|重要约束|
|---|---|---|
|物理供包台、楼层|生效站位配置|活动作业期间只读；不由当前画板标题决定|
|用户/模式|认证上下文或获批跳过配置|“李明”为示例；跳过模式不声称已认证|
|CAM0/CAM1|稳定设备ID映射与适配器状态|展示连接中/已连接未就绪/采集就绪/断开/重连/过期|
|WCS状态|通信健康与业务状态分别投影|TCP/HTTP可达不代表业务允许；仅模拟链路显示“就绪”|
|当前箱及波次|专用扫码输入，经WCS校验后的会话|新输入不能覆盖活动箱；未知显示—|
|Item码|本通道采集观察|字符串保留前导零，不把扫码回调次数当物理件数|
|SKU、任务ID、目标格口|当前作业版本的WCS验证结果|未取得时—；拒绝后不可沿用上个Item任务|
|Item关联波次|WCS Item校验结果|与当前箱波次分别保留；错波次并列差异，不直接改成当前箱|
|包装P、剩余需求D、本次供给R|批准的WCS数量口径，基础SKU单位“件”|未知与0分开；不能任意手输；D作用域待D-03|
|拆包移除M/保留R/计数S|已批准拆包模型及有效逐件证据|示例P30/D18/R18/M12；扫描保留方向未批准|
|本箱WCS已接受|唯一业务接受数量账，按当前session归属|不是点击次数、不是物理落格数量；尝试重传不多记|
|缺失SKU/数量|WCS结束核对快照|不是本地计划减点击数；必须关联版本、新鲜度、原箱|
|AGV就位/装载/离站|待确定的权威状态源|本次只展示未取得/条件未核验；不画已确认实体完成|
|最近观察/状态时间|事件时间、投影时间和时区|主屏短时间与页脚完整日期并用；记录明细保留完整日期|
|请求ID/发送尝试|客户端请求事实及对应回执|一次作业可多次尝试；重传不换业务请求身份|

### 4.2 中文状态词

|状态|主文案|可作出的结论|
|---|---|---|
|Idle/无有效箱|请先扫描周转箱 / 等待有效Item入场|设备可能在线，但无可执行作业|
|Observed|已识别，待校验|仅有观察结果|
|Validating|WCS校验中|正在等待任务与数量|
|ReadyForAutoDispatch|待自动提交|仍须批准自动分支与真实许可|
|AwaitingManualDispatch|待人工发车|仅批准人工路径且所有前置满足时能提交|
|UnpackRequired|需拆包 · 模式待确认|不得让“确认”替代规则决策|
|UnpackCounting|拆包中|有效计数未完成，计数方向按批准合同|
|AwaitingUnpackConfirm|待确认拆包|计数达标仍需人工核对实物|
|DispatchQueued|待发送|本地请求意图保存，不代表WCS收到|
|DispatchPending|WCS处理中|已发送/远端处理，不代表接受|
|Accepted|WCS已接受|明确接受事实；不是AGV已出发、已到格口|
|Rejected|WCS已拒绝 + 原因|明确业务拒绝，不无条件重试|
|OutcomeUnknown|结果待核对|可能已处理，不重复放货、不自动重发|
|Paused|软件已暂停新入场|不保证设备停止，不是安全急停|
|Closing/CloseUnknown|结束处理中 / 结束待核对|原箱保留，禁止扫描新箱覆盖|

本地保存成功、请求发出、业务接受和物理完成是不同事实。相机在线、WCS可达也不是可以供包的充分条件。显示当前通道状态时保留来源时间；失联场景显式标旧状态失效，不继续用旧绿点冒充当前正常。

## 5. 核心操作、权限与命令映射

命令名是UI与应用层的建议映射，不等于已存在源代码符号。正式实现须继承既有工程实际接口，且在应用层再次检查，不能只依赖按钮灰显。

|按钮 / 原型data-action|建议业务命令|启用前置、确认与反馈|
|---|---|---|
|登录 / login-form|AuthenticateOperator|非空、无重复请求；忙态禁提交；拒绝与网络错误不同；真实权限由WCS决定|
|校验周转箱 / tote-form|ValidateTote|未激活箱；只提交专用输入；校验中锁定；失败留输入和原因，不激活Item作业|
|手动发车 / dispatch:n|SubmitManualDispatch|批准路径、活动箱/版本、当前任务/数量/许可、设备新鲜、存储可写、无未知/在途；普通确认路径不重复弹窗；提交即锁定当前作业|
|确认拆包 / splitConfirm:n|ConfirmUnpack|D-04批准后，计数目标、物理处理和版本均满足；展示R/M；不能把未达量自动补齐|
|清空重扫 / clear:n|ClearAndRescan|仅可安全废弃的未提交草稿；有计数时确认对象、数量、修订；不删历史、未知请求或另一通道|
|结束供包 / end|CheckToteClose|活动箱；两通道屏障；未完成草稿/拆包/未知不能直接结束；等待WCS核对|
|取消少货 / close|CancelCloseDecision|只在尚未提交关闭时恢复当前箱；已发关闭请求不得本地取消回Active|
|确认强制结束 / forceClose|ConfirmForcedClose|真实少货快照、无未决、授权、操作员检查；锁定提交，WCS明确关闭才允许新箱|
|暂停入场 / pause|PauseAdmission|确认只停止软件新业务入场，已发请求继续核对；不叫急停|
|恢复入场 / resume|ResumeAdmission|依赖就绪且新鲜、无未决、现场复位满足；不重发历史请求|
|查看详情 / detail:ID|OpenOperationDetails|只读，不触发网络重发；页内复制完整标识|
|作业记录 / records|QueryOperationHistory|条件过滤及日期校验；加载、空、无匹配、失败分开；导出仅当前筛选|
|报警已读 / alarmRead|MarkAlarmReadLocally|不发送未批准复位，也不改变设备/业务状态|
|设备与设置 / settings|OpenDiagnostics|只读设备型号、版本、状态和时间；无来源则未提供|
|保存配置 / config-form|StageConfiguration|维护授权、无活动箱/未决、字段合法；新版本下次受控启动生效；不热改已发payload|
|登出 / logout|BeginProtectedLogout|无活动/未决可进入登录；否则提示处理原作业；换班继承合同未确认|
|导出诊断 / diagnostics|ExportDiagnostics|建议维护权限、脱敏；本例只导出模拟状态，不采集系统文件|

底部`demoRead/demoCount/demoPermit/demoResolve/demoRecover/reset`全部属于评审工具，不能进入生产菜单、不能由普通操作员用于标记成功。它们只注入样例观察/许可/回执，既不是接口重试，也不是生产恢复实现。

### 5.1 按钮八态及反馈

默认白底描边，主操作蓝底白字；悬停主色加深，次操作浅灰；按下再加深并微小位移；聚焦3px轮廓及3px间距；禁用灰底灰字，邻近说明具体原因；执行中禁用并用“正在提交/校验”或通道处理中反馈；成功由当前通道低干扰绿色结果承载，按钮变为详情而非可重复发车；失败保持拒绝或待核对状态与相应操作，不只弹一次Toast。

主按钮52px高、紧凑48px；普通可操作目标至少44×44px。底部评审工具32px只用于桌面设计演示，不作为生产触控标准。确认弹窗取消在左，具体风险动作在右；少货强制结束用红色，且必须勾选检查事实。确认弹窗不设自动倒计时确认或全局Enter默认危险动作。

### 5.2 焦点与输入

常规Tab顺序：辅助导航/用户 → 周转箱输入及校验（无活动箱时）或结束供包 → CAM0可用操作 → CAM1可用操作 → 历史入口。相机结果与键盘焦点无关，UI刷新不应夺取扫码输入焦点。录入箱码以字符串处理；回车只在箱码表单提交，不等于发车。

打开可取消抽屉时焦点移到关闭键，Tab限定在抽屉内部；Esc关闭后回原触发按钮。关闭请求已提交时Esc不取消远端业务。原型中评审台可用鼠标切换演示状态；生产不存在此例外入口。

记录和设备抽屉的背景视图不可操作，但后台已开始的作业处理仍继续；生产设计应保留全局故障通知可见性。主屏不提供人工Item码输入，所以不存在与自动码相互覆盖的正式路径；人工识别渠道由D-10/11另行批准。

## 6. 异常、阻断和恢复设计

|异常|影响及是否继续|本次可见操作与下一步|
|---|---|---|
|无码|当前观察无可执行任务|调整条码朝向/遮挡；受控清空重扫；不发送上一件数据|
|多码|不自动选择候选码；不能把两个码当两件|展示候选码；调整摆放后重扫；多码业务决策待合同|

|WCS明确拒绝|当前业务不接受|保留原因，纠正业务条件；不无条件重试|

|待发送任务积压|本地已保存意图不代表远端接受|突出暂停新入场、待处理数量和来源；上限/恢复窗口待D-07/15|
|本地存储失败/磁盘不足|不创建新的发送业务，整台阻断|保留现场Item；维护检查；不提供删历史继续按钮|
|AGV就位/装载许可未知或过期|不得自动放货或移动|条件化“状态未取得”；不显示假绿灯；等待权威反馈|
|结束供包超时|原箱关闭结果未知|既不能开新箱，也不能继续旧箱；核对原关闭请求|

|只读记录查询失败|并非无记录|重试查询只读；当前业务事实保持|
|报警已恢复|恢复证据与已读不同|保留发生/恢复时间；历史事件不再次计为活动故障|

PRD还列出分拣计划、订单、SKU绑定、超计划、格口禁用/满、尾包SKU缺失等WCS业务拦截。[P:L265–278] 正式实现将它们作为**同一拒绝/报警组件的不同原因和建议**，保留实际业务码与文本；本次没有为每个原因伪造一个已接通接口或独立管理模块。错波次和格口禁用有独立可进入样例，其余原因的真实返回格式与恢复动作仍需要WCS契约确认。

恢复原则：自动回执与人工处置都必须验证session/operation/revision/request身份；旧回执只归档到原作业，不能更新新箱。视图过小仅阻止新操作，不取消已发请求；恢复窗口空间后保持暂停，操作者核对后恢复。原型以场景epoch验证模拟回调隔离，不等于已实现生产持久化恢复。

# INSTALL-UPDATE-UNINSTALL-IDENTITY-01

2026-10-28，用户报告再次安装后日常启动被 `MachineRuntimePolicy.ValidateRuntimeAccount` 拒绝，要求修复安装、更新、卸载和重装闭环。基线 main `62936483`；独立 D 盘工作树，原工作区和客户数据不动。

## 证据和复用

当前桌面/安装后打开继承调用方令牌；本机 UAC 关闭、调用进程管理员组启用，既有普通运行检查按设计拒绝。不能通过删检查、改 UAC 或把配置清空来解决。并行 PR137 `76dd6078` 已有 `OrdinaryRuntimeProcess` 和真实受限子进程验证；本包复用该实现及来源，再覆盖安装完成打开、恢复监督入口与完整生命周期验证，不整合并行相机修改。

## 实施要求

- 日常桌面启动在配置/运行资源及恢复监督器之前转入同用户 NORMALUSER 受限进程；指定账户、程序完整性、管理模式和业务守卫全部继续检查。普通进程不重复转发；服务身份和监督子进程不换 PID 绕开原责任。
- 安装后打开直接沿同一启动机制；维护入口保持原独立 Windows 授权。进程创建只能说明已交接，不能报告业务就绪。
- 安装器明确区分新装、同源修复、不同源码更新、卸载后保留数据重装；保留既有数据/账户、完整备份、原请求、CAS 和结果未知核对规则。
- 验证实际 Windows 令牌和受保护 ACL，以及隔离产品的安装→同源再装→更新→失败修复→卸载→重装。隔离产品使用唯一 ID、受保护 D 盘目录与合成文件，不替换本机 sportmaster 登记、不启动设备。
- 同源发布的原生安装/首配/卸载按钮回归及单 EXE 准备/取消冒烟；更新验证记录和安装包身份，版本保持 1.0.0。

# SM 运行班次与记录

本版本从作业页查看班次效率，从“记录”查看原作业。班次页面与异常页面的早期设计和验收属于[历史资料](../archive/work-packages/WP-IPC-SM-SESSION-SHIFT-EXCEPTIONS-25.md)。

## 运行和查询

成功打开一个业务实例建立持久班次，开始时间覆盖本次启动准备；完全停止、排空读取和发送并释放驱动后才正常结束。页面、布局、管理模式及多个共享窗口不切班；受控配置重启新建班次。停止超时仍持有资源，不记录虚假关闭。进程被终止后，下次取得原数据根独占时把上班标为Interrupted，保存发现时刻，不编造正常结束时间。上一班按数据库递增序号选择，系统时钟回拨不改变顺序。

正常班次时长采用单调时钟，包含软件暂停；未知终点不显示均速。UTC与单调时钟偏差超过5秒标记时钟变化，近10分钟速度不可用。今天及近7天采用已生效站点时区和完整分钟边界；均速只在范围内运行区间可证明时显示，不含关闭间隙。旧固定时刻配置原字节保留以兼容历史，SM保存契约拒绝修改固定时刻，不再用它决定当前班。

观察和请求是两类事实。一次送达应用的非调试相机有码观察算一次识别，人工输入不假造相机识别；同码独立观察不合并。连续空场帧不能推断包裹漏读。请求首次T1准备时固定班次，首次登记发送尝试计一个请求；重试/迟到结果只差量更新原请求所属班。Accepted且有格口才计取得格口；Rejected、Unknown/Conflict单列。所有次数均不代表物理完成件数。

未确认结果按原作业编号核对。确认离位且实际执行和回执责任收口后，未确认请求从当前作业移入历史保管。记录仍显示未知结果，维护人员可查看原请求和已保留回包。内置 RCS 没有权威查询合同。

班次归属、结果差量、分钟和班次汇总与原业务事实在同一 SQLite 事务内更新。历史清理只处理符合条件的已结明细，保留永久防重凭据及已计汇总。

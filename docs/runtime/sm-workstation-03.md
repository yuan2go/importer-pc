# 首页条码输入与包裹图片 · SM-WORKSTATION-03

2026-10-30，PR155增量源码实现，起点`31586427`。用户要求先完成功能、后测试。本包未执行构建、测试、WPF渲染、PDA输入、SDK调用、RCS外呼、安装或现场验证，保持草稿。下文说明代码路径和使用流程，不是已运行证明。

主入口为**作业、记录、设置、日志**；紧凑窗口的“页面”菜单同样四项。设置与日志仍需原临时管理模式，入口可见不等于已授权。设置下提供参数设置、诊断与恢复、相机调试；相关状态仍归原Application，页面切换不重建设备连接、作业或RCS发送器。

## 首页输入

左/右位分别有独立条码输入、来源选择、提交、核对当前位及清空输入。输入框保持空值起始，不把示例条码写为生产值。点击当前已读条码查看图片，输入草稿不冒充当前已确认条码或格口。

1. 确认真实包裹所在左/右位，将焦点放在该位输入框。
2. 键盘填写完整条码，或选择“PDA键盘”后扫描。PDA应通过Windows键盘输入并以Enter结束；输入来源是操作员声明，不能冒称已鉴别某台PDA硬件。本包不新增安卓/网络/串口协议或凭据。
3. Enter或“提交”提交一次。保留前导零和原始字符，不静默去空白；多行、控制字符、超过4096字符的原始输入拒绝，最终有效条码继续服从原选码规则（1～256等原约束）。超限不能把截断片段送入业务；清空输入后重录。
4. 输入期间当前位观察/作业改变时拒绝该提交，保留草稿；核对真实包裹及内容后再点“核对当前位”。新相机输入不覆盖人工草稿，轮询不抢焦点。
5. 只有已准入才清空该次输入。“已准入”表示独立作业成立，RCS结果看原作业，不表示业务接受或物理完成。失败保留输入；提交期间新输入不被当作下一件，需等待结果后重扫。

提交结果不明时保留原命令和只读输入，按钮改为“核对本次提交”。相同ID与完整内容读取原回执，不能自动生成第二ID盲重发。原作业已持久成立且原调用已结束时，可以只补齐提交回执，不执行原请求。没有足够事实的Pending继续保留，交原命令/作业核对；清空输入不能解除责任。

人工命令经`IParcelWorkstation.SubmitParcelBarcodeAsync`进入原Application：有界独立命令容量2、单一业务gate、运行ID/配置修订/当前位双身份、操作员会话及执行时准入复核。先同事务持久接纳命令与完整输入/主体，再使用原选码、容量、连接、暂停/隔离、原件责任和外呼守卫。人工输入不更新设备健康、不借用SDK epoch、不调用`EmitReference`，没有相机`AcquisitionIdentity`；仅当前SM且未配置要求同帧的必需业务图像阶段可用。相机失联或必需能力不足不能靠补录绕过。每个明确的新输入仍是独立识别，由RCS去重，不做同码本地去重。

输入观察和作业增加可省略的`OperatorInputEvidence`，保留命令、声明输入类型、真实已登录主体/会话（未配置登录时明确本机工作站主体）和提交时间。旧记录缺字段仍省略，不改原构造/解构ABI和旧JSON原件。记录行及详情显示输入来源，来源事件和设备读码不混淆。

## 包裹图片

首页点击已读条码，或记录行点击条码/详情点击“查看包裹图片”，打开同一原生弹窗。窗口固定原作业或当前观察身份，不随下一包到来替换图片。支持适应窗口、物理显示像素1:1、放大/缩小、Ctrl+滚轮、左键平移及识别四边形；条码和来源文本可选择复制。图片来源显示原作业/观察、相机、epoch、帧号、采集时间、像素与原图SHA256。

图片只按原观察或原作业`AcquisitionIdentity`取得，进一步核对设备、epoch、来源事件、采集时刻和观察摘要；读盘验证元数据、压缩件及解压后原始像素哈希。不能按条码相同猜配图片，也不能把当前实时图填给旧记录。历史未采图、轮替、删除、失败、读取中或来源不匹配分别明确显示；缺失时可刷新固定原身份。

手动键盘/PDA键盘没有同帧相机采图事实时显示“无对应采集图像”。本次不会触发额外拍照或把相机上次画面归给人工输入。隔离调试输入仅在管理调试中查其证据，不从普通作业图片读取扩大权限。

`ReadParcelPictureAsync`使用原OwnedRead容量4与停止所有权；开始和返回时复核操作员会话，返回前可取消，关闭窗口取消等待并清空图像，真正读任务结束前仍由Application持有资源。弹窗会话改变清空图片；图片读取不发RCS请求、不要求为日常查看进入管理模式。非SM的共享记录页仍显示原只读条码，不出现SM图片动作。

## 同帧留存与资源

MVS仅在启动前安装一个`IParcelFrameSource`日常接收者，沿原采集循环取得解码前原始Mono8副本、完整识别结果及几何、相机/周期/帧/观察/事件身份。有码帧经有界非阻塞交付留存；与管理调试共享只读原始副本，不新增SDK handle、连接、解码器或发送器。隔离切换及来源永久标记继续沿02的原业务栅和SDK缓存边界；日常留图不能解除隔离。

日常集合位于现有D盘业务根内`parcel-pictures/{index.db,images/}`，与`camera-inspection/`、业务数据库及必需业务图片分开。复用原无损图像存储引擎和完整性机制，但队列、额度、故障及生命周期独立。不存在SDK/客户原图随程序提交或公开上传。

| 资源 | 当前源码边界 |
|---|---|
| 接收与原图 | 每集合128项通道、128MiB待写原图、单图32MiB；两集合独立预算，原采集循环另持有当前帧。|

当前完整业务备份的既有清单不包含这两类可清留图集合。仅恢复业务备份时，历史业务事实保留、相应图片可能缺失，界面如实说明；不能复制活动SQLite文件冒充一致性备份。原业务恢复、原请求、隔离持久栅及现场实体核对保持原合同。

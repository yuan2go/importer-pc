Windows开始菜单、桌面快捷方式、SCM及注册表是操作系统入口。它们只保存指向D盘的登记/兼容元数据，不将项目负载再复制到C盘。原用户路径保留兼容入口，以便冻结的旧模拟接收账仍访问原来的同一份数据；正式数据根及受保护机器/账号目录直接访问D盘，不使用链接绕过权限检查。没有修改原请求报文、合同、目标参数或历史证据身份，没有自动发送未知请求。

生产路径选择保存在64位 `HKLM/Software/ImporterPc/Storage` 的 `Root` 字符串中。本机值为 `D:/ImporterPc.Deployment`。只允许System/Windows安装管理员写入；运行端验证登记所有者、写权限、本地固定卷、普通祖先及卷根不能删除受保护子目录的边界。未登记存储根时继续使用原Windows默认位置；损坏或可被非维护主体改写的登记拒绝使用，不接受用户环境变量覆盖认证根。

不要手改这个值或单独搬动机器/账号目录。完整迁移须停止应用，核对源/目标范围，保留ACL及逐文件校验和，保管回退副本，完成原责任检查/完整备份/同源安装提交，再修复快捷方式与服务；以新的普通Windows进程核对真实路径。账户账与开通标记不能丢弃或覆盖，服务重启撤销旧会话。当前没有已开通的软件管理员账号；用户通过“登录与账号”自行选择真实账号和密码并批准首管开通，没有默认密码。

此次保持原单账户运行范围。新增Windows账户不自动取得原账户数据或软件管理员身份；其D盘个人目录须由安装维护按该账户SID建立并授予必要权限，不能将整个受保护根改成所有用户可写。跨Windows账户、改安装使用范围与换机不包含在本次同机迁移验证内。

本次先逐项核对1,658个原安装/配置/用户文件约485MB及权限；首次目录数组写入错误导致预检失败，保持C盘原件并退回。修正后同源介质完成原责任预检、完整备份和安装升级，随后原件全部迁入D盘回退目录。认证服务运行、4个快捷方式、ARP版本/目录、真实用户目录、原机器/程序目录已无C盘负载，以及安装EXE环境报告退出0均已核对。没有自动启动业务或设备；未将该过程称为完整安装器交互、重启、双账号或换机恢复验收。


该脚本只设置当前进程的TEMP/TMP、dotnet用户目录、NuGet包/HTTP缓存和UTF-8，不更改全机环境。Codex的MSIX包会隔离旧AppData路径，跨卷兼容入口在该包视图中可能无法解析；开发和验证应直接使用上表D盘路径。迁移核对特意通过Explorer启动的普通Windows进程执行，确认无包身份且真实文件落在D盘，不能以包内路径视图代替正常安装状态。保留的旧包内入口本身没有数据文件，不影响正常Windows启动入口。

2026-10-29，基线 main `035b69eb`。用户完成首次配置、再次保存并重启后，仍显示相机/RCS待配置。本机配置账保留了Pending，但启用失败并回退到原Effective；失败为 `Extension directory must be provisioned by maintenance`。用户明确要求解决实际运行故障，当前全部内置，先停用外置扩展，不做页面改版。

内置MVS与RCS已随受保护安装发布，原生依赖按嵌入清单、精确ABI、长度/hash/AMD64及ACL检查，识码引擎亦随包。旧装配仍对所有Production连接调用外置Store并要求独立扩展部署签署，错误地阻断当前内置组合。修复取消SM内置组合对该外置制度的依赖，目录和信任缺失不再影响内置目录读取、配置校验、构造及准入。

当前SM明确拒绝外置配置及安装/维护动作，不从外置绑定静默回落内置。其他业务与共享独立扩展实现保留；不删除历史包或改变历史请求实现身份。内置准入只绑定已完整校验并构造的配置hash，单纯结构校验不能取得运行准入。当前管理模式、普通账户、机级租约、SDK实际依赖/序列号、RCS参数、响应关联、Unknown、固定原报文与受控停止/重启守卫保留。不生成投产批准，不把本机模拟RCS响应当作现场接受。

本机更新后发现第二根因：MVS未枚举到所配置设备时原代码抛出通用配置异常，Application因此回滚整份候选。用户明确：配置完整应显示出来，相机未发现只显示离线。现将这一设备发现结果在原生/解码器清理成功后分类为既有 `ObservationConnectionException`，复用Application按位置隔离的启动逻辑；发布Disconnected且无有效Ready租约，保留已启用配置与独立RCS。SDK加载/ABI、清理失败和未释放所有权仍为启动故障，不降级为可恢复。原配置、原请求及真实身份匹配不改写，离线位拒绝供包，设备返回后沿原授权单机重连恢复。

用户随后明确要求：两处根因修复通过定向验证后，经PR合入main，从实际main生成新安装包，并卸载当前安装。卸载沿当前原登记、完整备份、固定原清单及Windows授权执行，保留配置与数据，不删除其他产品、厂商SDK或MVS软件。

必要验证：内置目录无Store/Trust诊断、单相机完整候选、外置拒绝、缺序列号拒绝、实际已保存Production候选只读完整校验；MVS软件识别/连续采集/缓冲归还/三次同码独立请求，RCS心跳/超时/原请求恢复；同源冻结打包及原安装更新、原配置启用与实际连接单独记证。CI保持停用。

# 工业化管理密码恢复设计 · IE01-S

状态：目标设计，尚未替换固定恢复入口。基线、范围和实施入口见[总设计](industrial-engineering-01.md)。优先级P0；先交付此切片，不等待MSI、文档重构或整体格式化。

## 1. 威胁模型与选定方案

基线`LocalManagementMode.PasswordRecovery.cs`确有固定恢复密码的SHA-256验证器，`ResetPassword`可经RPC进入；在线锁定不能阻止离线猜测。公开哈希应按已披露的共享验证材料处置；不能据此声称明文已被破解、每个站点已入侵或风险已修复。

管理模式主要防止供包员误改，Windows管理员本来就能控制机器、程序和服务。本包选定**Windows管理员批准 + 明确本站重置确认 + 受保护服务核验**，无需额外保管恢复码。它只允许设置新管理密码，不直接获得管理会话，不改变操作员，不解除业务隔离，不修改RCS凭据，不清偿未知请求。

普通用户、过期管理会话、知道旧根密码的人，以及能够连接普通管理管道的进程，都不能因此重置。系统管理员恶意替换整个OS、离线篡改受保护存储、使用旧系统镜像，不在本机软件能够独立抵御的边界内；安全下限仍应阻止正常安装/回退重引入旧恢复入口。

站点专用随机恢复码和供应商离线令牌保留为以后独立ADR选项。没有真实离线支持需求、密钥保管人和吊销办法时，不同时开发两套备用通道。

## 2. 权限与入口

| 动作 | 授权 | 条件 |
|---|---|---|
| 进入管理模式 | 现行站点管理密码 | 失败锁定、15分钟会话、服务端复核 |
| 修改密码 | 有效管理模式 | 新密码确认、撤销旧会话和委托 |
| 忘记密码后重置 | 提权的Windows管理员 + 本次本站确认 | 不要求旧密码；不自动进入管理模式 |
| 首次设密 | 既有安装批准通道 | 已有凭据不得被“首设”覆盖 |
| 卸载程序 | Windows管理员 | 保留责任和数据；与管理密码分离 |
| 备份恢复/配置修改 | 对应现有授权 | 不能借重置接口获得其他维护许可 |

日常程序保持非提权。普通“忘记管理密码？”入口说明“需要此电脑的Windows管理员确认”，启动来自受保护、已验证安装缓存的窄功能helper；UAC取消只返回原窗口。UAC关闭时同样核验实际令牌；组名、客户端布尔值或“已经弹过UAC”均不是证据。

安装损坏或主程序无法打开时，Windows安装项/可信修复工具提供同一任务。服务不可用时先修复服务；不能创建未保护的本地凭据文件、默认为首次设置或进入生产成功。

## 3. 重置协议与原子性

复用现有ManagementModeBroker的身份及受保护存储机制，新增窄动作契约；不把原`ResetPassword(rootPassword, newPassword)`换个标签继续调用。

1. 非提权界面向权威服务申请短期挑战。逻辑绑定InstallationId、受保护根身份、CredentialRevision、目标动作、随机nonce、申请进程PID/创建时间、登录会话、过期时间和OperationId。有效期设计为2分钟；挑战不含密码，写到受保护状态，不接受任意客户端生成的批准票据。
2. 提权helper独立验证服务端身份和当前安装；服务通过受保护管道模拟客户端/检查其真实令牌、启用的管理员身份、登录会话及挑战归属。明确拒绝远程网络管道、匿名、普通运行账户、被替换服务、重放和过期挑战。现有普通认证管道可连接不等于可调用重置。
3. helper显示软件名、本站标识和“仅重置管理密码，不修改设备与业务记录”，要求输入并确认新密码后明确点击“重置”。本机确认是交互确认，不宣称证明人在物理控制台前；远程桌面是否允许由现场Windows政策决定，不绕开它。
4. 服务端在提交前再次核验管理员、挑战、当前安装和凭据修订；获取既有凭据锁，原子保存新盐/慢哈希、递增CredentialRevision、撤销所有会话/持续委托并核销挑战。审计记录同一OperationId、授权方式、Windows SID、安装身份、时间及结果；不记录新密码、输入长度或验证器内容。
5. 返回提交回执；原非提权界面显示“密码已重置，请重新进入管理模式”。回执丢失只能核对同一OperationId/凭据代次；不能自动重复重置或把超时当失败后再写一次。

安全审计的持久意图写入失败则不提交；终态审计与凭据更新须有可恢复的一致提交记录。提交后通信失败保留已提交事实，不能恢复旧凭据以制造表面失败。挑战与会话内容不进入剪贴板、URL、命令行、普通日志或诊断包；新密码只经受保护IPC传输，控制生命周期并尽量清理可变缓冲。

## 4. 凭据存储与旧入口退出

沿用现行随机盐、PBKDF2-HMAC-SHA256 600000轮和32字节派生值；核对实际实现后使用统一Create/Verify，不另写SHA验证器。随机盐至少16字节；记录算法/参数版本，目标IPC上测量验证耗时与并发预算，不能为提速降低已定安全参数。OWASP对PBKDF2-HMAC-SHA256建议600000轮；这不构成本产品的FIPS认证。[依据](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

现行管理密码允许5～256字符的事实保留。5字符、纯数字仍存在弱口令风险；本包不静默提高下限导致现场无法进入，而是在设密中建议较长口令、不使用固定示例。更强口令政策若推进，应单独设计存量验证、过渡和现场交付；不能声称慢哈希让弱密码安全。

实施顺序必须包括：

- 删除固定验证器、恢复密码输入及所有可达的旧RPC处理分支；对旧动作名明确返回“该恢复方式已停用”，不得落到兼容路径或本地fallback。
- 更新服务/主程序/helper为同源协议组合，旧客户端不能被新服务授权；已安装旧服务仍有风险，主界面升级不算完成。
- 升级时递增授权代次并撤销旧会话/委托，不重新生成业务操作员身份。业务配置与原请求保持不变。
- 部署受保护的MinimumRecoverySecurityEpoch。安装、修复、回退及凭据恢复都校验，禁止通过正常产品流程装回含共享恢复入口的版本。
- 普通备份恢复不降低机级安全下限，不复活旧会话；跨机恢复沿隔离接管，由目标机管理员重新建立本机凭据绑定。凭据损坏拒绝受限业务，不能删除文件后当成未设置。

安全下限属于受保护产品族政策，普通本站永久删除不移除它。当前维护工具必须拒绝旧介质，但无法靠新代码让历史安装器自动理解这一政策；旧安装器和裸EXE另由撤回渠道及现场软件执行允许名单控制。若Windows管理员主动使用旧介质替换服务或清除整个政策，属于前述管理员控制OS的边界，不能承诺客户端自行防住。

## 5. 会话续期

复用已有最后两分钟内“续用15分钟”。增加非阻断提示，一次会话同一到期时间只提示一次；不夺取条码输入焦点，不因鼠标移动或页面刷新自动续期。服务端核验同一未过期会话，首次认证时刻保留；续期不延长原维护入场票据或调试轮次。多窗提示共享状态，只有一个成功续期结果生效。

到期、退出、改密、重置和服务不可用同步撤权。保留草稿内容但屏蔽未授权读取；重新认证后恢复上下文并重新检查修订。未提交导出清理临时文件；已进入不可逆提交的任务保留事实并安全终止后续步骤，不能回滚业务账。

## 6. 已披露材料处置

本次设计不公开复述旧密码/哈希、不尝试破解、不联系现场人员、不改Git历史。修复发布需有安全说明：受影响版本范围、旧入口废止版本、Windows管理员恢复路径、旧服务升级方法和验收证据；尚未部署的站点仍列为待处理。

先轮换/废止产品能力，再评估历史清理。历史重写不能撤回clone、fork、旧Release或已安装二进制，且会破坏现有SourceCommit证据；若以后执行，必须有单独范围和引用映射，不擅自force-push。旧介质标为安全撤回并退出推荐渠道；删除/替换已发布资产另走发布变更，不能覆盖原哈希冒充同一介质。

供应商一次性令牌若以后需要，至少绑定Machine/Installation、CredentialRevision、动作、随机nonce、有效期和防重放账；私钥只在授权签发系统，客户端仅持公钥；有吊销和时钟不可信处理。此选项在本轮为延期设计，不是已支持接口。

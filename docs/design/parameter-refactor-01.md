## 准入与兼容决定

驱动只复制有界原始解码候选及完整性事实，业务筛选不得把被截断集合当唯一。可信来源/epoch/sequence/同实体关联先成立；完整候选零匹配拒绝，多有效码歧义拒绝，唯一有效码再走原身份/去重/左右隔离/容量/权限守卫。原始候选、筛选结论、选中码及规则指纹进入原输入/作业证据；无新外呼测试。原请求、原配置和报文继续冻结。

旧配置缺规则保持可读、无损往返，并显式显示旧版严格单码兼容；不猜客户正则、不静默写 `.*`。维护人员显式填写规则、完整校验并保存后，待受控重启应用。新增字段为空时不改变旧序列化字节；公共契约/业务/精确扩展版本沿现有兼容清单更新。

## 编辑与失败闭环

保存前验证结构、字段、精确安装描述与跨类别约束；生产部署资格/SDK启动条件留给原受控启动与准入守卫，不能使软件无法打开编辑参数。四分类只是同一完整草稿的编辑范围；首配与日常共用参数模型/控件/静态验证及配置账。字段错误可定位并保留原文；异步结果不得覆盖更新输入。未改、未保存、校验失败、保存中、待核对、Pending、应用失败、运行未知分别呈现。Stage 回执或异常不证明未落盘：应用按规范化候选指纹与原配置修订核对；未确认前禁止再次 Stage。CAS 冲突保留输入，不推进原草稿基线。保存不应用，Reconnect 不应用 Pending；启动与当前准入证据分别显示。

## 用户追加：软件打开与业务就绪分离

缺少参数、无效正则、驱动/组件未安装不能阻止软件打开：直接复用既有“首次配置”页面补全，不新建缺配专用窗口。日常设置与首配共用模型、控件和静态校验。不能连接时仍保留原配置/维护入口，只有作业和外呼受守卫限制。缺少整个 Sportmaster 种子时提供 Application 拥有的固定双位 Production 引导草稿，不悄悄运行模拟。缺少原身份且已有业务数据时不能以新身份覆盖责任，仍可打开界面选择原配置/恢复。

系统必需值均有软件默认：队列64、调用预算1500ms、未清偿作业10000、常驻历史200、写入保留64MiB；工位外部编码默认取当前工作站标识（独立字段，可修改），首次新站标识station-01。计划备份默认关闭，启用时提供60分钟/10份及当前用户数据目录下的默认备份路径。旧配置明确给出的值不被默认覆盖；原账缺字段的默认显示与待保存候选有区别，保存与应用仍分开。真实IP、实体关联资格、组件取格口编码和业务筛选规则不属于软件级系统默认，不编造客户值。

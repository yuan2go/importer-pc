# 公开范围与材料处置

## 已核验

目标仓库 `yuan2go/importer-pc` 的visibility为public；首次读取分支列表为空，规则集列表为空。连接具有push权限。未改变可见性，也未绕过分支保护。

用户授权资料入库，同时明确要求：公开仓库不得提交未获公开许可的客户材料。现有资料未包含客户公开授权证明。归档授权不能被默认为第三方客户材料的公开许可，删除客户名称也不能自动解决该问题。

## 实际入库的既有成果

- `docs/reviews/issues.json`：SS-REVIEW-001 v1.0的完整17项技术缺陷/风险表，原样保存。内容为生成的原型与工程评审，不包含客户名称、人员名、私密链接、客户原始正文或真实凭据；样例身份不代表生产数据。
- `docs/ui/tokens/tokens.json`、`tokens.css`：SS-UI-VIS-001 v1.1的完整通用设计变量，原样保存；不含字体二进制或客户标识。

其余新增文件仅建立阅读、来源、限制与修订状态，不冒充此前已存在的成果。没有新增开源许可证或宣称拥有第三方资产再授权权利。

## 暂不公开

原始PRD/产品HTML、引用的客户附件、依赖原始材料的完整设计/开发/UI说明、带客户标识或样例身份的HTML/PPTX/截图、嵌入这些内容的评审全文与历史日志。它们均进入单独的非公开交付包，未进入任何远端分支或Git对象。

不公开Canva协作链接、临时签名URL、内部文档链接、账号/组织标识和容器用户目录。原始来源映射仅在非公开清单中保存。

## 脱敏与完整性

本次没有把客户材料粗暴删段后当作完整公开稿，也未用摘要替换原件。公开的三个既有成果经过内容检查后无需脱敏，保持原SHA-256。非公开当前阅读副本仅增加归档警示并重定位文档链接；对应原稿逐字节保留，变更另记。

## 完整入库的关闭条件

资料所有者提供明确的公开授权范围（包括衍生设计和图像），或明确授权转到适当的私有资料仓库；随后逐文件复核公开范围、删除真正秘密/不可分发文件、更新manifest，再进行普通提交与远端内容核验。在此之前，工作包只能判为“公开子集已入库”，不能判为“全部资料已在main”。

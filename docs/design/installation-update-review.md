# SM 安装与覆盖更新复查

当前业务版本固定为 1.0.0。安装使用完整介质，交互、静默和批量入口共用配置准备及部署执行代码。本次复查不修改开发电脑的实际部署、机器登记或现场数据。

## 路径与处理结果

| 场景 | 当前处理 |
| --- | --- |
| 全新电脑，无机器存储登记 | 预检使用内置 D 盘根；授权安装时创建机器目录和权限，不要求预建目录或改注册表。 |
| 已安装，同为 1.0.0，来源提交不同 | 允许覆盖；保留账户、数据、配置和原请求，不以来源或文件清单变化拒绝。 |
| 供包台仍运行，或旧进程尚未释放资源 | 全局和站点所有权检查阻止写入，提示关闭。关闭后重新安装，不检查历史作业完成、暂停或输入责任。 |
| 原启动配置目录不存在，或目录内缺少 business.json | 从原数据中当前配置账的已生效配置生成私有临时种子；授权安装补齐缺失文件。保留已有其他文件。 |
| 安装登记不存在，但所选数据目录仍有本站配置 | 从该数据目录识别唯一原站点和模式，保留非默认设置，不创建另一个默认站点。 |
| 原站点目录存在，但没有配置账 | 保留目录对应的站点和模式生成首配种子，不补造配置账，不读取或改写业务库。 |
| 原程序目录或原发行清单已删除 | 当前 SM 1.0.0 完整介质可修复。已有但损坏的清单仍作为完整性错误处理。 |
| 保留数据卸载后重装 | 复用保留的数据及当前配置；安装不因历史业务责任要求清场或备份。 |
| 取消介质准备、预检或 Windows 授权 | 不把取消当成功；准备和预检不写机器部署状态。已发送操作是否完成由原回执决定。 |
| 复制、组件或服务安装发生可确认的提交前错误 | 保存失败记录及原登记；排除磁盘、权限或系统错误后可重新安装。 |
| 断电或进程结束，记录停留在 Prepared / ReadyToCommit | 在持有停机所有权和安装独占锁时，比对原登记；确认未提交则结束旧记录，允许新的安装操作。ReadyToCommit 使用实际嵌套 Location 格式。 |
| 登记已提交，快捷方式、已安装应用入口或最终回执失败 | 核对原登记并走系统入口修复，不将原操作改成提交前失败，不重新安装来掩盖结果。 |
| 原登记已被其他操作改变、记录不完整 | 不推断成功或失败，保留原结果核对路径。 |
| 数据目录中有多个站点、配置损坏或身份不一致 | 保留原件并明确报告；不猜测站点，不用默认配置覆盖。 |
| 介质损坏、空间不足、路径被链接替换或访问被拒绝 | 在对应检查或写入处失败并保留原因；这些真实系统条件无法用取消业务限制解决。 |

## 本次新增修复

1. 缺失安装登记时，交互及静默入口把所选数据根传给共用配置准备；预检接受从原配置账恢复的当前配置。
2. 自动结束已证实未提交的 SM 安装记录，解除旧中断记录对新安装的永久阻挡。只有 Prepared / ReadyToCommit、完整原身份和未改变的原登记符合条件；提交目标或改变后的登记不会被关闭。
3. 停机占用异常保留原 Windows 错误码及内部异常，卸载预检继续提示先关闭供包台，不误判为缓存或权限故障。Windows 实际文件占用回归已在修复前复现失败、修复后通过。
4. 回归使用合成的非默认站点及不同的已生效、待生效 RCS 设置，核对配置账和业务文件哈希不变。中断回归使用实际两种安装记录结构。

# 原生安装、启动修复与独立基础配置
> 单 EXE 交付增量见[菜鸟供包台安装程序](single-exe-installer-01.md)：现场双击一个 EXE，自动准备固定介质后进入本页原生向导。原 ZIP 仍为兼容介质，历史验证按原来源保留。
> COMM-00～10 当前操作见[产品操作指南](commercial-productization-01-operations.md)，实现与冻结验证见[实施结果](commercial-productization-01-results.md)。本页的历史版本/原验收不改写；当前边界仍受四层职责、唯一权威、指定账户和原请求守卫约束。

本指南属于 STARTUP-DEPLOYMENT-02，适用于本次新发布的 Sportmaster、DirectPlc、WcsToPlc Windows 候选。旧媒介按其 SourceCommit 和随包指南操作。本实现采用 Windows 程序/数据分离、按需提升、并排部署和失败保旧等实践；不宣称 MSI 事务、工业标准认证或现场验收通过。Windows 原生 UAC/ACL/快捷方式及实际窗口交互为 NOT_RUN，真实 SDK/设备/合同为 BLOCKED，Production 仍为 NotReady。

## 安装及升级

1. 从可信渠道取得同源单EXE与交付回执，双击后自动准备和核验文件，再显示原生安装选项；不需要先点击欢迎页“下一步”。旧ZIP/Setup.cmd为兼容入口，按其同版说明使用。
2. 程序核对app/desktop、完整文件库存及源码身份；哈希只证明完整性，不代替发布者信任。准备阶段可取消，提交阶段关闭窗口不代表取消成功。
3. 选项页核对程序目录、数据目录与两个快捷方式选项，升级沿原部署带入。本机采用D盘受保护根；无登记的系统目录兼容回退不是本机部署建议。当前向导无运行账户/模式/信任包选择器，也不要求新站立即完成真实连接；精确身份、离线包和权限仍由安装机制核验。
4. 阅读摘要，点击安装并响应固定helper的Windows授权。复制、备份、原责任检查和受保护登记沿原机制；真实结果读回后才显示完成。未知结果停止重复安装，固定操作核对闭环待LIA-01完善。
5. 完成页可选择打开供包台；正常运行使用原合法非提权入口，不依赖cwd。已有配置和唯一配置账保留。首配当前规则见上方入口，连接可明确延后但不能获得业务资格。

实际安装前停止原实例；安装 helper 持原应用所有权锁，无法取得时拒绝切换。升级前保全完整备份和原责任，DB2～6仍按匹配发布的维护/升级规则处理。程序并排部署不等于回滚数据库；旧程序不能打开已升级的库。

若取消 UAC，关闭提示后可重试。若媒介损坏，使用可信完整媒介重新运行 Setup。若机级政策损坏/丢失且存在租约，或原 SID 不匹配，错误明确保留现场材料；不得删除政策/租约。源于安全身份不明确的故障不能由向导猜测改权修复。

## 启动失败后的修复

启动页显示实际阶段和异常，提供“重试启动”“离线维护”“安装/修复”“复制诊断”“停止并退出”。只有原实例完整 Stop/Dispose 成功，才进入维护或创建新实例。停止未完成会保留资源责任和诊断，不能强杀或提前释放锁。

可独立双击 `Maintenance.cmd`，或使用已安装的“启动修复”快捷方式；也可运行 `desktop\Ipc.Desktop.exe --maintenance`。配置/数据路径均可通过文件夹选择器指定。显式命令参数仍为 `--config <目录> --data-root <原数据根>`。

维护界面无需业务 Start 成功，不构造 reader/SDK/外部端口。它读取原 Effective/Pending 和原修订，展示身份、状态、扩展诊断，提供现有能力参数、调用超时、队列/作业容量和基本重量策略的表单。站、模式、拓扑、提供者版本及设备身份保持原值。修改后先校验，填写维护原因，再保存待生效修订。

Windows 保存使用已安装的受保护匹配 helper 提升；日常业务不提升。操作员业务登录与管理模式分开，受限离线修复仍须现有管理模式及精确请求授权，Windows管理员身份不能代替它。helper 收到固定操作与散列固定的请求，取得同一 application-owner 锁后重新核对原账 hash/CAS。精确原配置字节与变更记录落在原目录 `startup-maintenance/<operation>/`；沿唯一 configuration.json 保存 Pending，Effective、DB、原请求和原件不改。DB 格式检查使用临时 DB+WAL 副本，避免 SQLite 只读连接在原目录创建 sidecar；Windows临时副本使用 `WindowsStoragePaths.MachineRoot/maintenance-workspaces`，本机沿HKLM配置的D盘受保护根，所在卷需容纳副本及保留空间；完成后删除本次临时副本。当前 `ParcelStartupMaintenance.StageCore` 接受匹配DB9，原DB8/7→8说明保留历史归档。旧库按匹配发布清偿并受控迁移；离线检查/备份不迁移原库。

保存成功只表示 Pending 已读回。正常启动仍执行原责任、确认、资源启动和 Production 守卫；不会因修复自动 Resume、改写旧请求或重发 Unknown。配置已被其他维护修改时保留草稿并报冲突，须重新读取比较。

原账损坏时只显示诊断，不写空账替代。旧支持摘要导出已删除；使用当前复制诊断、管理模式日志查询/导出及真实维护入口。程序文件/种子问题走安装修复；完整账或存储故障使用下述恢复。

## 完整备份恢复

在离线维护页选择备份数据库及其同名 `.recovery` 同伴目录，选择一个新的隔离数据根，点击“检查恢复计划”。程序检查 COMPLETED、完整文件集合、所有 hash、原 Application/站/模式和容量；预检不创建目标。核对显示目标后明确执行恢复，Windows 请求维护授权并要求原应用所有权释放。

恢复固定 DB 与 COMPLETED 身份，再次校验并复用 ParcelRecovery，不覆盖已有目标。成功生成 RESTORED-ISOLATED 标记，界面重新读取新目录，原损坏账/原库保持不变。重试启动仍隔离、暂停并核对原请求、原回执、真实外部事实及数字范围；不得在原根和新根同时操作设备。创建完整备份的既有运行内/离线命令见 [Windows交付指南](windows-application-delivery.md)。不把手工复制在线 db 当完整备份。

## 可选扩展与基础配置

内置提供者及基本表单独立于扩展库。扩展目录未部署、信任缺失、库存损坏等呈独立诊断；不因此抹掉原绑定。绑定到扩展的原能力显示精确包/模块身份，缺失时不能伪装内置提供者。真正需要该扩展的校验、保存和启动仍失败；Production 的真实能力、签名、合同和部署资格检查保持严格。

本向导只做安装和启动修复；原作业恢复、实物处置、受控配置激活及保留数据的程序移除规则见 [Windows交付指南](windows-application-delivery.md)。不提供自动清除业务数据或永久租约的卸载动作。

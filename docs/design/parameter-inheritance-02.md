## 依据与迁移原则

旧字段/分支/读取位置以用户提供的旧系统盘点为输入证据。其引用的 `Importer_CS/ui/SettingsFieldRegistry.cs` 和 `Importer_CS/FormSystemConfig.cs` 所在旧工作树在当前主机不存在；旧实现未取得的行，必须标记“用户盘点、未核验读取代码”，不能称为完成旧现场迁移。当前新工程的消费者逐项用源码核验。公开提交只包含本次通用裁决，不复制旧客户原稿、内部服务、SDK或凭据。

同名不等于同义。`code/deviceCode/nameNumber`、`plcIp/plcUrl`、层号、判稳次数及默认重量须由真实读取位置确认后再转值。没有语义证据时保留原值待核对，不生成自动导入器或默认生产配置。新字段需具备实际消费、校验、失败和恢复路径，不能仅可保存。

## 本轮有效所有权

| 所有权 | 参数及实例约束 |
|---|---|
| 系统 | 全台取格口身份、独立心跳身份、数据/记录、备份、本机显示。内部 StationId 不改。运行相关记录策略走原配置修订；显示名称/目标效率/布局走当前用户展示偏好。 |
| Application | 条码允许与排除、包裹重量接受范围、等待期限、可选作业登录及会话期限；状态/命令守卫仍在业务中。不同主流程不加 mode/bizType 开关。 |
| Drivers | observation、weight、plc、camera 对应的采集、连接、协议及信号质量。一个实现可有多个实例，角色/数量由 Application 确定。 |
| Integrations | integration/WCS/RCS、login、upload 的服务连接与协议转换。保持现有单连接角色，不扩建任意实例管理。 |

目录、搜索、字段校验、错误定位、差异审阅和首配共用这份职责映射。能力库存沿既有 `CapabilityInstances`，不因为显示归类改写精确绑定或旧请求。Sportmaster 固定左右 Reader 各自参数、共享一个 RCS；不加入称重/PLC/采图/上传入口。旧不适用绑定如已存在需保留可诊断错误，不能静默丢字段。

系统唯一编辑取格口 zoneId/projectId/stationCode；对应 Reader 编辑取格口 bcrCode；心跳 StationCode 与每实例 bcr-code 保留独立来源。RCS 参数投影仍写同一完整候选，协议仍由组件转换。

## 本期真实行为

- 条码：在 `BarcodeFilter.Pattern` 上追加可省略的排除正则。先检查完整性，再逐项检查合法码、整串允许、整串排除；排除优先否决该候选。剩余恰好一个才继续原实体/左右/容量/权限守卫。重复条目不合并。两正则共用25ms单次和100ms总预算；规则指纹包含排除。旧 null 严格单码、旧仅 Pattern 的序列化和指纹保持。候选测试复用同一 Application 机制，修改任一规则使旧结果失效。
- 可选登录：直接编辑已有操作员角色绑定，启用/关闭和会话期限在业务任务中说明；连接/敏感引用归登录组件。维护认证不跟随关闭，不新增凭据系统。
- 系统记录：常驻历史是内存/同库归档数量；新增可选诊断日志保留天数只管理 RuntimeJournal 的非权威滚动诊断。原审计、未决作业、回执、图片和恢复证据不在其删除范围。保留原容量上限，天数是最长保留期限而非最低承诺；旧未设置保持旧轮转行为。
- 本机显示：可设置显示名称及明确单位为件/小时的目标效率，仅作显示；不替换任何内部/协议编码，不控制输送或改变业务成功统计。布局继续复用原标准/紧凑偏好。界面仅真实支持浅色/简体中文，不提供无消费者的主题/语言选择。显示偏好单独保存后立即显示，不增加运行 Revision。
- 已支持称重 Application：保留真实测量来源、单位、精度、新鲜度和等待期限；补可选业务重量范围。驱动仍拥有解析/换算/判稳。零值、不稳、超时、范围外不会变成有效测量；配置重量是显式来源，不能冒充超时默认测量。

上述运行字段沿完整候选、CAS、RuntimeId、审计、Stage/Inspect、Pending/Effective及受控重启；重连不应用Pending，Unknown只核对原提交，原请求/目标/合同/报文和精确包保持冻结。

# WP-IPC-RUNTIME-03：工位框架与供包参考运行闭环

版本1.0；设计形成日期2026-10-16；分析基准 `39747a8c35b748da71bf9acfd56a9c9812b199b4`。状态：**独立参考实现已交付开发分支；核心验证及WPF编译通过，Windows运行/真实联调受阻**。本文件保留原S0～S5和AC-01～11定义；实际成果和边界见[交付报告](../runtime/delivery.md)及[验证回执](../runtime/checks.json)，不视为客户生产放行。

## 1. 为什么现在做

仓库已经有归档工具、问题表、技术基线和决策准备，但没有生产C#工程。继续只增加准备材料不能验证模块组合、业务状态、多UI和持久化恢复。先形成可运行、可失败、可恢复、可发布的参考产品，同时把未知现场规则隔离为显式外部条件，是当前最有价值的推进路径。

本包不是客户供包软件已完成的承诺，也不是一个简单Mock成功演示。运行核心、SQLite事务、请求执行器、UI绑定、配置/日志/报警及恢复是真实实现；仅设备事件、外部协议与尚未确认的业务参数使用清晰标识的工程夹具。生产模式缺资料时拒绝准入，不静默回退。

必读：[项目指令](../../AGENTS.md)、[索引](../INDEX.md)、[框架主设计](../design/framework.md)、[框架决策](../design/framework-decisions.md)、[D决策包](../readiness/decision-pack.md)、[修订验证交接](../readiness/revision-and-verification.md)、[历史问题表](../reviews/issues.json)、[公开范围](../baseline/PUBLICATION.md)。不依赖本聊天或受限下载链接。

## 3. 实施范围与依赖顺序

### S0：阅读、基线与范围整理

核验最新main、开放PR和工作区；读实际AGENTS/索引/设计/相关代码及测试。只处理本包相关过期指引和冲突，已正确整理不重写，旧证据保留。若有新业务代码，形成文件级继承/改动表，不并行造第二套框架。

仍无旧工程时执行F-02：C#/.NET10/WPF/GenericHost/SQLite，锁定可用版本；不能以旧工程缺失无限推迟新参考实现，也不能宣称与旧现场兼容。提供真实解决方案与构建/发布入口；核心库不依赖WPF便于隔离验证。代码组织由实现者决定，保留责任边界而非机械复制几十个空项目。

### S1：完整运行基座与产品装配

实现产品/模块清单、契约与依赖检查、显式注册、实例绑定、标准/紧凑视图选择、单实例/资源所有权、启动/停止和健康状态。必需模块缺失、版本/位数/路径冲突时给出可诊断阻断。首版明确注册为主，不要求未使用的动态插件系统或热卸载；设备/外部实现仍可在允许名单中切换。

配置分产品、站点和展示三层；草稿验证、维护权限、待生效、失败保留旧版本及受控重启生效完整实现。禁止新配置重定向旧请求。模拟与生产根目录、身份、端点允许规则隔离；Production缺真实能力时报明确NotReady，不注册fixture成功返回。

### S2：当前供包参考业务与共享状态

实现一个工位业务实例、一个参考箱会话、两个逻辑通道、设备观察/准入/作业/请求/尝试身份，应用命令守卫与版本控制。参考共享箱/双实体位只是显式fixture模型，生产映射继续由D-05/06决定。

提供可从UI及测试控制的两种设备能力实现：人工事件脚本源、文件回放源；它们共享读码端口，来源稳定，实例分别绑定两通道。支持明确的实体入场、无码、多码、非法格式、重复观察、合法同码新实体、拒绝纠正、离场和复位。下一件通过显式事件继续同一箱，不切换场景重置整个程序；复位不能抹除旧请求。

实现合成任务校验、等量/不足/超量参考策略、拆包有效计数与受控清空、提交、关闭检查/少货取消和确认、CloseUnknown核对、新箱准入。**这些仅是覆盖分支的工程策略**，以独立fixture ID、配置版本和屏幕标识隔离；不沿用其值作为生产默认。没有真实权威语义时不启用生产自动发车、手动强制放行或人工改码。

例如可用包装9、需求6、差额3的合成案例；策略文件显式说明扫描保留件、参考数量单位、模拟承运/复位事件，不称为客户规则。两通道争同一任务需求由有状态fixture端点原子裁决，业务客户端不能两边各自扣减后假装一致。

### S3：真实持久化、外部端口与故障恢复

实现框架§7/8的本地事务和数据模型：业务事实与意图原子保存、原请求领取、发送尝试、接受/拒绝/Unknown、唯一计量、操作审计、历史查询、清理与备份恢复边界。不是仅用内存Repository通过测试。

提供独立的本机loopback契约夹具：明确SIMULATION，使用合成身份与报文，固定请求ID+payloadHash，不同内容同ID拒绝；维护自己的持久接收账，能够模拟“已处理但丢响应”、查询不支持/无记录、业务拒绝、延迟/乱序、关闭未决。客户端与夹具不共用业务数据库。夹具地址和路径是工程协议，不称为实际WCS接口；公开README清楚标注。

验证客户端重启时Prepared/Dispatching/Unknown的恢复差异，服务端已处理而客户端丢回执不能新建身份重发。人工核对入口记录证据与责任，模拟端点结果注入仅在专属模拟控制中可用，不成为生产“强制成功”按钮。备份恢复后不自动重放可能已处理任务。

有界队列、网络请求取消、故障传播和原生资源接口生命周期都应有实现；没接真实SDK的部分可隔离验证资源所有权，不伪造真机PASS。图像/秤/PLC/RCS/DCS不在此包实现范围。

### S4：可操作WPF、多UI、诊断与交接

交付主工作台、记录/请求/发送尝试详情、报警与关闭核对、设备及配置诊断；标准与紧凑布局使用同一业务服务。两UI并行观察或反复导航不新增连接/发送器/业务实例，重复命令仍集中防重。

继承框架§10与公开tokens的信息层级；无需受限原图也应有完整中性界面，不交纯文字console替代桌面。保留条码前导零、错误全因、关键数量/拆包进度、当前阻断和主操作；后台更新不清草稿/滚动，焦点进入弹窗并返回，扫码回车不触发高风险操作。辅助抽屉打开时仍发现新阻断。

实现独立报警身份、正确关联、已读与恢复分离、多故障并存；日志和诊断导出脱敏。提供模拟操作员与维护角色，不把该身份提供者用于Production。登出/退出有未决任务时保留责任和证据；生产认证/换班批准不足时报阻断，不自行决定权限。

### S5：发布与必要运行验证

交付实际可用构建、运行、离线发布、初始化、备份、升级预检查/回滚和诊断操作说明；版本/依赖/配置示例能复现。程序数据目录不放发布目录，模拟数据不进入生产目录。模块目录缺件、损坏库、存储不可写、重复实例、配置无效时应启动诊断而不是伪绿灯。

Windows环境可用时完成WPF启动/布局/发布冒烟；不可用时完成能够运行的核心/夹具/持久化检查、交叉编译能做的部分，记录桌面验证BLOCKED并提供实际发布产物或产物阻塞，不拿Linux核心测试代替Windows验收。禁止伪造截图、DLL或可执行文件。

## 5. 风险驱动验收

每项记录环境、commit、配置/fixture版本、操作或命令、结果与证据。一个测试可覆盖多条风险，不以数量/覆盖率代替证据。以下“建议样本”不是客户吞吐指标。

|验收ID|必要验证|完成条件|
|---|---|---|
|AC-01|装配与多UI|选择允许实现/布局有效；未知/不兼容模块拒绝；导航及两个视图不重复创建业务或发送器|
|AC-02|许可组合|设备/存储/WCS/身份/许可/Unknown分别与OperatorPaused组合，暂停恢复不绕过其余原因；命令入口同样拒绝|
|AC-03|连续作业|建议至少20个合成作业，包含同码新实体、重复观察、拒绝纠正、两个通道，保持同箱连续，不切场景复位|
|AC-04|身份和数量账|同请求多尝试/重复回执只计一次；两通道竞争需一致；拆包/关闭记录数量与合成策略及历史快照可复算|
|AC-05|不明结果与崩溃|在T1前后、T2后、远端处理丢回执、T3保存失败处故障注入；至少使用实际SQLite及进程重启验证关键窗口，不只有Mock仓储|
|AC-06|迟到/配置变更|旧连接回调/旧作业回执不覆盖当前；请求固定原绑定；修改地址/布局/用户不重投旧请求|
|AC-07|故障与报警|Faulted/Unknown均能安全显示；左右一致；多报警不串已读，正确跳转；关闭Unknown能定位原关闭请求|
|AC-08|交互稳定|回执/刷新/resize不清草稿和滚动；弹窗焦点不逃；关键字段、拆包计数和操作可见；需要Windows证据的部分单列|
|AC-09|关闭恢复|少货取消/确认、关闭丢回执、退出/重启、备份恢复有保护；未经权威关闭不换箱|
|AC-10|资源与发布|有界队列满载无静默丢业务；取消/释放可观察；存储失败/缺件/第二实例可诊断；运行与离线发布冒烟|
|AC-11|生产防伪|Production缺SDK/合同/策略/身份必需项拒绝业务；不包含可误用的成功fixture入口，不连接外部生产端点|

开发前建立适当基线；期间只运行相关模块与上述风险；交付前必要构建、关键回归、启动/发布冒烟。若修改归档工具以适配新增源码/生成目录，保留其资料检测语义，只调整明确的资产范围，不删断言或增加宽泛白名单骗PASS。构建输出/包缓存不纳入Git和资料manifest；更新清单范围须有明确规则，旧资料继续可核验。

有效缺陷必须修复；过期测试依新批准契约有证据更新；环境缺失如实BLOCKED；无关历史问题登记不扩散。不能吞异常、跳过关键失败或虚构测试。

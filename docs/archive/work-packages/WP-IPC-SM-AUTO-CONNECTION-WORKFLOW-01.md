# SM-AUTO-CONNECTION-WORKFLOW-01

2026-10-29，基线 main `55efb064`。承接 SM-BUILT-IN-ONLY-01：当前 SM 使用内置 MVS SDK 采图、进程内软件识别及内置 RCS。用户要求相机恢复连接后自动重连，删除暂停/恢复供包与参数保存的手动暂停步骤，删除 RCS“稍后配置此连接”框，并修复停止时 `StopGrabbing 0x80000003` 导致无法退出。经 PR 合入 main，再由实际合并提交输出 1.0.0 安装包，用户自行安装；不重置现场数据，CI 继续停用。

## 当前实现

- `IAutomaticReconnectObservationSource` 显式声明可恢复源；Application 对已配置 MVS 的 Disconnected 状态后台重连，间隔从 1 秒退避至最多 10 秒。不要求管理模式或按钮操作。仍核验原 IP/物理序列号、独占租约、SDK ABI 和依赖完整性。
- 自动重连复用原设备锁、在途计数与 ObservationSession；先停止原句柄，再建立新 epoch。旧回调不能进入新会话；RCS 与原请求不重建、不重发。SDK清理失败、未交付输入、图像/解码错误不当成普通断线重试。停止时取消重连并等待真实原生调用归还。
- SM 保存参数在 Application 内临时阻断新准入，等待当前外呼/阶段完成，最多等待 10 秒。超时保留原配置并反馈未保存。完整校验、管理授权复核、修订 CAS、审计与 Pending/Effective 分离不变。其他业务原手动暂停规则不变。
- 删除 SM 作业页暂停/恢复按钮及缩小窗口导致的自动暂停。移除保存核对中的手动暂停动作；管理权限和受控应用仍有效。旧版遗留暂停在重启后通过实际就绪及原业务守卫才自动解除；当前维护再次暂停会取消这一旧状态恢复，不能覆盖维护动作。
- RCS 首配和日常共模删除“稍后配置”复选框。空服务地址表示待配置；填写地址后按完整参数校验，保存候选不再保留旧的 deferred 标记。仅打开页面不改写 Effective。
- 根据已安装官方 MVS 头文件，`0x80000003` 为 `MV_E_CALLORDER`。仅 StopGrabbing/CloseDevice 允许继续推进至 DestroyHandle/Finalize；原生缓冲仍先归还，销毁/终结必须成功才释放租约。其他返回错误及销毁失败继续保留所有权，可重试退出，不能伪报停止成功。

## 验证与边界

Application/SQLite/实际 ZXing-C++/本机 HTTP 合成链覆盖：离线激活和重启保留完整配置、普通投影仍为已配置、无管理授权自动重连、独占暂不可用重试、运行中断线返回后新 epoch、帧编号从 1 重启、同码独立请求、未暂停保存、清理失败阻断及停止后不再重连。Probe 覆盖 CALLORDER 后继续关闭/销毁、销毁失败持有租约、重试后才释放，并保留其他停止错误断言。

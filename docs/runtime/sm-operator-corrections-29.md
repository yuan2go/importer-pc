## 正常供包（继承 main 38cb7dc0）

按[SM-SAME-PLACEMENT-29](../work-packages/WP-IPC-SM-SAME-PLACEMENT-29.md)执行：每个投递位的一次托盘放置只创建一次RCS请求，持续同码观察指向原作业，不创建新的作业或请求。相机采集、视频和识别继续运行，以观察空托盘；不能冻结解码来实现等待，否则会失去空托盘事实。每位RCS请求仍按原处理顺序完成，另一位独立运行。

相机连续3帧无码且跨度至少800毫秒后结束该次放置，短暂反光和坏帧不作为释放；相机来源不能仅因时间过去而释放。空托盘后再次读到同码属于新放置，读取不同码按main规则进入新放置。人工输入是明确提交；人工与相机关联、未送达和超时后的新放置准入沿用main的原合同守卫，不自动重发原请求。畸形回包、冲突及无证据的未知结果仍须核对原责任；内置RCS不提供结果查询，不伪造结果查询。

新站显式选择Code128、Code39和EAN13；升级时保留已有站点码制，未配置该项的既有站点继续使用原All回退。只在新的首次配置模板中改变默认，不改写原站数据。

## 扫码调试

保持实时画面和本次读码在上、请求与回包在下；扫码操作栏不随正文滚动而消失。选择左右相机后点击“触发扫码”，在既有实机隔离中读取本轮；有效条码和同帧照片锁定，并显示绿色位置标注。RCS离线不阻止只读码。扫码本身不调用业务请求，只有明确点击“发送请求”且原权限、配置、生效、原图与请求守卫通过才可调用；准备人工请求不要求相机在线。再次扫码/离页清理仍取消原来从未发送的测试意图，已发送/未知请求不重发。测试时两位自动供包暂停，结束后按原流程核对恢复。

## 采集诊断

体检通过 `ICameraAcquisitionDiagnostics.ReadCameraAcquisitionAsync` 读取原采集所有者的被动事实，不申请预览缩略图，不触发取帧、读码、设备重连或RCS请求。当前连接周期、最近有效帧、帧时效、解码状态及历史异常帧分开呈现。预览缩略图按需生成，其暂时不存在不代表相机没有取到帧；历史丢帧不会否定后来取得的有效帧。连接确认过期与仍有新帧也分别说明，不能据视频或计数授予供包资格。SDK原始错误继续留在原诊断/导出，页面给出中文处置提示。

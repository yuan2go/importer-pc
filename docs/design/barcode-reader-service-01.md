# 独立读码服务设计

本文定义独立 MVS → VisionMaster → TCP 读码服务的内部边界；线上字段仅由[条码生产者协议 v1](../protocols/barcode-producer-v1.md)定义，不在此复制或扩展。供包台内置 MVS 扩展继续只诊断。真实接口/授权/触发证据不足时保持 Unavailable，不能以假解码器替代生产。

## 待裁决的接入边界

现行 v1 要求供包台 TCP 生命周期持有 `device:hikrobot-gige:<serial>`，服务以 SDK 独占相机，不再取相同独占租约。本轮服务持租约要求与之冲突，等待用户裁决后才能实现部署装配。v1 心跳没有就绪字段；遵循 v1 时，只在全部门控有效时发送心跳，任一失效立即封锁发布并断连，详细原因保留在服务状态中。不得私加字段让供包台误解析。

VM 安装目录及其方案 SDK 指南尚未核实。官方基础包安装指南与同包脚本项目显示 .NET Framework 4.6.1 及以上；算子 SDK 不能代替 `.sol` 方案 SDK。宿主/核心沿用 .NET 10，VM 独立 x64 worker 的精确框架及依赖必须据方案 SDK 确认，且不加入主解决方案或改变主锁文件。不能依据程序集名称猜测可调用方法或授权状态。

## 进程与所有权

服务宿主独立于供包台；每个配置实例单实例、每台相机单一采集 owner。复用原 MVS 原生 API、帧校验及有序清理，采集 owner 已从观察扩展分离到同一共享程序集内的 `MvsCaptureSession`，诊断包装和独立服务工厂调用同一 Get/Free/Stop 实现；服务宿主装配尚待接入边界裁决。

VM worker 承担不可取消的原生调用。宿主独占 worker 标准输入输出的有界二进制帧通道，不加载 VM 程序集。所有调用携带启动标识及递增调用序号；错误标识和迟到结果拒收。worker 一次只执行一个方案，固定 `.sol` 路径、SHA-256、流程及输入输出节点，不热换方案。配置及规则导出为固定顺序 UTF-8 字节并计算 SHA-256，覆盖所有影响识别和实体发布的字段。

## 缓冲及停止

配置 checked 计算原生缓冲节点、宿主固定池、worker 图像副本和有界结果所需预算，超限在打开相机前拒绝。宿主池使用一次预分配的固定槽，长期像素数组放 POH；每帧不分配大数组，不能用 ArrayPool 的可增长行为冒充固定上限。

采集线程只做帧验证、单调帧号检查、尝试租槽、复制以及立即 FreeImageBuffer。Free 成功后才将复制结果交给有界 FIFO。解码、TCP、日志和取消回调不得同步阻塞采集。租槽/队列满分别计数并锁定 Degraded，立即撤销就绪；不覆盖旧帧，不以丢弃最旧帧维持假健康。SDK 帧号缺口/倒退单独计数并 Faulted。

槽由采集、队列、解码唯一移交。复制异常、归还 SDK 异常、取消、队列拒收均明确回收。解码超时只能取消等待，不能提前复用原像素；先证明实际调用结束或 worker 退出，才归还槽。无法证明退出时保持 owner，宿主退出并由监督器处理，不再接新任务。

Stop 幂等且并发调用共享排空任务：停止准入和网络发布 → 封锁采集 → 等实际取帧/归还 → 排空或丢弃队列 → 限时等待解码 → 终止挂起 worker 并确认退出 → Stop/Close/Destroy/Finalize → 释放租约。外层取消不改变所有权。任何 native 清理挂起都由独立看门狗使服务退出，不能假报已停。

## 触发及候选

实体只由实际相机触发计数定义，帧号只校验采集连续性；两者不能互换。要求实际 TriggerMode/TriggerSource/TriggerSelector 与配置一致，采用固定 N 帧每触发。相同触发的 N 帧全部成功完成后才形成一个最终结果；触发跳号、倒退、额外帧、提前换触发或到期不完整均故障。计时只检测不完整，不据时间窗口构造实体。

完整候选先验证文本、码制、位置、质量和数量，再执行版本化长度/前缀/整串正则/码制规则。正则采用非回溯和有限超时。唯一候选才可选中，同帧多个匹配或跨帧冲突不猜质量最高者；输出明确无码/歧义状态。零码触发不能被省略。发布候选完整性须与 v1 明确的完整 event 约束一致，禁止截断以满足行长。

## 就绪与恢复

Unavailable → SelfTesting → Ready；任一异常进入 Degraded 或 Faulted 并锁定，不能由随后一次成功自行恢复。Ready 必须同时具备实际相机身份/触发配置确认、VM版本及授权确认、方案哈希及节点契约确认、合成自检、有效选择规则、无队列/帧缺口、TCP握手边界。

断连取消发布并丢弃跨连接队列；不缓存补发，不将旧触发赋新序号。受控恢复仍须现场处置原实体和供包台原请求；服务重启新 bootId，不声明原输入已经送达。监督器采用有上限退避，反复失败进入锁定；自动重启进程不等于恢复业务。

## 故障表

| 原因 | 服务行为 | 防护风险 |
|---|---|---|
| 配置/内存/规则无效 | 打开相机前拒绝 | 不可控内存与隐式猜码 |
| VM版本、授权、方案/节点不符 | Unavailable/Faulted，无就绪 | 有连接被误当可读码 |
| SDK帧号断档或损坏 | Faulted，独立采集计数 | 漏触发被隐瞒 |
| 池/队列满 | Degraded锁定，断连 | 解码积压静默漏包 |
| 触发组不完整/计数回退 | Faulted，拒绝部分结果 | 错配包裹 |
| VM超时/不响应取消 | 封锁，worker实际退出后回收 | 原像素提前复用 |
| 旧boot/call/Epoch结果 | 拒收并故障 | 重启后旧结果准入 |
| 普通无码/歧义 | 完成该触发，明确无码/异常结果 | 猜码及省略失败触发 |
| TCP断开/写超时 | 关闭发布边界，受控恢复 | 旧包裹重新发为新实体 |

## 回放与验证

离线回放读取外部 Mono8 原始帧及人工真值清单，复用相同解码端口和规则。所有样本进入分母，正确、无码、错读、执行错误分别统计，错读包含无码真值上的假阳性。按真值码制分组；Stopwatch记录每次尝试，nearest-rank计算P50/P95/P99，不输出真实条码。真实图像、真值及厂商示例不入库，仅生成合成夹具。

必要验证覆盖槽守恒、异常/取消/停止竞态、过载、真实触发映射、旧启动标识、选择歧义、授权失效门控、共享黄金协议、回放算术和假相机→假解码器→真实供包台解析。VM真实适配/相机、加密狗拔插、错读率、触发计数和24小时稳定性独立验收，不进入CI。

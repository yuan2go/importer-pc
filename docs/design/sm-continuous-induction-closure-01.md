# Sportmaster 连续供包与取件结束契约

当前业务契约，适用于 SM 双投递位、.NET 10 WPF、内置 RCS，以及 MVID 原生识码和 MVS＋ZXing-C++ 两条采集路线。

## 1. 取下即结束本件

可信空盘、绑定当前轮次的一次人工“已取下包裹”确认、有效 RCS 换车均结束旧件。原请求结果已确认时，取下后下一件独立处理，同车、同条码也允许新建任务，不要求启停、等待换车或维护核对原请求。

原件成功或明确业务拒绝不延续为下一件的投递位占用。已开始调用但远端绑定/取消尚未确认时，保留与本件轮次独立的本位发送围栏；取件、换车、停用、重启及历史保管均不解除，另一位可继续。协议只发送站点和相机编码，不含不可变车号绑定，因此不能把下一车到位或本地超时当作原请求已绑定的证据。只有原有效回包或外部核对证实原请求已绑定/取消后，才解除该围栏。原请求仍按冻结身份收口，保留真实结果、原报文、回执、永久编号与防重记录；取件不把拒绝或 Unknown 改为成功，也不自动重发、查询或撤销 RCS。

没有可信物理边界时，重复同码、换码、无码、画面运动、重连、显示三秒到期和切页都不证明是下一件。同一轮最多一次持久提交和首次外呼，相机、PDA、键盘原子竞争这一次提交权。

操作员停用结束本位使用；真实调用、执行和回执尚未收口时仍显示停用中。停用不伪造空盘，重新启用仍保留同次放置的自动抑制，避免包裹未取下就自动重发。真实心跳成员未确认、RCS 离线、资源未释放、存储故障和管理暂停继续执行各自守卫。

## 2. 身份与原子边界

| 身份 | 含义 | 生命周期 |
| --- | --- | --- |
| RoundId、Version | 当前物理包裹轮次及操作版本 | 取件即结束，后续任务不复用 |
| PlacementGeneration | 同车上的放置边界 | 每次可信取件更新，墙上时间重复也不复用 |
| ArrivalGeneration、VehicleNo | RCS 确认的小车到位 | A→B→A 是三次到位；取件不伪造换车 |
| OperationId、RequestId | 原任务和原取格口请求 | 原结果、报文、回执独立保管，不随取件重发 |
| Epoch、CaptureBoundaryId、CaptureTicks | 相机采集身份 | 取件、换车和会话切换隔离旧采集与迟到识别 |
| CommandId 与冻结轮次、版本、放置及到位代次 | PDA、键盘、人工确认的目标 | 重放返回原回执；旧命令不转投新件 |

结束轮次的同一事务中，释放本件 SubmittedOperation 和 SubmissionAttempted；TargetOperation 在远端绑定/取消未确认时独立保留。若尚未首次尝试，同时取消原准备意图；已经开始调用的请求沿原报文和总预算完成。旧回包、原图保存和异步结果只更新原记录，不重新占位、不结束新轮、不覆盖新件格口。

当前格式中已记载取件结束的记录，重开时恢复已经释放的资格，不复活旧本件提交占用；未确认的远端绑定围栏仍须恢复，不能随本件结束一并抹去。未证明取件的当前放置仍保留本轮一次提交事实。配置 schema3、DB14 不变，不通过修改原冻结配置或哈希放行。

## 3. 可信取件与换车

- 运行空盘至少 3 帧、连续 800ms；相邻有效帧间隔超过 500ms、丢帧、曝光异常和重连打断连续性。显式空托盘校准独立保留 800ms。
- 相机未校准或视觉不可靠时，不用无码、被排除底码或画面变化冒充空盘。操作员可对当前 RoundId＋Version 明确确认已取下。
- 同一次稳定空盘只关闭一次，不反复制造新件。空盘保持实际车号，新的正式候选或可信上件才能开始下一轮。
- 合法、未过期且匹配本站、相机编码、请求编号、成员版本与当前配置的心跳，可用实际车号变化独立分轮；短于 800ms 的换车无需再等视觉空盘。
- 两种边界沿原 SDK、解码和交付清理流程建立新 CaptureBoundaryId。旧帧即使晚完成，也不能成为下一轮输入。
- 空盘先到、换车先到以及人工确认与空盘竞态，只关闭其绑定的旧轮；迟到事件不得关闭后来开始的新轮。

## 4. 识读与提交

只把达到放稳时间的帧交给业务识码，默认 200ms；持续运动约每 1500ms 仍提供一次识别机会。MVID 放稳前只显示图片，不提交原生返回的条码。

默认 1000ms 是快速识读目标，不逐帧续期。到期后只在原包裹、车辆和相机会话连续在位身份仍可信时有界降频续读；连续性破坏、重连或疑似换件后，只允许原位补录、取件或新边界。

全部原始候选留证；经合法性、允许和整串排除规则筛选后，业务、UI 与 RCS 使用同一正式候选。底码全被排除不证明空盘或上件；两个同码物理标签仍是多码。相机与人工补录共用本轮一次提交，人工提交后相机只记观察。

外呼顺序为：候选校验 → T1 持久接纳 → 有界资源等待 → 当前轮次及代次最终复核 → T2 持久首次尝试 → HTTP → T3 原回执落盘。资源等待发生在 T2 之前；本地许可不代表远端收到。T2 前取件取消发送，T2 后按原冻结请求收口。

真正的 HTTP、执行、原图和存储资源仍有界。旧请求不占下一件的业务提交权；实际资源耗尽仍明确提示容量原因，不能伪造执行完成。左右位独立，公共 RCS、存储或管理暂停如实执行。

## 5. 结果与页面

- 成功、业务拒绝和 Unknown 均属于原件。取件立即撤下当前操作归属；有唯一新候选时不再显示旧件。
- 成功格口按首次显示时间保留至少三秒展示机会；旧轮已结束且新件未开始时，可短暂显示“上一件格口·仅供查看”。回看不占提交权，不开放旧图片或旧操作入口。
- 业务拒绝显示 RCS 原始消息、取件说明及“取下后本件结束，可继续处理下一件”；不因普通拒绝要求维护解锁；暂停、离线及成员待核对时列出实际限制，处理后再上件。
- Unknown 保留结果未确认的真实说明。取件后退出当前包裹轮次，远端绑定未确认时仍保护本位发送；实际调用、回执与身份责任收口后进入历史保管，永久防重继续保留。
- 新件等待、离线、停用和当前件异常均由 Application 的真实准入决定。显示三秒到期只结束展示，不假造取件资格。
- 顶部小车号与实际心跳状态独立于包裹状态，包裹异常不能遮住已核验的车号；缺失或过期时仍显示待确认。每次实际心跳日志关联原始请求/响应、HTTP状态、协议核验、完整性、耗时、左右成员和车辆；旧配置/启停响应明确标记，凭据脱敏，超过日志正文上限明确截断。
- 心跳成员真正迟到、身份、连接、存储和资源生命周期问题独立处理，不从原件请求结果推导整位永久不可用。

## 6. 必须验证的行为

| 场景 | 预期 |
| --- | --- |
| 原件尚在原位，同码或换码再次输入 | 本轮不新增请求 |
| 无码、多码、非法码取下 | 同车下一件可自动识读或人工提交 |
| 已接单、拒绝或 Unknown 后取下 | 立即结束本件占用；成功/拒绝后下一件独立提交，Unknown保留远端围栏 |
| T1 未 T2 取下 | 原请求零外呼，保留取消证据 |
| 原 HTTP 仍在途时取下并提交下一件 | 绑定未确认时阻止本位下一件发送；确认后才放行，旧响应只更新原件 |
| 旧帧、PDA 命令或取件命令晚到 | 不新建、重发、覆盖或结束新件 |
| 同车、同码连续两个可信物理轮次 | 两个独立任务与永久请求编号 |
| 已确认取件但遗留请求占位记录，重开软件 | 沿原取件事实释放本件提交占位，保留Unknown远端围栏及原始结果 |
| 左位旧请求、右位新件 | 两位独立；公共离线和实际资源限制仍准确执行 |
| 停用／启用但包裹未取下 | 不伪造物理边界或自动重发 |

验证入口沿用 --sm-arrivals（含 SmPlacementIndependenceChecks）、--sm-round-lifecycle、--sm-arrival-cameras、--station-position-control、--sm-dispatch-resources、--camera-chain-reliability 与原生 WPF 的 --home-centered-states、--paused-workstation、--rcs-no-destination-ui。

本机可控相机、隔离 SQLite、回环 HTTP 验证不能替代客户 RCS、真实相机和现场节拍验收。真实 SDK、物理取件误判率、现场网络、断电与 24h／72h 长稳需现场验证；不得用合成短测签发现场资格。

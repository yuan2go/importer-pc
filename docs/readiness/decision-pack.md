## D-02：真实 WCS 契约与成功语义

关联：RV-01/06/07；REQ-023/024/039/049；BR-10/12/13/14/18。

建议共同答复：WCS 接口负责人、产品、客户端维护者。

需取得版本化的供包台—WCS 专用契约，确认以下内容：

1. 逐项说明验箱、Item 校验、供包提交、结束检查、箱关闭是否改变业务状态，是否预留需求或触发实体调度。
2. 每个阶段的接受、拒绝、处理中与结果不明分别表示什么；通信成功、WCS 业务接受、上游报告、实体完成分别由什么证据证明。
3. 请求身份的作用域和保持期限；同一请求重复到达的行为；已使用身份但报文不同如何处理。
4. 查询支持哪些业务阶段，结果保留多久；查不到能证明什么；不支持查询时，人工核对用什么权威证据、由谁执行。
5. 需求预留、释放、版本过期、并发分配和关闭屏障由谁负责；校验和提交合并时如何对应逻辑阶段。
6. 认证、错误分类、事件顺序、快照、断档恢复及报警身份如何提供。真实地址和认证材料只进入获授权受限位置。

## D-03：数量与自动/人工分支

关联：RV-08；REQ-015/016/036/041；BR-05/06/08/16。

建议共同答复：产品、WCS、现场业务。

- 包装内数量、有效扫描量、剩余需求、接受数量分别以什么基础单位计算？剩余需求属于订单行、任务还是目标格口，按哪个版本有效？
- 包装量等于、小于、大于剩余需求时，各自允许的动作和人工确认是什么？原材料中不足量自动/人工描述不一致，必须明确批准采用哪条规则。
- 剩余需求为零、未知、负数或版本失效时如何处置？双通道同时面对同一份需求时，由谁原子分配，失败方如何重新取得有效任务？
- 计件依据是哪一种业务事实？多次发送尝试、重复回执和重复观察如何避免重复累计？

## D-04：拆包方向、承运粒度和剩余件

关联：RV-02/08；REQ-017～022/036；BR-07/09/15。

建议共同答复：产品、现场业务、WCS。

- 扫描对象是保留件还是移除件？一个有效码代表一件还是多件，普通同 SKU 商品码重复时如何区分实体？
- 需求量为 N 时，最终一次承运 N 件还是 N 次供包？确认拆包、装载确认、供包提交的顺序是什么？
- 剩余件保留在哪个实体容器、归属哪个箱/任务，之后重新识别如何建立新作业身份？
- 清空重扫能够撤回哪些未提交事实？若已预留任务或请求结果不明，如何释放或核对，而不是只清界面？

## D-05：实体入场、装载、许可与复位

关联：RV-01/02/09；REQ-031；BR-05/12/17。

建议共同答复：WCS、AGV/设备负责人、现场实施及安全责任角色。

对入场、就位、装载完成、允许发车、离站和复位，分别提供：权威来源、对象身份、事件序号/版本、新鲜度、失效条件、控制权和发生顺序。确认以下边界：

- 识别发生时，货物是否已经放稳？哪个阶段允许动作，最终执行方如何核验？
- 接受后何时能接下一实体，拒绝后如何确认处置完成？不使用固定延时、条码变化或整箱重置代替实体事件。
- 软件暂停/恢复分别解除什么原因；其他设备、存储、身份、WCS 或实体阻断仍存在时，界面与命令应如何一致地保持限制？
- 信号过期、断连重连、漏事件和迟到事件如何收敛？软件暂停的范围须与现场安全急停分别解释。

## D-06：两相机、供包位与周转箱映射

关联：RV-02/04/09；REQ-005/032/033；BR-02/14/16。

建议共同答复：设备、现场实施、WCS、产品。

- 两相机观察两个独立实体位，还是同一实体的不同视角？稳定设备身份如何对应 CAM0/CAM1、实际供包位及 AGV？
- 两个通道是否共享同一周转箱会话？如果并非共享，哪些现有设计假设需要正式修订？
- 一个实体可能产生几个触发/观察，如何跨相机或重连周期关联？缺少关联证据时如何阻断错误归属？
- 一侧故障时，另一侧能否继续，依据哪些现场许可和受影响范围？不能从双列 UI 推导物理运行规则。

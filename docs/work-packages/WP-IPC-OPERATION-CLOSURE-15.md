## 3. AC15-02：每份接收责任、T3与重启

最新报告E8给出两份并发原查询的可达反例。修复接收发生/接管失败与请求ID混合的根因，覆盖接收开始、围栏、原件Flush、业务T3、清理、并发原身份核对、正常退出、进程中断和启动重放。内部模型、表/文件组织及必要的请求协调由Codex决定；不能只加未接线helper或只串行UI点击宣称全部消费者受保护。

功能验收：

1. 一份原件未保存，另一份同请求结果成功/重复/重放，不得抹掉前一未完成责任；有任一raw不代表全部接收已接管。未保存内容明确“未取得/不可恢复”，不伪造原件。
2. 已持久终态、原RequestId/报文/hash/合同/目标/精确实现、attempt和唯一接受事实保持；矛盾与原终态正交，不倒扣、重计或改成可盲重发失败。
3. 已完成接收和真正不确定窗口分开。既定可恢复场景在受控/异常退出后能够继续；确无可信证据的接收持续隔离并给具体诊断/核对入口。不得靠所有历史终态永久加锁代替归属，也不增加无批准通用解锁。
4. 恢复列表、原身份查询、当前阻断、准入/提交/结束检查/关闭/激活守卫、历史详情/导出/清理、维护预检、备份/升级/恢复及精确旧包保留使用同一责任事实。查询/T3未完成前的资源所有权保留。
5. 如需格式变化，追加前向迁移并同步reader/包身份；旧SQL/checksum及未知未来格式拒绝保持。无必要不强行升级格式。

必要测试：复用现有Rig、真实SQLite和可控本地契约，以确定性故障注入覆盖Q1原件创建失败/Q2成功；Q1已Flush但T3回滚/Q2接管失败及重启重放；已完成T3后中断与真实未完成接收分别验证。断言不同终态、原件/未接管责任可发现、原请求不可变、接受量唯一、原身份可核对、无静默放行和无盲重发。保留原同ID/迟到旧箱/单接管失败有效断言，不复制庞大排列组合。

## 4. AC15-03：箱结果、事实与当前可用性

补齐Context、CheckClose、Close阶段/请求身份/最后结果/原因和允许下一步的投影，贯穿当前箱、持久化后刷新、切页/重启和历史。仅Toast或藏入技术树不满足验收。

Accepted仍表示已发生事实；当前主服务、来源/投影过期或持续核对责任须就近可见，应用守卫准确禁用动作。辅助故障不回归A02，历史查询故障仍归原目标。部分关键命令补可见禁用原因；已有DisabledReason/AccessFeedback保持一致，不复制第二套判断。

## 5. AC15-04：输入与维护旅程

保留按作业/命令/输入版本、成功Persisted才消费的规则。补齐A尚在SendAsync/刷新期间收到B、A/A/B、Enter/Tab结尾、拒绝重试、迟到完成、切作业、身份失效、多窗和焦点切换的真实入口。不能静默拼AB、吞结束键/输入或清后来的新输入。

Codex自主选择有限接收/交互隔离方式；容量、拒收和重新扫描有清晰反馈，失败保留可处理草稿。业务实体准入、防重、CAS保持，不引入无依据自动提交、不绕拆包数量、不把同码不同实体误合并。

局部模块选择/新建/目标默认值读取不依赖完整草稿所有数值合法。编辑中允许暂空/非法，保存/预览仍严格校验并就地反馈。不能改回读Effective、吞异常或放松后台验证。

实际维护旅程：多设备/多服务JSON导入 → 跨页编辑字段/目标/参数 → 不完整草稿中选模块/新建 → 修正 → 预览/保存/重读 → 当前页选择修订直接激活 → Pending → 受控重启后Effective或失败保旧。非法导入/取消保留原草稿，双窗草稿独立、持久化竞争由应用CAS裁决。

UI-R03补A慢失败/B快成功、导入/新建使旧返回失效的可控时序；成功、错误和finally均属于发起对象/代次。保留权限、原责任、实体/激活屏障。验证实际页面事件链，不仅测helper或用CLI绕过坏页面说明UI完成。

## 6. AC15-05：追溯记录与局部UI结构

会话/箱与Item作业分别投影正确类型/标识，列表、详情、复制、筛选、导出语义一致，前导零和原ID保留；不只改列头掩盖错误值。结果、接受量、尝试摘要和原责任易辨认，技术树按需展开。

记录页改为列表优先、详情按需；未选详情不长期占多数宽度。返回、切页、刷新、迟到加载保留本窗筛选/选区/滚动/页码；鉴权、过滤/分页边界不削弱。分栏、抽屉或详情容器由Codex选择，不改全站导航。

筛选有可见标签、本地日期时间与时区、空值/非法范围反馈；查询转换与后台严格边界一致，不要求手拼ISO时区字符串。只补受影响时间边界和上下文验证。

按语义分主次动作，只读详情不持续占提交主视觉；收敛重复入口但保留必要操作。**同步调整ReviewFits的当前必要检查集合**：隐藏非必要控件不能永久禁止；关键事实/动作不可见时仍保护。不得删守卫、缩字或降低门槛换通过。

UI07只在受影响组件复用现有tokens/字体栈/图标/颜色，不做无关主题改版或添加字体文件。长原因、任务/条码、波次差异和拆包标签纳入同一客户区验证，原Wrap和v1.1实物保留。

# SM DB12 到 DB13 离线接续

## 已观察的问题和边界

232b39f1 在 schema3 配置对象中增加始终序列化的 `ReadTimeoutMs=1000`，读取原配置及冻结请求配置后再序列化，会改变确认哈希。本机原账没有丢失；读取被拒后，维护页仍生成空的参数标签页。原业务库还登记为 DB12，正常运行要求 DB13。这两个问题分别处理，SDK 恢复和重复安装不能代替数据接续。

期限改为可省略字段，缺省运行值仍为1000毫秒。省略字段读取后继续省略；原确认哈希按原内容核验，绝不重签原账。明确保存其他期限时走原完整草稿和 CAS。此规则同样适用于原请求内的冻结配置。

## 接续流程

只支持 SM、原 schema3 配置、DB12 原基线 `620E0F1348806A739C86081232B05BCE62861EEFE28E7617769F6F15B481EABD` 及完全匹配的实际结构。SQL 固定在 `src/Ipc.Application.ParcelFlow/Storage/sm-db12.sql`，来自 DB12 原写入器；未知结构、其他版本、损坏身份或恢复隔离状态均拒绝。

原投递位仍为“停用中”时拒绝接续，保留原参数供核对，由维护人员先处理原放置和启停责任。DB12 没有当前轮次身份，不能让 DB13 的“无当前轮次”规则把旧停用中误判为包裹已移出。

1. 启动修复读出原参数，显示“先接续原数据”，暂不允许编辑保存和启动。管理人员明确点击接续入口，执行时核验管理授权。Windows 使用已登记同版维护程序和原授权委托，不绕过 UAC。
2. 持有真实 `application-owner` 停机租约，复制 DB/WAL、配置及原件到既有维护隔离目录；不在预览阶段打开原 DB。确认原件哈希未变化后，在私有副本上增加结构，并用当前 Repository 维护检查核验原配置、作业、冻结配置及原件。没有启动相机、SDK 或 RCS。
3. 展示接续计划，绑定原文件哈希和启动种子身份。执行重新取得停机及配置所有权，重新核验计划。数据变更、空间不足、权限失效或仍在运行时拒绝。
4. 在本站 `startup-maintenance/<操作号>/` 持久保管原 DB/WAL、配置账和启动种子及其清单。它是接续前原件保管，不冒充可换机恢复的完整备份；图片和回执原件仍留原位。
5. 一个 SQLite 事务中创建 DB13 的轮次表和索引、建立未知在位且自动抑制的相机周期、写接续及旧请求保管审计，再核验真实 DB13 结构，最后提交新身份和原结果。原作业、请求报文/目标、回执、防重、编号所有者和编号范围不重建、不重编号。
6. 事务提交前进程中断由 SQLite 回滚，仍需重新检查计划；原件保管留存。提交后回执丢失，按同一计划身份读取事务内的接续结果，不重复转换。没有跨配置文件提交：配置账和种子始终原字节保留。
7. 接续后重新读取参数；不会自动启动。维护人员核对原请求、设备和放置状态后重试正常启动。正常运行仍只接受 DB13，不增加 DB12 运行路径。

## 原请求、编号和物理边界

原请求的冻结内容、结果和编号是业务事实。接续在审计账中标记其身份，新版不发送或查询这些旧请求，也不通过原“不兼容请求清理”或历史到期清理删除它们。原 CommandId 返回原回执；新人工提交仍竞争当前轮次首次提交权，自动编号沿用原编号账的上界。

没有待落盘回执和图片责任的接续旧 Unknown 单独计为历史保管，不占当前轮次或真实在途，不阻止合法设置生效。原记录仍从记录页读取；实际待落盘回执、原图写入和身份冲突继续执行原守卫。这不是确认旧包裹已离位。

接续不证明旧包裹已移出，也不把旧作业伪造成新的当前轮次。投递位初始为未知、自动抑制，可靠空盘证据解除抑制；明确的新人工操作仍按当前轮次规则受理。重启及相机会话变化仍须按现规则校准；人工降级不是全自动验收。原未确认请求保留未知结果，不伪造完成。

## 必要验证

| 风险 | 定向验证 |
|---|---|
| 省略字段改变身份 | 原配置及冻结配置不含期限时哈希仍匹配，缺省为1000；修改内容仍拒绝；打开及保存未修改设置不补字段。 |
| 错版、伪造版本或结构 | 固定 DB12 SQL 建库，异常结构在写入前拒绝；普通当前读者继续拒绝 DB12。 |
| WAL、原账和编号 | 使用真实事务生成请求及回执，构造原 DB12 DB/WAL；接续前后逐行比较原请求、回执、CommandId、永久所有者/范围。 |
| 中断和结果未确认 | 子进程在提交前终止；重开仍为完整 DB12；提交后模拟回执丢失，从原事务回执收口。 |
| 升级启动 | 新指纹启动保留旧确认/Unknown，零重发；原 CommandId 零重发；同码新人工轮次仅一次调用且编号越过原上界。 |
| 读取失败页 | 原生 WPF 读取失败不展示空参数页，不提供保存；原目录、诊断和恢复入口保留。DB12 原参数可见且只读，接续前不允许保存启动；重新读取当前格式目录后，同窗口恢复检查和启动动作。 |

验证仅使用隔离合成数据和回环 RCS。开发电脑原账不执行转换；Windows 目标机覆盖安装/UAC 接续、真实双相机、客户 RCS 和现场持续运行须另行验收，未运行不得算通过。

# SM 运行观察、日志与受控执行

当前双程序功能归属见[双程序设计](sm-dual-desktop-operator-operations-proposal.md)。第一阶段基线为 main `c9fe4167547dfa83ca25eb21173745bfb361e22d`（#275～#282），其验证不能证明第二阶段控制能力。历史整合盘点和旧结果保留在 Git 历史，不再作为当前入口说明。

## 唯一运行所有者

每个有效部署只有工作站的原 Application/Host 持有生产状态、相机 SDK、RCS、业务数据库和原请求。安装的供包应用 EXE 在进入工作站启动流程前识别唯一参数 `--operations`，直接打开独立的 WPF 运维进程，只使用公共契约、IPC 和日志查询。视图程序集不创建业务实例。状态观察、登录及切页不取得调试工作区，不暂停生产。

## 独立的观察与控制通道

观察沿 `IParcelPresentationSource` 的有界最新快照订阅，只传运行总览 DTO，不传完整配置、凭据、图片或原报文。工作站普通设置摘要单独使用现场字段投影，只含原IP/序列号/相机编码/仓及生产线编号等现场值和去除用户信息、路径、查询的RCS主机；专业参数和历史原配置、原请求仍保持原授权投影。两个异步管道工作者，128 KiB 帧上限；每连接3秒，客户端连接/读取共2秒。保留原 Application 的单调发布时间，排空订阅、读取和刷新不续期；5秒无新数据即撤下实时值。未连接不代表停机，历史日志不能补成实时状态。

显式控制使用另一个 `.control` 命名管道及协议 v2，类型化代理和生成的固定分派清单；不接受任意方法名、程序路径或数据根。请求2 MiB，响应48 MiB（仅显式的原图等有界契约需要）；四个工作者、最多两个控制会话。每次命令新建连接，持续租约每秒确认，5秒未确认开始回收原会话。命令只发一次，回包丢失不自动重放；配置保存沿原候选和修订核对，维护沿原备份身份、目标及回执核对，原请求仍由原 Application 收口。在线完整备份响应丢失后仅核对冻结的原目标，不重新创建；目标当前存在完整集合不能冒充原命令回执。

双通道均使用 SID ACL、首实例独占及拒绝远程客户端；只提供 Identification 级令牌。双向核对受保护安装、实际进程路径、用户 SID、Windows 会话；消息绑定协议、安装身份、RuntimeId、请求号、PID及进程启动时间。工具只能从自己的当前登记安装解析目标。启动核对库存/程序/托管依赖；每次执行重新核对登记和权限，安装被取代立即失效。正式/测试实例各有登记、数据根、进程及 IPC 目标。

控制连接取得本连接的管理会话；请求携带发起时的授权身份，取得执行许可后核对本连接当前授权及其有效期，原服务执行时再次绑定该会话，排队旧操作不能借用新窗口授权。较早窗口只结束原会话，不撤销后来窗口。日志范围也归本连接，不能读取其他连接的查询句柄。协议帧完整读取后确认，半包、超时及未确认连接只结束自身。Windows管理员及同用户恶意代码注入不属于该本机进程隔离的抵御范围，库存哈希不是发布者签名。

## 调试会话和异常回收

明确进入设备调试后才由工作站取得原整站管理工作区，暂停自动供包、读码及人工提交，保留预览和原请求。现有能力不足以证明按位隔离，因此不新增按位承诺。会话关闭、断连或确认授权撤销时，服务端按原工作区身份取消本窗读取、等待真实调用收口并释放原范围。原软件暂停及投递位启停分别保留。授权服务通信未确认不能当作撤销成功；实际释放失败保留所有者、错误及清理重试，不报告恢复成功，也不关闭其他工作区。没有自动重发业务命令的路径。

## 日志和合法离线能力

日志中心的在线完整模式复用原 `SoftwareLogControl` 及日志服务，保留查询、时间/级别/来源/正则筛选、分页、原文/上下文、复制、导出、异常详情和业务记录关联；执行需要本窗管理授权。原日志模块继续正常产生记录。

无需管理密码的运行日志模式只枚举当前登记数据根中合法运行模式/站点的 sportmaster/diagnostics，使用原共享读取器；不读取数据库、配置账、认证日志、图片或机器安全目录，不授予导出发布。固定文件对象和长度/哈希、16 MiB单文件预算、10分钟查询寿命、200条分页、凭据脱敏、取消及完整性提示保持。主程序未运行或 IPC 中断时仍可合法读取同一范围，工作站启动不受此查看阻塞。关闭取消并等待本窗查询，释放文件句柄。

离线配置、备份、恢复、上一部署回滚、旧版本/记录清理及卸载通过原安装记录绑定的同版受保护维护缓存处理。工具先结束自身操作并退出，缓存等待该 PID/启动时间对应进程真正退出，再核验实际业务所有权。每项动作继续使用原权限、冻结清单、部署CAS、维护进度及未确认结果机制。IPC断线从不代替运行占用检查。维护后启动的是当前登记工作站，不从维护缓存创建生产实例。

## 同包安装与验证边界

同一安装包登记一个供包应用 EXE。菜单运维项传入 `--operations`，桌面工作站无参数。IPC 核对管道对端的真实进程映像及 Windows 命令行角色，再校验会话、运行实例和授权。覆盖安装更新旧运维链接，受保护的回滚库存按原格式保留，退役后沿原清理计划删除。桌面仅工作站；勾选开始菜单建立工作站和运维两项，未选中均不建立；安装完成默认启动工作站。程序文件使用权按部署范围与维护互斥，工具不持有生产业务租约；主程序退出但工具仍开时仍阻止删除正在使用的程序文件。退出/崩溃后核对实际锁，不能只看进程信号。完整安装器、Maintenance.cmd和启动故障修复入口继续可达。

跨进程测试使用真实Windows进程、令牌、命名管道、文件句柄及WPF窗口，设备与RCS使用明确可控边界。构建、静态检查、模拟业务、原生UI/PDA输入、受保护安装往返、厂商SDK、客户RCS和现场验收分别记录；不借第一阶段绿色CI或源码编译宣称第二阶段生产交付合格。

# MANAGEMENT-MODE-01 · 管理能力改为模式

2026-10-22用户纠偏：管理员不是另一个账号，而是防止操作员误改功能参数的管理模式。本轮以最新main `0bf86a0a588b75b95aa1963e8fe88dad976ca803`为基线；PR82～87已合并，核对无其他open PR，工作树清洁后建立`codex/management-mode`。SM1.10.2/c9e482a的发行和Windows/模拟/现场证据保持原身份。

| 裁决 | 范围 |
|---|---|
| 保留 | 普通模式只见作业和记录；管理模式开放参数、日志及按需维护；四类参数、同一完整候选、暂停/排空/CAS与保存/生效区别、原请求防重；受保护凭据、失败保护、撤权取消及审计机制；D盘存储。 |
| 改为模式 | 站点单一管理密码，进入/退出管理模式，15分钟自动退出；无用户名、人员角色切换或账号列表。操作员真实账号/免登录状态独立显示，模式进入、退出和修改密码均不改写当前或在途操作员身份。 |
| 删除 | 正常流程中的管理员账号开通、登录、增删启停账号、管理员身份/角色展示；不将固定隐藏账号当作模式实现。 |
| 兼容 | 原1.10.2已配置账号的部署要求用原凭据验证一次后明确设置统一管理密码；不自动选择旧账号或覆盖原凭据，不把Windows资格当作进入模式。原凭据只供转换及历史回退保管；新格式损坏或服务缺失拒绝受限操作。 |

MODE-01：只有管理模式激活时，Application/服务层才允许参数读取/编辑/导入/恢复/保存、日志查询/上下文/导出和维护。进入/浏览不暂停供包；退出/到期/改密码立即撤销受限工作，保留草稿但重新进入模式后才能继续。管理授权是独立会话证据，不是OperatorIdentity；参数审计同时保留操作员（如有）和模式会话。

MODE-02：首次设置密码采用现有安装维护批准通道，无默认密码；只存强密码哈希，不泄露凭据。原System宿主、服务登记及受保护根复用，不并建第二套权限系统。旧部署目录/SCM标识为兼容保留，不代表仍有管理员账号。管理密码修改需要当前有效模式，并撤销原授权。旧凭据转换仍执行失败锁定和不可覆盖守卫。

MODE-03：首配、保存核对、常规/紧凑页、共享业务窗口和异常提示统一改用模式；管理模式与操作员登录分别呈现。无有效模式不能靠旧页面或直接调用越权。配置保存的原业务条件不放宽。

必要验证：单一密码/无账号API、首次设置及不可覆盖、失败保护、改密码/退出/到期撤权、旧凭据转换、服务失效、操作员和在途身份不变、参数守卫和日志任务取消。受影响构建、原生WPF入口/确认/草稿及发布冒烟；不重复无关全量回归，不将旧PASS重标为新版本验收。

现行语义替代OPS-ADMIN-LOGS-01及旧V2/V3/首配中冲突的管理员账号要求。业务流程、配置归属、原合同和帮助支持删除保持。纠偏前当前指引保存在[原字节归档](../archive/pre-management-mode-01/README.md)；历史D/RV、发布介质及授权边界保持。

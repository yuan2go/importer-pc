# SM-TASK-FIELDS-01 · 作业卡恢复任务字段常驻

2026-11-01。用户要求：波次、任务号、商品编码、返回数量是现场需要的信息，必须在作业卡上常驻显示。基线 main `55e3def`（含 PR169），分支 `codex/operator-copy-industrial-02`。

PR169（SM-OPERATOR-UX-18）把这四项移进了“查看详情”。本包按现场要求恢复，替代 UX-18 中“波次/任务/SKU/数量进原作业详情”的条款；UX-18 的其他决定（实心格口、提示音、焦点目标、暂停撤下格口、小屏优先级等）不变。

## 实现

- 作业卡在格口结果区与操作按钮之间恢复 `TaskFields`：一行四格，“标签 + 值”内联，值可选择复制，悬停显示完整值。
- 显示条件与格口一致，绑定 `ShowConfirmedTask`：只有当前身份的有效格口、且未暂停/未失效时显示；处理中、拒绝、格口未确认、暂停、相机离线时随格口一起撤下，不显示上一件的值。
- 值沿用原 `TaskValue` 规则：回执缺失显示“未返回”，未取得任务显示“—”，状态中断显示“已失效”。保留前导零。
- 单行内联布局约占 22 DIP，尽量不压缩 800×420 下的格口字号。

## 测试

- `OperatorUx18`：由“任务字段离开作业面”改为“任务字段随确认格口常驻”。
- `StationLatencyUi`、`StationResponsiveUi`：由“TaskFields 不存在”改为“TaskFields 不可见”（处理中、拒绝时）。
- `TaskHierarchy02` 原有的可见性断言恢复有效。

## 验证边界

本环境无 .NET SDK，Windows 构建与 UI 验证 **NOT_RUN**。重点复核：`OperatorUx18` 在 800×420 下“格口实际绘制字号 ≥ 44 DIP”和“提交按钮在屏内”两项，以及 1366×768 截图中四个字段的截断情况。

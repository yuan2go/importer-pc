## 2. 已明确、已调整与仍未确认

已明确：Windows工位场景；本轮是设计文档，不改业务代码；下一任务要能真实实现与运行，不能仅交目录；公开材料必须检查权限；真实和模拟不得混淆。

初步设想中保留：四类责任；业务打包选择；业务可配套多个页面/布局；硬件实现可配置选择。经本轮修改：基座不做业务总控，服务不等于Windows服务，UI绑定是契约与交付绑定而非状态生命周期绑定；“组件”收敛为外部集成适配器；libs不是通用DLL倾倒目录。

本轮不采用的GPT扩展可能性：并非所有模块都动态插件化；不先做在线插件市场、复杂工作流、全量品牌驱动、强制设备进程、Web应用迁移或图像云存储。对话中无证据表明用户已否定某种.NET版本/框架，因此不虚构“用户否决WPF”等历史；以下运行技术是本次明确推荐的新参考产品选择。

未确认并保留：旧C#工程/发布库、设备型号/SDK、实体关联/联锁、数量/拆包、WCS副作用/幂等/查询、现场角色/换班和验收指标。它们不因框架建议而成为批准规则。

## ALIGNMENT-01 实施决定（2026-10-16）

- F-03/F-04/F-05落地：显式产品定义/工厂注册；Platform不判供包双通道或数量，通用观察契约不依赖Supply；只随产品安装已允许模块，缺能力拒绝。

- 有效客户区适配扩展到800×420 DIP，显式紧凑/自动单列与固定主操作；原tokens不倒改，Windows六种屏幕/缩放和焦点/扫码仍NOT_RUN。

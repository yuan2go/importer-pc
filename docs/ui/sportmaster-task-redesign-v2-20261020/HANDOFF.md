### 2.2 首次启动的五步

| 步骤 | 任务与主要信息 | 完成条件及失败处理 |
|---|---|---|
| 1. 业务模块 | 选择或核对已安装的独立 Application，并配置本模块条码筛选、请求数量、指定格口及应用队列/调用预算/作业容量 | 只有 Sportmaster 时明确固定显示。缺少必需组合或模块规则非法时就地说明；不把不同主流程混成通用流程开关。 |
| 2. 系统配置 | 区域、项目、供包台编码、本地工作站/目录及必要本机设置 | 同正式系统表单及校验；本地身份与 RCS 编码分开，错误保留其余输入。 |
| 3. 驱动配置 | 依据安装清单选择适用类型，为左右两位置分别配置实例、IP、相机业务编码及必要硬件参数 | 实例数由 Application 决定；缺失、重复绑定或硬件参数非法有具体对象说明。 |
| 4. 组件配置 | 配置唯一 RCS 连接、source/locale 与请求编号；只读核对系统/模块/实例来源 | 不重复编辑业务字段；当前协议未支持的远端探测/查询明确标示，不能用业务 POST 测试。 |
| 5. 检查与完成 | 完整关联检查、差异、保存范围、受控启动及运行确认 | “已保存”不等于启动成功；设备会话、收到条码、RCS 有效回应各有验证状态，真实链路未验不能显示通过。失败保留输入/候选，定位准确阶段。 |


目标 → 首次启动自动进入 → 按五步补齐同一候选 → 保存/启动状态可判断 → 错误定位、输入保留、按证据恢复 → 就绪后进入作业。首次配置未完成退出时可沿既有加密草稿续办；已配置站点的故障进入维护/恢复，不能以“重新首配”清空已有责任。此处的软件接收许可不是设备安全急停。

## 3. 每个相机框的三组固定信息

左右布局、位置名称和三组顺序保持稳定，两位独立更新。每一组解决不同的判断：相机信息回答“来自哪台设备”，扫描信息回答“这一包是什么”，任务信息回答“RCS 为这一包返回了什么”。

| 分组 | 主信息 | 次要信息和行为 |
|---|---|---|
| 相机信息 | 左/右位置、实例名称、连接状态 | 保留已认可的设备头部。可查看对应业务编码和设备身份；“已连接”只表达设备层，不等于已收到条码或业务成功。 |
| 扫描信息 | 本次唯一选中条码 | 相机原始候选先经 Application 筛选，保持前导零、原始顺序和重复条目；候选完整性、选码结论与规则指纹可查。无唯一条码时显示拒绝原因，不人工选码。 |
| 任务信息 | 本次目标格口 | 格口保持最大视觉权重；波次号 `waveNo`、任务号 `taskId`、SKU `skuId` 和返回数量清楚列示。空值和失败反馈占据原位置，不让布局跳动。 |

请求数量来自当前业务模块配置，响应数量来自 RCS。用户样例中前者是 JSON 整数、后者是 JSON 字符串；UI 不用请求数量补空响应，不擅自增加数量比较、拆包或逐包确认。尺寸和重量为 null 时不制造测量结果，也不据此增加包裹图片预览。

### 3.1 更新顺序及异常

| 状态 | 扫描信息 | 任务信息 | 下一步 |
|---|---|---|---|
| 等待扫码 | 显示等待本位相机；没有伪造条码 | 波次、任务、SKU、数量、格口均无上一件值 | 自动等待。 |
| 新条码已收到 / 请求处理中 | 显示新条码及来源 | 全组进入本次处理中，旧任务全部退出当前区 | 自动等待匹配回应，不重复提交。 |
| 有效成功响应 | 保持原条码 | 同一份回应原子更新格口、波次、任务、SKU及数量 | 按本次格口作业；“取得格口”不等于物理完成。 |
| 筛选未通过 | 本次候选与无匹配/多码/不完整/超时等结论可查 | 本次未请求 RCS；旧格口与旧任务不得继续显示为当前结果 | 检查本次输入与规则；不新增人工挑选、提交或重试请求。 |
| RCS 明确拒绝 | 保持本次选中条码 | 解释本次拒绝；没有成功格口 | 查看本次异常，执行 Application 允许的处置。 |
| 超时 / Unknown | 保留本次原件和原请求 | “结果暂未确认”，不把上件任务填回来 | 查看原请求/诊断。当前协议无查询能力时明确说明，不以重发代替查询。 |
| 相机中断 | 保留可确认的当前条码和来源；说明新扫描受影响范围 | 已知本次结果的保留/失效由应用事实决定 | 进入该实例诊断；另一位是否可继续由实际 Availability 决定。 |
| RCS 异常 | 已读条码与请求责任可见 | 说明哪几位受影响、哪些请求仍未知 | 诊断服务、查看关联参数；恢复连接不会自动清偿旧请求。 |
| 快照过期 / 状态失效 | 标明最后确认和过期 | 隐藏不可信投递结果，保留历史查看入口 | 读取运行状态/诊断。 |
| 新字段缺失、null 或类型不符 | 不改写扫描来源 | 缺项明确未返回或协议异常，不沿用上件值；旧记录标“历史记录未包含” | 按协议规则处理，详情可复制原技术证据。 |

原始相机观察、是否准入、当前作业及未决原请求分别保留。若新扫描未准入而本位仍有未决原件，当前“新扫描”不冒充原作业；原责任在异常详情与维护投影中仍可见。迟到、重复或错请求的回应不能覆盖新件或串到另一位。记录属于固定历史区域，不以自动滚动列表代替当前任务。

恢复接收沿 schema 3 的真实合同：容量与共享前提满足且至少一位 `PositionReady` 时可具备恢复资格；未知原件仍阻断本位，健康另一位可以恢复。全站共享故障和容量限制仍优先阻断。按钮读取 Application Availability，提交时由 `CanResume()` 再核验，不能把解除软件暂停等同两位同时准入或清偿原请求。依据 `src/Ipc.Application.ParcelFlow/ParcelGuards.cs:7–13`、`ParcelCommands.cs:81–82`。

## 4. 参数体系：分类、类型与实例

### 4.1 系统配置

系统配置面向当前供包台的**站点标识 / 数据与记录 / 本机偏好 / 维护与迁移**。`zoneId/projectId/stationCode` 按用户指定在系统中维护；请求策略和应用处理预算进入业务模块页。分类不改变底层唯一配置权威，普通本机偏好与运行相关参数仍采用不同的生效方式。

| 字段或能力 | 表单位置与控件 | 必填/校验与生效影响 |
|---|---|---|
| `zoneId` 区域 ID、`projectId` 项目 ID | 站点标识；整数输入 | 沿现有正整数 Int64 合同；用户例值不是默认。影响新请求上下文，保存完整修订后受控重启。 |
| `stationCode` 供包台编码（取格口） | 站点标识；文本 | 与本地 StationId 明确区分；整台唯一维护。旧左右值不同，迁移必须展示两值和目标差异。 |
| `StationCode` 工位编码（心跳） | 系统身份；独立文本 | 当前代码已有；旧值缺失时仅在编辑候选建议继承本地 StationId，保存且生效后才用于运行；RCS 心跳启用时非空、最长256、无控制字符。与取格口编码并列核对，差异不自动覆盖。 |
| 本地工作站/目录 | 站点标识与本机目录 | 展示本地身份，目录选择与迁移分开；不能借编辑 RCS 编码改数据库身份或目录。 |
| 常驻历史、磁盘保留、计划备份开关及备份 | 数据与记录/维护与迁移；带真实单位的数值与路径控件 | 保留当前元数据和实际范围；关闭计划仅取消后续调度，不删除原恢复集，条件字段不校验/不提交；完整备份与接管资格仍独立判断。 |
| 本机显示偏好 | 本机偏好；枚举/开关 | 沿既有用户偏好能力本机保存或即时生效，反馈明确，无需每次完整运行修订确认。 |
| 维护身份/原因、配置差异/审计、模板/备份/恢复、旧格式核对 | 维护与迁移及对应任务窗口 | 维护认证沿现有要求；技术内容按需展开，日常表单不要求编辑 JSON。 |

计划备份沿真实合同：关闭时保存 `BackupSchedule=null`；只有启用时才校验并提交目录、周期及保留份数。依赖输入可在保存前的编辑副本暂留，供撤销或重新启用使用；成功保存后以真实候选为准，不能把无效依赖值恢复成已保存设置。保存失败仍保留本次输入。原型的开关与平面内存字段不定义生产存储格式，关闭计划不删除已有恢复集。依据 `src/Ipc.Application.ParcelFlow.Desktop/StructuredConfiguration.cs` 的 `BuildBackup`。

### 4.2 业务模块配置

入口显示当前已装配的 **Sportmaster** 及其适用业务参数。这里配置本模块的运行规则，不选择、更换或重建 Application。首配可以核对已安装模块；日常业务模块页沿同一应用实例工作，不出现用来切换 Sportmaster/DirectPlc/WcsToPlc 主流程的下拉。

| 字段或能力 | 表单位置与控件 | 规则与来源 |
|---|---|---|
| `BarcodeFilter.Pattern` 条码筛选规则 | 条码筛选；规则文本和本地候选测试 | 复用当前 Application 的 .NET 整串匹配及 25/100 ms 预算；1–2048字符。旧空策略保持空沿用严格单码；已配置后清空是错误，不能隐式切成关闭。规则与样例改变即使旧结果失效。 |
| 请求 `quantity` | Sportmaster → 请求规则；正整数输入 | 当前合同为正整数 Int32；说明“请求数量”，不能写“相机识别数量”。返回数量仍显示 RCS 原响应。 |
| `specifiedChute`、请求 `chuteCode` | 请求规则；开关与条件文本 | 指定时格口必填；不指定时完整候选省略原 chute-code 键，请求 chuteCode 序列化为 null。保留未参与发送的草稿须清楚说明，不能偷偷提交旧值。 |
| 应用输入队列容量 `queueCapacity` | 处理预算；整数 | 当前 Application 输入容量，区别于单台驱动的回调队列；沿应用校验与满载行为。 |
| 全局调用超时 `timeoutMs` | 处理预算；带 ms 单位的输入 | 属本 Application 的调用预算，不改称单相机或单 RCS 连接超时。 |
| 未清偿作业容量 `maximumOperations` | 处理预算；整数 | 沿现有业务语义与范围，不改称线程数或并发量。 |

业务模块、系统、驱动和组件四类共同编辑同一完整候选。模块页修改请求规则后，组件页的只读预览必须来自同一草稿/生效来源，并能明确区分二者；保存、CAS、排空与受控重启仍为统一闭环。

### 4.3 驱动配置

进入驱动分类首先看到已安装且适用的类型，选中类型后列出它服务当前 Application 的实例。Sportmaster 在同一海康类型下显示“左位读码相机 / 右位读码相机，已配置 2/2”，每个实例有独立连接与状态；没有全类型 IP 输入，不能用一次编辑暗改两位。

驱动可声明类型配额，但具体实例数量由 Application 决定；海康类型上限 8 不意味着 Sportmaster 能保存 8 个运行相机。当前业务两个位置完整时不显示泛化新增主按钮；首配通过缺失的业务位置补齐实例。更换类型/设备是受控编辑，不改一项名称就更换稳定身份。

| 实例页分组 | 字段 | 规则 |
|---|---|---|
| 业务对应 | 左右绑定、相机业务编码 `bcrCode` | 属当前 Application 的实例业务映射，不覆盖已声明的心跳 bcr-code 参数；编码与实例一起查看和迁移。 |
| 心跳对应 | `bcr-code` 相机编码（心跳） | 当前 Hikrobot 1.0.3 已有第6参数；RCS要求所有绑定读码实例提供，最长256、无控制字符、按Ordinal比较不能重复。与取格口 bcrCode 独立，不自动同步。 |
| 设备连接 | `device.ip` 相机 IPv4 地址 | 必填、规范 IPv4、最长15；无默认，不修改设备自身 IP；错误可定位并保留其他输入。 |
| 设备身份 | `device.serial` 预期序列号 | 可选、最长32；稳定 DeviceId、实例 ID、实际身份可查，运行内身份迁移沿原机制。 |
| 输入与实体 | `entity.mode` 实体关联策略 | observe-only / trigger；现有默认 observe-only，仅观察不能准入。trigger 不是配置硬件触发的开关。 |
| 解码 | `code.encoding` 条码字节编码 | utf-8 / ascii，当前 schema 默认 utf-8，严格解码。 |
| 高级容量 | `queue.capacity` 回调队列容量 | 整数1–1024，当前 schema 默认128；区别于业务模块的 Application 输入队列。 |

上述真实 schema 来源于 `src/Ipc.Drivers.Hikrobot/parameters.json`。端口、曝光、口令及复位没有此驱动的字段依据，不沿用 V1 演示端口。高级组可折叠但可搜索/定位，不能藏在层层菜单。对象切换保留草稿，错误与未保存标记跟随实例，不把左位校验反馈画到右位。

### 4.4 组件配置

组件分类按已安装且适用能力显示；本轮只连接一个 RCS 实例，左右两位共用它。连接页维护服务地址、source/locale、精确实现与版本，高级组维护请求编号区间，连接组维护已安装组件的心跳间隔（默认5秒，1–3600秒）。心跳工位及左右相机编码只读引用各自对象，不能以检测按钮触发新心跳。系统的站点 ID/供包台编码、业务模块的请求规则及驱动实例的相机业务编码在组件页只读汇总，并分别提供“前往系统配置/业务模块配置/对应实例”的定位，不再重复编辑。

服务地址沿 HTTP(S) `/rcs/sorter/api` 的现有规则，禁止凭据/query/fragment；请求编号沿原独占区间及溢出验证。协议的 version/index/command 只读，`requestId` 由原请求准备/持久编号机制生成，不成为操作员每包输入。未安装、已安装不适用、无参数与连接不可用分别表达；不会为了占位显示可点击却无行为的连接测试。

### 4.5 旧配置迁移与单一权威

迁移先展示原对象、旧字段、新位置、新值和适用 Application，再进入同一完整草稿。区域/项目从原 RCS 参数迁入站级业务上下文，请求规则迁入当前业务模块，bcr 从左右键映射到对应 Reader 实例，供包台编码只有旧左右值相同时才能无歧义提出合并；冲突保留原值等待明确处置。UI 层字段搬动与底层契约升级必须一起完成。

新请求使用生效配置的冻结上下文；旧未决请求保留原 payload、target、prepared bytes、合同与包版本，不能随编码/IP/组件修改重写或重发。省略的默认值、未知兼容字段和敏感引用原意保留。模板白名单继续限制可迁移内容；把字段移到“系统”不自动获得模板导入资格。

## 5. 编辑、保存、生效与连接检查

对象表单改变编辑范围；底层仍保存经过整站关联校验的完整 `ParcelConfiguration` 修订。状态区显示编辑基线、已保存候选、运行确认/是否未知及本次变化对象，不虚构三套独立版本计数。普通对象切换留在同一草稿；可能覆盖输入、重读或关闭时才需要离开处理。

| 状态 | 必须表达的事实 | 操作与失败闭环 |
|---|---|---|
| 未修改 | 当前对象、基线与实际运行确认 | 保存禁用且说明没有改动；仍可查看适用诊断。 |
| 编辑未保存 | 修改对象和字段数，保存范围 | 撤销仅撤本次编辑；其他对象和运行不受本地撤销影响。 |
| 正在校验 | 当前候选及关联对象 | 保留输入，局部忙碌；新异步结果只能匹配原候选。 |
| 字段错误 | 字段附近中文原因，摘要可跳首错 | 非法文本保留，不自动改0、不清空表单。 |
| 关联冲突 | 冲突双方、路径及待解决原因 | 可跳相关对象；重复绑定或站码迁移冲突不能以全局“无效”带过。 |
| 正在保存 | 正保存完整修订，运行状态独立 | 防重复提交；维护认证、原因、软件暂停、排空及 CAS 沿原要求。 |
| 已知写入前失败 | 明确尚未保存与原因 | 草稿保留；按原因修复后再保存。 |
| 保存结果待核对 | 不能确认是否已写入 | Stage 后的普通 Rejected/异常也可能已落盘；以规范化候选指纹和原配置账核对，核对前不重复提交。 |
| 已保存待生效 | 已保存候选及“待受控重启”，实际运行仍单独列示 | 可离开；提供变更摘要和既有受控启动路径，不宣称连接已切换。 |
| 正在应用 | 对象、阶段、整站影响及待确认部分 | 软件接收保持真实阻断，不能以进程已启动代替所有资源就绪。 |
| 应用失败 | 失败阶段及可确认运行事实 | 分清旧配置已确认、已停止和运行未知，不能默认回滚成功。 |
| 离开未保存 | 继续编辑 / 保留草稿离开 / 放弃本次编辑 | 保留原输入；持久草稿沿加密机制，原型内存模拟不冒充跨进程保存。 |
| 恢复默认/上一有效 | 差异、范围和真实来源 | 仅有声明默认或有效证据时提供；形成新候选，再校验、保存、受控生效。 |

当前运行参数为 Restart，定向重连不应用 Pending。Effective 内容存在不能单独证明资源已启动或允许供包；匹配的启动确认、当前健康及业务准入各自判断。

连接检查显示“哪个对象、运行值还是编辑值、检查到哪层、时间、下一步”。地址合法、传输可达、设备会话、收到条码、RCS 有效业务回应分别列示。测试编辑参数不保存、不应用、不发 `dest_request`；不存在安全探测契约时显示相应层未支持/未验证。海康 Probe 会取得资源，不能在运行旁抢占设备；当前 RCS Health 包含本地生命周期及最近心跳 HTTP 交付/失败证据；2xx 仍无心跳应用确认，当前 Query=false。检查按钮只读已有证据，不能另发心跳或业务请求。重连、查证原请求、确认报警已阅和恢复接收语义分开。

## 6. 主要按钮的任务契约

| 按钮/操作 | 对象与启用条件 | 执行中 | 结果与失败处理 |
|---|---|---|---|
| 编辑实例 | 已安装适用类型下的确定实例 | 加载该实例草稿，标清来源 | 对象标题/字段/绑定一致；加载失败保持原对象，说明原因。 |
| 检查修改 | 当前完整候选有可检查内容 | 局部校验中，防重复 | 字段/关联结果可定位；不保存或启动。 |
| 保存修改 | 满足维护资格的完整候选 | 保存中，列变化对象 | 待生效、已知未写入或结果待核对分别反馈。 |
| 查看变更 | 草稿或待生效候选 | 读取比较 | 旧值/新值/对象并列，秘密只显示变化事实。 |
| 撤销本次编辑 | 有未保存内容 | 本地还原 | 仅作用说明中的对象/本次草稿，不回滚运行。 |
| 检查连接 | 有明确对象和安全支持层 | 标目标、输入来源与层级 | 失败定位相关字段、保留输入、可复制技术详情；不以测试顺便保存。 |
| 受控重启/应用 | 原应用资格与待生效候选满足 | 阶段与整站影响可见 | 读取真实确认；失败保留候选并展示可确认运行状态。 |
| 核对运行状态 | 应用结果不明或当前运行内容未知 | 只读核对启动与配置确认 | 可能确认旧/新运行、已停止或仍未知；不保存、不重启、不应用，Pending和软件暂停保持。不能在没有证据时断言旧配置仍运行。 |
| 查看本次详情/异常 | 当前或选中原件身份明确 | 局部加载 | 对象固定，扫码不改动作目标；失败保留上下文。 |
| 查看原请求 | 原请求存在 | 读取本地证据 | 当前 RCS 没有结果查询，不把查看按钮接业务 POST。 |
| 恢复接收 | 原应用返回可恢复资格，状态与窗口可用 | 等待确认 | schema 3 容量与共享前提具备且至少一个位置就绪即可解除软件暂停；提交时再核验，未知原件仍单独阻断所属位。不代替安全联锁。 |
| 查询/导出记录 | 筛选合法且固定快照完成 | 查询/导出本范围 | 空结果说明条件；失败保留旧快照，已选详情不漂移。 |
| 首配上一步/下一步 | 当前步骤状态允许 | 校验相关内容 | 原输入保留，步骤回退不改已保存配置。 |
| 首配完成 | 完整配置和启动状态满足相应资格 | 保存/启动阶段分开 | 转入作业并显示真实许可；失败回到准确对象/阶段。 |
| 导入模板/恢复 | 文件、版本、Application 及证据满足 | 预览差异/隔离恢复 | 先改草稿或隔离副本，不自动开放业务/重放请求。 |
| 导出诊断摘要 | 时间范围合法且预览有效 | 导出已审阅内容 | 文件和范围明确；失败保留预览，不上传或扩大采集。 |

仅在会影响操作判断的位置显示禁用原因。耗时操作不阻塞整页；后台轮询不抢键盘焦点、不重置输入/选择/滚动，验证错误和忙碌不会把固定操作栏挤出可视范围。

当前配置/数据字段详见 [迁移表 CSV](data/ui-v2-field-migration.csv)与[同内容 JSON](data/ui-v2-field-migration.json)，共 **54 条**；原截图字段/状态的逐项去向见 [V2 overlay](data/ui-v2-original-field-overlay.csv)，共 **58 条**。这些数字是字段/状态条目数，不是页面、截图或设计文件数量；图像和文件数量以本版索引及清单为准。

## 8. 视觉规格与 Windows 实现

主方向为克制浅色、固定左右、较大作业结果、紧凑准确的参数表单。相机头部沿既有识别方式，组间用清楚的标题和分隔建立层级，不堆嵌套卡片、装饰徽章或持续动画。字体、颜色、尺寸的最终数值以同版 `source/styles.css` 为准，WPF 在原有 ResourceDictionary/标准控件上落实，不以更换技术栈为前置。

### 9.2 任务走查要求

本表是 V2 验收目标，**执行结果只以 V2 的实际 QA 记录为准**，不能把此前 V1 的通过记录记为本版通过。

| 核心任务 | 一次有效走查应覆盖什么 |
|---|---|
| 左右连续作业 | 左新扫码/右成功、左等待/超时、迟到回应、下一包、缺字段；三组信息对应同位同包，旧任务全组清出，另一位按实际影响更新。 |
| 修改指定相机 | 驱动类型 → 右实例 → IP/bcr；切左再返回不串对象、不丢输入，变更摘要只含实际修改，数量由业务规定。 |
| 校验错误并修正 | 非法 IP、站码迁移冲突、指定格口缺值；首错可定位，其他输入及非法原文保留，修正后正常继续；业务模块规则变化同步出现在组件只读引用，不能改到系统身份。 |
| 判断保存/生效 | 保存成功待重启、明确未写入、Stage 后结果未知、CAS冲突、应用失败与运行未知；确认来源正确、不重复提交。 |
| RCS 异常处理 | 从作业进入带对象诊断，看清验证层及影响；无查询能力明确，原请求不重发；恢复后回到同位作业且保留未决责任。 |
| 离开未保存 | 继续、保留、放弃的作用范围清楚；普通对象切换留在同一草稿，覆盖输入/关窗有保护。 |
| 首次启动 | 空配置自动进入独立五步，各步必需输入可填写并校验；只显示安装适用项，两相机单组件；未完成续办，完成后日常导航没有首配。 |

这些流程同时检查六项商业质感：重点、组织、密度、状态、连贯性、真实显示。复用现有受影响验证，补必要迁移、回复字段、并发/恢复和防串包场景；不为增加数量重建重复套件或镜像实现测试。Windows 实机按实际分辨率/缩放/客户区 DIP/输入方式记录正常、长字段、异常与弹窗；真实相机/RCS/现场资格独立记录。没有编造耗时或改善百分比。

### 9.3 优先级与少量待确认

P0 完成三组作业关联、四类配置单一归属、左右实例定位、首配生命周期及保存/生效可靠性；P1 完成原功能迁移、诊断/记录/备份/支持与同版原生质量收口。二者均在本轮完整实施范围，不以 P1 为由遗漏必要任务。

集中待确认仅限实际外部条件：目标工控机/DPI/输入；新增回应 quantity 的后续业务含义及新增字段缺失时的精确协议处理；实际旧左右 stationCode 存在冲突时的目标值，以及心跳/取格口编码是否应同值；真实驱动触发/身份资格与 RCS 联调证据。波次/任务/SKU需要显示、参数分类与字段归属、双驱动实例及单组件连接已明确，不再重复要求用户选择。

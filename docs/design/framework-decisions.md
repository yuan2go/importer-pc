# 当前框架决策

本表保留F编号，规定当前职责；不重写外部D批准和RV验收状态。[框架](framework.md)给出机制与守卫。[整理前原文](../archive/pre-contract-convergence-02/README.md)保留C/R/L来源、初始方案、增量决定与引用原件。

| 编号 | 当前决定 | 边界 |
|---|---|---|
| F-01 结构 | 模块化单体，基座机制、业务所有权、UI投影、端口与显式装配 | 不引入无依据分布式总控 |
| F-02 技术基线 | C#/.NET10/WPF/SQLite/Windows x64，继承既有获授权实现 | 不宣称旧现场迁移或设备验收完成 |
| F-03 业务与多UI | 一个业务实例供多个页面/布局使用，业务单一状态所有者 | 页面不拥有连接/发送器，切页不重发 |
| F-04 选择时机 | 构建选择业务和精确依赖，配置激活受控；SM只用内置MVS＋软件识别/RCS | 其他允许业务的外置扩展继续支持；不任意热插 |
| F-05 驱动 | 能力、实现、实例与角色分开，来源/回调/epoch/设备租约明确 | 同码不等于实体，采图不等于识别 |
| F-06 文件加载 | 内置模块受安装与SDK字节身份校验；外置扩展在其适用业务验证精确闭包、签名与独立信任 | SM不要求外置目录或配置签署；ALC不是崩溃沙箱 |
| F-07 进程 | 默认桌面进程内运行；SM使用进程内软件识别 | 不无依据强制每驱动独立进程 |
| F-08 通信 | 显式应用命令、设备事实、带版本快照；执行时守卫复核 | UI不直控硬件；当前可用性不改写已接受事实 |
| F-09 持久化 | SQLite持久意图、原始回包、独立接收责任和事务证明；原请求固定身份 | Unknown不盲重发；拒绝旧格式并保全原件 |
| F-10 配置 | 唯一完整候选及配置账，CAS/Pending/Effective，资源成功后确认 | SM保存自动有界静默等待；不另建扩展配置权威或手动暂停前置 |
| F-11 当前业务 | SM、DirectPlc、WcsToPlc各自Application；参考业务独立 | SM无PLC，真实规则依证据，模拟不授予生产资格 |
| F-12 交付验收 | 真实SQLite/边界验证，精确发布身份，必要构建与启动冒烟 | Windows/SDK/客户协议/现场分开，未运行写NOT_RUN |

管理模式、机器运行身份、D盘存储与原请求责任适用于相应执行入口。恢复、安装、修复、卸载和日常运行各守权限，不以新建目录、改包版本或重写配置绕开旧责任。实现变更在开发分支分批验证并通过main PR交付；CI保持用户指定的停用状态。

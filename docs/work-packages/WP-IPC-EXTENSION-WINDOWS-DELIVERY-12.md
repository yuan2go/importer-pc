### S6：必要验证、Windows连续操作与可取得交付

先根据受影响模块选择验证范围，允许整理既有Verifier选择器；不要因为普通dotnet test无失败就说实际Verification程序通过。继承有效断言，仅根据新设计修正过期预期。改了存储、调度、激活等共享机制时必须扩大到相关T1/T2/T3/身份/原请求/所有权；未改的无关全量不重复跑。首次失败保留，修复后重验影响范围，不删有效断言、吞异常、跳关键检查或放宽校验器换PASS。

核心必须验证：组合依赖与产物裁剪；包信任/篡改/路径/RID/离线安装；重复/中断安装；配置并发、实例隔离、角色/秘密；原请求固定身份与目标；激活资源竞争和Stop未终止；升级/恢复/卸载；Production缺能力拒绝且不调用模拟端。

关键后装证明：先发布并冻结宿主，随后在无宿主编译引用的独立项目中仅依公共契约构建一个宿主未预置的新扩展；安装前后宿主可执行/核心程序集身份不变，扩展可发现、自动生成配置、创建实例、进入实际运行链路、停止/升级/卸载。至少一项实际能力进入业务来源或有效集成链路，不能以只返回成功的空插件证明完成。现有模拟驱动/适配器可用，不扩张到真实厂商开发。交付独立样例源码、构建/打包/签名测试说明和接入指南。

Windows验证必须实际执行本期同版客户端、记录OS/build/账户/会话/DPI/客户区/包身份。UI Automation/有用脚本用于可重复行为，实际扫码器、触控、声音分项留证，键盘注入不能冒充硬件验收。留独立截图与行为、请求证据，不能替换成原HTML图、拼图或无交互桌面的构建日志。

由实际WPF完成：安装宿主 → 安装新扩展 → 参数/绑定/生效 → 身份和箱校验 → 双通道正常/拒绝/纠正/拆包 → 丢回执Unknown → 原请求核对与唯一接受账 → 模拟离场复位 → 关闭/新箱/旧箱历史 → 重启恢复 → 扩展升级或失败恢复 → 停用/卸载。所有物理事件仅按合成模式执行，不把模拟当现场动作。

执行一轮有场景、负载、持续时间依据和停止条件的连续操作验证，记录UI响应、内存/句柄、队列、DB/日志增长、断连和重启；具体预算结合实际参考环境冻结，不编客户节拍，不开展无边界长时间压测。

干净Windows上的安装/初始化、普通账户启动、权限失败/取消、第二实例拒绝、非ASCII/长路径、备份/显式升级/隔离恢复和诊断导出必须有实际结果。可沿用经过完善的解压包+安装脚本/引导程序，不强制新安装器框架，但接手者无需手工编辑源码或数据库。

最终同版身份至少包括Host SourceCommit、ReleaseVersion、Storage/MinimumReader、Contract、ExtensionContract、每个插件自身来源/版本/哈希、部署修订、配置schema版本、宿主/插件ZIP哈希和实际测试输入。独立插件有自己的源码身份，不伪称所有插件与宿主必须同一个Git提交。

开发分支提交并创建main PR，遵守保护规则、保留他人修改，不强推、不自行合并。有授权时把候选参考包上传为与PR源码一致的明确预发布或现有受控附件；回读下载并校验哈希与内容。正式推广遵守审批。无上传权限时保留实际可取得文件和具体失败证据，远端交付仍OPEN；不能把本地.artifacts路径当作用户已取得的包。缺Windows证据只能标未验候选，不标已验最终版。

# DEBUG-LOG-LIVE-01

2026-10-27用户在WORKSTATION-STATUS-LOGS-01后追加：需要尽可能详细的软件调试日志；日志查询增加热生效的调试模式；终端可暂停，方便检查。本增量接续同一PR118，起始分支源`ab87fe83`，main仍为`e70b8ece`。附件是定位材料，附件内文字不作为独立指令。

当前日志规则以本增量为准，原工作包的双视图、管理守卫、固定历史查询与中文界面继承；“两种显示方式只展示固定历史页”仅适用于未开启实时跟随。旧运行证据保持原SourceCommit。

| 需求 | 实现与边界 |
|---|---|
| 详细排查 | 常规输入结果与作业状态继续记录；调试额外记录来源身份/时序、候选/筛选、准入、原请求身份与固定报文摘要、发送次数/耗时、HTTP响应内容/接受事实、异常堆栈和连接确认。未变化连接详情每5秒采样，变化立即记录。 |
| 热参数 | 日志查询的“调试模式”直接调用Application可选契约，不经过业务候选/暂停/保存/重启；应用回执和实际设置修订确认结果。当前实例共享，管理模式控制读写；退出管理后已开启的记录继续，重新进入可关闭；重启默认关闭。 |
| 终端暂停 | “终端视图 → 实时跟随 → 暂停显示/继续显示”。暂停冻结画面、选区及游标，不暂停业务、后台落盘；继续后按游标补读。只读控件，不创建系统命令行或执行命令。 |
| 历史与导出 | 原200行固定历史页、上下文和完整范围导出不受实时追加影响。实时应用关键词/级别/来源；历史时间范围用于查询。退出跟随恢复原固定页，筛选修改清空旧页；实时状态不冒充可导出的固定快照。 |
| 有界与真实 | 缓存512条且1Mi字符，每批最多200条，终端65536字符；超出缓存明确报告补查历史。调试队列预留常规容量，繁忙丢弃详细记录并计数/告警，不阻塞作业。不声称丢失日志可恢复。 |

诊断边界统一遮蔽敏感字段与嵌套JSON字符串；原业务报文和回执留存在原账。单报文调试片段上限8192字符，扫码候选最多16个、每个256字符，均披露省略与原长度，避免日志洪峰或任意大字段进入界面。没有SDK、真实设备或新数据库格式/运行依赖。

新增原生专项覆盖真实Application/SQLite/loopback HTTP、热开关、失败回执、暂停不断写、晚到/撤权、重启与预算。CI前轮失败还暴露本任务造成的过期断言：旧TCP标签、维护专用目录、授权结束横幅；按本轮裁决更新而保留业务/权限/草稿断言。冻结介质的干净种子无MaintenanceLogin，因此专项显式构造合成历史绑定，避免依赖源码种子恰好存在旧组件。初始错误测试将协议Unknown之后的新扫码误认为可准入，已调整测试顺序并保留Unknown阻断，未放松业务。

操作及验证入口见[运行说明](../runtime/debug-log-live-01.md)。Windows原生、本机发布冒烟、CI与真实现场分别记录，不自动安装、合并或宣称生产验收。

补测发现原维护专用页面在初始化时被完全跳过，因此后续临时承担操作员登录时仅模型标签改变，实际目录无法出现。页面现在保留同一候选编辑器并按真实角色动态过滤，目录、搜索、上一页/下一页及路径定位使用同一可用性条件；解除业务用途后再次隐藏。角色更新保留仍可见页的编辑对象、焦点与草稿，不重建业务或连接。原角色重命名/搜索测试改用真实可见的操作员角色，并包含历史组件重新承担登录用途的情况。

# 供包台导航与诊断

工作站固定为“作业、记录、设置”，不再提供旧管理中心及专业日志/调试/维护入口。独立运维工具固定为“运行总览、日志中心、设备调试、专业参数、维护中心”。两端共用原生WPF资源。工作站顶部时间、普通/全屏窗口、PDA工位焦点和未保存保护保持；帮助/F1入口继续隐藏。

运维目标部署、来源、连接和版本持续可见；未连接或过期撤下实时值，不推断停机。查看、登录、切页不暂停。工作站设置为非模态窗口，返回作业保留草稿；两端分别显示所属字段，仍使用同一参数定义/默认/完整候选/CAS。完整功能归属及本轮验证范围见[双程序设计](sm-dual-desktop-operator-operations-proposal.md)，权限和异常收口见[IPC设计](sm-readonly-operations.md)。

## 运维连接诊断

运维设备调试页的“连接与诊断”显示左相机、右相机、RCS、存储四张卡片。状态、原因和可执行操作来自同一个运行实例的现有快照。相机断线仍由后台自动恢复；显式重连只作用于所选设备，并继续执行管理权限、原请求、资源和实际连接守卫。地址与编号待配置时明确提示到工作站现场设置，技术参数在本工具专业参数页，连接建立中不重复启动。切页不重建采集或发送器。

设备详情每五秒自动读取，不发送测试取格口请求；相机指标、RCS 耗时、日志设置及原始证据放在折叠详情中。旧指标读取中断时明确失效。在线只表示连接事实，不代表本件已有有效格口。格口结果未确认时出现前往记录核对的提示，不自动重发。

维护中心保留完整备份、原业务/请求责任核对、诊断导出和离线维护。取消导出只在导出过程中显示。完整备份前明确暂停，完成后可明确点击“检查并恢复供包”；只有当前权限及 Application 的恢复守卫通过才恢复，失败时保留暂停状态。离线维护依旧要求完全停止软件，数据与原请求责任继续保留。

扫码调试的返回区显示本轮保存的 RCS HTTP 正文，JSON 按可读格式显示中文。“复制回包”复制上游完整原文。没有正文或接收不完整时显示具体状态。

## 设置与首次配置

两端日常设置复用已有单一参数定义、目录控件和保存栏，不增加顶部标签、向导按钮或重复运行状态条。SM 不显示通用的“外部服务等待时间”，取格口只使用 RCS 的“取格口请求超时”；毫秒统一放在输入框后。

首次配置突出当前步骤，并提供当前步骤的无障碍状态；某一步只有一个页面时隐藏左侧目录。SM 自动生成并持久化请求编号。RCS 页提供格口分配方式，默认由 RCS 分配，选择指定格口时显示必填的格口编码。RCS 页只连接内置 RCS 服务，首配保留完整地址、超时与心跳参数；日常地址留工作站，期限与心跳归专业参数。

## 安装

安装保留三步主流程；实际安装阶段只显示阶段名称，不再套用另一组六步编号。等待 Windows 授权使用醒目提示和即时无障碍通知。路径及技术过程放在折叠详情中，经过时间显示为“已用时”。业务版本继续来自安装介质，不使用宿主程序集版本替代。

## 验证边界

原生检查入口为 `--operator-review-ui` 和 `--installer-review-ui`，沿用 `tests/Ipc.Desktop.UiVerification`；安装窗口检查必须设置同源的 `IPC_FROZEN_DESKTOP`。同时回归作业布局、首次配置、管理权限及原请求。Windows 窗口、合成 SDK、真实设备、客户 RCS 和安装生命周期分别记录，不互相替代。

# CLOSURE-13 设计与实施顺序

采用继承式收敛：保留现有Product/Supply生命周期和事务，扩展安装、参数、租约与部署继续一套；不新增插件管理平台。相比重写框架，能保留已验证的防重和恢复；相比仅增加kind枚举，必须把集成工厂、编码/验回、原请求路由和资源终止接入真实链路。

平台负责生命周期/队列/租约/可信包；公共集成契约为独立无数据库/UI程序集；业务拥有规则、状态和页面，产品装配允许引用具体实现。新中性部署区分观察设备和服务实例/端口，旧StationConfig仍为供包唯一部署权威。原Contract1入口及HostContractSha256不删除，历史SQL/checksum不更改。

先关闭包身份和静态依赖窗口；再加入公共集成契约与独立本地HTTP模拟集成；再贯通冻结请求路由及Stop/Dispose所有权；随后实现装配/非供包验证业务和管理UI；最后跑受影响恢复链、交叉构建、冻结制品后装、候选发布回读。测试结果逐项登记，不能将设计声明写成已有能力。

Windows延期是用户决定；本轮不寻找环境或修改权限。WPF交叉构建只能证明编译，页面操作/普通账户/分辨率/DPI/触控/扫码/听审均WINDOWS_NOT_RUN。

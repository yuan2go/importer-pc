# SM 运行状态日志

普通日志应能回答：何时开始或停止供包、谁或哪条业务守卫改变了准入、左右位正在处理哪件包裹、有没有发出原请求、为什么当前不能继续。无需先开启调试模式。日志只是诊断证据，业务库及原请求回执继续承担最终业务事实；查询和导出不改变业务。

每条 Application 运行日志使用 `ImporterPc.RuntimeLog.v1`，带 UTC 时间 `At`、运行实例 `RuntimeId`、实例内递增 `Sequence` 和单调耗时 `ElapsedMs`。同一实例内用序号和耗时排查墙钟调整及异步通知先后。关键事件包含供包状态、管理中心、投递位启停和作业阶段，不再只看识码或 RCS 报错。

暂停入口传入实际触发原因：操作员主动暂停、窗口空间保护、创建备份、进入历史清理、进入离线维护或应用待生效配置。调用方没有提供原因时明确记录缺失，不把所有暂停都归为操作员点击。状态快照同时记录经过本次心跳核验的小车号和状态，缺失或过期时留空，不沿用旧的空闲提示。

| 记录 | 用途 |
| --- | --- |
| 供包台状态变化 / 状态快照 | 启动、控制动作后及变化时记录；稳定状态每30秒记录一次，导出中间时间段也能找到状态基线 |
| 供包命令开始 / 结果 / 异常 | 按命令编号核对 Pause/Resume 的请求、CAS冲突、拒绝、提交或结果未确认，不把点击等同于成功 |
| 软件暂停状态已记录 | 写明暂停前后、业务事件、命令编号和操作者；来源与暂停状态在同一 SQLite 事务提交，重启后快照仍带来源 |
| 管理窗口切换开始 / 完成 / 未完成 | 按窗口身份区分管理围栏和软件暂停，关闭后写出实际恢复状态，不把“恢复原状态”解释为一定可供包 |
| 投递位启停 | 保留命令、原模式、实际模式、操作者、原作业及放置标识；停用中自动完成也有记录 |
| 输入处理完成 | 关联相机、连接周期、观察、帧、全部候选及筛选、受阻原因和作业；重复输入按5秒汇总首尾时间、帧和次数，变化立即记录 |
| 作业阶段、开始请求格口、取格口结果 | 用作业、采集身份、原请求编号、协议请求编号串联；记录冻结目标及报文哈希、尝试次数、回应和耗时，保留 Unknown 的核对责任 |

状态记录的 `State` 用于判断当时准入：全局软件暂停和来源、管理窗口身份、启动/停止阶段、配置修订、配置确认、恢复/容量/维护守卫；每位包括启停模式、相机与人工两条来源的准入及阻断原因、连接周期、相机确认、自动识码策略、当前输入/作业和未完成原请求。`Evidence` 提供观察及帧身份、时间、放置保持和空托盘计数；连接确认时间和原始诊断在 `Dependencies`。状态变化哈希排除不断变化的帧号与健康确认时间，避免每帧输出整份状态。

复盘先按 `RuntimeId` 分班次，找到目标时间之前最近的状态快照，再按序号应用后续状态变化、命令结果、输入及作业事件。识码成功只说明产生候选，输入 Admitted 才说明创建业务；Dispatching/尝试次数及原请求记录用于核对发送责任，Unknown 不能当作未发送。软件暂停、管理窗口围栏、投递位停用和 RCS 离线识码暂停是独立事实。实际图片绑定观察或原作业，不能按条码猜配。

`Journal` 带丢失计数及写入故障；序号缺口、轮转造成的时间段缺失或写入失败必须保留“不完整”的结论。每位原责任列表最多16条，同时给出总数；超出时查原业务记录。快照中的原责任长条码、目标和错误片段带原字符数及截断标记，完整内容查对应输入、请求及原业务记录。没有历史暂停来源时 `PauseOriginKnown=false`，不得猜测来源。`DevicePortsReleased` 只说明设备端口停止已确认；`ApplicationOwnershipReleased=false` 明确提示应用独占所有权仍未结束，不能把停止快照当作卸载准入。快照只证明记录时刻，稳定周期之间没有记录不能证明包裹离开或资源已释放。凭据继续经过同一脱敏边界，条码、请求编号及现场状态不作为凭据隐藏。

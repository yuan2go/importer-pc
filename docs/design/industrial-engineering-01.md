## 1. 产品目标与成功口径

目标是让新人知道当前能做什么、故障时怎样安置包裹、怎样取得帮助；让实施人员可以独立完成可追溯的安装、配置和退役；让开发者能用同一套命令证明变更没有破坏原请求和恢复边界。

“一页纸装好、配好、开始作业”需要明确两类读者。供包员不承担 Windows 管理员、IP 规划、相机序列号、RCS 合同和凭据准备。供包员一页作业卡覆盖日常使用；实施人员一页部署卡覆盖安装到首件，两张卡引用同一本不超过20页的实施手册。不能靠把必需准备工作藏到计时开始之前制造30分钟达标。

| 指标 | 定义与目标 | 证据要求 |
|---|---|---|
| 新人完成旅程 | 未用过产品的实施人员，凭一页部署卡，在已备妥授权安装包、D盘、Windows权限及合法站点参数的机器上，30分钟内完成安装→首配→首个明确结果→卸载 | 分别记录准备耗时、主动操作、机器等待、求助次数；模拟和真实设备分组，不能相互替代 |
| 安装操作量 | 普通新装3个主界面，主要决定≤5项；升级/修复保留原根且不重复首配 | UAC另计系统确认；异常、目录冲突、风险确认不隐藏，单独记录 |
| 卸载 | Windows管理员发起一次任务，默认保留数据、备份开启；不依赖业务密码和原安装包 | 正常无占用矩阵无需重启；异常占用如实返回需清理/3010 |
| 故障可行动 | 每个当前可见故障码都有原因、影响、一个首选动作、包裹处置及升级条件 | 自动检查代码覆盖；动作是否安全仍需评审和现场验证 |
| 安全 | 已修复介质中没有共享恢复密码及其验证器，旧入口不能调用；所有旧管理会话撤销 | 服务边界负向测试、升级/备份恢复/降级测试及部署覆盖清单 |
| PR质量 | 目标为每个PR自动构建、核心回归和结果发布，核心必跑数量不得为0 | 本轮仅设计，现有Actions仍停用；实施阶段变更与分支必需检查一起交付 |
| 软件响应 | 安装、测试连接、导出与停止均异步且可见；预算到期不伪报终态 | 原生WPF输入/取消验证；阈值作为设计预算，在目标IPC校准 |

时间、点击量是体验指标；安装完整性、权限、实际设备身份、未决责任和未知结果保护是放行条件。体验达标不能抵消这些条件失败。

## 2. 必须继承的现行合同

1. C#/.NET10/WPF/SQLite模块化单体，继承既有四层职责。Platform提供部署、权限、诊断机制；Application拥有状态和守卫；UI只调用正式应用契约；驱动/适配器只提供事实。一个Application服务全部页面，不另建连接、权限账或业务账。
2. SM使用内置MVS采图、进程内软件识别、内置RCS，无PLC。模板只改变合法草稿，不引入TCP端口、MvCodeReader或外置扩展资格。每台相机的实际IP、物理序列号、唯一相机编码必须由现场填写；取格口与心跳使用同一映射。
3. 最新main的[SM-SAME-PLACEMENT-29](../archive/work-packages/WP-IPC-SM-SAME-PLACEMENT-29.md)优先：连续采集、逐帧观察仍存在，同工位同一次托盘放置只请求一次RCS。空托盘规则、不同码和显式人工提交沿原实现；不在本包重新发明实体去重。
4. 相机自动业务与人工键盘/PDA分别准入。人工输入不以相机存在/在线/编码为前提；RCS、容量、原请求及身份冲突守卫继续有效。无相机模板不等于模拟运行。
5. SM当前没有日常“暂停/恢复”按钮；普通导航为作业/记录，管理模式开放设置/日志/调试。本包不因指南中的旧措辞恢复这些按钮。内部停机、测试隔离和保存屏障沿现行合同。
6. 四类参数编辑同一完整候选。草稿、待生效、正在使用的配置分开；沿当前main批准的规则，纯条码规则及已配置相机/RCS的连接参数在条件允许时立即生效，仅重新连接受影响设备。未确认请求、维护/调试读取、启停设备或混入其他设置时退回保存后重启。保存执行时检查授权、CAS、在途和原责任；配置生效不代表设备连通。
7. 相机、RCS允许暂未配置，但缺哪个能力就拒绝依赖它的业务。RCS空地址表示待配置，有地址必须完整；不用的相机IP/序列号留空，不再加一个“稍后配置”开关。
8. Unknown/Conflict固定原请求、目标、合同和报文字节；当前内置RCS没有权威结果查询合同。查看记录不能改称“查询成功”，重新放置不获得重发未知原请求的资格。
9. 全部项目、程序、业务数据、缓存、维护临时数据使用D盘。已有受保护根从HKLM读取。D盘不可用给出可行动错误，不静默落到C盘，不用链接绕权。现有机器级服务/OS登记的路径另按管理员政策核验，不能把D盘目标说成已全面迁移。
10. 当前数据格式以同源清单和实际读取器为准，基线SM为Parcel12；不提供通用旧格式转换。此前获准的特定升级各守原身份，不扩展为任意降级/回滚。REQ/BR/CAPI/D/RV和历史验收不倒写。

## 3. 关键设计决定

| ID | 决定 | 原建议的调整 |
|---|---|---|
| IE-D01 | 以Windows管理员授权、本站确认和受保护服务复核重置管理密码 | G采用这一条主方案；不同时上线随机恢复码和供应商万能恢复入口 |
| IE-D02 | 默认保留现有安装事务内核，增加统一交互和静默前端 | A3不能绕过原计划、CAS、回执和Unknown；A10不把整套EXE事务简单塞进MSI自定义动作 |
| IE-D03 | 程序回退只切换经过兼容证明的二进制；不回退业务数据库 | A5遇到格式、凭据协议、SDK或安全下限不兼容明确禁用 |
| IE-D04 | 卸载程序、清理残件、永久删除数据是三个任务 | A6允许管理员移除程序并保留未决责任；A8永久删除不能用“仍然卸载”清偿责任 |
| IE-D05 | 维护helper来自受保护缓存并在D盘独立目录运行 | A7不使用可被普通用户替换的任意%TEMP%；普通清理优先无重启，异常如实报告 |
| IE-D06 | 连接检查按配置、传输、采集、识别、协议和业务接受分层 | B2的“已连通”不能成为“可作业”或一次隐式试发格口请求 |
| IE-D07 | 一个受限诊断导出和一个普通概览导出，均本机保存、不自动上传 | C1/C3的一键求助交付为“导出/复制交接信息”；发送他人需用户明确指令 |
| IE-D08 | 提供轻量“使用帮助”，复用现有诊断和版本入口，不恢复旧支持服务 | 本轮C3为新的目标设计；旧“删除帮助”仍准确描述基线实现 |
| IE-D09 | 现场手册和故障目录由同一版本化源生成，开发证据独立索引 | D不立即批量搬走证据或改写Git历史；先做清单、授权、可用性及链接验证 |
| IE-D10 | 测试先接入标准发现，再按风险迁移真实行为用例 | E2不以“启动整个控制台且退出0”的一层包装宣称逐用例发现或产品覆盖率 |
| IE-D11 | 正式发布签名、数据兼容与可恢复性分别设门禁 | A1/F不能把签名等同SmartScreen信誉、安装成功或现场资格 |
| IE-D12 | 分阶段收紧格式/分析器，只禁止新增技术债，安全修复优先 | E3已有TreatWarningsAsErrors，继承；避免首次全仓格式化掩盖缺陷修复 |

## 4. 统一状态和命令契约

复用既有应用契约及MaintenanceExecution，不另建通用工作流引擎。下列名字是待实施的逻辑字段，不声称已有同名API。

每个可能产生持久副作用的命令至少绑定：OperationId、动作种类、Application/Installation身份、目标根、ExpectedRevision或登记指纹、计划指纹、调用主体和授权代次。接收确认、持久提交和最终完成分别表示；客户端超时不能新造OperationId重复执行。

| 对用户状态 | 技术事实 | 允许下一步 |
|---|---|---|
| 等待检查 | 尚未生成可执行计划 | 填写/测试/取消 |
| 请核对后继续 | 已固定本次影响、目标和授权要求 | 明确提交或返回编辑；修改后原计划失效 |
| 正在处理 | 尚可在声明的安全点取消 | 请求停止，并等待真实释放 |
| 正在完成 | 已越过不可逆提交点 | 只读进度；关闭界面不等于取消 |
| 结果待确认 | 提交可能发生，终态证据不足 | 核对同一操作；不再次安装、删除或发送 |
| 已完成 | 权威回执与实际事实满足该动作完成定义 | 打开普通入口/定位文件/退出 |
| 还需处理 | 已退役、有残件、备份或启动失败等明确事实 | 保留原操作，显示具体补救；不显示笼统成功 |

授权在服务真正执行和提交前复核。只读核对不依赖已被卸载的业务服务，仍要求对应Windows授权。管理会话失效时撤销受限读取和未提交动作；已提交事实保留，新的会话不自动接管旧委托。

## 5. 风险、依赖和取舍

| 风险 | 控制 | 不能承诺的内容 |
|---|---|---|
| 固定恢复验证器跨站复用 | IE-D01、旧RPC拒绝、凭据代次撤销、受保护安全下限、发布覆盖核对 | 无法凭删除源码使已安装旧程序失效 |
| 卸载/回退逃避Unknown | 保留责任账和退役标记；回退兼容矩阵；永久删除单独门禁 | 不承诺端到端恰好一次或无条件恢复生产 |
| 提权路径被替换 | 受保护缓存、独立信任、公钥身份、实际句柄/路径及ACL检查 | 不把自带SHA清单当独立信任 |
| 连接检查触发调度 | 默认仅只读证据；有副作用测试另走现有隔离和明确发送 | 不编造RCS ping/Query/试单接口 |
| 导出泄露数据 | 字段允许清单、内容遮盖、大小时间预算、权限分级和本机确认 | 脱敏不等于取得对外披露许可 |
| 发布/CI成为提权通道 | PR无签名密钥，可信发布重建、最小权限与受保护环境 | 不让不可信PR进入现场runner或生产网络 |
| 设计一次覆盖过多改动 | 安全→生命周期→体验→质量/发布的可独立验证切片 | 不以一次大PR、全仓重排或MSI重写作为前置 |

外部依赖包括正式发布者主体/证书或托管签名资格、现场Windows管理权限、受支持OS及硬件矩阵、合法SDK交付资格、真实RCS合同/测试环境、技术支持联系方式和现场取放确认。缺少它们不阻止编写代码和合成验证，但相应生产/发布门禁保持未通过。

## 7. 外部依据与适用边界

以下官方文档和OWASP指南于2026-11-03读取；具体方案是本项目根据现有权限、状态和部署模型作出的工程选择，不代表第三方对本产品的认证。

- SmartScreen按下载信誉判断，因此正式签名之外仍需在真实下载渠道验收提示行为：[Microsoft Defender SmartScreen](https://learn.microsoft.com/en-us/windows/security/operating-system-security/virus-and-threat-protection/microsoft-defender-smartscreen/)。
- Windows访问令牌用于服务端身份和权限核对：[Access tokens](https://learn.microsoft.com/en-us/windows/win32/secauthz/access-tokens)。
- 密码存储采用随机盐及慢哈希；本项目已有PBKDF2实现，详见安全设计：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。
- Restart Manager旨在减少重启，不能保证所有占用均可解除：[About Restart Manager](https://learn.microsoft.com/en-us/windows/win32/rstmgr/about-restart-manager)。
- 静默参数与重启语义参考Windows Installer，EXE需自行实现兼容契约：[命令行](https://learn.microsoft.com/en-us/windows/win32/msi/standard-installer-command-line-options)、[退出码](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes)。
- PR和签名发布分离、动作固定提交及最小权限：[GitHub Secure use](https://docs.github.com/en/actions/reference/security/secure-use)。
- .NET10支持两种测试平台，应显式选择，避免混用参数造成无效报告：[dotnet test](https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-with-dotnet-test)。
- MSIX需评估提权、服务和数据访问适配，不可视为现有EXE的无成本外壳：[Prepare to package a desktop application](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-prepare)。

# SM 正式与测试实例同机边界

业务版本均为 1.0.0。`--test-instance` 在构建时确定测试身份，程序、机器政策、密码、配置、数据库、个人偏好、维护登记、快捷方式、WER 和恢复任务各自独立。

## 目录和维护

测试程序位于 `D:\CainiaoSupplyStationTest`，数据根位于 `D:\ProgramData\ImporterPcTest\data` 内，受保护根固定为 `D:\ImporterPcTest`。正式构建拒绝使用这些测试区域及其父范围，包含备份与恢复选择。测试构建还只读核对正式受保护登记，保留其当前和上一部署的目录所有权，避免旧正式部署恰好位于测试保留区域时被接管。

检查解析现有祖先的实际目录身份，拒绝链接；8.3 短路径和 `..` 不能绕过。登记读取、离线维护读账、程序回滚、旧文件清理和数据永久删除均复核边界。已存在的交叉归属明确失败，保留原登记和数据，不自动迁移。

测试维护范围始终限制在自身上述三个区域内。即使正式登记缺失，手填启动修复的配置路径也不能读取正式配置后再写入其种子；不以“另一实例未登记”推断目录空闲。

测试版的备份、完整集交付、原图/诊断导出及部署日志须位于 `D:\ProgramData\ImporterPcTest` 内。建议备份使用 `backups`，交付使用独立子目录；原有业务目录排除规则继续生效。正式版拒绝选择测试区域。备份列表在核验候选和生成删除身份前检查归属，因此另一实例已关闭、没有 WAL 的业务库也不能被当成可删除的孤立备份。测试版不消费共享备份，避免两套独立恢复账无法互证引用。

## 专属测试设备

允许真实测试相机及测试 RCS。另一实例保留的启动种子、各站点当前格式配置账的 Effective 和 Pending 均作为资源保留证据；停止、停用或保留数据卸载不自动出借其中的设备。已明确删除数据的登记不再保留设备。检查只读配置，不打开业务库、不改变原配置确认哈希。

- 相机身份读取在创建 SDK 前检查 IP，枚举得到序列号后再次核对；采集在初始化及打开句柄前复核 IP 和序列号。命中另一实例时拒绝。
- 每次实际打开相机同时取得两套已安装实例原机器租约目录中的序列号锁，可协调尚未更新的正式客户端已有锁。按目录排序获取，部分失败释放已取得的锁；释放失败保留所有者并报告，不伪报成功。访问另一套租约目录的权限不足时拒绝打开，不自动修改权限。
- RCS 配置按主机和端口排除重合；发送前重新读取保留证据，实际建连接时解析双方地址，核对 IPv4、IPv6 映射及 DNS 别名。使用刚核验的地址建连接，禁止第二次隐式解析。测试连接不保留跨请求池连接，避免继续使用旧解析目标。
- 新生产请求在持久首次尝试之前的资源许可阶段执行一次检查；真正发送前再次核对。已经开始的原请求保持原编号、报文、期限和真实结果，不改投新地址、不重发。

另一实例登记、配置或机器政策不可读、损坏、超出读取范围时，保留原证据并拒绝相关设备操作。检查无法判断未登记设备、未配置的生产服务器、NAT 后端或人工代理的真实用途；专属测试网段及现场资源清单仍需现场核验。同机磁盘、系统运行库和计算资源继续共享。

## 验证和交付

核心测试分别按普通身份和 `TestInstallation=true` 编译运行，覆盖双向目录拒绝、祖先/历史范围、独立外部文件区域、Effective/Pending 保留、相机序列号及双目录真实文件锁、RCS 地址别名。应用验证使用可控 SDK 创建点和传输入口，确认拒绝发生在 SDK 枚举、网络传输和删除意图创建之前。CI 单独保存测试身份的 TRX，避免普通构建结果冒充测试构建。

源码修复不改变已经交付的 `28ef1d2c` 安装包。正式与测试包均应从包含修复的同一来源构建后进行验收。仍需在隔离 Windows 上执行完整安装、首次启动、两个启动顺序、各自升级/回滚、保留数据及删除数据卸载、提交前/后中断恢复，核对另一实例目录、SCM、计划任务、快捷方式、WER、密码和原请求未被改写。真实相机和客户 RCS 单独验收。未签名和策略阻止保持真实状态，不绕过系统策略。

# 作业卡状态与现场验收

本文写 SM 双工位作业卡现在的行为，以及在真实工控机上验收“看得清、操作快、不误导、易恢复”的方法。状态由 Application 的业务事实和准入投影；行为变了直接维护本文。

## 阅读顺序

每个工位卡片从上到下：工位名和小车提示（相机连接在底部）→ 当前条码（输入框）→ **结果区**（状态符号 + 状态文字，下方是格口号或原因）→ 下一步 → 波次、任务、商品、返回数量 → 提交 / 查看详情。

- 结果区始终回答“现在该做什么”。取得格口时格口号是全页最大的字（按可用窗口连续缩放，6/16/更长字符基准分别为72/44/28 DIP，上限112/72/48 DIP，先换行再适配）；没有本次有效格口时显示原因；轮次结束撤下本件操作归属；首次成功显示起3秒内、下一件尚未开始时，可显示明确标注的上一件摘要和当前扫码资格。
- 状态用文字表达，颜色辅助识别。需要符号的结果区使用成功 ✓、需处理 !、未确认 ?、处理中 ◷。已确认的 RCS 业务拒绝使用与等待投包一致的浅灰居中布局，深红标题显示接口消息，完整条码显示在输入框，结果区不重复显示条码摘要。
- 左卡永远是左工位，右卡永远是右工位；一个工位的故障先显示在本卡，顶部只加一句摘要（如“左位相机离线，可手动输入”）。

## 当前轮次状态

作业卡只消费 Application 的 CurrentRoundId。条码、正式候选、图片、格口和任务字段须同轮；成功结果首次显示起计时3秒；旧轮结束、下一件尚未开始时，独立显示“上一件格口·仅供查看”、原条码和任务号，并显示当前“等待投包/可人工扫码/等待下一车/受阻原因”。它不回填条码输入框，不开启上一件图片、详情或提交操作，不延迟真实准入；新轮开始或当前新车的新码已读到时立即清除，即使输入尚未持久受理也不显示旧格口；读码提示不授予提交权。迟到回包不生成该摘要，重复刷新不重置计时。暂停、停用或快照失效时以当前状态为先。

| 状态 | 显示与允许动作 |
|---|---|
| 等待投包/扫码 | 没有可信上件且无码时正常等待，可 PDA/键盘提交，不创建虚假超时 |
| 正在识读 | 默认1000ms的同轮窗口，调整多码/非法码不续期，可原位补录 |
| 识读异常可补录 | 说明尚未请求 RCS；连续同件可靠时安全续读，否则可PDA；视觉无法确认移出时提供本轮取下按钮 |
| 正在获取格口 | 本轮条码和原请求；不重复提交，可信移出仍可结束本轮 |
| 格口已取得 | 本轮格口及任务。纯人工/视觉降级确认后3000ms撤下展示，已接单仍等待下一车；可靠在位按真实移出结束 |
| 等待取下确认 | 视觉不可靠异常可点击本轮“已取下包裹”；可靠空盘自动完成，不重复确认 |

可信空盘与有效换车并行结束旧轮。同车未外呼或有无副作用确证时，取件后真实恢复可投；已接单等待下一车，Unknown及副作用不明拒绝显示“请求待核对”，只影响相关位。旧回包、计时器、按钮、图片及人工草稿不覆盖新件。等待投包由Application真实准入决定，相机不可用而人工可用时显示“相机不可用，可人工扫码”。

## 输入与节奏

点击卡片或 F2/F3 选位，PDA/键盘沿用同一本位输入通道。人工提交持久接纳后返回，本位忙碌不锁另一位。编辑草稿与已提交码分开，连续A/B不拼接，重复回车不重新使用旧展示码。原命令结果不确定时查原 CommandId，不盲换命令重发。

成功3000ms恢复不证明物理离开；持续原包的自动来源仍抑制。可信取下再上件或一次新的完整人工提交才开始新业务，同码新轮允许。相机与人工在同轮共用一次提交权。详见[当前轮次契约](sm-parcel-rounds.md)。

输入决策、RCS实际调用及轮次时长分开测量，阶段P95不能相加。默认1秒识读含放稳实际等待，不能被慢解码或新候选刷新；无可信上件的降级路径不倒推期限。两种相机方式的真实性能及物理证据可靠性分别现场验收。

## 现场验收

请没有参与开发的操作员，在真实工控机、实际 Windows 缩放和实际站位下完成。记录第一次停顿、看错、重复点击和开口询问的位置，这些就是下一轮的改进点。

| 场景 | 做法 | 通过标准 |
|---|---|---|
| 第一眼 | 打开软件后直接问：哪个工位要处理、格口是多少、下一步做什么 | 约 3 秒内答对 |
| 看清格口 | 在实际站位量出能看清格口号的最远距离；分别看 100% / 125% / 150% 缩放 | 实际站位能看清；记下最远距离 |
| 连续供包 | 左右各连续放 20 件，含同一件放着不动、拿走再放；记下“单帧识别耗时”和“取格口耗时” | 有可信物理证据时自动流转；证据未知时可人工提交；同一轮不重复请求；可信移出后回到“等待投包”；放上到出格口的等待操作员可以接受 |
| 新旧切换 | A 取得格口后可信移出，再放 B | B 出结果前看不到 A 的格口 |
| 扫码枪 / PDA 连扫 | 快速连扫 A、B；用 F2/F3 切换工位后再扫 | 不拼接、不丢失、不落到另一工位 |
| 相机断开 | 拔左相机网线 1 分钟再插回 | 只有左卡提示；右位照常；插回后自动恢复，不需要点击 |
| RCS 停止 / 超时 | 停 RCS 服务；再让 RCS 响应慢于“RCS 请求超时” | 未送达与未确认分开显示；未确认不自动重发；记录页可查到本件 |
| 重启 | 正常关闭再打开，分别核对仍占位和已离位的未决请求 | 直接进入作业页；仍占位保留原守卫，已离位且收口的历史只在记录可查 |

结果按 AGENTS.md 分开记录：Windows 实机、真实 SDK、客户 RCS、现场验收，没做的写“未运行”。

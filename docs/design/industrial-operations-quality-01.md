# 工业化操作、诊断、文档与质量设计 · IE01-OQ

状态：目标设计；不把现有能力重复列成待重做项目。基线和全量追踪见[IE01](industrial-engineering-01.md)，实施/验收见[工作包](../work-packages/WP-IPC-INDUSTRIAL-ENGINEERING-01.md)。

## 1. 首配与连接检查

### 1.1 五步首配与安全模板

继续沿用现有独立五步首配及首配/日常共享配置模型。步骤的具体字段依当前实现及后续增量，不以本设计重新移动字段所有权。场景选择嵌入已有首步，不增加第六步：双相机、左位相机、右位相机、仅人工输入/设备稍后接入。场景名只说明计划使用来源，不自动创建设备身份或启用Simulation。

系统/业务/驱动/组件四类仍编辑同一完整候选。模板继承StartupSiteTemplates允许名单与同源身份规则；新增内置场景模板仅填合法拓扑意图、通用容量和已批准码制策略。真实IP、物理序列号、唯一相机编码、仓ID/生产线ID/供包台编号、RCS端点/凭据不能从另站复制或作为示例默认写入。更改模板显示差异并保留已填真实字段，覆盖须明确选择；不得默默清空另一位配置。

未使用相机IP/序列号均为空，部分填写定位错误；实际相机编码的取格口/心跳映射共用一处。RCS空地址为待配置，有地址就全量校验。新站日志/已结历史默认7天、窗口启动模式沿现有字段，不把场景模板变成第二份配置账。

完成步显示能力清单：各位是否配置/成功采图、RCS是否配置/有何种协议证据、配置是否已保存/待生效/正在使用，以及哪些来源当前允许作业。例：“左相机已采图；右相机未配置；RCS尚未配置——请先配置RCS”；不能据一台相机绿勾显示“可以开始供包”。

末步仍唯一“保存并打开作业”；只读回草稿不显示完成。已保存但启动失败留原账、提供准确修复入口。打开作业后Application按来源判断：RCS有效且人工准入条件满足时可人工输入，左相机就绪仅授权左位自动来源；所有能力未配时可查看界面但不能发请求。

### 1.2 分层检查与副作用

复用同一Application内的设备资源所有者。配置编辑器不直接创建SDK连接，不让测试抢走正在运行的设备租约。

| 检查层 | 能证明什么 | 界面文案与动作 |
|---|---|---|
| 字段/格式 | 完整候选合法，尚未接触设备 | “填写完整，可以检查连接” |
| 网络 | 指定目标的有限网络检查结果；ICMP失败不必然离线 | “网络检查未完成，请检查本机网卡和目标地址” |
| SDK/设备 | 实际SDK字节/ABI合法，IP与序列号绑定，租约可用 | “已找到相机；序列号一致”或准确冲突原因 |
| 采图 | 在本次连接代次取得有效帧，时间与格式明确 | “已采到图像”；不能叫“扫码成功” |
| 识别 | 本次帧的独立软件识别事实 | “已读到条码/未读到条码”，不推定实体或RCS接受 |
| RCS传输/协议 | 当前配置下某种获准协议的真实响应 | 写明“连接已建立”“心跳已响应”等实际证据，保留时间 |
| 取格口业务 | 原独立请求的明确业务结果 | 只在已授权业务/调试发送中产生，不能由连接检查伪造 |

内置RCS若没有专用无副作用探测合同，就显示“该接口不支持独立业务测试”；可展示已有真实心跳证据，不能自行POST一个假条码、发明ping/Query、把HTTP任意返回当可供包。管理员需要实际试单时跳转已有按轮调试、明确发送一次，并保留原请求责任。

候选测试结果绑定CandidateRevision/指纹、设备身份、连接代次、开始/完成时间和证据层；字段变更立即标为旧结果，测试不会保存或激活候选。正在使用同一连接时复用只读快照；需要独占试连的候选先通过Application测试屏障和明确影响确认，不能双开SDK。释放失败保留资源故障，不让下一次测试覆盖。

设计预算：普通网络/连接检查单项10秒、整次30秒，实际SDK若无法安全取消则显示“正在等待设备释放”并保持owner。异步命令防重入；取消请求、取消完成和超时分开。网络不通、序列号不符、SDK缺失、权限不足、被占用和无有效帧分别给下一步。预算由目标IPC实测调整，不通过超时后遗弃后台任务制造快速成功。

## 2. 作业提示、会话和使用帮助

沿现有主题、TYPOGRAPHY-01、左右位结构及最新作业字段。信息优先级为：当前有效格口或本件异常→当前条码/必要任务→设备辅助信息。不得为加入帮助/统计挤掉任务字段，或降低关键字号。普通模式不增加管理功能常驻导航。

### 2.1 故障目录与可行动提示

建立有版本的结构化故障目录，由Application/适配器先输出类型及上下文，Presentation根据类型取文案。逻辑字段为Code、ProductScope、Severity、Cause、Impact、ParcelAction、PrimaryActionId、RequiredAuthority、EscalateWhen、ManualAnchor、EvidenceFields。多种原因使用类型化子项，不能所有异常都归“设备不健康”。

保留既有CP-UNKNOWN等字符串编号，不强改成数字码导致历史无法定位。安装/维护错误码使用自己的稳定命名域，退出码是进程层结果，不替代故障原因。文案同源生成软件文本与手册；主句/按钮/小号可复制故障码分别呈现。未知异常提供通用安全提示和诊断ID，不吞掉原因，也不直接显示敏感原文。

| 状态 | 主句与包裹处置 | 首选动作 |
|---|---|---|
| 格口结果不明 | “格口尚未确认。请将包裹暂放一旁，保留本条记录。” | 查看本次记录；无Query合同不显示“查询/重发” |
| 明确未送达/被拒 | 按当前类型说明原因；保留原记录，新放置仍需原准入守卫 | 展开现场动作；允许时取下后重新放上，不能用于Unknown |
| 相机断线 | “左相机已离线，左位自动识别暂不可用。” | 检查左相机；人工输入是否可用由Application另判 |
| 未读到条码 | “托盘上未读到条码。”保持中性色 | 空托盘直接放件；有包裹则条码朝上或人工补录 |
| 存储不足 | “记录空间不足，当前来源不能受理新包裹。” | 查看存储；不建议删除未完成记录 |
| 配置待生效 | “更改已保存，正在使用原配置。” | 按实际资格安排重新打开；纯规则热生效显示真实结果 |
| 安装结果待确认 | “安装可能已完成，请先核对本次结果。” | 核对本次安装；不再提交一次 |

首选动作必须保持原对象上下文、权限及Revision，禁用时显示原因。可读性不能靠把所有状态改成一个“重试”按钮实现。自动重连只恢复设备连接，不代发任何业务请求。

### 2.2 续期与引导

复用管理模式已有最后两分钟续用逻辑，在标题附近提示“管理模式即将退出，未保存输入会保留”，提供“续用15分钟”。不弹阻断模态、不抢条码焦点、不倒计时播报干扰每次识别。撤权与草稿边界见安全设计。

首次普通进入作业页最多4个可跳过提示：看本位当前格口；没有格口先看本件提示；查看记录；需要改设置时进入管理模式。不介绍当前不存在的暂停按钮，不自动进入调试或发送测试请求。提示只在非忙碌安全时显示，首次真实条码输入/结果到达即收起，不遮格口、不改变键盘/PDA输入目标。状态保存在本机Windows用户的展示偏好中，帮助里可重新打开，不改业务配置。

本轮目标新增轻量“使用帮助”，放在标题次级菜单/现有关于入口：一页作业卡、部署卡、故障手册、诊断导出和版本详情。普通模式只读非敏感内容及概览包；受限诊断需管理模式或独立Windows管理员授权。文档离线可读、随包同源，支持联系方式只有在取得真实批准资料时显示，不填虚构电话或邮箱。不恢复旧支持摘要服务、自动上传、聊天后台或新导航大模块。

### 2.3 原生交互验收

使用现有WPF控件、主题和命令机制；局部异步操作可采用现有等效命令，不为套用skill引入整个MVVM框架。按INotifyDataErrorInfo语义关联字段错误；Tab/Shift+Tab顺序、Esc返回、默认按钮安全、屏幕阅读标签和焦点复位明确。不能依赖颜色/悬停读出失败原因。

测试标准/紧凑及既有最低客户区、100%/150%/200%系统缩放，长条码/长中文原因/展开项/大字体/多窗/过期权限。用原生Dispatcher、输入和实际截图记证；HTML原型与网页检测不能替代WPF验收。本次只设计行为，未生成或验收新版原生画面。

## 3. 一键诊断与支持交接

### 3.1 分级与内容

诊断包不等于备份，不含可直接恢复生产的数据库。默认用户选择目录后本机生成zip，显示内容摘要和敏感级别；完成后提供定位文件与复制交接说明，不主动发送邮件、上传云端或调用支持接口。

| 内容 | 普通概览 | 管理/Windows管理员详细包 |
|---|---|---|
| 产品版本/ReleaseId/commit、包校验摘要 | 是 | 是 |
| 当前故障码、非敏感健康概览、时间/时区 | 是 | 是，附各层事实与证据时刻 |
| 24小时日志 | 否，避免越权读取日志 | 固定截止时间、受限来源、字段遮盖 |
| 配置 | 无站点目标/身份等敏感字段 | 仅明确允许字段；不复制完整JSON后靠正则补救 |
| 安装/维护回执 | 非敏感终态摘要 | 脱敏只读投影，不含批准票据或完整路径身份秘密 |
| 磁盘/网络 | 容量、网卡状态摘要 | 按需允许的本机接口/目标检查；不扫描网段 |
| 数据库、原报文、图片、dump、凭据 | 默认不包含 | 仍默认不包含；另走明确授权证据流程 |

所有层级排除密码、密码哈希、恢复材料、会话/委托、私钥、认证头、连接串、URL查询秘密、完整业务条码及未经许可现场图片。无法可靠投影的文件直接不收集；配置未知字段默认排除。IP、序列号和人员/包裹标识按类别遮盖或包内一致代号化；详细原值不能以“已脱敏”名义自动加入。

安装服务不可用时走独立维护只读入口，验证受保护安装身份和Windows管理员，不降低到普通文件夹读取。普通概览不能成为日志权限旁路。

### 3.2 一致性、资源和失败

逻辑Manifest记录包schema、生成器版本/源、起止及截止时间、时区、授权级别、每项来源/状态/大小/SHA256、截断/缺失原因、遮盖规则版本和错误。多个来源不是同一事务快照，必须给出各自时间，不能把拼合包称为一致性备份。

默认取固定截止前24小时，日志按现有轮转读取器获取稳定选择；轮转/截断如实标记。初始预算为总量100MiB、单项20MiB、总时长60秒、受控收集并发≤2、支持取消。超限可生成明确Partial包，必须列缺项和截断范围；不得显示“完整导出成功”。无法完成最小清单/遮盖验证则失败不发布。

目标文件只写新文件：同一目标卷临时写入→关闭流→检查zip/清单及遮盖→原子发布。中断、磁盘不足、目标已存在、权限撤销要清理未提交临时文件；清理失败标明具体路径。撤权立即停止读取/发布；已发布文件无法通过撤权收回，应在导出前告知交付范围。收集不占供包关键锁，不暂停、不重连、不发RCS、不运行任意用户脚本。

测试合成秘密（金丝雀）覆盖混合大小写、嵌套JSON、URL、异常文本、日志轮转与未知字段；zip内逐文件检查。原生dump等无法可靠脱敏的二进制不进入默认包。遮盖测试通过不代表取得对外分享许可。

## 4. 文档与证据治理

### 4.1 三层结构

| 层 | 建议产物 | 内容与预算 |
|---|---|---|
| 现场一页卡 | 作业卡、部署卡各1页 | 合成图+短步骤；作业卡强调本位格口与异常包裹，部署卡写先决条件和安装/首配路径 |
| 实施手册 | 不超过20页的可打印离线手册 | 安装/更新/回退/卸载各≤5个主步骤，附例外说明、首配、连接层级、备份恢复、故障目录、诊断交接 |
| 开发入口 | 现有架构、ADR、工作包、测试和证据 | 保留编号/原件；明确目标、实现、模拟、Windows、设备和现场状态 |

手册页预算：准备1，安装更新卸载回退4，首配与测试4，作业及异常2，备份恢复/退役3，故障码4，诊断与支持1，版本/术语1。故障数量超过预算时保留20页主手册并附自动生成的完整故障索引，不能删掉故障行凑页数。打印PDF/图文卡的生成、页数和视觉核验是实施交付项，本轮未制作成品。

README目标顺序为产品用途→可信下载/适用系统→两张一页卡→实施手册→开发入口；不得指向未签名候选并暗示正式可投产。INDEX目标只分类导航；历史日期公告移至CHANGELOG和自动生成工作包目录。当前事实由精简入口说明，详细来源可追溯，不能用新设计覆盖尚未实现的现状。

术语映射：原操作→上一次操作；Pending→待生效的配置；Effective→正在使用的配置；CAS→设置已被其他窗口修改，请重新核对；Unknown→结果尚未确认。术语替换只影响展示，开发字段/日志证据/合同编号不改；“已识别”“已取格口”“已接受”“已完成”继续分开。

### 4.2 文档与发布绑定

现场文档包含适用ReleaseId、生成源、文档版本和更新时间；帮助只打开本包内容及稳定锚点，不运行文档脚本或从远端加载任意HTML。故障目录自动校验可见代码覆盖、动作存在/权限以及链接，手册生成失败阻断相应正式发布。旧代码保留旧手册，不能将旧故障说明静默覆盖成新语义。

### 4.3 证据体积治理

核查显示docs体积主要不在Markdown正文，详见核查记录。先按类别、单文件体积、引用数和授权统计，分别制定保留/外置策略。建议源码仓库保留最小复现、摘要、SHA及稳定逻辑EvidenceId，大型合成证据进入受控证据仓库或授权Release附件；LFS只是存储方式，不解决公开许可。

迁移顺序为：资产清单与许可→目标权限/保留期→原字节上传并读回校验→建立EvidenceId到原SourceCommit/新位置映射→验证所有链接与离线取回→后续提交调整当前引用。历史归档、哈希及失败证据不重写；新位置不可访问则保留源或明确受限。仅工作树删除不缩小Git历史，不能承诺clone立刻减少；历史瘦身另行授权、提供旧SHA映射并评估所有引用。不能把生产日志或私有附件搬到公开Release。

## 5. 质量工程与CI设计

### 5.1 最小可信流水线

本轮只设计；现有三条workflow仍为workflow_dispatch。实施时新增/收敛稳定的PR门禁，而不是把所有历史工作包测试无差别跑一遍。目标触发为pull_request和push main，使用无现场网络/密钥的Windows runner，先加载D盘project-environment；merge queue若启用，增加对应merge_group触发。

| 检查 | 必须内容 | 结果 |
|---|---|---|
| core-build | 固定global.json/locked restore，SM及受影响共享装配构建 | 稳定必需检查名，失败不进入发布 |
| core-regression | 安全恢复、CAS/权限、原请求Unknown、托盘放置、SQLite恢复、部署事务和资源释放 | TRX与日志，必跑目录非空，缺用例失败 |
| native-ui | 无硬件的WPF/Dispatcher合成验证 | 标明合成范围；真正交互桌面另在隔离VM |
| documentation | 链接、故障目录/手册对应、清单、公开范围检查 | 当前文件坏链失败，不借历史私有缺项造假链接 |
| quality | 约定范围格式、已启用编译警告及新增分析器 | 增量治理，基线豁免可追溯且不掩盖安全缺陷 |

真实SDK/客户RCS/设备测试使用显式Trait/类别单独执行，环境不足时写NOT_RUN/BLOCKED_EXTERNAL，不能把被跳过计入必跑PASS。核心必需检查总会产生结果，不能因路径过滤使必需状态永远等待；全跳过不算绿灯。分支保护将这些稳定检查设为required，管理员旁路和实际保护政策须单独登记。

PR jobs为contents:read，不提供签名、发布、现场账户；actions固定经审查的完整commit SHA，checkout不保留凭据。不能用pull_request_target执行PR代码；自托管runner不接不可信PR，硬件/设备runner与生产网络隔离。设置并发取消旧PR任务、超时、固定工件保留期和依赖缓存信任边界；失败日志也保留，但扫描敏感内容。

### 5.2 标准测试发现与覆盖率

第一阶段选定MSTest+VSTest作为统一发现入口，版本需实施时核验并写锁文件；不修改全局runner模式去混用MTP参数。.NET10两平台兼容差异见[官方说明](https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-with-dotnet-test)。WPF测试运行在独立STA子进程，默认不并行共享桌面；真实系统生命周期另在隔离VM。

把现有控制台验证逐套映射为可发现测试，保留原命令可复现；每套有稳定TestId、风险类别和超时。先建立薄适配，随后把关键断言整理为可复用fixture/独立用例，不能多个测试重复跑全部Program入口或把测试名称当实际覆盖。子进程适配要核验退出码、预期结果数及失败输出，进程超时杀树后仍报告资源清理/外部状态，不简单返回PASS。

覆盖率分别报告：进程内产品代码、UI子进程、系统生命周期/原生SDK未覆盖范围。只覆盖适配器几行代码不能称为产品覆盖率。第一阶段采集基线并为安全与持久化关键分支制定覆盖要求；不凭空设全仓80%并大批排除困难代码凑数。测试发现为0、预期核心TestId缺失、挂起或assertion失败均失败。

### 5.3 格式与分析器

现有Directory.Build.props已经开启Nullable、TreatWarningsAsErrors、锁文件和确定性构建；继承，不重复声明成新增成果。增加.editorconfig并固定分析级别/严重性，先检查Platform/Installer受影响文件和新增代码。format使用同一SDK、排除生成代码及未获授权资产；必要纯格式提交与行为修复分开。

长单行按权限、事务、资源清理等风险排序拆解，提取有语义的方法，保留可读diff。禁止用全局NoWarn、跳过测试、删除不变量断言或吞异常换绿灯。不能仅按行长把代码切碎后宣称可维护性完成。

## 6. 发布管理与更新通知

统一主.次.修订的产品显示，BusinessVersion与不可变ReleaseId、SourceCommit、SDK/依赖库存保持映射。已经发出的某版本不换字节；修复重新发新修订。向用户展示新功能/修复/注意事项、允许更新/回退路径、是否需停机和数据兼容性，不默认展示commit。

可信发布流程：受审查提交→锁定依赖构建→必要测试→独立签名→最终字节库存/哈希→实际下载字节核验→候选小范围试用→正式推广。签名作业只处理可信源，独立于PR；软件自签清单与Windows Authenticode职责分开。正式签名证书/Publisher、SDK分发授权或目标矩阵缺项时保持候选状态，不用测试证书替代。

每次Release交付安装包、SHA256、用户更新说明、兼容/回退矩阵、依赖与许可清单/SBOM、同源手册和可公开验证摘要。私有依赖、现场日志和受限SDK不随“完整Release”自动公开。准确写出Windows原生、系统安装、SDK/RCS、目标IPC和现场哪些已验；旧PASS保留原SourceCommit。

自动检查更新为可选延期能力。默认离线可用，组织配置允许才访问固定HTTPS元数据；超时静默退出，版本降级/预发布/产品不符不提示。下载链接只是提示，元数据需可信签名/安全下限校验，不能让GitHub latest重定向或仓库被替换就自动执行代码。不收集站点/人员/相机信息、不自动下载、不安装、不改变受保护配置；网络失败不能阻断作业。新版本已发现也只在非关键时机显示次级通知。

撤回有安全问题的版本要保留其来源和事件记录，取消推荐渠道并提供替代版本；回退仍受安全下限，不引导用户退回固定恢复口令版本。发布分批观察失败率、启动/回退和诊断结果，达到事先定义的阻断条件停止推广，不能现场越修越散而没有版本身份。

## 7. 可用性与运维验证

每次大版本至少2～3位未接触产品的人做形成性验证，角色含实施人员与供包员；它能发现卡点，不能证明总体成功率。若要对外声称普遍30分钟达标，应扩大样本并报告分布/失败原因。测试脚本固定任务与站点合成数据；观察员不口头提示，求助即记录。

旅程：找到可信包/先决条件→安装→五步首配→区分已配置和可用→合法首件→处理一个故障→导出诊断→卸载。模拟与真实设备分开；供包员另验证空托盘、成功格口、被拒、Unknown、断线与人工补录，不能靠模拟页的成功动画计时。

记录任务完成率、总/主动/等待时间、点击和决定数、求助、错误操作及恢复、关键包裹处置、是否理解保留数据。关键失败（错误格口、越权、重复Unknown请求、丢责任）为阻断，不用其他人的快速度抵消。每个卡点映射故障目录/交互修改及回归用例。

运维观察指标包括真实安装失败阶段、备份/回退可用性、清理残件、配置待生效时长、连接证据过期、Unknown数量和诊断包缺项；默认本机汇总，集中监控不在本包范围。阈值在目标工控机上取得基线，不能从合成延迟或帧率直接推定现场产能。

## 8. 界面交接清单与一页卡文案

以下定义新增/受影响界面的结构和状态，供实现与原生验收使用。沿现有WPF主题，不是另一个视觉方案；按钮文字为目标文案，实施时与实际控件和帮助内容共同冻结。

| 界面 | 主内容与唯一主要动作 | 必须覆盖的状态 |
|---|---|---|
| 安装欢迎/位置 | 产品/版本、自动判断动作、默认根；主要“安装/更新/修复”，高级区容纳路径和快捷方式 | 新装、更新、同版修复、路径冲突、D盘缺失、不兼容版本、空间不足 |
| 安装进度/完成 | 当前阶段/经过时间/可取消性；完成后普通用户“打开软件” | 可取消、已提交、待确认、入口待修复、完成、清理残件 |
| 密码恢复发起 | 本站标识、需要Windows管理员说明；“请管理员重置” | 未提权、UAC取消、服务不可用、混版拒绝 |
| 提权密码重置 | 本站/作用说明、新密码及确认；“重置管理密码” | 字段错误、挑战过期、凭据变化、提交中、结果待确认、完成 |
| 首配完成 | 能力清单、真实失败原因、保存/生效状态；“保存并打开作业” | 双/单/无相机、RCS未配、单侧离线、保存冲突、启动失败 |
| 参数连接测试 | 相机/RCS字段旁“检查连接”，结果分层且显示时间 | 候选旧结果、检查中、取消待释放、身份不符、采图失败、无独立探测合同 |
| 故障上下文 | 本件原因、影响/包裹处置、一个主动作；技术码展开可复制 | 读码失败、断线、拒绝、Unknown、过期结果、权限不足 |
| 诊断导出 | 内容级别与目标摘要；“导出到本机” | 无管理权限、收集中、超限Partial、撤权/取消、目标冲突、完成并定位 |
| 卸载 | 移除程序/保留数据说明、默认备份、次级永久删除；“卸载程序” | 未决保留、在途阻断、备份失败、仍保留数据确认、残件/3010、已移除 |
| 永久删除审阅 | 具体根/数据/保留项/责任预检；二次明确“永久删除本站数据” | 未决拒绝、共享引用、路径不安全、提交中、部分删除、已完成 |
| 使用帮助 | 作业卡、部署卡、故障目录、诊断、版本；当前任务优先 | 离线可读、未知故障、缺联系方式、旧文档版本不符 |

一页卡文案是目标交付草稿，需随实现最终冻结和打印排版验证。它们不能提前作为当前版本操作手册发布。

### 作业卡：看本位结果，再处理本件包裹

**开工前**：打开“菜鸟供包台”，确认所在工位及可用来源。显示“待配置/不能受理”时交给管理人员，不反复扫码尝试绕过。

1. **放件**：包裹条码朝上放到本位托盘，等待屏幕显示本件结果。托盘为空时显示“未读到条码”属正常；已放件仍读不到时调整标签，或使用允许的扫码枪/键盘补录。
2. **看格口**：只认本位、本件、当前有效的格口。相机一直读到同一包裹时，系统保留这次放置的结果，不持续发新请求。
3. **看提示**：没有格口先读主提示。明确被拒/未送达时按提示处理；“结果尚未确认”时把包裹暂放一旁，保留记录，请管理人员核对，勿反复重放制造新请求。
4. **交接问题**：进入“记录”查看本次作业；必要时从“使用帮助”导出本机诊断包，按现场指定渠道交接。设备危险按现场安全流程处理，软件操作不能代替安全急停。

页脚：改设置需要管理模式；供包员不需要知道管理密码或Windows管理员密码。支持联系方式由正式交付资料填写。插图只用两幅合成图：本位有效格口、结果未确认及包裹暂放；不使用客户现场照片。

### 部署卡：完成安装，再逐项确认能力

**先备妥**：可信安装包与SHA256、可用D盘、Windows管理员、批准的站点/RCS资料，以及使用相机时的合法SDK、实际IP/物理序列号/唯一相机编码。记录准备耗时；缺设备可配置人工来源，缺RCS则不能执行取格口业务。

1. **安装**：打开安装包，确认软件版本与D盘位置，按“安装”并完成Windows授权。更新/修复使用原登记目录；提示结果待确认时先核对本次操作。
2. **首配**：沿软件五步填写站点及所需来源；相机和RCS可暂留空，不能填示例值冒充实机。初次管理设密沿批准入口完成，不存在默认密码。
3. **检查**：在相机/RCS旁检查连接，区分已找到相机、已采图、已识别和RCS证据。最后核对能力清单，保存并打开作业；“已保存”不一定已生效。
4. **首件**：按作业卡测试一个合法包裹；模拟环境写明“模拟”，真实环境保留真实接口与结果证据。结果未确认时保留原记录，不重发未知请求。
5. **移除或交付**：需要卸载时从Windows应用列表进入，管理员确认，默认备份并保留数据。无需业务密码或原安装包；遇到残件/需重启按原结果处理。永久删除另受退役/责任检查，不是普通卸载的默认步骤。

页脚：忘记管理密码请Windows管理员使用本站重置入口；不使用共享恢复密码。更多例外见同版实施手册。新版本功能尚未交付前，不把本卡投放现场。

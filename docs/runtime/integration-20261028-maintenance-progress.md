本轮接续已保全 WT048 的 LI-R03 任务意图：备份、恢复、修复、升级、卸载必须有可理解的等待和真实结果。LI-R03 是原审查标签，不重占当前生命周期工作包的 LIA-03 编号。实施基线为 WT024 合并后的 main `3a25d6ba3bea686b6bb7caaef919bb1dec2d4b12`；本记录属于增量候选，合并状态及最终 SHA 以整合终态账为准。

## 实现与停止边界

- `MaintenanceExecution` 用同一锁裁定取消、提交和完成；接受取消先置标志再发 token，避免信号尚未传播时抢先提交。阶段切换和字节观察在进入 UI/pipe 前有预算，重复预检仍显示本阶段真实进度，不按时间生成百分比。
- 原窗口保留可选择的源/目标、阶段、字节与等待时间；取消入口独立于禁用的表单和页脚。点击只表示请求，资源实际释放后才显示取消完成。原操作未知时公共写入口阻断再次提交，只读检查保留原未知上下文。
- 原责任快照、SQLite 分批备份、恢复集枚举/哈希/复制和恢复预检贯穿取消令牌。原权限、原 owner、路径/配额、完整性和固定请求身份检查保留；仅本次取消导致的 SQLite INTERRUPT 映射为取消，其他错误保留。
- 备份以 `COMPLETED.json` 发布为封口；恢复以 `RESTORED-ISOLATED.json` 发布为封口；卸载以退役标记写入为封口。作为升级/卸载子阶段的完整备份，不提前封闭整个后续操作的取消；独立准备变更则以其完整备份发布为终态。
- 新安装在准备受保护数据根前封口；升级/同源修复在机器策略首写前封口，之后复制程序、安装共享组件、更新服务及系统入口不承诺取消或回滚。系统修复在监督器/投影修改前封口。已经退役后的固定清单继续清理只显示实际等待与结果，不撤销退役。
- helper 绑定真实父/子进程、开始时间、原请求 SHA 和保护负载；Ready/Begin/Cancel、观察帧及终态均有界。取消终态要求已接受的本次取消及退出码 3；完成帧仍须核对实际退出码。坏响应及时断开本次管道，让 helper 停止可取消准备；不终止可能正在提交的进程。终态之后的迟到取消写/清理失败不能覆盖原终态候选，也不能放宽退出码一致性。

恢复成功只是文件完整与隔离，不接管生产根、不解除原业务责任，不发起设备或 RCS 动作。已生成的准备文件、未完成/完整备份和隔离目录保留；取消不等于回滚已发生的机器变更。组件核验按当前组件边界响应取消；无法中断的系统 IO 结束前保持等待，不显示虚构完成。

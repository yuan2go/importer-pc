# SM-PLACEMENT-PRESENCE-29

2026-11-02 现场反馈：包裹放上托盘后相机一直识别、一直向RCS发送取格口请求，不合理，需修正。用户以现场交互流程明确改变“每次独立识别交RCS去重”的方案。基线 `b16d3f939eb53c168d79aba87029723c4babdf19`（PR182合入后main）。

## 现场流程（用户原述要点）

1. 操作工将包裹条码面向上放入托盘，托盘位于相机下方。
2. 相机读码后向RCS请求格口；格口返回供包台，小车带着托盘去指定格口，下一台小车托着空托盘过来。
3. RCS请求失败时，操作工取下包裹放到一边，换一个包裹放上；或把同一个包裹重复放几次，直到取得格口、小车驮走。

## 合同变更

一次托盘放置只发一次取格口请求。连续采集照常逐帧识别，但同一位置上，上次请求的包裹仍在读码区时，其后续识别属于同一次放置，不建作业、不发RCS。放置结束只认相机的正面证据：

- 同一相机连续报告无码帧达到放置空置间隔（默认1000毫秒：包裹被取下，或托盘被小车带走），之后再识别到的条码（含同码）为新一次放置；
- 或识别到另一个选中条码（换了包裹），立即为新包裹。

单帧漏读短于空置间隔不算离开。RCS应答期间排队的帧，只要观察时间早于空置开始，处理时仍属原放置。键盘/PDA人工输入是操作工明确意图，不受此限，但会开始自己的放置。软件重启后以各位最近一件作业的条码预置，避免仍在托盘上的包裹被再次发送，直到相机看到读码区空置。

这不是“同码即同实体”：判定依据是读码区是否空置过，同码重新放上仍得到独立的新原请求。原请求、Unknown、防重、超时和接收/业务接受守卫不变；不重发原请求，不改外部协议、quantity或商品码语义。仅对逐帧上报读码反馈的相机来源（内置MVS）生效；参考/TCP等逐事件来源保持原行为。

## 显示与统计

- 同一次放置的重复识别仍记为观察（`Duplicate`，`SamePlacement=true`，关联原作业），作业页继续显示该作业自己的结果（格口/未分配/超时），不再闪“处理中”、不再按帧响读码/成功/异常提示音。
- 重复识别不计入识别次数或准入受阻统计。
- 超时、未送达提示改为“取下包裹再重新放上”；参数页读码方式改为“逐帧识别上报（同一次放置只请求一次）”。

## 实施

- `ParcelPresence.cs`：每位放置保持、空置判定、排队旧帧归属、启动预置。
- `FlowDefinition.PlacementClearMs`（默认关闭）；`SportmasterFlow` 默认1000毫秒。本包不新增参数页字段，现场需调整时另行授权纳入四类参数完整候选。
- 读码反馈回调更新空置水位；`ProcessTrustedObservationAsync` 在新准入前判定同一次放置。
- 契约：`ParcelInputSnapshot.SamePlacement`、`ParcelReadFeedback.SamePlacement`（显示提示，不是准入权限）。
- 新增 `--placement-presence-29` 回归；将依赖旧合同（同码逐帧独立请求）的背压/原图/软件流程/界面用例改为不同包裹，删除旧断言依据为本合同变更。

# 当前 Parcel12 数据操作

当前客户端新库直接创建格式 **12**。普通启动仅核验当前格式；非当前库不得直接启动运行。SM 的运行班次和统计说明见[运行班次](sm-session-shift-exceptions-25.md)。本文是当前安装介质的操作入口；DB11历史说明及验证保留原来源，不作为当前操作指引。

## 保留数据更新

使用当前业务的完整安装包和已登记的安装入口。原实例必须完全停止，管理权限、部署归属、独占租约、原请求与回包责任检查均有效。已知格式10/11只有既有受控离线升级路径可以升级至12：先严格结构、身份与版本检查，完成数据库、WAL及配置/原返回配套文件的完整备份和哈希核验，再事务升级。其他旧格式、结构不匹配或缺备份时拒绝并保全原件。

不要手动修改格式号、复制活动数据库、删除WAL或以新目录绕过原责任。升级不重写原请求报文、原始回包、永久请求号归属和历史审计，不把旧记录补造成新班次。升级后的暂停与核对流程继续有效；不得因安装成功便直接宣布业务恢复。

## 备份、恢复和回退

数据库文件与同名 `.recovery` 目录必须一起保管；以 `COMPLETED.json` 的完整恢复集清单和哈希核对，不把单个数据库文件视为完整备份。恢复使用维护中心，恢复到新目录，复用原隔离恢复、权限和原目录退役守卫，不覆盖原目录或猜测安装位置。

旧程序不能直接读取12。若必须回退，使用匹配旧版本、经核验的升级前完整恢复集，先核对升级后新增的外部请求和本机事实，再按原恢复/接管流程处理；备份不能撤销已发送的外部效果。不得只改版本号或仅替换旧EXE。结果未确认时先核对原次操作，不重复升级、恢复或卸载。

## 原请求和设置

格口未确认的请求保留原身份、合同、目标和报文字节。内置RCS没有结果查询合同，不自动重发，也不以当前目标代替原目标。新独立扫描与重发原请求不同。

设置保存与生效分开：只改条码规则且满足完整候选屏障时可热生效；混合修改全部待重启。若原责任或启动检查阻止生效，旧设置继续使用，已保存修改保留；先处理异常与诊断，再检查并重新保存，不能反复重启或清数据解除守卫。

真实SDK、客户RCS及现场验收另行记录，安装完整性和软件模拟不代替这些验收。

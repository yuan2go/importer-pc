# 工业化安装、更新、回退与退役设计 · IE01-L

状态：目标设计，未更改安装器或系统。总范围见[IE01](industrial-engineering-01.md)，密码权限见[IE01-S](industrial-security-recovery-01.md)。沿用WindowsDeploymentSetup、MaintenanceExecution、受保护登记和原操作回执；不新建第二套安装账。

## 1. 部署资产与事务

| 资产 | 存储及权限 | 生命周期 |
|---|---|---|
| 程序版本目录 | D盘受保护程序根，普通运行账户只读 | 不可变版本目录；独立库存、签名及最终文件哈希 |
| 唯一部署登记 | 管理员配置的受保护根及现有HKLM政策 | 唯一当前版本、数据根、机器/安装身份及原操作指纹 |
| 维护缓存 | D盘受保护维护根 | 同源签名helper、必要依赖、清理清单及信任证据，不依赖可删除发布目录 |
| 业务数据/配置 | D盘受保护数据根，沿现有授权 | 更新/卸载默认保留；原请求与永久身份不因换版本消失 |
| 完整备份 | 审阅过的新目标，独立于待删除目录 | 一致性数据库与完整恢复集，完整标记最后发布 |
| 操作日志/回执 | 受保护操作目录，按安装身份分区 | 持久意图先于副作用；Unknown只核对同一操作 |

所有提权路径在执行前重新解析实际目标和ACL，拒绝目录穿越、重解析点绕权、卷根/系统根/用户目录误选、产品根重叠及清单外文件。删除依据实际部署身份和有限清单，不能以用户文本路径递归删除。信任锚来自独立批准的发布者政策，不从待执行目录自证可信。

统一阶段为：发现既有部署→只读预检→审阅固定计划→Windows授权→取得维护独占并重新核验→准备/完整备份→提交登记→修复系统投影→核对终态。明确显示可取消点；提交后不提供“取消即撤销”。正在运行的SDK调用必须真实退出，超时不杀线程、不伪报资源释放。

## 2. 三个主界面的普通向导

1. **欢迎与位置**：显示产品名、目标版本，以及自动判断的“安装/更新/修复”；新装带出D盘默认程序和数据根。位置可展开编辑，快捷方式等进入高级选项。已有部署读权威登记并锁定原根，改根是独立迁移任务。D盘不存在/不可写/预算不足时就地说明下一步，不自动选C盘；不要求供包员理解SourceCommit。
2. **安装**：开始前同页展示影响摘要（更新版本、保留数据、预计停止影响及备份目标），明确点击安装后才修改系统。预检正常不另弹技术核对页，异常才要求处理。阶段、经过时间、可取消状态和真实失败原因持续可见；大文件/备份无可测总量时不用假百分比。
3. **完成**：成功才显示可启动；“立即打开”由默认选中的选项控制，启动的是原普通用户上下文。提权管理员不能把生产主程序以管理员身份直接启动；无法安全返回原上下文时提供普通快捷方式。已提交但入口修复失败显示“安装已登记，启动入口待修复”，保留原操作，不提供再次安装。

计数以3个主界面、≤5项主要决定为目标；UAC是Windows确认。首配五步不合并进安装向导，安装成功不表示配置生效或设备可用。新装/更新/修复分别验收，不能只录一条成功视频。

## 3. 静默安装与批量接口

新增EXE参数前端，将简化输入转换为现有固定计划，使用同一预检、权限和执行内核；保留`--deployment-plan`协议及原退出码，不使历史脚本语义改变。下列为拟新增参数，实施前不可当现有命令运行。

```text
Ipc.Installer.exe /quiet /norestart /log="D:\deploy\station-install.log" /dataRoot="D:\ProgramData\ImporterPc\data"
Ipc.Installer.exe /quiet /repair /norestart /log="D:\deploy\station-repair.log"
Ipc.Maintenance.exe /quiet /uninstall /norestart /log="D:\deploy\station-uninstall.log"
```

`Ipc.Maintenance.exe`为目标helper名称，可在实现时沿现有启动入口命名；不能宣称现有介质已含该文件。

- `/quiet`无任何产品对话框；已提权管理员/SYSTEM可执行，未提权返回740，不尝试弹UAC。缺必需参数、已有根冲突、需人工处理的旧责任均返回明确错误，不静默选择模拟模式或默认密码。
- `/dataRoot`只对新装合法，受保护管理员政策优先；更新传入不同根直接拒绝。新装非交互首次设密留给独立批准任务，不把密码放命令行、计划明文或CI日志。
- `/log`只写允许的新文件，拒绝重解析点和覆盖现有文件；日志父目录/ACL先校验，敏感数据遮盖。结果JSON回执与可读日志分开，均包含同一OperationId和错误码。
- 安装/修复/卸载互斥；未知参数拒绝。重复调用先查权威原操作，明确已完成且目标一致才能返回幂等成功；Prepared/Unknown/进行中不能换ID重试。批量调用者可指定稳定请求ID，冲突载荷拒绝。
- 默认不重启；`/norestart`显式兼容部署工具，不提供自动强制重启默认值。静默不自动启动业务、不连接设备。`/quiet`永久删除不纳入第一批能力，防止RMM误退役。

| 新简化接口退出码 | 含义 | 部署平台处理 |
|---:|---|---|
| 0 | 核验完成，或同一目标的已完成操作 | 成功；仍不代表现场资格 |
| 3010 | 动作已完成，存在明确已登记的重启清理要求 | 成功但需安排重启，产品不主动重启 |
| 87 | 参数/路径/模式无效 | 修正输入，不重试写操作 |
| 740 | 缺Windows管理员权限 | 交给授权部署通道 |
| 1602 | 用户在可取消阶段取消 | 记录取消；若已提交则不返回此码 |
| 1618 | 同一安装身份有操作持锁 | 查询原操作，不并行安装 |
| 1603 | 已知失败或前置条件不满足 | 根据JSON错误分类处理 |
| 1627 | 结果未知，需核对原操作 | 禁止自动重试；回执指向核对入口 |

这些码是EXE主动制定的契约，参考Windows Installer惯例，不宣称本EXE已经是MSI。机器可读ErrorCode进一步区分DowngradeBlocked、BackupFailed、OriginalOperationNeedsInspection等，不能仅靠退出码做业务裁决。旧高级计划保留原退出10等语义。

## 4. 更新、保留与回退

### 4.1 版本与兼容

版本比较按解析后的SemVer数值及预发布规则，禁止字符串字典序。BusinessVersion用于产品显示和顺序；ApplicationId、架构、发布身份、数据schema、配置schema、管理凭据/管道协议、SDK/ABI及安全下限共同判断可运行组合。

相同版本且同一不可变ReleaseId是修复；同版本不同内容默认拒绝并要求新修订版本，不用commit差异掩盖介质替换。较新版本满足已批准兼容矩阵才更新；普通路径拒绝较旧版本，二次点击不能覆盖数据或安全不兼容。预发布只在显式渠道允许，Production不自动从稳定版切到预发布。

更新不擅自进行格式迁移。仅发布清单声明且有当前授权/测试的路径可执行；迁移前独占停机、完整备份、严格只读结构核查，提交后不反向迁移。未知格式写入前拒绝并保全原件。

### 4.2 事务与崩溃恢复

| 中断位置 | 恢复行为 |
|---|---|
| 暂存/备份前后，未提交 | 旧部署继续权威；临时产物按原清单核对后清理 |
| 新程序已准备，登记未切换 | 原版本仍权威；核对原OperationId，不靠目录日期判断 |
| 登记已切换，快捷方式/服务投影失败 | 维护态，只修复同一已提交安装的系统入口 |
| 首次普通启动/新配置激活失败 | 沿现有激活机制保留失败证据；满足回退门禁才给回退动作 |
| 调用方丢回执 | 只读核对同一原操作；禁止新计划覆盖Unknown |

开始维护前阻断新准入并有界排空，仍有在途外呼或原生资源则拒绝进入破坏性阶段。不能为实现无重启强杀进程后把在途请求当未发生。

### 4.3 版本清理

“只保留上一版”改为：至少保留当前版与最近一个**兼容且不低于安全下限**的回退候选；被未决原请求、安装回执、恢复或SDK依赖引用的版本继续固定。没有合法回退候选时明确提示，不保留有已知恢复漏洞的版本供一键回退。

清理是独立有回执任务，在新版本登记、普通启动及必要观察确认后执行。候选只从受保护库存计算，按文件清单删除，清单外文件保留并报告。容量不足时先明确拒绝或请求管理员清理，不能先删唯一可恢复版本再冒险更新。旧目录被固定时显示原因/大小，不承诺磁盘总量永不增长。

### 4.4 一键回退

“回退到上一可用版本”先预检：数据/配置可由目标读取，原请求冻结实现可解析，凭据/IPC协议匹配，SDK身份有效，满足安全下限，所有owner已真实停止，且有完整备份。任一未知即禁用并解释。

回退仅切换程序登记/系统入口，不把旧DB覆盖到当前根，不丢弃更新后接受事实；启动后重新按现行Application守卫核验，不自动重发或解隔离。需要旧数据才能运行时给“暂不能回退，请保留数据并导出诊断”，恢复备份走独立隔离接管任务。失败回到原登记或保持明确维护态，不启动两个版本。

## 5. 卸载与残件清理

ARP入口交给安装时缓存的可信维护helper，不依赖可能损坏/已删除的业务EXE。交互页只选择“保留本站数据 / 同时删除本站数据”，默认保留；点击一次“卸载”执行，不创建备份，不提供恢复、版本回退、版本清理或输入确认文字。静默卸载不备份，保留数据。

Windows管理员可在软件起不来或忘记业务密码时卸载。只检查供包台是否已完全关闭并释放所有权；未关闭就提示“请先关闭供包台，再卸载”。两种数据选择均不解析配置或业务数据库，不检查请求是否完成，不创建备份，也不将关闭软件写成请求已完成。程序尚持有资源时不能卸载。

helper在D盘受保护独立目录运行，先验证源、签名、最终哈希和必要依赖；不从普通可写%TEMP%提权执行。helper完成父进程/服务真实退出后，按安装清单移除本产品版本、快捷方式和专属服务登记。共享SDK/服务/根只在引用数为0且归属可证明时处理；不卸载其他业务或厂商驱动。

安装时持久保存已安装库存及可信签名/身份，卸载依靠该库存和原删除回执，自动继续可核验的未提交操作与原清单余项，不再索取原版安装EXE。库存读取只检查清单身份和相对路径，程序目录已删除仍能完成核对；实际删除前检查全部路径的重解析边界。完整新版安装包可用同包helper清理原安装库存，不要求执行损坏的旧helper。库存损坏或来源不可信时保留原件，不遍历整个目录猜测删除范围。

文件仍被占用时先说明占用者，允许用户关闭并重试同一清单；可评估Restart Manager协助关闭本产品，不能未经确认关闭其他程序或会话。必要时登记有限的重启后删除路径并返回3010；其他删除失败报告残件，不能仅因文件存在就要求重启。残件清理本身可幂等续办、不可变更根，不依赖已移除业务服务再验证管理密码。

完成定义分开显示：卸载完成且数据保留/数据已删除/尚有文件待清理/需重启。完成页只提供关闭；余项提供重试卸载，Unknown须先查看原结果。操作日志和受保护维护缓存位于待删目录之外，保留原清单和最终回执。

部分数据目录已删除不阻断原清单重试。数据清理回执和部署登记之间中断时，核对同一操作及原目录范围后继续完成登记；仅登记和回执都确认删除完成时显示成功，不要求恢复已删除的目录。

## 6. 永久删除与设备退役

“同时删除本站数据”默认不选，说明删除配置、记录、图片和日志且不可撤销。选择后与程序卸载一次执行，不创建备份、不另设检查或二次确认页面。卸载由Windows管理员执行，只要求供包台已完全关闭，不检查未完成请求、恢复标记或换机交接状态。

删除仍检查安装登记、原清单、根目录归属与重解析边界，不越过安装登记范围删除其他目录。原请求、数据库和配置内容不参与准入；选择保留时原样保留，选择删除时按本站文件清单删除，不改写请求状态。

计划按顺序列出：本安装的配置/数据库/图片/日志→专属登记→无共享引用的本站政策/服务→最终回执。产品族安全下限、其他安装/业务引用不属于本站删除清单；界面明确披露这些保留项。检查每个实际绝对路径和重解析边界，不能对整个HKLM\SOFTWARE\ImporterPc或ProgramData根一刀删除。标识/审计的保留义务和备份外副本先在手册写明；受保护终态回执在外部审阅目标交付并核验后，才能移除最后本站登记。

失败保存精确已删/未删清单，状态为PartiallyPurged，不允许随后恢复成可作业空站绕过原责任。未知提交核对原操作，不重复递归清理。普通文件删除不等于SSD安全擦除，也不能删除组织备份、远端系统或Git历史；设备介质销毁另按组织政策。

## 7. 签名与Windows登记

签名顺序必须与字节清单一致：构建不可变候选→签自有PE文件（含helper/服务）→生成最终媒体哈希/库存→构建单EXE→签最终EXE→计算外部SHA256与发布清单→在Windows验证最终下载字节。签名后不得修改程序集资源、嵌入包或清单。第三方SDK保持厂商原签名/哈希和分发许可，不改签假冒本公司开发。

现有`verify-distribution-signature.ps1`只覆盖app/desktop顶层Ipc.*，不能直接宣称覆盖所有文件。扩展为显式PE库存：安装器、独立helper、服务及发布目录全部自有PE；校验证书链、批准签名者、用途、可信时间戳、SHA256摘要及最终字节。批准发布者政策支持证书轮换，不仅把一个旧thumbprint永远写死。离线吊销不可核验应单列状态，不能伪报在线核验。

私钥保存在受控签名服务/HSM，不放仓库、安装包或普通PR secret。正式公司名称、证书主体和发布者政策由实际授权资料提供，不能编造Publisher。证书资格未备妥时发布候选明确未签名，不达正式交付门禁。签名能证明发布者/完整性；SmartScreen另有信誉判断，需在真实下载渠道、联网/离线和企业政策矩阵取证，不能承诺“签名后永不拦截”。

ARP补齐：DisplayName、仅版本号的DisplayVersion、真实Publisher、InstallLocation、签名图标、正确转义的UninstallString/QuietUninstallString、ModifyPath、以KiB计算的EstimatedSize及必要联系信息。commit/ReleaseId进入详情/回执；ARP不存凭据。登记只投影当前权威部署，不反向成为第二权威；更新/修复/卸载结果一致。

## 8. MSI/MSIX的后续决策

A10保留为后续评估，不进入本轮关键路径。先做两类小规模技术验证：WiX/MSI对受保护程序、服务、ARP和修复的声明式管理；MSIX对管理员操作、D盘数据、服务/SDK和离线部署的实际适配。交付记录Windows版本、企业部署工具、修复/升级/卸载行为和限制。

不能把现有整套EXE安装事务作为一个巨大自定义动作：两套回滚/登记权威和任意业务数据迁移不天然原子。若选MSI，Windows Installer拥有其声明资产，应用维护层只拥有业务数据和原责任；少量必要自定义动作须可延期执行、有补偿/失败恢复和窄权限。若MSIX无法满足现场政策，继续受支持EXE，而不是强迫改变业务架构。

## 9. 生命周期验证范围

公共Windows runner可做构建、纯文件合成与隔离内核测试，不能代表真实Windows10/11、UAC、交互桌面、SCM故障和重启矩阵。完整系统测试在可恢复快照的隔离VM，分别覆盖干净新装、已有当前版更新、同版修复、禁止降级、兼容/不兼容回退、卸载保留、残件续办和永久删除。

每条危险阶段注入中断：复制、备份、登记切换、SCM、快捷方式、凭据代次、最后回执；核对原登记/数据/业务责任/资源/残件，不只看退出码。特殊矩阵包括D盘缺失/空间不足/权限不足、路径别名与重解析点、服务不可用、文件被占用、无原安装包及多产品共享。所有测试使用合成产品身份和独立D盘根，不能卸载当前用户的真实部署。

实际验收编号见工作包IE-V03～12/20/23。无需重启的目标只适用于正常释放资源的已验证组合；不得删除失败断言或自动重启机器换PASS。

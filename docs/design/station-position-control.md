# 投递位启停

SM 左右投递位各有“启用 / 停用”按钮，普通操作员即可执行。两位初始启用；状态随本站数据保留。启停与相机配置、相机是否在线分开，启用位可独立通过键盘或扫码枪供包。相机离线只在底部设备信息区提示，不使整个作业区变红。

## 状态与责任

| 当前条件 | 点击停用后的行为 |
|---|---|
| 无已开始发送尝试的请求，或本轮调用、执行及回执保存已完成 | 直接已停用，结束当前轮次并释放相机；心跳移除本位成员，仍持续探活 |
| 本轮请求已开始发送尝试，实际调用、执行或回执保存仍在进行 | 停用中，拒绝新条码，保留本轮结果与相机预览，继续心跳 |
| 停用中，本轮调用、执行及回执保存结束 | 自动结束本位轮次并停用，不等待空盘或 RCS 未知结果的后续确认 |
| 停用中点启用 | 取消停用，保留原轮次与原请求，不重新发送 |
| 已停用点启用 | 恢复准入条件检查和对应相机连接，另一位不变；先核对撤车与远端责任，再由实际心跳确认启用 |

操作员点击停用表示本位结束使用。停用只等已开始发送尝试的本轮请求及其回执责任，不需要空盘校准、视觉移出、无码帧或另点“已取下包裹”；准备但未开始发送的请求随本轮结束取消发送。轮次结束、启停状态和命令回执共用一个事务，保留操作者和原任务。此操作不写入“物理移出”证据，不解除自动重复抑制；再次启用后，同一放置不会自动再发请求，人工新件提交及可信移出仍走原规则。已发原请求保留原报文、目标、编号及真实结果，Unknown 等实际执行和回执收口后按原条件保管。空盘模型继续服务正常自动分轮，与投递位停用无关。

## 相机与心跳

已停用位启动软件时不连接相机，保存相机参数和显式重连也不能绕过启停状态。Application 沿现有设备锁和资源守卫停止相机，退役旧会话后再释放，旧回调不能进入当前会话。停止返回成功后才发布“相机已断开”；释放失败记录完整异常、保留占用并阻断自动重连。启用后沿既有连接流程重新打开该相机。停用中保留相机预览，不为确认空盘额外识码。

心跳沿原协议，不新增状态字段。启用位及当前调用/回执未收口的停用中位保留成员，已停用位移除；两位已停用或没有有效编码时发送空数组探活，不伪造身份。新集合的实际协议响应确认本次成员同步；旧心跳或旧取格口仍可能迟到生效时，相关位须维护核对远端依据后恢复。启用不清除已提交到位资格，同车不重发。投递位启停不伪造 RCS 连接确认；停用中和已停用位的小车提示由 Application 撤下，晚到响应也不能恢复绿色可投包。具体报文见 [RCS 心跳](../runtime/rcs-heartbeat-01.md)。

## 持久化与界面

Application 对每个位使用独立控制修订号，避免相机持续观察造成无意义冲突。命令回执、控制状态和审计在同一 SQLite 事务写入；重复命令返回原回执。启停事实使用独立审计所有者，不随包裹历史清理删除，不修改数据库格式版本。记录页可按游标查看时间、投递位、操作、操作人和当时任务号。

按钮至少 44 DIP 高。停用中说明等待本轮请求及结果保存完成，显示取消方法并保留本件结果；已停用显示灰色区域和启用按钮。扫码目标不能停留在停用位；已有目标停用后移到另一启用位，两位均停用则清除目标。左右结果区保持对齐，小窗口仍保留启停状态、格口和提交动作。

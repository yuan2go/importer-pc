## 13. 必要修订顺序与 Windows 验收步骤

### 13.1 优先级与完成条件

|顺序|项目|可执行完成条件|
|---|---|---|
|1：P1|A-01持续冲突证据／阻断|关键矛盾分支和重启保持证据、账与限制；对应UI恢复记录可查。|
|2：P2功能与语义|UI-01、UI-02、A-02、A-03、A-04|箱拒绝持续反馈、实体列正确、健康归因一致、组件直接激活、导入草稿不丢。|
|3：P2交互呈现|UI-03～06；R-01及UI-R02～03按验证结果处置|首屏可识别结果、标签／禁用原因可见、主次动作清楚；无串扫／迟到回填污染。|
|4：验收门禁|G-RUNTIME、G-DPI／UI-R04|完成正式Windows入口、限定关键状态、真实DPI与输入原始证据；保护与正常支持分别结论。|
|5：P3收尾|UI-07与长期负担|状态资源、字号／图标统一；真人记录支持可读／稳定性结论后再确认持续使用。|

P1为相关实际运行放行前必须解决的高影响缺陷；P2为相关功能完整验收前必须修订或证实关闭；P3为关键功能之后的统一工作。G是证据门禁，不是假设存在的代码缺陷。未获批准的生产规则仍由原决策流程处理，不能通过UI修订顺带“批准”。

### 13.2 正式 Windows 测试准备

在已授权 Windows 11 x64 测试工位，使用当前SHA可追溯包、按交付说明准备machine policy／账号权限和新的测试数据根；通过station.ps1 -Action Run或其正式DLL入口启动。使用明确Simulation组合和隔离接收端，记录core／插件／配置／程序包SHA，禁止混入现场地址。桌面入口支持--config、--data-root、--view、--layout；模式取配置，不使用不存在的--mode参数。[I01](https://github.com/yuan2go/importer-pc/blob/8cabf06d3c6d53ba551b65e58a13db6cdcaba16a/src/Ipc.Desktop/App.xaml.cs)[V02](https://github.com/yuan2go/importer-pc/blob/8cabf06d3c6d53ba551b65e58a13db6cdcaba16a/docs/runtime/windows-06.md)

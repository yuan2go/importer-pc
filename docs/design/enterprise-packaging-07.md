# 企业打包选型（IE-P07）

结论：**继续以现有 EXE 安装器为唯一安装权威，不做 MSI 或 MSIX。** 需要用企业工具批量分发时，用 Intune Win32 应用或 SCCM 应用直接包装现有 EXE 和静默命令。

## 为什么

现有 EXE 安装器已经负责这些事，并且每一步都有原事务回执：
- 受保护的安装库存和维护缓存；
- 管理服务；
- D 盘程序和数据根；
- 版本防降级；
- 兼容回退、旧版清理、只移除程序；
- 静默命令与回执核对。

| 方案 | 能否保住上面这些 | 主要问题 |
|---|---|---|
| MSI（WiX） | 只能把这些逻辑全部写成自定义动作 | MSI 自己也有事务和修复/卸载逻辑，会出现两个安装权威：MSI 修复可能覆盖受保护库存，“添加/删除程序”里也会出现两个条目。等于重写一遍生命周期。 |
| MSIX | 不能 | 写包外位置（D 盘数据、HKLM 机器策略）和长期运行的服务都受限，没有自定义动作；回退和清理与 MSIX 自身的版本管理冲突。 |
| Intune Win32 / SCCM 包装 EXE | 能 | 分发工具只负责送达和调用 `Ipc.Installer.exe /quiet ...`，按退出码和 JSON 回执判断结果，安装权威仍然只有 EXE。 |

## 包装要点

- **安装命令**：`Ipc.Installer.exe /quiet /norestart /log=<日志> /dataRoot=<D盘数据根> /operationId=<GUID>`。每次下发都要用新的 operationId；重发同一个 operationId 只核对原结果，不会重做安装。
- **检测规则**：读安装登记里的版本号，不靠文件时间判断。
- **返回码**：0 表示成功；3010 只在确实安排了重启时出现。其他返回码一律按失败处理，并取回日志和 JSON 回执。
- **卸载**：走“添加/删除程序”里登记的静默卸载命令，默认先做完整备份。

## 验证状态

- **已完成**：选型分析。软件升级通过人工运行完整安装包完成，客户端不提供版本更新检查或新版本提示。
- **未运行**：在隔离的 Windows 环境和真实 Intune/SCCM 租户里，用最终签名 EXE 做一次下发、检测、更新、卸载。这需要 Windows 虚拟机、管理员权限和企业管理租户；没有这次验证之前，不宣称支持企业批量部署。

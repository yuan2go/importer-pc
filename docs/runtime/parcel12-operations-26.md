# 当前 Parcel14 数据操作

当前客户端新库直接创建格式 **14**。普通启动仅核验当前格式；非当前库不得直接启动运行。SM 的运行班次和统计说明见[运行班次](sm-session-shift-exceptions-25.md)。本文是当前安装介质的操作入口；DB11历史说明及验证保留原来源，不作为当前操作指引。

## 保留数据更新

当前仅支持配置 schema3 和 DB14；不提供 DB12 到 DB14 的迁移或离线接续。开发更新按卸载清理后重新安装处理，非当前格式在写入前拒绝，原 DB/WAL、配置、原请求、回执和永久编号在未明确选择删除前保持原件，不手改格式号或哈希。

不要手动修改格式号、复制活动数据库、删除WAL或以新目录绕过原责任。安装不重写原请求报文、原始回包、永久请求号归属和历史审计；不得因安装成功便直接宣布业务恢复。

## 备份、恢复和回退

数据库文件与同名 `.recovery` 目录必须一起保管；以 `COMPLETED.json` 的完整恢复集清单和哈希核对，不把单个数据库文件视为完整备份。恢复使用维护中心，恢复到新目录，复用原隔离恢复、权限和原目录退役守卫，不覆盖原目录或猜测安装位置。

旧程序不能直接读取14。当前程序不提供旧格式升级或降级；备份不能撤销已发送的外部效果。不得只改版本号或仅替换旧EXE。结果未确认时先核对原次操作，不重复恢复或卸载。

## 原请求和设置

格口未确认的请求保留原身份、合同、目标和报文字节。内置RCS没有结果查询合同，不自动重发，也不以当前目标代替原目标。新独立扫描与重发原请求不同。

设置保存与生效分开：SM 条码规则和已配置设备的连接参数在当前执行责任收口后可热生效，混合修改待重启。尚未离位的未决作业和待提交回执仍受保护。确认离位且执行及回执责任收口的 Unknown 保留在“记录”，不占当前容量，也不阻止配置激活。若当前责任或启动检查阻止生效，旧设置继续使用；按保存提示检查“设备与诊断”及本位包裹，再重新打开。

真实SDK、客户RCS及现场验收另行记录，安装完整性和软件模拟不代替这些验收。

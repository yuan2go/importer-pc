## 操作

设置 → 相机调试，默认“扫码调试”，原连续审计、会话查询、图像导出及模拟/本地筛选入口保留在“历史证据”。左侧扫码及请求，右侧深色原图检查区；窄窗口上下排列并局部滚动，使用现行Noto字体/字号与44DIP操作控件。用户附件只作本地参考，未作为图片资产、示例条码或现场证据入库。

1. 选择左/右相机，填写操作说明，确认停止真实投放并核对两位实体。点击**触发扫码**；首次由Application建立持久实机隔离。已有其他/中断隔离不得自动接管，须核对并明确结束原会话。
2. 进入本轮时清空上一轮照片、条码、请求与结果的本窗显示。原采集owner完成循环边界和SDK内部缓存清理，再进入读取；按钮显示“扫码中…”。这是软件读码轮次，不更改相机触发参数或冒称硬件曝光触发。
3. 等待唯一有效条码。NoRead、零匹配、多匹配继续等待，不默认第一码；30秒无有效结果或权限/资源失败显式结束等待，保留隔离，不自动再开轮。
4. 唯一结果在采集回调中先关闭解码门，再锁定同帧像素、识别坐标和身份；上方显示完整条码，原图以绿色矩形框标出实际码位置。等待落盘后自动填充请求条码和真实冻结JSON，**不调用RCS**。请求/图片/原结果保持，下一包不覆盖，按钮成为**再次扫码**。
5. 可检查图片、缩放/平移/1:1及请求内容，然后点击**发送请求**。该按钮明确调用配置的真实RCS；结果显示原阶段、发送尝试、原回执预览及失败原因。重复核对同一发送命令，不换ID自动重发。点击**再次扫码**开始下一轮并清空旧显示，原请求/回执仍保留；只撤销从未尝试的旧预备意图。

结束前确认测试件已移除并核对原实体/原责任，再点“确认清场并结束调试”。发送中须等真实调用返回；停止采集不解除隔离。已发Unknown/Conflict不能被下一轮、清场、切页或重启擦除或重发。原资格允许时才恢复生产，新包不能被上一轮测试格口指导投递。

RCS待配置、无固定请求预览能力、必需业务图片/测量条件不适用时，照片和码仍可锁定，但不能制造可发送请求。健康、身份、容量、配置、原责任或管理守卫关闭时禁发。图片缺失/轮替不借实时图补配，绿色框仅来自当前选中码的实际坐标，不画示意方框。

## 所有权与隔离

`ICameraReadRounds`提供Arm/Read/Send明确契约；Application拥有一个当前轮次及有界工作者，WPF只做投影和命令调用。`InspectionRegistration`增加可选软件解码门与轮次切换标识；同一MVS owner继续取/还SDK缓冲和确认硬件连接，未开轮、成功锁定或失败/过期后不再调用解码器。选中相机开一轮，另一相机保持不解码；没有额外SDK连接、解码器、发送器、PLC或外置扩展。

每轮新命令先持久登记，再由原SDK采集线程执行缓存切换。切换中解码门关闭；所有边界确认后才开门。取消只取消等待，不伪报原生资源释放或自动复产。重连改变epoch时本轮失败，需要明确重新触发；重启先恢复业务隔离并保持解码暂停，不恢复自动轮次。

采集回调不等待WPF或RCS，原图经原有界诊断集合交付；唯一赢家先锁轮次再通知后台。后台等待原图持久化，记录原帧、码、管理主体和轮次，独立创建带`DebugRequest`证据的测试意图，复用原`PrepareWcs`冻结实际请求。SDK隔离观察仍只留下Blocked输入，它没有被生产准入或回放。测试意图不是正常生产当前包裹；记录和详情明确标识“手动调试”，其原图查看继续要求管理授权。

只有对应`SendCameraRound`命令可为该原意图打开一次进程内发送许可，原T1/T2/原始回包/T3流程保持。执行时复核管理期限、操作员、真实相机epoch/健康、生效配置/原目标/原实现、原请求完整摘要及未决责任；原软件暂停/隔离仅对此明确测试意图受控例外，不解除整站生产守卫。普通自动推进和“继续原阶段”不获得此许可。发送预算关联管理撤销，取消后的可能外部效果仍按Unknown原责任处理。

同ID不同内容拒绝；已登记的Arm/Send重查只返回现时事实，不重放。SDK切换、落盘、冻结、发送中的旧轮次不能被并发替换；多窗命令核对ExpectedRoundId。其他窗口主动开始新轮次时，本窗已经锁定的图/码/请求不会自动改成其他轮；旧轮的发送按钮关闭，须显式再触发。单纯切页后再进入可读取Application当前轮次，不创建采集或外呼。

清空显示不删除历史事实。明确停止或结束会话时可以取消当前及重启恢复的从未尝试测试意图；已发原请求、原T1报文/目标、独立接收责任和Unknown继续保留。未完成的持久命令仍沿原命令核对机制处理，不能因UI重开伪报完成。

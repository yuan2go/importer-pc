## 实施前规则

当前只接受 DB10。永久数字编号、冻结请求和归档原件是原责任，不补填缺失所有者，不以历史性能实现替换新拒绝守卫。保留独立数值类型/正值/跨作业复用与请求唯一性 SQL；保留归档原字节哈希、完整冻结请求哈希及行身份检查，保留可写打开前的只读验证和可写连接上的复核。

准备删除同一次打开中已由所有权遍历重算的最大编号查询，并为同一轮遍历复用一个带整数参数的查询命令。读取端还须拒绝与写入端同样禁止的空白请求身份；先构造原件/所有者哈希都自洽的非法反例，避免旧测试仅因缺所有者而通过。

## 验证计划

- 保留原 17 类损坏反例；封闭修改连接后核对拒绝、原数据库字节、WAL/SHM 状态、目录和所有者行不变。新增纯缺失所有者、合法重算归档哈希但冻结请求变化、单独所有者哈希变化，以及空/空格/制表请求身份反例。
- 取消必须在真实只读 SQLite 连接已读取归档记录后发生，观察到 readonly=1 且未进入可写打开边界。使用独立、已关闭的 DELETE-journal 合成副本检查字节与文件集合不变、句柄释放；正常重开另行验证，不把 WAL 协调文件变化误判为业务原件改写。
- 性能样本一次生成 2000 条明确未外发的合成原请求，1000 常驻、1000 归档，最高所有者编号位于归档。父 main 与候选使用各自精确生产 DLL、同一验证程序和数据库；各预热一次，再串行 AB×5、BA×5。只计公开构造器，预算核对、哈希、Dispose 和报告均在计时外。逐次核验原字节、所有权摘要、最大编号与退休上界，记录原始样本、中位数、范围和环境；不设虚构性能 PASS 阈值。

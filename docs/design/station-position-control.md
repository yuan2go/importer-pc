# 投递位启停

SM 左右投递位各有“启用 / 停用”按钮，普通操作员即可执行。两位初始启用；状态随本站数据保留。启停与相机配置、相机是否在线分开，启用位可独立通过键盘或扫码枪供包。相机离线只在底部设备信息区提示，不使整个作业区变红。

## 状态与责任

| 当前条件 | 点击停用后的行为 |
|---|---|
| 没有当前放置和执行责任 | 已停用，拒绝新条码，停止本位心跳，主动释放相机 |
| 当前放置尚未结束，或仍有执行或回执责任 | 停用中，拒绝新条码并停止本位心跳，保留原作业与相机连接 |
| 停用中，Application 确认放置已结束且执行与回执责任收口 | 自动变为已停用，释放相机 |
| 停用中点启用 | 取消停用，保留原请求，不重新发送 |
| 已停用点启用 | 恢复准入条件检查、心跳和对应相机连接，另一位不变 |

放置结束使用现有空托盘或换码事实，不以小车 IDLE、计时器、结果显示到期推断实物已离开。人工条码没有相机离开证据时保持停用中。软件重启也不代表原包裹离开：停用中的放置守卫随启停事实保留；原请求未确认时继续保留原编号、报文和目标。新班次不恢复已完成的旧作业卡。

## 相机与心跳

已停用位启动软件时不连接相机，保存相机参数和显式重连也不能绕过启停状态。Application 沿现有设备锁和资源守卫停止相机，退役旧会话后再释放，旧回调不能进入当前会话。停止返回成功后才发布“相机已断开”；释放失败记录完整异常、保留占用并阻断自动重连。启用后沿既有连接流程重新打开该相机。停用中保留相机采图及必要恢复，以确认原放置结束。

心跳沿原协议，不新增状态字段。启用位按已有相机编码发送，停用中和已停用位不发送；全部停用不发空报文。选择与相机连接状态无关，没有编码时不伪造身份。每次选择变更使旧在途响应失效，不能恢复停用位的小车提示；具体报文见 [RCS 心跳](../runtime/rcs-heartbeat-01.md)。

## 持久化与界面

Application 对每个位使用独立控制修订号，避免相机持续观察造成无意义冲突。命令回执、控制状态和审计在同一 SQLite 事务写入；重复命令返回原回执。启停事实使用独立审计所有者，不随包裹历史清理删除，不修改数据库格式版本。记录页可按游标查看时间、投递位、操作、操作人和当时任务号。

按钮至少 44 DIP 高。停用中显示取消方法并保留本件结果；已停用显示灰色区域和启用按钮。扫码目标不能停留在停用位；已有目标停用后移到另一启用位，两位均停用则清除目标。左右结果区保持对齐，小窗口仍保留启停状态、格口和提交动作。

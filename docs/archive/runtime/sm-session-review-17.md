## 合并前发现并补修的边界

在未修改产品源`55b41560`上新增受控原生用例，实际复现：旧成功快照等待管理状态读取时，新故障先显示；旧读取完成又把Fresh重置为true并复活目的地。该用例是显式合成显示投影，不向Application写入虚假业务事实。基线日志前两项合并检查PASS，随后故障保持断言FAIL；不把静态推断写成全部负向复现。

补修把最新通知版本和最新完整快照的发布时间分开合并，待应用完整结果不被较新的只读通知清掉；窗口保留一个最新投影，不引入事件队列。新故障取消旧纯UI应用资格，实际管理读取仍等真实返回；Base在await之后再次检查取消，故障期间不应用成功快照。新完整成功发布可恢复，但不重发原请求。存储致命事实先建立，再发快通知，避免发布者用尚未完成的致命信号清空故障。

另核对Rendering/DWM回调：在真正完成合成前被后续读到提示替换的观察，不再记为已绘制；显示提示身份与已测身份分开，后续当前观察补一次测量，提示仍去重。实际WPF同帧A→B用例要求A不记成功、B有正确指标，且没有新增RCS请求。

## 问题判断与修复

历史现场证据足以说明当时没有产生已记录的条码结果，但不能证明完整 SDK 帧到达、软件解码曾经执行，或当前没有在途业务。ReadOperations 是并发只读调用数；Ready、网卡收流、解码库加载均不是成功解码证据。厂商工具使用另一算法读码成功，也不能单独证明应用调用逻辑错误。

源码确认两个实际缺口：预览缩略图原先依赖 DecodeAllowed，扫码锁定/隔离暂停解码时也停止更新；相机缺少持续的取帧/解码阶段诊断，空结果不会形成业务记录，原健康变化日志无法解释没有条码的原因。本轮修复这两个缺口，不把它们冒充历史双相机故障的已证实唯一根因。

MvsPreview 在原 SDK 所有者释放缓冲前生成有界缩略图，与是否解码分离；最多 5 帧/秒、640×480，页面最多每秒读取 4 次，离开后预览需求 2 秒过期。无需新连接或第二个取流器。原始解码与观察/请求守卫不变，视频帧不产生业务请求。Application 校验管理权限、设备和 epoch，3 秒旧帧不显示。页面切换、卸载和撤权均清空预览。

新增 IObservationDiagnosticsSource 只读端口及每 epoch 的 AcquireCalls、NoData、Frames、DecodeStarted/Completed、EmptyFrames、Candidates、Delivered/Rejected、暂停状态与帧/解码时间。runtime-progress 的 Connections[].Acquisition 每秒更新；开启日志调试时相机每 5 秒采样，不依赖健康状态变化。FrameStale 仅用于排查，不扩大人工条码供包的准入条件。

调试页面按本轮 HTML 设计重排：左侧实时画面、右侧完整条码与同轮锁定照片同时显示，照片保留绿色定位框；下方请求条码/发送按钮及请求和响应并排。窄窗口上下排列并允许滚动。照片缩放、诊断及隔离确认使用折叠区域。页面显示真实 Application 状态，不采用原型的模拟连接/模拟发送值。既有五项导航新增矢量图标，普通模式权限不变。

## 现场定位顺序

1. 在管理模式调试页选择实际相机，确认实时画面及取帧诊断。无新帧且 NoData 增长，检查完整帧交付、SDK 状态、触发模式、像素格式与网络，不以 NIC 字节数代替完整帧。
2. Frames 增长但 DecodePaused，检查本轮是否已锁定以及现行隔离/作业状态；按触发扫码开始新轮，不绕过守卫。解码启动不增长或启动后不完成，应保留阶段与故障诊断定位调用/卡阻。
3. DecodeCompleted 与 EmptyFrames 增长而 Candidates 为零，保存同一原始图像，在同版本软件识别器中复现，并检查清晰度、尺寸与支持码制。厂商工具可作图像对照，不能替代同算法复现。
4. Candidates 增长但 Delivered 不增长，按 Rejected、故障及业务守卫检查上报；已 Delivered 后无业务结果再检查队列、过滤、原作业责任和 RCS。不要把扫描成功、请求发送和物理供包完成混为一谈。

手工条码仍可独立于相机提交；RCS、原作业责任、暂停/隔离及管理权限等原请求守卫继续生效。

## ADR COMM-A：安装技术与唯一权威

保留原生 WPF 引导、Windows ACL/UAC、并排发布和 `WindowsDeploymentSetup`。本次不叠加 MSI/MSIX 第二产品事务：现有精确扩展消费者、机级账户和跨版本责任并非通用文件组件卸载可表达。系统“已安装应用”是受保护部署登记的可修复投影，永不反向决定配置或数据位置。增加显式操作日志与重入核对，系统修复/卸载均回到同一固定 helper 和应用所有权/责任检查。不能称为 MSI 原子事务；跨系统登记失败须可从唯一登记重新修复。

程序根默认兼容 ProgramFiles；自定义本地固定卷路径必须无重解析、无数据/程序交叠，维护主体拥有且运行身份不可修改。新增受保护根批准记录只承担可信路径清单，不增加部署位置权威。根批准、复制、helper 校验、证据祖先 ACL、快捷方式、升级、修复、卸载及应答安装必须同源。

## ADR COMM-B：配置修复和草稿

首配和统一设置共用 Application 契约及既有结构化字段/精确能力目录。非生效草稿绑定原配置 hash、产品和安装身份，CAS 保存；运行从不消费草稿。草稿不要求真实连接/Production 资格，敏感参数不得以普通明文草稿持久化。结构校验、包闭包、完整部署资格分层显示；提交 Pending 与正常激活仍执行原严格校验。

未确认 Effective 的候选使用显式维护授权修复意图，固定原 envelope/hash、候选 hash 和原确认事实。在同一 owner 下读取完整责任：未结作业、原件、冲突、恢复/过载/编号隔离等均不能绕过。启动在构造任何新端口前再次验证修复意图和责任，调用原 BeginActivation/ConfirmActivation；只有候选资源启动成功才成为 Effective。失败/中断仍保旧、保留尝试、须明确重存，不能先清 Confirmation 或要求坏 Effective 先成功。

## ADR COMM-C：连续操作、查询和维护

继承现有单实例/左右位/epoch/健康/命令守卫及两套 Sportmaster 布局，补任务入口、状态原因/动作和帮助。历史筛选与导出使用业务仓库、稳定序号上界和统一筛选；流式有界导出，取消不发布部分文件。CSV 用显式文本编码和可还原精确原文，公式型合成输入必须验证。

备份列表/策略触发原完整恢复集引擎；计划不自动暂停业务，条件不足明确待执行。恢复只到新隔离根；模板仅白名单配置意图，不含旧身份/凭据/已用编号。升级前原责任预检及完整备份，卸载默认保留数据/身份/证据/扩展，不删除厂商驱动。诊断预览与离线帮助同时从运行内和独立维护可达。

## ADR COMM-D：恢复后的原机目录接管（编码前补充裁决）

继承完整恢复集与新根隔离；补充显式“原机迁移接管”，解决仅选新数据目录不足以保证原根退役的问题。恢复本身继续不改原DB/config字节；接管是单独授权操作。在原根/新根均无运行owner、恢复集合身份及原部署登记均匹配时，先落原根退役围栏，再提交唯一部署登记到新数据根；以操作回执解释中断点。运行从登记解析位置，旧根发现退役围栏则在读取业务库之前拒绝启动。接管不删除旧根，也不清新根隔离、未决请求或编号责任。

新根须经维护认证核对恢复证据后显式确认，之后仍由原请求/健康/范围守卫判断能否恢复新入场。换机时不能读取/核验原机的退役围栏及机器身份，保持隔离；原账户/秘密作用域/真实设备/精确包/资格/外部分配范围须取得实际交接证据，不用本地文字勾选伪造跨机器证明。正常恢复与迁移接管分别验收。

## ADR COMM-E：新语义的旧读取者门槛（编码前补充裁决）

收尾复核发现仅保留DB7和文字“不能旧EXE回读新库”不足：旧发布不认识初始修复/恢复接管语义。追加DB8无业务数据重写的语义迁移，沿现有future-reader迁移门禁拒绝旧7读取者；SQL1～7原文/校验不改。7→8仍先清原责任，未决原请求须匹配原发布清偿，不提前把它们封在新格式之后。升级前完整备份保留实际原库格式，不借备份迁移原库或检查副本。初始坏配置的新运行尝试在端口前完成安全迁移后仍可从独立修复接续。构建成功的DB7中间介质保留身份，不作为最终候选；DB8以新冻结源重新生成并验证旧读取拒绝/字节保留。

## ADR COMM-F：有原责任时的同源程序修复（编码前补充裁决）

升级与卸载继续拒绝Unknown/原件责任；同一SourceCommit的程序文件损坏不能因此失去修复入口。仅受保护装配层根据原登记和完整可信介质判定“Repair”，不能由计划调用者把不同源码升级标为Repair。Repair持有同一应用owner，先核验原库/原件并完整备份，再并排恢复同一冻结发布；不改原Effective/Pending、原请求/目标/合同/包引用，不清责任、恢复/过载标记，不启动业务。后续Start仍验证原实现字节、资格及原责任；不匹配继续拒绝。不同SourceCommit一律Upgrade守卫；系统项修复仍只是原登记投影。该裁决不允许回退旧EXE读新库。

## ADR COMM-G：完整恢复集中的独立维护证据（编码前补充裁决）

沿原恢复集引擎扩充 startup-maintenance 的原配置/操作记录及加密草稿/历史；这些是本包新增的私有维护证据，不能迁移后只留在退役原根。受同一安全路径、文件/容量配额、逐字节哈希和完整清单验证约束，派生锁文件不备份；备份时与草稿CAS互斥。恢复仍把新根隔离，不把原根退役围栏、旧接管确认或程序部署登记当作可复制的启动权威。DPAPI密文保留原作用域，跨机不会因此取得解密或生产资格。

### 静态组件审查收尾修正

使用独立构建、RSA-PSS签名的TestOnly参考包实际调用冻结介质预检，发现安全解包要求目标根已存在，而审查路径只创建了父临时目录。修正为在解包前创建该包的哈希目标目录，保留原路径/链接检查及最终清理；不执行组件、不创建业务数据根。合法签名包、内容篡改、缺少精确依赖、冲突版本和Production拒绝TestOnly信任必须在新冻结介质上分别验证；原失败介质保留身份。

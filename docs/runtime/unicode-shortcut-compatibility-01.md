
# Unicode 快捷方式的创建、修复和清理

本增量继承 PR110 `980a1383` 的 IShellLinkW/IPersistFile 实现，保留精确中文名、菜单参数、上一部署归属和安装权限。工作范围见[工作包](../work-packages/WP-IPC-UNICODE-SHORTCUT-COMPATIBILITY-01.md)，真实源码、失败及回归见[验证记录](validation/unicode-shortcut-compatibility-01.md)。

## 运行行为

创建和归属读取统一使用 Unicode COM；不调用 Resolve，不改系统区域或全机代码页。桌面名仍为 `菜鸟供包台.lnk`，开始菜单仍有运行、启动修复、安装维护三个版本化入口。四种选项和历史默认保持。

链接的完整原目标和原参数决定归属。改目标或改参数的条目保留。更新稳定桌面链接仍须同应用、同账户、同数据根，且目标准确属于受核验上一部署。修复不能采用用户可写描述文件、同名 EXE 或乱码猜测来接管链接。

精确候选位置上若是目录、reparse、无文件目标的链接、损坏文件或无法读取的条目，操作明确失败并保留原件；不再将目录或空目标视为已清理。只对确实不存在的文件执行幂等跳过。其他真实 IO/COM 错误继续向上传递。

COM 包装对象只拥有一个根 RCW；Dispose 可重复调用，释放后访问抛 ObjectDisposedException。接口视图不分别 FinalRelease，不通过强制GC回收资源，不在跨线程共享包装对象时声称线程安全。

## 故障后继续

安装/升级沿原部署流程，先提交唯一受保护部署登记，再创建快捷方式投影。投影失败仍由原流程记录 CommittedNeedsSystemRepair；不能把它报告为完整安装成功，也不能回滚原业务责任换取成功状态。

缺失入口和已归属条目的描述/图标可由原启动修复入口重建；用户冲突条目必须先由所有者明确处置，再沿原维护入口继续。产品不会自动删除冲突文件来重建链接。隔离测试中的“移动冲突夹具后重试”是夹具所有者的显式操作。

卸载按固定清单识别当前中文入口、历史带后缀桌面入口以及 Importer PC 下的历史菜单。旧版卸载不删除新版稳定桌面；原 EXE 缺失时仍读存储目标，不搜索其他版本。分享冲突解除后可以重入；尚存目录、空目标或坏文件不能伪装成成功清理。若上层已提交 RemovedDataRetained，继续沿原介质、维护日志与 ResumeRemoval 核对，退役事实与清理完成分别处理。

本轮没有改变上层登记、备份/权限资格、受保护根策略、数据库/SQL、原请求或自动重连合同。也没有引入暂存替换协议或声称消除了跨进程 TOCTOU；中断 Save 的物理故障与恶意竞态未获新验收资格。

## 隔离回归

在干净 D 盘源码树执行：

```powershell
. ./scripts/project-environment.ps1
./scripts/verify-shortcut-codepages.ps1 -Output D:/DevCache/importer-pc/usc-new-evidence
```

输出必须是全新目录。脚本为三个独立 apphost 选择 en-US、zh-CN、UTF-8 manifest；原选项回归和新增生命周期回归都先严格核验实际 GetACP=1252、936、65001。脚本保存各日志、manifest、源码状态及实际二进制哈希。不调用正式安装，不登记 HKLM、任务或服务；不改变系统区域设置。

原生目标读取另用独立 unmanaged-buffer COM 声明验证；中文及超出GBK的字符、历史入口、修复、升级、保护/IO失败、路径守卫和有界资源循环分别计证。目标 EXE 均为不执行的合成文件。Windows10非UTF8 manifest 的限制、真实安装/UAC/卸载、受保护描述文件恢复成功、目标IPC及现场24h/72h继续按验证记录区分 NOT_RUN/BLOCKED。

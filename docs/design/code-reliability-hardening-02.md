# 代码可靠性02 · 当前增量设计

适用于[工作包](../work-packages/WP-IPC-CODE-RELIABILITY-HARDENING-02.md)，继承稳定性01/PR100及DB9。以下为现行增量约束；[实施](../runtime/code-reliability-hardening-02.md)和验证结果独立记录。

1. 崩溃验证只在隔离Simulation目录用真实Application和SQLite。外部控制器掌握进程句柄，在明确屏障收到后终止整个被测进程；没有finally/Dispose清理。来源日志与模拟服务端接收账由控制器独立保留。恢复只核对/应用已有原件，不放开Unknown或新造请求。测试进程不是生产服务。
2. 启动与停止共享所有权边界；停止先围栏并取消启动，等待实际启动终止，才关闭已构造资源。超时/取消不等于结束，不提前销毁连接、句柄、CTS或租约。重连及旧回调仍沿原Epoch/资源串行门；不增加业务状态权威。
3. 日志查询固定文件对象/长度/顺序，首次扫描形成有界定位索引，后续页只读取相应原记录；原文不整体缓存。所有原位置继续按文件ID、行号/hash验证；定位缓存超过131072行时明确提示并使用原有流式读取，完整原文/导出继续保留；不把缓存预算变成记录上限。快照撤权/过期/淘汰立即取消、禁止新租用，最后一个真实读取退出再关闭文件/CTS。查询四份、读者并发及运行停止排空保持。
4. 日志表格摘要、原记录解析及上下文拼接在后台完成。一次呈现采用总字符预算，超出部分明确标出，仍可用既有全部匹配/时间范围导出完整脱敏原记录。布局、字号、200条页、0～200上下文、操作回执、原文/hash、权限与迟到保护保持；不是UI重设计。
5. SQLite仍WAL/FULL及有界等待；先持久承担输入再交接成功。写锁是共享存储风险，单侧通信异常不是共享故障。真实争用测量后再决定等待预算，不将取消包装为底层完成，不无限排队/重试。
6. RuntimeJournal探测间隔和查询寿命使用单调计时；只在这些必要边界提供可控时间依赖。记录时间、外部时间、审计与按UTC日期的跨重启保留保持墙钟语义。健康证据前跳到期、回拨到未来必须诚实失效，不修改全机时间或新建通用时间框架。

历史设计、原审查、失败、SourceCommit、SQL及checksum保留；不改变D/RV批准，不以合成短测替代真实SDK、物理断电及24h/72h资格。

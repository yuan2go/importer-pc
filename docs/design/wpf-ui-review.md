# WPF 工业桌面 UI 审查方法

用于 SM 供包台及其必需共享界面的设计审查与局部整改。目标是看得清、操作明确、简约一致，且不损坏原业务。入口是项目级 [hallmark-wpf](../../.agents/skills/hallmark-wpf/SKILL.md)。这是一份工作方法，不是新设计系统或现场资格证明。

## 规则与材料

[AGENTS.md](../../AGENTS.md) 是当前产品规则；相关说明从 [INDEX](../INDEX.md) 读取，重点是 [字体](typography-01.md)、[作业卡](work-card-states.md)、[导航](operator-navigation-20261103.md) 和 [生命周期](../runtime/lifecycle-ux-current-guidance-01.md)。发生冲突时列出双方位置，以现行规则和真实调用核对；不直接把较旧文档的状态表写回代码。用户提出新规则时先说明与现行规则的差异，再在同一改动中同步规则与实现。

先看原始材料：当前提交的 XAML/C#、实际装配的资源、绑定与命令、运行截图、输入过程、状态快照和相关测试。历史效果图只是设计参考；没有提交号的截图不能用来证明最新 main 的缺陷或修复。

当前资源入口为 `src/Ipc.Desktop/Themes/Workstation.xaml` 和 `src/Ipc.Presentation.Wpf/UiTypography.cs`、`TypographyScale.cs`。沿宿主实际加载路径确认使用者。颜色复用主题语义键，字体沿用已交付的 Noto Sans CJK SC Regular/Medium，不另建调色盘、字号表或字体平台。

## 从 Hallmark 保留什么

本适配参考 Hallmark 2.0.0 固定提交 `407fa689f4a276f2fd389208d271d0fef08f5058`，只采用审查方法。完整来源与许可见 [来源记录](../../.agents/skills/hallmark-wpf/UPSTREAM.json)。

| 上游方法 | WPF 适配 |
|---|---|
| Pre-flight：先读项目与真实材料 | 先确定生效的宿主、资源、应用契约和原生基线，不先选风格 |
| Audit / scoped redesign | 默认只读审查；明确授权后才按目标控件做局部整改 |
| Before / kept / after | 记录并复核绑定、命令、输入、窗口归属、状态和数据语义，不只比较图片 |
| Floor / Reflex / Finish | 本项目重新定义为行为底线、设计问题、修饰建议，不沿用网页 gate 编号或总分 |
| Fresh review | 有条件时独立复审，并问“旧版做对了什么”；否则明确是自审 |
| Browser render checks | 换成真实 WPF 窗口、DPI、输入与既有 UI 验证；网页检测结果不作为原生结论 |

不引入网页主题抽签、跨页面求异、Hero、图片占比、营销文案字数预算、CSS/OKLCH 规则、浏览器 sloplint 或运行时依赖。上游主 skill 不直接作为本项目指令加载。真实状态标识和双工位分组不因“不要卡片/状态点”等一般审美禁令被删除。

## 一轮审查怎么做

**界定范围。** 写清目标页面、当前基线、改动文件与必须保留的操作。`audit` 不改项目；`study` 只提取原则；`refine` 才落实明确要求的修改。只改退出窗，不顺带重做导航、安装器或业务层。用户已授权的范围不重复索取确认。

**建立保留清单。** 从真实使用链记录 `DataContext`、`Binding`、`Command` / `CommandParameter`、事件、校验、`x:Name`、AutomationId、快捷键、焦点/选区、复制/滚动、Owner/模态归属及取消行为。不是永远禁止改内部名字：授权整改确需变更时，要列出全部引用、等价行为和验证；不能静默丢失能力。视觉变更不新增权限判断、请求、防重或恢复策略。

**检查状态而非单张图。** 至少覆盖目标控件的正常、不可用及异步变化；按真实业务选场景，不为了凑“八状态”发明业务。检查禁用原因、处理中的反馈、返回结果与失效状态；不能以按钮 `IsEnabled` 代替 Application 执行时的守卫。

**按影响整改。** 先修误导和操作障碍，再修层次、对齐及密度，最后处理边框等细节。复用现有样式和语义资源，不为一个弹窗引入通用设计平台。只读审查列问题即可，不为了显得完整凑数量或加装饰。

**同条件复核。** 比较前后状态与操作，列出保留、改变和未验证项。输出的是证据和缺口，不是“美观评分达到 90 分，所以可交付”。

## 审查分级

| 类别 | 例子 | 处理 |
|---|---|---|
| 行为底线 | 提交串工位、PDA 拼码、旧格口冒充新结果、Unknown 被隐藏、焦点不可辨、取消执行退出 | 确认的回归必须修复；证据不足明确阻断相应结论，不能审美豁免 |
| 设计问题 | 顶栏错行、左右操作行错位、弹窗大数字抢占注意力、无意义容器、普通按钮过度强调 | 说明影响和最轻有效整改；合理保留须有当前场景依据 |
| 修饰建议 | 不影响识别、操作的少量间距或边框差异 | 建议项，不单独阻断交付，不扩大任务 |

“未验证”不是“通过”；“未发现问题”也不是“所有状态已检查”。记录实际覆盖范围，不把静态发现当作运行复现。

## 针对当前供包台的检查

| 区域 | 核对内容 |
|---|---|
| 主窗口与菜单 | 不新增品牌标题；顶部供包状态和右侧统计同基线；反馈窄栏无内容时收回；52 DIP 收起栏与边缘拉手不遮挡内容，图标有说明、键盘焦点，视觉变小不等于命中区域失效 |
| 工位状态 | 等待投包、RCS 离线、已停用采用既定居中结构；离线保留条码且解释连接问题，不要求纠正有效条码；当前格口、拒绝、处理中及 Unknown 不被空态覆盖 |
| 并发与输入 | 左右卡片和操作行对齐；一次放置/重连保留规则不变；PDA A/B 不拼接、不串位；F2/F3、Esc、切页、切窗和其他输入控件的焦点语义保持 |
| 设备与业务 | 相机离线仍可合法人工输入；RCS 在线不等于结果成功；小车状态只是提示，不新增准入条件；停用中不伪装成已释放 |
| 退出确认 | 遵守当前约580×340 DIP紧凑布局和字体角色，长内容可完整读；不用大警告图标、数字卡片或黄色横幅；默认取消，确认窗 Esc/×取消；继续退出之后仍保护草稿、停止和释放 |
| 退出事实 | “状态读取有效”不是“业务安全”；Unknown 数量0不是无历史责任；可见作业不是未完成作业数；不能声称草稿已保存、已发请求被撤销或资源已释放 |
| 共享资源与性能 | 样式调整覆盖实际使用者；不在刷新时重建连接或控件树；检查虚拟化、订阅释放、Dispatcher 阻塞及持续动画，但不能由一次审查推断24×7合格 |

简约依靠去掉多余强调和重复信息，不依靠缩小关键文字或删掉异常说明。大号格口与普通确认窗的数字是不同信息角色，不能机械统一。主题已定义的真实状态色不因审美偏好更改含义。

## 原生验证与必要测试

先在 Windows 项目根目录执行 `. ./scripts/project-environment.ps1`，按当前环境规则使用 D 盘隔离输出、合成数据及测试配置，不操作正在供包的实例。测试入口以执行提交的 `tests/Ipc.Desktop.UiVerification/Program.cs` 为准。

| 改动风险 | 优先复用的原生入口（按需选择） |
|---|---|
| 退出确认 | `--station-exit-dialog`；涉及关闭生命周期再核对 `--startup-close` 及相关业务回归 |
| 待机/离线/停用构图 | `--home-centered-states`、`--station-position-control-ui`；涉及暂停遮盖结果时加 `--paused-workstation` |
| 导航/窗口 | `--operator-workspace`、`--management-center`、`--window-preference` |
| 输入与焦点 | `--position-input-ui`、`--continuous-pda-input` |
| 字体/尺寸/共享布局 | `--chute-readability`、`--station-responsive-ui`，并抽查受影响的其他宿主 |

命令示例（每次一个场景；第一个程序参数是仓库路径，不是开关）：

```powershell
. ./scripts/project-environment.ps1
$repo = (Get-Location).Path
dotnet run --project tests/Ipc.Desktop.UiVerification -- "$repo" --station-exit-dialog
```

当前入口按分支选择场景，不能把多个开关拼进一次运行后宣称全部执行。运行前读对应夹具和依赖；安装器检查等要求同源发布产物时，按其现行说明设置，不能借用旧提交的二进制。

布局基线参考1366×768 DIP，覆盖目标设备实际可用客户区及低高度窗口；按改动涉及的范围选择 Windows 100%、125%、150% 的真实缩放。记录物理分辨率、DPI、客户区DIP、最终渲染字号与场景。缩放PNG、浏览器截图和仅设置WPF窗口大小不是实际系统DPI证据。跨显示器是目标部署需要时的追加场景，不能虚报覆盖。

检查正常/悬停/按下/禁用/键盘聚焦等适用控件状态，焦点样式应一致且不遮挡命中；不会仅因为去掉大蓝框就关闭所有焦点提示。保留长中文、长条码、双位内容不等长和异步刷新场景。可读性须结合实际操作距离；真实操作员验收单列。

只新增覆盖现行风险的缺失断言，不做整页像素锁定、私有实现字符串匹配或无关测试扩张。变更方法文档/skill本身时，仅做结构、链接、来源、范围和差异检查；不为文档引入业务依赖或伪造Windows通过记录。代码变更再按AGENTS执行构建与受影响测试。

WPF焦点机制参考 [Microsoft FocusVisualStyle](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/styling-for-focus-in-controls-and-focusvisualstyle)；列表虚拟化与模板性能参考 [Microsoft 控件性能](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls)。这两类检查仍需实测，不能只凭属性存在判定通过。

## 交付记录（写入当前 PR 或用户指定位置）

不为每次小改新建工作包；持续规则更新当前文档，证据放现有流程或 PR。报告可直接按以下结构填写：

```text
范围/模式：audit | refine | study；目标页面；保留项；明确不做什么
身份：基线提交 → 改动提交；OS；物理分辨率/DPI；客户区DIP；场景与数据来源
发现：编号 | 类别 | 事实/判断/待验证 | 文件:行或截图/日志 | 操作影响 | 整改/保留理由 | 验证
保留核对：输入、绑定/命令、窗口/取消、权限、原请求、配置、协议、数据
前后对照：同场景截图或说明缺失；旧版做得更好的地方；复审人或“自审”
结果：文档/静态检查、编译、本机测试、CI、Windows原生、真实SDK、客户RCS、现场验收分别填写
未运行/阻断/失效条件：缺少什么；哪些结论因此不能成立；状态来源、显示环境或业务规则变化后重验哪些项
```

截图、日志与配置按 [PUBLICATION](../baseline/PUBLICATION.md) 处理；不把用户上传图、真实条码、凭据或客户数据自动公开。生成图、合成运行、真实设备及客户现场各有边界，不相互替代。

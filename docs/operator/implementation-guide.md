# 实施与维护手册

适用：IE01候选，SM 1.0.2。打印稿与本文同源，附完整故障目录；实体打印、原生截图及新人旅程尚未验收。当前实现与待实施项以[进度](../runtime/industrial-engineering-01.md)为准；本手册不为缺少的功能提供虚构入口。

## 准备

取得获准分发的同源完整介质、版本/源身份/哈希、D盘容量和Windows管理权限；明确目标OS、网络、相机IP/物理序列号/编码、仓ID/生产线ID/供包台编号及RCS合同。全部开发缓存和测试数据使用D盘。受保护根读取管理员配置，不以链接或新空目录绕权。

当前SM使用内置MVS采图、进程内识别及内置RCS，无PLC；不要准备TCP读码端口、MvCodeReader或外置扩展信任。现场SDK字节、ABI、物理设备及分发许可仍须核验。各次托盘放置仅发一次RCS请求；识别/保存/请求接受/物理完成分别记录。

## 安装与更新

1. 完全停止原软件，保留当前记录及未决包裹；核对安装介质来源与目标版本。
2. 打开安装器，核对程序/数据目录和操作种类。新SM默认程序`D:\CainiaoSupplyStation`、数据`D:\ProgramData\ImporterPc\data`；已有站保留原登记路径。
3. 明确安装并完成Windows授权，等待真实阶段和完成回执。原责任或资源检查失败时保留原件处理。
4. 以普通用户打开，完成或核对配置生效；安装完成不等于相机/RCS就绪。
5. 结果待确认时只核对该次安装，已提交但入口失败只修复原系统入口，不创建新操作覆盖。

普通路径拒绝降级、缺少恢复安全代次和同版本异字节介质。仅现有获准的特定数据升级路径可执行，格式/结构不明时写入前拒绝。未决安装记录会阻止新安装；不得手动修改其状态。

静默参数为候选功能，必须在已提权的部署上下文执行；不弹产品窗口、不自动启动设备、不自动重启。示例路径需由实施人员检查权限和归属：

```text
Ipc.Installer.exe /quiet /norestart /log="D:\deploy\station-01.log" /dataRoot="D:\ProgramData\ImporterPc\data" /operationId=<本工单的32位GUID>
Ipc.Installer.exe /quiet /repair /norestart /log="D:\deploy\repair-01.log" /operationId=<另一工单的32位GUID>
```

首次日志只写新文件，不覆盖已有文件。`/log`为可读文本；独立JSON回执写到同一路径加`.receipt.json`，含相同操作ID、退出码及文本日志SHA256。启动日志不代表完成，只有结束回执核对后才按退出码处理；回执发布失败时保留原事务与暂存证据，不覆盖或伪报成功。

自动化为同一工单保存同一个非空32位GUID；重放时须保留原参数、日志位置和同字节介质。重放只核对原事务，明确已完成且当前登记一致才返回原成功码；不会重新安装、备份或覆盖原日志/JSON回执。日志缺失/被外部改动另行标记，不把它当成部署权威。Unknown/进行中保持1627，不能换ID绕过；未提交的准备物和备份保留。

全部SM程序、数据和机器政策根须使用管理员批准的D盘位置；未配置受保护D盘存储根时在机器变更前拒绝，不落到C盘。日志父目录也须由管理员保护：缺失的目录按明确ACL创建，已有可被普通用户改写的目录拒绝，不自动放宽权限。已有存储位置的迁移仍须独立核对，不自动修改HKLM。高级逐站计划仍使用原`--deployment-plan`协议及其原退出码；不能与简化EXE退出码混用。静默安装/真实系统往返尚未完成隔离VM验收。

## 新版本提示（可选）

软件不会联网检查更新，也不会自动安装。需要提示现场有新版本时：

1. 在本机数据目录（默认 `D:\ProgramData\ImporterPc\data`）下建 `updates` 文件夹，放入 `release.json`：

   ```json
   { "Product": "importer-pc-sportmaster", "Version": "1.0.3", "PublishedAt": "2026-11-10",
     "Summary": "一句话说明", "Media": "\\server\share\Setup-1.0.3.exe", "Sha256": "<安装包的 SHA-256>",
     "Revoked": ["1.0.1"] }
   ```

2. 多台工位共用一份说明时，在 `updates` 里只放 `source.txt`，第一行写共享文件的完整路径，例如 `\\server\share\release.json`。
3. 维护中心的“软件更新”会显示：有新版本、已是最新，或当前版本已撤回（`Revoked` 里列出的版本）。只有当前装的是预发布版时，才会提示预发布版本。
4. 说明文件读不到、格式不对或共享 3 秒内没响应，只显示“无法读取”，不影响作业。安装仍按上面的“安装与更新”步骤执行。

## 首配与日常设置

1. 沿独立五步首配填写真实站点字段，不将示例值、模拟响应或另一站身份复制进生产默认。
2. 每台相机填写实际IP、物理序列号和唯一编码；取格口与心跳共用映射。未使用相机的IP/序列号同时留空。
3. RCS空地址为待配置，有地址必须完整；缺RCS不能取格口。人工键盘/PDA是独立来源，不要求相机已配置，但仍受RCS、容量及原责任守卫。
4. 核对保存结果；纯条码规则、已配置相机/RCS的连接参数在符合条件时立即生效，只重连改动设备，另一位继续供包。未确认原请求、维护或调试读取时，以及启停设备或混入其他设置时，保存后须重新打开。新地址连不上会显示离线，配置生效不等于已连通。
5. 按[作业卡](quick-guide.md)核对首件，真实采图、识别、RCS传输、业务结果分层记录。

场景模板、配置旁连接检查及完成能力清单尚在P03实施，不把本手册当作已新增这些控件的声明。四类参数仍编辑同一完整候选；发生并发修改时重新核对，不覆盖其他窗口。

## 管理模式与忘记密码

管理模式与操作员身份、Windows安装权限分别管理。普通模式仅作业/记录，管理模式开放设置/日志/调试。会话15分钟，最后两分钟可从菜单续用15分钟；到期、退出、改密或重置撤销原授权，未保存草稿保留但受限。

忘记管理密码：打开“忘记管理密码？”→输入并确认新密码→Windows管理员授权→核对本站标识并确认重置→使用新密码重新进入。没有共享根密码，也不把Windows管理员身份当成日常管理模式。服务缺失/损坏先修复同源安装，不能删除凭据文件当作首次设置。

重置报错后先“核对上次重置”；如果尚未完成且确认仍有效，等待后再核对。只有服务确认旧请求已完成或旧确认已失效，才能结束原次处理或重新发起。重置不改操作员、相机配置或原请求责任。

## 卸载与残件

1. 完全关闭业务实例，从Windows应用列表进入本产品维护。
2. 核对原部署和备份位置；完整备份默认开启。若不备份，明确接受恢复风险；备份失败不会自动改成不备份。
3. Windows管理员授权卸载。程序移除，配置、业务记录、设备身份与未决责任保留，不需要业务密码。
4. 核对“程序已移除/数据保留/残件/需重启”的实际结果；独立维护缓存和原库存支持继续清理，不依赖原安装包。
5. 新卸载不会安排重启删除；锁定文件保留，解除占用后续清。旧卸载已经登记的重启义务仍按原回执核对，不手动递归删除任意目录。

旧部署没有新维护缓存时需要受信修复路径，不能猜删。永久删除仍在P02后续实现，当前不提供“一键彻底删除”操作步骤。未知/未交接责任即使能卸载程序，也不能因此永久删除。

卸载意外中断时，先选择“查看上次卸载结果”。只有明确显示“登记切换前中断”，才可选择“结束这次未提交的卸载”，经Windows授权再次核对后重新审阅；这一步不会卸载或删除业务数据。已退役则继续原库存清理，无法核对时保留原操作并联系实施人员，不能直接发起第二次卸载。

### 配置或软件无法打开时，仅移除程序

此方式只适用于具备当前生命周期协议4、受保护维护缓存和应用停机围栏的新SM安装。旧安装无法证明停机和原操作恢复能力时拒绝执行，不把未查到进程当作安全证明。

1. 完全关闭本应用的所有窗口和运行实例，从Windows应用列表打开维护。
2. 明确取消“卸载前创建完整备份”，展开“软件或配置无法打开时”。此方式不会创建完整备份；如仍可正常备份，应优先使用普通卸载。
3. 点击“检查仅移除程序的条件”，完成Windows授权，核对程序目录及保留的数据、配置目录。仍有运行者或停机能力不能核验时先处理原因。
4. 明确“仅移除程序，保留数据”，再次核对不备份的后果。程序移除过程不读取、修复或清空作业账，也不解除未知责任。
5. 结果未确认时只查看上次卸载结果；有残件按原库存续办。数据与原记录全部保留，重新安装后仍须核对原责任。

当前为候选实现：实际Windows令牌/UAC/SCM及最终EXE的损坏配置卸载矩阵尚未验收。停机围栏保持到资源完整释放；只返回“停止”或资源释放失败时，不允许继续卸载。Windows数据和机器租约根均须使用管理员批准的D盘存储。

## 程序回退

1. 完全关闭业务软件，从Windows应用列表打开维护，展开“版本回退”。
2. 选择D盘完整备份目录，点击“检查回退条件”。无兼容声明、存在未决请求或程序仍在运行时，先按原因处理；不要删除记录绕过检查。
3. 核对当前/上一版本和备份位置，明确确认“备份并回退”。Windows管理员授权后，等待完整备份和原次切换结果。
4. 结果未确认时点击“核对上次回退”；若登记已切换而入口未完成，只点“修复上次回退的入口”，不要再次回退。
5. 完成后关闭维护窗口，从开始菜单以普通用户重新打开。回退只切换程序，业务数据保持当前状态，不会还原旧数据库或重发原请求。

此入口为IE01候选实现，最终安装包/系统矩阵尚未验收。历史版本缺少新兼容声明时禁用是预期行为；需旧数据才能运行的版本不能直接回退。

## 清理旧版本

1. 确认当前版本已用普通用户打开并完成本次更新必要观察，再完全关闭业务软件。构建、回环或模拟测试不能代替这次观察。
2. 在维护窗口选择完整备份目录，展开“清理旧版本”，明确勾选已完成观察，点击“检查旧版本”。
3. 审阅拟删除目录与保留原因。当前版、上一版、兼容回退候选及归属不明的版本保留；有未决责任、待生效配置或其他历史站点根时不能清理。
4. 明确“备份并清理旧版本”，完成Windows授权，等待原清单结果。不会删除业务数据、清单外文件，也不自动安排重启删除。
5. 失败后先“核对上次版本清理”；文件仍被占用时关闭占用程序后“继续原清单清理”。也可明确“保留余项，结束清理”：未确认余项保留，原范围退出后续清理候选，不冒充删除完成。

当前是管理员明确发起的清理，尚无自动普通启动成功证明，不会更新后静默删除。合成文件/SQLite和原生控件测试不代表受保护库存、UAC或最终EXE生命周期已经验收。

## 完整备份与恢复

备份包含数据库及同名`.recovery`配套恢复目录，以`COMPLETED.json`及完整文件集合/哈希为准。单个数据库文件不是完整恢复集；不得复制正在使用的db、删WAL或改格式号。

恢复使用现有维护入口和新隔离目录，核对原机退役、机器身份、RCS范围及实体交接后才按原政策启用。备份不能撤销已发送的外部效果。程序回退不能把旧数据库覆盖到当前根；数据不兼容时保留原件并联系实施人员。

新站日志/已结历史默认7天；保存保留策略不等于已执行清理。只处理符合条件的已结历史，未决和永久请求身份仍保留；不能用清理未知记录释放“容量”。

## 故障与交接

按[故障目录](fault-codes.md)处理；主句说明发生什么，下一步必须说明包裹怎样安置。记录版本、带时区时间、本位、原作业/操作ID、已知及未知事实，按现场批准渠道交接。当前RCS没有权威结果查询，不用替代POST假装查询，不盲重发。

日志需管理模式，查询/导出范围固定。维护中心及诊断页已有“导出诊断包”入口：进入管理模式，选择D盘上程序/配置/数据目录之外的新ZIP路径，导出后核对文件。诊断包仅含白名单摘要，不是备份，不包含原始日志正文、业务库、条码、图片、凭据或原报文；当前包的manifest标为Partial，界面也提示“含未收集项”，说明24小时日志覆盖不能证明完整。安装项包含登记摘要，以及安装、静默部署、卸载、回退、旧版本清理每类最近一次回执的状态、时间、动作和退出码，不含路径、账户、哈希或文件清单。技术支持按清单缺项继续核查，不能把“没有摘要”当作“没有异常”。取消、失权或校验失败不发布完成文件。

软件右上角“帮助”（F1）任何人都能打开：内含供包员作业卡和故障目录（与打印稿同源），以及“导出诊断概览”。概览不需要管理模式，只含健康计数、版本和磁盘/网卡状态，不含日志、配置或作业，不证明设备实际联通。实际版本/验证边界见进度记录。

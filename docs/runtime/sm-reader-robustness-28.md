重复搜索只在原图位置及连续印刷图案证据一致时归并。同码不同位置仍是多候选；同位冲突码拒收整帧。堆叠同码之间的空白带用于拆开原生识别器偶尔合并的扫描带。完整候选交既有Application筛选；默认StrictSingleCode拒绝多候选，不选择首码。不同帧仍分别观察、分别上报，不合并实体，quantity仍为1并由RCS去重。

四角映射回原图，原图字节不改；注释角点可裁到图像边界，但码基线端点必须属于原像素。搜索区域最多32个，总旋转像素4Mi，图案校验最多8Mi次采样、扫描带高最多4096、候选不足64条；触及上限拒收整帧，不输出截断候选。所有池缓冲、pin和原生条码在成功/失败路径释放。固定包装器的图像视图只有终结器；在原生调用期间显式保活视图和选项，避免GC提前终结导致坐标损坏，由包装器终结器释放视图。强制并发GC的32帧池缓冲测试覆盖精确码值、原像素及坐标；旧实现已负向复现。依据为该NuGet固定提交的[包装器实现](https://github.com/zxing-cpp/zxing-cpp/blob/287c85df6f961c8efbfb5ffd736cd9457b8b890e/wrappers/dotnet/ZXingCpp/ZXingCpp.cs)。搜索为有界CPU工作，不承诺目标IPC吞吐；当前最新帧背压、清理及健康守卫保持，现场需测实际节拍。

## 快照、推送和原请求

Application在同一短锁内把最新相机帧水位和对应观察反馈写入快照。WPF先应用观察反馈，再应用帧水位；当前输入的设备、epoch、SourceEventId与最新有码帧不一致时，只能展示对应的新条码等待态。缺少配套提示时清空条码，禁止旧格口/任务/图片；超时仍失效。旧快照不能回退水位，新窗口也使用同一守卫。单独实时通知、单独快照、通知延迟均有回归。

人工来源按新观察单调时钟独立处理；另一投递位保持独立。旧RCS响应只更新原作业，不能借用为当前包裹格口；Unknown原请求责任不解除，不盲重发，不以无码、同码或等待时间推定实体完成。

# SM 包裹轮次与原请求生命周期

业务依据为 2026-11-11 用户确认的 C01—C20。每位仅一个当前 RoundId；条码可以为空。轮次、自动重新触发资格、原请求执行责任分别持久化，UI 不用最后一条作业猜测当前件。

## 到位、输入与物理证据

有有效bcrCode的生产位以可信小车到位代次作为唯一自动重新提交依据，车号相邻变化才推进；每次到位最多一次生产提交。空盘不再结束并开放该路径，视觉只提供上件、放稳与诊断。完整契约、缓存切换、人工输入版本及异常撤车恢复见[按小车到位分轮](sm-vehicle-arrival-rounds.md)。

空车不创建轮次、不开始识读期限。可信上件或首个正式候选建立RoundId，沿现行合法性、允许与整串排除规则筛选；排除底码不建件，两个同码标签仍按两个候选。多码、非法码可在默认1000ms期限内纠正，放稳、筛选、留图和持久接纳消耗同一窗口，不因新帧续期。到期只允许人工补录。没有可信上件且无正式候选保持等待。

## 一次提交与异步执行

相机/PDA/键盘竞争同轮一次提交资格。接纳事务关联 RoundId、OperationId、CommandId 和冻结原请求；人工接口在持久接纳后返回。本位输入决策不等待网络，也不让本位 Busy 锁另一位。受管理执行每位最多保留128个真实在途任务，防止轮次已结束而远端持续不返回时无限累积；达到边界就在取得提交权前明确拒绝本位本次输入，保留补录及取下能力，不影响另一位额度。不复用扫码队列大小或历史 Unknown 数量作为外呼限额，不宣称此技术上限已经通过现场节拍验证。

执行器取得实际执行资源后，在首次调用端口前重新核验当前轮次和发送守卫，持久记录一次发送尝试。轮次先结束则准备请求不外呼；尝试先成立则原调用按原目标、报文和期限收尾。禁止自动重试、假查询、假取消或依赖远端业务去重。RCS 每次新提交是独立包裹，分配格口可能已调度小车，本地结束不能撤销远端效果。

RCS 客户端保留总计8个HTTP/1.1连接的边界：取格口独立池最多7个、心跳独立池最多1个。取格口在端口内先取得单次发送许可，左右位各自FIFO、两边都有等待时轮流获得释放的资源；等待容量各128，等待预算沿用原请求超时，不新增现场队列参数。等待时没有发送尝试；轮次结束取消该轮尚未尝试的等待。许可就绪后 Application 再核验轮次、权限、连接及准入，在外呼前持久记 T2；发送只可执行一次。超时未取得许可时明确记为本件未发送，不伪造RCS拒绝或Unknown，不自动重试。已进入发送的许可直到实际调用及响应正文收尾才释放，停止等待真实排空。

这里的执行任务上限、发送许可、调用 SendAsync、正文开始写入、远端接收及业务接受分别留证。许可不证明已写正文，T2不证明远端收到，本地HTTP结果不能替代客户RCS接收日志。修复前受控回环复现了8请求挂起时第9件已登记尝试、结束轮次后仍被连接池发送的问题；`sm-dispatch-resources` 以实际HTTP阻塞验证零晚发、左右公平、心跳及停止排空。[.NET连接池语义](https://source.dot.net/System.Net.Http/System/Net/Http/SocketsHttpHandler/ConnectionPool/HttpConnectionPool.cs.html)与[独立处理器连接池](https://learn.microsoft.com/dotnet/fundamentals/networking/http/httpclient-guidelines)说明了为何资源等待必须在T2之前控制，不能把连接数差异本身当作缺陷。

可信换车立即结束旧当前轮次及展示，不等待旧 RCS；取下与视觉空盘不能给同车再开生产提交。本位继续启用且已经进入当前人工失败待确认分支时，移出仅记物理事实，须点击目标轮次的“已取下包裹”后继续供包。操作员主动停用本位时，按本轮实际调用及回执责任收口后结束轮次，不要求空盘或另点取下确认；停用不产生可信物理移出的证据，自动重复抑制继续保留。旧轮先结束、失败后到则只入记录，不弹旧按钮。所有按钮、图片和定时器明确归属轮次及版本，旧命令不得作用于新轮。取下命令核验目标轮次/版本，不因另一位回执改变全局修订号而拒绝正确点击。

纯手动或视觉不可靠时，确认有效格口后 3000 ms 结束本轮、恢复等待；这不是物理移出。自动重复抑制继续保留，持续原包/原码不重报。有编码位只有可信新到位才能开始新业务；新车同码允许，原 CommandId 重放不允许。有编码位只由可信换车开放下一次提交，视觉空盘不重新触发。

轮次建立依据与提交来源分开：可信在位建立的轮次在 PDA/键盘补录后仍按到位变化结束；补录来源只决定本次请求来源和失败后的人工确认责任，不把该轮改成纯手动。纯人工建立且没有可信物理轮次依据的作业，或当前视觉不可靠的作业，成功后沿3秒显示恢复。人工/PDA失败仍必须明确点击取下，进入 RequireRemoval 后视觉移出不替代操作。

## 恢复与格式

Parcel DB14 持久保存轮次、本位到位代次、车号、提交关联及远端责任事实，配置仍为 schema3，并提供独立 ReadTimeoutMs。当前轮次占用、真实在途和历史 Unknown 分开。结束时间、原因、筛选快照、原请求关联及人工确认可查询；无码轮次不是伪造空条码作业。

原请求编号、原始响应、回执事务、永久身份和 Unknown 保管沿用现有机制。重启不重发原请求，不重新给予自动期限；未发送的旧轮按中断结束，已尝试的不确定调用保留 Unknown，原始响应已落盘的可本地补应用。恢复当前人工失败责任及自动抑制；已结束轮次的晚到结果不恢复到作业页。

只接受当前 DB14 基线，写入前拒绝旧格式并保留原 DB/WAL；不兼容、不迁移、不清库。开发使用隔离目录，现场重新安装使用当前格式；旧原件另行保管。完整备份包含轮次表，清理不删除未结束轮次或其原请求依赖。停止后的现有保留期维护在完整备份核验后，压缩已结束且原作业已安全退休的原始观察/图片，保留轮次、请求、结束原因及原始证据哈希审计；未提交轮次适用同一备份围栏。图片删除失败留待下一次合法维护。

记录页按时间、投递位及条码/轮次/请求号查询，也可选择结果、结束原因或识读情况。识读列区分多码、无合法码、排除码、超时及异常；自动超时后人工补录仍可按自动超时检索。物理移出、人工取下和成功显示结束分别查询，不混同为物理离位。

## 测量与验收

输入完成指输入决策及异步交接完成，不代表 RCS 完成。独立关联输入耗时、实际 RCS 尝试时长、轮次起止及结束原因；不能相加阶段 P95 或把输入缩短宣传成端到端加速。

输入处理器直接返回处置事实，不从作业卡的最后输入反推。持久输入回执、阶段日志和本运行计数共用 `PhysicalEvidenceProcessed`、`AutoRepeatSuppressed`、`NoFormalCandidates`、`UntrustedSource`、`Expired`、接纳、重复或受阻等结果。合法在位和重复观察可以没有新的作业卡输入；它们只关联原 RoundId/OperationId，不能为统计补造输入或覆盖人工条码、格口。处理失败仍保留未完成输入及真实守卫。相机输入、人工命令、轮次及外呼事实分别统计。

尚未完成：目标工控机及物理PDA验收、真实SDK双相机联机、现场在位样本、客户RCS联调、至少真实班次的异步任务/内存/句柄持续运行验证。CI的合成在位事件、原生键盘注入和短回归不替代这些证据。当前未执行现场重装或部署，旧格式原件须保管。

必要验收覆盖 T01—T18：筛选/纠正/期限、无证据等待、一次提交竞争、发送前结束零外呼、A/B 乱序、旧按钮与图片、3 秒后防重、人工失败确认、双位/多窗口/PDA、崩溃及 Unknown/备份责任。PDA节奏使用所属窗口原生消息中的键时间，字符与回车共用同一来源时钟，不拿延后的WPF派发时间推断扫描速度。Windows 原生、真实 SDK、客户 RCS、在位样本与现场持续运行分别计证，未运行不宣称通过。

## 相机物理证据实现与适用边界

### 样本复核工具

复用管理中心连续采样及诊断导出，保管原 ZIP、`frames.jsonl`、来源提交、设备/IP/序列号、相机会话、帧号、时钟证据和独立标注。导出的 `images/*.pgm` 是原始 Mono8；当前件归档的原始 Mono8 PNG 也可回放。不要使用预览缩略图、截图或有损转换。复制[清单模板](../../config/tray-presence-samples.example.json)，逐帧填写原文件 SHA256、尺寸、会话、帧号和相对时间；模板占位符故意不能执行。明确空盘校准的帧须有操作员空盘标注，其余帧可以未标注，不能以模型自身输出当真值。

```powershell
dotnet tests/Ipc.Application.Verification/bin/Debug/net10.0/Ipc.Application.Verification.dll --sm-presence-replay D:/samples/capture/manifest.json D:/samples/review-new.json
```

该离线开发工具使用生产 `MvsTrayPresence`，不加载 SDK、不创建业务或 RCS 请求。源文件只读，拒绝路径逃逸、哈希/尺寸变化和会话倒退，输出必须在原样本目录外且是新文件。每个会话重建模型，帧号缺口打断连续性；只有显式标记才校准。报告保留参考哈希、曝光/差异、稳定帧数和时间跨度、未知/未标注帧及“标注在位却判空盘”数量，不自动出具合格结论。

`HostElapsedMs` 是复核清单中的时间证据，`ClockBasis` 明确为经独立核对的主机单调时间、仅采集墙钟或合成时间。诊断导出的 `CapturedAt` 可用于墙钟回放；没有独立主机单调证据时不能填 `HostMonotonicVerified`，也不猜 SDK 时间戳单位。墙钟回拨、缺帧或未标注导致无法核对的部分保持未知。视觉移出诊断的连续性仍须真实样本核查，不作为有编码位的提交门槛；回放通过不替代运行会话、真实 SDK 和现场验收。

MVS软件路线与MVID原生路线都在同一MvsAcquisition中取得完整、紧密排列的Mono8原图。校验IP/序列号、会话、递增帧号、尺寸、载荷及丢包后，才采样物理证据；SDK借用图像先释放，再交付Application。设备时间戳没有宣称与主机同步，判定使用主机单调采集时间。MVID返回的条码列表和软件识码结果均不参与物理判断。Scene只用于放稳识码；RCS车号决定到位，状态文字不作上件证据。

设备与诊断的相机详情提供“确认空托盘并校准”。每次执行重新核验管理授权、窗口归属、相机会话健康及本位无当前轮次。操作员须确认画面真实为空；软件不能从未知第一张图自行证明空盘。校准以明确确认后的首个有效帧冻结候选，采集至少3帧、800ms稳定参考；期间画面变化、曝光异常或连续性中断就明确失败，必须重新操作，不滚动学习后来放入的包裹。参考按会话持有，不跨重启、重连或设备替换复用，不自动适应背景，防止静置包裹被吸收为空盘。校准属于开工/恢复时的设备设定，正常逐件循环无需人工确认。该新增操作不改写配置账、业务格式、编号或既有原请求。

每个有效帧以192×128网格采样，使用差值中位数消除小幅全局亮度变化，差异超过24灰阶的样本占比≤0.1%为空盘候选、≥1%为在位候选，中间输出未知。全局亮度变化超过12灰阶或近黑/饱和样本达到20%时输出未知。在位至少3帧且100ms，移出至少3帧且800ms；相邻有效帧间隔超过500ms重新累计，帧号缺口同样打断连续性。连续状态约每秒更新证据及参考哈希、尺寸、差异比例、亮度差、帧数和时间跨度；移出候选累计期间保留最后已确认的在位状态，完成800ms才切换为空盘；曝光等真实失效立即输出未知，不掩盖失效。Application不将超过1500ms未更新的在位证据视为可靠。识码暂停仍观察物理状态；有效到位及缓存边界完成后不再要求视觉Present才能正常识码。软件识码与采图并发交付共用发送顺序，旧解码仍按采集时刻受取下边界限制。

现场必须核验：最小及最大包裹、与托盘相近颜色/纹理、透明/反光包装、手臂遮挡、托盘位置偏移及更换小车、光照/曝光/焦距变化、振动、GigE丢帧，以及两件无可见空盘间隙的连续投放。模型需要相机固定、空盘画面可重复且包裹在网格中具有足够可见差异；小物件或与空盘视觉不可区分的物体不能仅靠图像保证检出，必须用现场样本证明适用性，必要时改变视角/照明或增加物理传感证据，不能调低阈值伪报验收。当前阈值为代码模型基线，尚未获客户现场样本资格。移动中只确认“有可见物体”，识码仍受放稳门槛约束。

## WP-LIA-01 安装与卸载原操作恢复

**目标与闭环：** 用户知道是哪次操作、目前提交到哪里、保留什么、可以做什么；关闭/重启后能够核对并续办原清单。终态来自可信记录，不来自窗口退出码或目录存在。

**涉及模块：** `Ipc.Desktop/StartupSetupWindow.cs`、`ProductMaintenanceWindow.cs`；`Ipc.Assembly/ParcelStartupServices.cs`；`Ipc.Platform/WindowsDeploymentMaintenance.cs`及现有安装进度/请求/回执模型。优先补投影与连接；若安装还缺可稳定寻回的原操作身份，扩展现有受保护记录，禁止另起日志作为第二权威。

**实施顺序：**

1. 定义用户可见的操作对象与状态表：尚未提交、执行中、已提交待系统投影修复、已完成、已退役待清理、需Windows重启、额外文件保留、证据不足。状态间转换必须能追溯到已有回执和登记。
2. 安装Unknown加入只读“核对本次安装”，可刷新/复制摘要/按真实状态去首配或修复；关闭后从同一介质找到原操作。未知不得再次提交；核对失败保留证据和输入。
3. 卸载界面消费完整`WindowsRemovalReceipt`，把原数据保留与异常残件分开。退役阶段从同源完整介质进入固定清单续办；保留必要UAC/清单校验，不依赖已移除的管理服务。
4. 明确取消只对尚未提交阶段生效；进行中关闭/超时与“取消安装成功”不可混用。主按钮、焦点、Enter/Esc根据实际阶段变化；结果页可复制状态和原回执位置。

**现行指引清理：** GD03/GD04；单EXE、startup-deployment、commercial operations中所有成功/中断继续说明按状态表更新。原PR107卸载终态修复及历史证据保留。

**必要验证：** 现有helper/回执测试加边界用例；在可回滚VM或专用隔离Windows中，实际单EXE/系统卸载入口、UAC拒绝、提交前后断管、重复点击、占用文件、额外文件、退役后中断、原EXE已删除、重启后复核。对每次执行记录源SHA/介质hash/登记/回执/原生截图。无环境先完成纯状态读取与模拟验证，安装验收仍NOT_RUN。

**验收标准：** 每一种实际状态在UI有唯一、真实的解释和合法下一步；只读核对零重复安装；续办零清单外删除；无原请求重发；原配置/身份/秘密/业务数据/扩展/共享驱动保留；被拒动作说明解除条件；终态确认必须读回。陌生实施人员按任务卡M02/M05完成，无需阅读JSON或源码。

## WP-LIA-02 保存、停止、重新启动与生效核对

**目标：** 把运行内参数保存和主窗退出连成可追溯的应用流程，保留“稍后应用”。不把配置保存强制变为立即停机。

**模块：** 共享参数ViewModel/ConfigurationSubmission/SaveReview、Sportmaster根窗口/辅助窗与CloseGuard、ParcelApp启动/停止、ParameterRuntimePresentation；通过Application现有契约预检，UI不自行判断是否可重发/清责。

**实施顺序：**

1. 结果页显示运行修订、待应用修订、变更对象和影响；新增通往现有受控退出流程的入口。无更改/保存未知不能显示“已应用”。
2. 根退出预检汇集未清责任、未保存窗口、Pending及重新打开位置。正常辅助窗保持轻量；有实际影响才要求相称确认。不能为了退出强制删除/重新发送Unknown。
3. 复用排空、StopOwner和部署启动机制；停止失败继续持有资源并可恢复界面。不得通过启动第二实例或改变SID提权完成重开。
4. 下次启动展示实际Effective/失败修订及连接待配置/健康/准入差异；失败保留原账和证据，明确修正或恢复路径。重连继续用运行配置并解释。
5. 到期、退出管理模式、关闭确认期间输入有明确归属；需要落盘就走现有加密草稿，不静默复制凭据到新文件。

**指引：** 参数V3、parameter-refactor、management-mode、startup工作包仅更新本包新增行为；不重写四类归属、统一供包台编号或PR107已完成字段。旧请求固定原版本、原报文、原目标写入验收。

**必要验证：** 定向覆盖A→Pending B→Effective B、B启动失败、保存Unknown、权限到期、重复关闭、多窗/多草稿、停止超时、关闭期间迟到回执、再启动与原请求恢复。当前主窗口/实际部署启动至少各一条原生全链；100%/125%实际DPI与最小受支持分辨率分开记录。

**验收：** 用户在每步均能指出“编辑/草稿/已保存待应用/运行中”；状态与账一致；能取消退出保留上下文；生效后有读回依据；无自动Resume、无新旧目标混发、无导航重建实例。任务卡M03/O04有独立观察记录。

## WP-LIA-03 历史查询范围与对象上下文

**目标：** 看到的列表、详情、页码和导出都明确属于同一次查询，能用业务对象名称找到记录并前后核对。

**模块：** `HistoryEditing`、`ParcelTargets`、`HistoryPage`、当前Position角色映射；尽量不改后端查询/导出。保持固定上界、原文、前导零、归档和发送尝试计量。

**实施顺序：** 统一条件变更通知及dirty状态 → 展示已应用范围摘要与未应用提示 → 投递位选择使用名称+稳定ID并保留历史位 → 页游标栈支持前后浏览 → 导出动作与范围状态一致、完成后可定位文件/回执。取消和失败保留旧结果时明确其归属，禁止静默重查扩大范围。

**指引清理：** 原作业记录指南同步“范围快照/当前编辑条件/详情对象”区别；日志保持自身已有实现，不借机重建共用万能查询框架。

**必要验证：** 三页合成数据、左右同码、已归档/当前作业、查询后新增记录、时间含/不含边界、长ID/前导零、编辑后直接翻页/导出、查询期间再改条件、取消导出、已有文件拒绝。原生UI必须接真正`IParcelHistoryApplication`；先明确夹具能力，不让fallback导致假阳性或假阴性。

**验收：** 未应用条件立即可见；前后页保持同一上界，选中详情始终为原作业；名称选择正确映射ID；导出行数/字节/hash与固定范围相符，部分文件不冒充完成；键盘可以选择、查询、翻页、复制、取消，不困在滚动容器中。O03/M04现场观察通过后才评价习惯匹配。

## WP-LIA-04 当前岗位指南与交付身份

**目标：** 给不读源码的人一条可照做的当前路径，同时保留所有历史材料的身份。

**范围：** INDEX、getting-started、startup-deployment、commercial operations、single-exe、windows-delivery、管理模式和参数增量索引；不修改原验证日志、SourceCommit、D/RV批准或私有资产。

**步骤：** 以GD01–GD07为处置清单 → 建立“最新源码/当前可交付介质/已安装现场版本”三栏 → 正常与恢复入口分别按窗口文字编写 → 用当前安装形态核对截图/步骤 → 历史页加日期/版本范围与指向当前入口的链接。缺功能写明缺口，不提前承诺。DirectPlc/WcsToPlc明确参考壳与真实资格，不能复用SM任务完成声明。

**验证与验收：** 链接/版本/命令/控件名称核查；每一个“已通过”均能对应源SHA、介质哈希、环境和实际执行范围；每个“点击某入口”都能在对应版本实际找到；隐含的安装高权限不混同操作员或管理模式。先交一份可评审文档，随01/02/03实施逐项更新。

## WP-LIA-05 原请求交接与现场验证

**目标：** 操作员能把正确实体和原请求交给有权维护者，维护者能取得权威事实后按合同继续；收集真实人因证据。

**可立即完成部分：** 复用原作业详情/原请求/原回执/阻断原因形成可复制交接摘要；包含工位/侧、扫描时间、原请求身份与目标版本、已知/未知事实、禁止重发提示、实际维护入口。敏感信息按已授权范围呈现，不把SDK/凭据/生产原件上传外部服务。增加“为何不可核对/恢复”的具体能力说明。

**外部依赖：** 获授权的RCS结果查询或人工裁决流程、去重/重试语义、角色权限、现场实体保管责任、机器/设备资格和编号范围。未取得之前，不实现假查询、不自动重发、不宣布Unknown可闭环；不编造批准人。

**必要验证：** 用固定原请求在真实许可测试环境验证未发送/已发送未接受/已接受未回执/回执冲突/迟到结果；逐个确认查询无副作用和恢复条件。DirectPlc/WcsToPlc另核PLC接受与物理完成。按[任务卡](evidence-and-field-plan.md)开展操作员及实施维护观察，记录提示与恢复，数量按风险/角色覆盖决定，不预设虚构完成率。

**验收：** 技术合同证据、原生交互、真实用户观察、现场设备结果四类分别归档；G01有明确可执行流程或保持阻断。仅在取得相应证据后更新关联D/CAPI/RV状态；本包局部通过不关闭全部历史评审。

# 投递位启停

SM 左右投递位各有“启用 / 停用”按钮，普通操作员即可执行。两位初始启用；状态随本站数据保留。启停与相机配置、相机是否在线分开，启用位可独立通过键盘或扫码枪供包。相机离线只在底部设备信息区提示，不使整个作业区变红。

## 状态与责任

| 当前条件 | 点击停用后的行为 |
|---|---|
| 没有当前轮次 | 已停用，拒绝新条码，主动释放相机，继续心跳 |
| 当前轮次尚未结束 | 停用中，拒绝新条码，保留原请求与相机连接，继续心跳 |
| 停用中，可信移出或本轮人工确认使轮次结束 | 自动变为已停用，释放相机，不等待旧请求结果 |
| 停用中点启用 | 取消停用，保留原请求，不重新发送 |
| 已停用点启用 | 恢复准入条件检查和对应相机连接，另一位不变，心跳持续 |

可信移出来自当前相机会话显式校准后的空盘模型，不以无码、换码、小车 IDLE、计时器或显示到期推断实物离开。当前人工/PDA请求失败或视觉不可靠的请求异常进入人工确认分支后，必须取下后点击本轮“已取下包裹”，视觉移出不替代点击。该分支的停用提示明确写出这一步；可靠视觉确认移出则无需点击。人工或视觉不可靠的成功结果沿原规则在3秒后结束显示轮次，保留自动重复抑制；可靠视觉仍在位则等待移出。重启按轮次恢复规则处理，不以重启证明原包裹离开；原请求未确认时保留原编号、报文和目标，新班次不恢复已完成的旧作业卡。

## 相机与心跳

已停用位启动软件时不连接相机，保存相机参数和显式重连也不能绕过启停状态。Application 沿现有设备锁和资源守卫停止相机，退役旧会话后再释放，旧回调不能进入当前会话。停止返回成功后才发布“相机已断开”；释放失败记录完整异常、保留占用并阻断自动重连。启用后沿既有连接流程重新打开该相机。停用中保留相机采图及必要恢复，以确认原放置结束。

心跳沿原协议，不新增状态字段。所有已配置的有效相机编码在启用、停用中和已停用时均持续发送，两位都停用也继续。没有有效编码时不发空报文、不伪造身份。投递位启停不清除 RCS 连接确认；停用中和已停用位的小车提示由 Application 撤下，晚到响应也不能恢复绿色可投包。具体报文见 [RCS 心跳](../runtime/rcs-heartbeat-01.md)。

## 持久化与界面

Application 对每个位使用独立控制修订号，避免相机持续观察造成无意义冲突。命令回执、控制状态和审计在同一 SQLite 事务写入；重复命令返回原回执。启停事实使用独立审计所有者，不随包裹历史清理删除，不修改数据库格式版本。记录页可按游标查看时间、投递位、操作、操作人和当时任务号。

按钮至少 44 DIP 高。停用中显示取消方法并保留本件结果；已停用显示灰色区域和启用按钮。扫码目标不能停留在停用位；已有目标停用后移到另一启用位，两位均停用则清除目标。左右结果区保持对齐，小窗口仍保留启停状态、格口和提交动作。

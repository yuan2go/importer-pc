# RCS-TIMEOUT-ERRORS-01

2026-10-26，起点 main `77d2db61`，分支 `codex/rcs-timeout-errors-01`。开工远端无开放PR，原工作区四个未跟踪附件未修改。

需求：组件配置增加取格口请求超时；超时提示重新扫描；无有效格口时展示拆包或其他异常的message。复用现有HTTP适配器、配置账、原请求/回包保管和双位投影。

本包替代旧RCS说明中仅系统调用预算和通用拒绝提示的当前行为。历史协议、测试、D/RV及发行身份不改写。公开变更只含通用代码、合成接口夹具和必要说明，不复制用户接口全文、示例业务标识或真实地址。

新增不可变组件版本 `1.3.4`。`request-timeout-ms` 属组件，默认5000毫秒，范围100～30000，覆盖连接及响应读取，保存后受控重启生效。新版本省略该项也采用5000；旧内置绑定保留原预算/身份，已有冻结报文不改写。业务层使用冻结的组件超时，避免较短的通用预算提前截断。超时保留未知结果和一次发送；读取超时保留收到的响应前缀、hash及Complete=false。

只有关联匹配、success=true且格口有效才显示格口。有效NEED_UNPACK保留独立状态及完整拆包明细。其他拒绝直接显示message，缺失则回退code。关联匹配但缺少/空白格口时保持未知并展示message；非法JSON或关联不匹配使用通用异常，原件保留。

超时后立即允许新请求，还是核对原请求后重新扫描，已向用户提出选择，尚未收到答复。当前只实现提示，保留未知请求阻断，不把提示当作放行。该业务策略仍待确定，本包以草稿PR交付独立完成部分。

验证及边界见[运行记录](../runtime/rcs-timeout-errors-01.md)。不操作真实RCS、设备、安装、注册表或生产数据。

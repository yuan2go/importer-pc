## 1. 验证范围的选择规则

每次修改先回答“哪个事实、权限边界或失败恢复行为可能变化”，再选择下表中对应场景。优先复用已有有意义的检查，只增加能够证实新风险的缺口检查；不为每个属性、按钮或内部调用写一组镜像实现的测试。

|变更类型|必要检查|何时扩大范围|
|---|---|---|
|纯文档/索引/提示词|变更文件来源与边界、相对链接/锚点、清单尺寸和哈希、敏感内容、Git 差额与远端回读|出现具体链接/清单/来源冲突时修复相关条目；不因此启动全部业务测试|
|文案、布局、导航|受影响窗口构建；在 Windows 上走实际任务、焦点/可读性与辅助窗口状态；复用已有 ViewModel 行为验证|触及公共资源、Dispatcher 或共享 Shell 时覆盖实际受影响页面；不重跑无关迁移/全部协议场景|
|配置、首配、安装、权限|对应持久边界/身份的定向检查，加受影响装配构建；涉及 Win32/UAC/ACL 的部分必须原生验证|共享 MachineRuntimePolicy、装配契约或路径格式改变时，覆盖所有真实调用入口和支持组合；不只验证新向导|
|业务守卫、恢复、持久数据|受影响流程的状态/原请求/失败前后证据检查及必要重启场景|修改共享仓储、SQL、请求身份或资源生命周期时扩大到依赖它的 Application；历史未改路径可引用原证据但不能冒称新运行|
|打包、更新、扩展组合|固定新源码产生精确产物；检查实际文件集合/合同/包闭包与来源；从解压或安装后的介质做启动/停止冒烟|宿主契约、公共 DLL、加载政策或目标架构变化时验证受影响精确组合；不以开发目录运行替代发布介质验证|

共享修改覆盖 Sportmaster、DirectPlc、WcsToPlc 及实际受影响的 Supply/Inspection 入口；不把此要求解释为补做延期的 DirectPlc 完整 UI。一个场景可覆盖多个验收编号，结果中列明映射即可，不为凑编号重复执行。

## 2. 风险验收清单

### CPV-01：文档先行与唯一现行入口 — COMM-00

- **基线：** README 与 INDEX 有较旧“当前”描述；框架/F 决策有历次增量；原审查与结果是形成时证据。[核对与清理清单](../../reviews/commercial-productization-01-baseline.md)已给出处理边界。
- **必要证据：** 编码前记录所读工作包、设计、相关运行维护说明与源码差额；当前入口指向本包；七份被收敛的旧文档原字节可核验；改动文档链接、哈希和清单一致。既有历史资产问题与本包新增问题分开统计，不增加无依据豁免或修改历史文件换 PASS。
- **环境/阻塞：** 仓库内容即可完成；远端有并行变更时先核对再更新，不强推。
- **状态：** NOT_RUN；本次实际文档检查由交付记录单独报告，不改写本计划为运行通过。

### CPV-02：安装位置与部署提交 — COMM-01 / COMM-07

- **基线：** 原生四步向导已存在，程序目标固定于 Program Files，受保护并排发布后最后提交部署登记；已有实现不代表全部 Windows 故障路径已验。[源码](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Platform/WindowsDeploymentSetup.cs)。
- **必要自动检查：** 新程序位置从选择、规范化、摘要、受控请求、helper 到回执/启动/维护保持一致；数据根、程序根和备份目标不混淆；源介质/配置/信任在预览后变更被拒绝；失败保留原登记及原数据。按实际新增写入边界选择中断点，证明未提交、已提交和需清理的部分可辨认，不能把局部成功说成全部未发生。
- **必要 Windows 检查：** 默认路径与一个受支持的自选本地受保护路径完成安装；覆盖中文/空格的代表路径、权限不足和重解析路径拒绝；UAC 取消及一处实际部署失败后旧启动入口仍可核验。自选目录应按公开支持条件接受或明确拒绝，不静默改用别处，不对无关已有目录递归改权/删除。
- **环境/阻塞：** Win32 ACL、重解析点、快捷方式和提权链需要真实 Windows；网络盘、移动盘等未声明支持的路径不能凭跨平台检查声称支持。
- **状态：** NOT_RUN。

### CPV-03：指定运行账户与提权隔离 — COMM-01 / COMM-03 / COMM-07

- **基线：** 最终共享政策允许指定 SID 的非提权 UAC 过滤账户，拒绝错误 SID、实际提升及系统/服务账户；Supply/Inspection 已补同一前置门禁。[政策与来源](../publication-deployment-20261019.md)。
- **必要自动检查：** 使用原共享身份判定测试覆盖实际变更；所有正常入口在配置/持久资源初始化前执行门禁，独立维护走其授权入口；安装/维护不会静默重新绑定已有 SID。拒绝前后原配置、DB/WAL 和业务数据文件集合保持，独立诊断写入单独列明。
- **必要 Windows 检查：** 指定标准账户与指定 UAC 过滤账户可正常启动；错误账户、实际提权运行和系统/服务身份按最终政策拒绝；安装授权可由不同维护账户完成，读回的运行归属仍是选定账户；匹配 helper/受保护文件被换版本或改字节时拒绝。
- **环境/阻塞：** 真实令牌、跨账户授权和 ACL 必须原生验证；字符串 SID 夹具和源码顺序检查不能代替实际令牌。
- **状态：** NOT_RUN。

### CPV-04：组件选择、独立信任与前置条件 — COMM-02

- **基线：** 离线包经已有扩展设施安装，依赖处理与独立信任存在；安装不创建业务运行实例、模块或 SDK。[装配入口](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Assembly/ParcelStartupServices.cs)。
- **必要检查：** 目录选择只允许当前 Application/架构/合同支持的精确组合；必需依赖缺失、版本冲突、错误签名、文件变动和 Production 测试信任分别给出可执行诊断；失败不以已安装清单伪造激活。组件未选择时不出现无关必填页；选中且业务必需的能力缺失时不允许开工。厂商驱动安装失败/重启待完成状态不被直接标为 Ready。
- **环境/阻塞：** 包校验可用获授权合成夹具；真实厂商安装器、SDK 和硬件的版本/分发资格及原生行为需要相应输入，缺失时不能生成虚假成功。
- **状态：** NOT_RUN。

### CPV-05：首次配置、退出继续与数据身份 — COMM-02 / COMM-08

- **基线：** 当前安装输入是 `business.json` 来源目录；已有离线维护复用唯一配置账，拒绝用新 seed 绕开数据根内原站/模式。Production 的 `ports.Validate` 另要求精确配置资格，现有离线 Validate/Stage 直接使用该校验。[ValidateSeed](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Assembly/ParcelStartupServices.cs)、[ReadState / StageAsync](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Application.ParcelFlow/ParcelStartupMaintenance.cs)、[ValidateDeployment](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Assembly/ParcelCapabilityFactory.cs)。
- **必要检查：** 全新站、已有正常配置、未完成首配、损坏账、DB 存在而配置账缺失分别路由；中途退出/重启保留可说明的草稿且不生成可生产假象；已有配置不反复强制首配。原站点修复不能通过改站号/模式/根目录创建空账规避责任。站号、真实设备稳定 ID、左右角色、RCS 所需参数进入同一候选及修订链；重复设备绑定或必需信息缺失有明确阻断。设备未在线或资格缺失时可保存允许保存的非生效草稿，准确列出未完成项；满足完整部署校验后才能 Stage 为 Pending，不能用草稿保存绕过原准入。
- **环境/阻塞：** 流程与持久身份可用合成数据验证；真实枚举/设备身份稳定性需厂商接口与设备。首配不能要求对端成功执行业务请求来证明参数有效。
- **状态：** NOT_RUN。

### CPV-06：配置草稿、CAS 与生效原子性 — COMM-03

- **基线：** 现有 Stage 保存 Pending、保留原配置字节、复核 hash/owner；不构造设备，不改原 DB。运行生效仍由原 Application 链负责；当 `Confirmation.Required` 时，当前启动不尝试 Pending 而先校验/创建 Effective，存在首次坏配置难以通过离线 Stage 修复的静态风险，尚未复现。[维护实现](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Application.ParcelFlow/ParcelStartupMaintenance.cs)、[启动条件](https://github.com/yuan2go/importer-pc/blob/b8f449ec91f8f7efd8bc5079ca38e19bc877ebf5/src/Ipc.Application.ParcelFlow/ParcelRuntime.cs)。
- **必要检查：** 两个维护草稿竞争时旧版本不能覆盖新值；表单切换、异步校验、失败与返回不清除当前输入或写入过期结果。保存、Pending、激活中、Effective、失败各有准确回执；激活失败保留旧有效值和仍持有的资源/包租约。停止未完成不能接着启动第二实例。若修改提交边界，覆盖一次提交中断后重读，证明状态与实际账一致，无第二权威配置。修改上游地址只影响获准的新请求，历史请求不随之迁移。
- **必需修复场景：** 构造未确认 Effective 持续启动失败的合成案例，验证新候选经过同一 owner、原责任检查和完整资格校验后具有可完成的受控修复路径；存在原未决责任时保持相应拒绝。保留原配置/确认字节与审计，不得以直接清除确认标记或清账绕过门槛，也不能让坏 Effective 先成功成为修复前提。Production 候选缺资格或配置 hash 已变化时保留可继续草稿并拒绝越级 Stage/激活，不复用旧 qualification 换取成功。
- **环境/阻塞：** 账本/CAS/生命周期用受影响测试验证；维护授权/ACL 与实际重启入口仍需 Windows。未触及旧迁移 SQL 时不为此全量重跑全部旧版本。
- **状态：** NOT_RUN。

### CPV-07：独立 Application、角色与连续作业 — COMM-04

- **基线：** 当前框架要求打包选择独立主流程、多页共用实例，登录按确认策略可选。[框架](../../design/framework.md)与[UI 状态](../../ui/STATUS.md)。
- **必要检查：** 进入记录/设置/报警、打开辅助窗及切换布局不重建 Application、reader 或发送器；左右通道事实独立，设备回调不依赖文本框焦点。登录启用/未启用两种已支持策略下，操作员和维护动作执行实际 Application 命令守卫；按钮禁用不代替命令授权，业务登录可选不取消 Production 所需维护认证能力。连续扫码时保留前导零、长码和明确受理反馈，不能因刷新重复提交、丢草稿或把新扫描写入错误任务。
- **环境/阻塞：** 共享实例/业务守卫可自动验证；扫码输入焦点、模态/辅助窗、键盘与目标触控必须 Windows。真实换班/权限规则不足时保持相关路径未放行，不发明客户角色批准。
- **状态：** NOT_RUN。

### CPV-08：分层健康、连接恢复与动作证据 — COMM-05

- **基线：** 已有启动诊断与库存诊断；健康、时效和业务准入是独立概念。[框架 §5/9/10](../../design/framework.md)。
- **必要检查：** 缺依赖、未配置、已安装未激活、连接失败、过期/Unknown、对端拒绝和业务阻断显示不同原因及下一步；旧连接代次与过期快照不能保留绿色状态；重连不会自动恢复失效许可。只测试连接采用无业务副作用方式；合同没有此方式时准确说明检测边界，不能发送真实任务替代探活。告警确认与清除分开，打开辅助窗仍能发现关键阻断。
- **环境/阻塞：** 版本/代次/过期与受控断链用现有夹具；设备连接和外部探测方式按真实合同验收，不能从网络可达推断业务可用。
- **状态：** NOT_RUN。

### CPV-09：Unknown 与原请求责任 — COMM-05 / COMM-07 / COMM-08

- **基线：** 原请求固定身份、原报文、目标、合同及精确版本；Unknown 不允许通用重发。[框架](../../design/framework.md)、[RCS 说明](../sportmaster-rcs-task.md)。
- **必要检查：** 选取实际受影响的超时/重启/配置改址/升级或恢复场景，核对原 request/attempt、raw、目标与合同未被改写。发生发送后无权威结果时保持待核对；操作员恢复、重连和“重试启动”不能重新 Execute 或清除阻断。若合同允许结果查询，按原身份 Query 并保存权威证据；不支持时保留明确人工/外部核对出口。请求成功、请求拒绝与实体物理完成不得互相替代。
- **环境/阻塞：** 持久语义可用现有防重/重启夹具；真实 Query、幂等与结果解释需合同。此项是改动恢复/发送链时的必需门槛，不能用“减少测试”省略。
- **状态：** NOT_RUN。

### CPV-10：历史、指标与导出 — COMM-06

- **基线：** 既有事实模型区分 Operation、Request、Attempt 及接受事实，历史数据属于原账。[框架 §6–10](../../design/framework.md)。
- **必要检查：** 同条码的不同作业仍可分别查询；请求/尝试/响应详情关联正确，取消旧查询不覆盖新筛选结果。选择有代表性的日期/时区边界、长码和导出格式即可；列表、详情和导出的口径一致。条码/格口/请求 ID 保持字符串与前导零，面向电子表格的格式用公式型合成输入核实安全文本语义，不把 CSV 加引号当充分证明；必要转换与精确原文可追溯。Sportmaster “取得格口”仅表示相应响应事实，不能作为物理分拣完成量。大范围导出有页/条数/字节预算、取消和容量反馈，不全量载入内存、不阻塞操作 UI 或泄漏未选数据。
- **环境/阻塞：** 使用合成历史记录及受支持导出格式；真实业务 KPI 未定义时不生成未经批准的效率/完成率。无必要不建立通用压力基准工程。
- **状态：** NOT_RUN。

### CPV-11：升级、迁移与失败保留 — COMM-07

- **基线：** 当前并排部署保留原 seed/数据，最后提交登记；旧 DB 升级和原件恢复有既有维护约束。[安装结果](../startup-deployment-02-results.md)、[质量恢复维护](../architecture-quality-closure-01.md)。
- **必要检查：** 新媒介预检展示程序、配置、DB 与精确扩展的兼容性及原责任；升级前的停止/所有权、完整备份、空间与外部未决条件必须真实检查。针对本次变化选取关键中断边界，验证重入可判断原状态；失败不静默删除原库、租约、seed 或已记录责任。若修改迁移，覆盖实际支持的入版本、未决责任及不可逆边界；不能以换回旧 EXE 声称 DB 已回滚。备份落后于外部世界时恢复仍进入核对隔离。
- **环境/阻塞：** 可先验证文件/账本/SQL 逻辑；Windows 文件占用、ACL、启动登记和安装中断需原生。未改迁移范围不追加无关版本笛卡尔积测试。
- **状态：** NOT_RUN。

### CPV-12：修复、系统卸载与保留政策 — COMM-07

- **基线：** 原 WPF 安装提供并排修复和开始菜单入口；尚不代表 MSI/系统级卸载已实现。[原交付边界](../startup-deployment-02-results.md)。
- **必要检查：** 所选安装技术具备真实注册、版本识别、修复/卸载操作与可用错误回执；卸载前核对活动实例/共享包引用/未决责任。默认保留业务数据、完整备份及可核验记录；需要删除时明确列出作用域并由用户执行相应操作，不能递归删除外部目录、其他产品、仍被引用的扩展或厂商共享驱动。失败/取消后登记与实际文件一致，遗留内容可说明、可处理；修复不重置站点身份和配置账。
- **环境/阻塞：** Windows“已安装应用”、安装器机制、文件占用和实际权限必须原生验证；有卸载命令或编译通过不等于可验收卸载。
- **状态：** NOT_RUN。

### CPV-13：完整备份、原站恢复与新站模板 — COMM-08

## 3. 执行与留证

实施结果按工作单元列出适用 CPV 编号、实际检查、源码 SHA、介质 SHA256、环境及状态。一次场景覆盖多个编号时保留一份原始证据并交叉引用；不复制日志制造验证数量。失败保留原始结果，修复后追加新结果；测试本身过期时说明行为依据和差额，不删关键断言换 PASS。

结果只使用有范围的状态：PASS、FAIL、NOT_RUN、BLOCKED。NOT_RUN 表示未执行；BLOCKED 必须列出缺失的具体 SDK/合同/设备/账户/环境及其影响，不能泛写“环境限制”。下表明确升级结论所需的证据：

|可以作出的结论|必要依据|
|---|---|
|文档工作包已交付|设计/实施逻辑/验收/提示词齐全，现行入口收敛，文档差额检查完成，实际提交推送并回读；不暗示业务代码已实施|
|某工作单元的软件实现已完成|该单元全部适用的软件路径已实现，受影响构建和必要检查有证据；剩余原生/真实输入逐项列出，不能把尚未完成的软件收口写成外部阻塞|
|某固定参考候选已验证|实际运行和检查对象为同一固定介质，明确验证平台、Application、配置、包组合和场景；没有覆盖的平台/组合不能继承结论|
|Windows 产品体验已验收|实际 Windows 身份/ACL、安装维护与 CPV-15 任务可用性在声明支持的代表环境上通过|
|允许现场商业运行|还须真实 SDK/设备/外部合同/角色规则、未决责任及目标场景验收满足既有准入；不以本包局部 PASS 关闭旧 D/RV 或替代现场授权|

缺少 Windows 或真实设备时，继续完成不受影响的实现、文档和定向验证，提交可复核成果与准确剩余；不得宣称整个商业化工作包验收全部完成，也不为等待外部输入停止所有软件工作。许可收费、集中管控、多语言/OEM 等条件项未触发时不生成空实现或测试平台；若范围后来明确，应先更新设计、边界与适用验收。

## 1. 新的设置工作区

- 在原窗口和同一 Application 中打开专注设置工作区。参数页隐藏重复的日常宽侧栏，用明确“返回作业”返回；不另建连接、VM 或强制登录。
- 左侧一个设置目录：系统、业务模块、驱动、组件四组；组内直接列页面/实例。取消“横向四类标签 + 另一列对象菜单”的叠层。搜索按名称、用途、技术键和实例定位真实字段。
- 右侧单一白色填写区域；正文/输入16 DIP、字段标签14 DIP、页标题至多20 DIP、分组标题16 DIP；字重及离线字体按TYPOGRAPHY-01。统一4/8间距，浅灰侧栏、克制蓝色选中与主要操作。输入视觉高度36～40 DIP，鼠标/键盘表单采用桌面密度；正式关键动作命中区至少44 DIP。
- 顶部持续说明站点、当前作业状态和运行模式；普通暂停使用紧凑状态条，错误/过期状态保留明确原因。软件暂停不是安全急停。参数工作区不常驻左右作业摘要，计时器继续读真实快照；返回作业显示原实例及最新状态，不自动恢复接收。
- 技术键名、实例ID、协议和内部说明移到“技术信息/高级设置”按需查看。不能隐藏必填项、错误或当前选择真正需要的信息；搜索和错误定位自动展开所属字段。

## 2. 四类与字段

系统：供包台标识、数据与记录、自动备份、显示偏好；业务模块：条码筛选、取格口请求、处理参数；驱动：按已安装描述及 Application 固定的左右实例编辑；组件：一个共享 RCS 连接。字段来源和范围沿现有契约/描述，不编造默认和生产值。

取格口 `zoneId/projectId/stationCode` 归系统；请求数量/指定格口和规则归业务；相机取格口 `bcrCode` 按具体实例编辑。心跳 `StationCode/bcr-code` 与取格口身份仍分别维护，不静默合并。新相机数量与左右拓扑由 Application 决定，不作为任意可增删设置。旧配置冲突只在真的检测到冲突时出现。

## 3. 一个可理解的保存流程

日常底部只显示修改摘要、可查看的差异及主要“保存更改…”入口，不要求用户依次执行“检查完整候选/保存准备”。点击后自动执行现有字段与完整候选校验；错误定位并保留全部输入。校验成功后在一次明确审阅中呈现修改、暂停/授权/原因等实际条件；最终提交继续调用现有模型、Application 校验和 Stage/Inspect。

打开保存审阅不绑定 `CanConfigure`，否则未认证者无法进入授权；真正提交仍使用该守卫。`CanConfigure` 的现行条件是已暂停、维护授权、无在途外呼；不擅自扩张为所有历史原件必须清偿。保持 Revision/RuntimeId/CAS、冻结候选、原因及结果核对。忙碌只锁定冲突操作，刷新不重建输入控件。

保存成功只表示待受控重启。已保存、运行中、待确认分别显示；重连不应用 Pending；结果未知先核对上次保存，不重复提交。重启与恢复接收继续沿实际资格，不在此设计中创造自动恢复。

## 4. 取消“维护与迁移”总入口

不再把全部技术能力放进这个日常总入口。按实际任务提供：

| 实际能力 | 新入口和使用时机 |
|---|---|
| 计划/立即完整备份 | 系统 → 自动备份；“立即备份…”明确包含数据库及同名恢复目录，不能伪称只导出参数。 |
| 同版安全模板导入/导出 | 设置次级菜单 → 导入设置模板… / 导出设置模板…；导入预览后仅进入草稿。不能改成任意完整配置导入。 |
| 原机恢复、原账确认 | 诊断/高级工具的具体任务；从故障状态提供带上下文入口。原外部事实核对与独立维护流程保持。 |
| 旧左右站码/旧格式冲突 | 仅检测到旧格式/冲突时提示“需要核对旧设置”，不作为常驻导航项。 |
| 安装、能力库存、JSON、旧策略 | 设置次级“高级工具…”下按实际任务访问，沿原适用性；Sportmaster不显示不适用的称重/图片业务入口。 |

低频入口迁移不得删除真实必要能力。权限、原请求责任和持久化逻辑不由 UI 规避。
